### 冒烟 r1 与格式修正

第一轮冒烟在 dev 预热和 5 条 test 上全部失败，trace 错误为 `Error: unknown format: 3`。原因是冻结 FLEURS 中有 32-bit IEEE float WAV，旧 `read_replay_audio` 使用 Python `wave` 模块读取，无法识别 float 容器；这与部署阶段已经遇到并修复的输入格式问题相同，但回放客户端尚未同步。

修正为用 `soundfile` 读取单声道 16 kHz WAV，按 `round(sample × 32768)` 裁剪到 int16，不重采样、不裁剪、不改变声道。新增 float32 转换与立体声拒绝两项单测，本地与远端各 17 项测试通过。该轮 5 条失败不计入正式分母，证据保留在远端 `runs/smoke-20261022-r1`。

该轮作业退出码为 0，但 5 条 trace 均为失败，暴露了编排器当时只校验计划数、不传播回放失败的问题。轮后已在作业脚本中加入“目标轮与 dev 预热均不得有失败 trace”的判据；正式轮本身 0 失败，故该修正不改变正式分数。

### 冒烟 r2

修正后 5/5 回放成功，0 运行失败、0 协议异常。冒烟 WER 为 27.5%（S 7、D 25、I 1 / 120 词），complete 0/5（4 条只在 `t_end` 前出现，1 条全程未出现）。冒烟只验证协议、时钟、格式和资源，不据此调参，也不进入正式分母。

### 正式 r1

正式轮于 18:40:55 提交，18:40:59 作业开始，18:42:48 服务就绪（102.1 秒），18:43 开始回放，19:08:55 完成评分并退出，作业退出码 0。100 条逐例会话全部成功，服务在结束时停止，`vc list` 与登录节点进程检查均无遗留。1 条 dev 预热单独保存，不计分。
