- 每个 arm 只改 `unfixed_chunk_num`（`0` = 我们的配置，`2` = 官方默认）；`unfixed_token_num` 固定为 5。 各 arm 都在一条事件里同时记录 raw 转写与"只暴露已定稿前缀"的转写，所以两种暴露口径在同一轮里同时被测。
- `raw 改写` = 官方示例口径下模型替换已产出文本的次数；`可见改写` = 我们口径下运行时看到的改写次数，**必须为 0**；
- `提交延迟` = 最终词在"已定稿前缀"里首次出现的时间减去它在 raw 转写里首次出现的时间（即运行时比官方口径晚多久拿到这个词）；`挂起的词` = 每一拍 raw 转写比已定稿前缀多出的词数在**该样本内取中位数**（刻意扣住的可改写尾巴有多长）；`冻结` = 定稿前缀落后 raw 超过 8 个词的最长连续时长（token 级提交修复前的症状）；`提交停滞` = 解码器回改到"已交给调用方"的 token 的次数（正常应为 0）；`最终转写距离` = 与 baseline arm 的**词级**编辑距离中位数。

## 判据

- **可见改写必须为 0**（任一 arm 出现非 0 就说明该配置不能给运行时用）；
- 若 `window-2` 相对 `window-0` 的**可见最终距离中位数明显大于 0**，说明官方窗口会改变我们最终交给模型的文本，此时要看它多花的提交延迟（运行时晚多久拿到词）再决定是否对齐官方；
- 若两者最终距离都为 0 且 `window-2` 的提交延迟更大，则保持 `unfixed_chunk_num: 0`（当前配置）。
