# TT-010 低门槛放行与损失平衡修复

2026-10-26按用户明确指令在现有TT-010内实施，不新增issue。先更新研究范围、工作单及中文损失设计，再修改代码。此次交付是训练前修复与CPU核查，尚未重新训练，也未启动TT-011外部测试。

## 放行标准

正常接话、陈述接话和打断最低成功率各1%，当前开发分母对应8/800、4/400、4/400；陈述属于正常接话子集。保留综合机会分高于初始化基线、停顿误start与附和误stop不超过基线加0.02。要求完整开发推理、正负指标无未知且分母与基线一致。宽松门槛用于排除零能力候选，不能宣称模型质量合格。

每轮先按资格选模，合格full优于合格pilot，同阶段再比较综合分。最终使用实际选中的full候选重新验收，另存online_gate.json和逐项原因，避免沿用pilot放行结果。无合格full候选时不启动外部测试。历史无新门槛配置的行为保留。

用前次真实pilot结果重新检查，综合分改善及两项误动作约束仍满足，三项正例下限均失败，因此新gate明确拒绝全部keep。相关数值与原因见[audit.json](audit.json)。

## 损失函数

完整保留所有轨迹窗口，基础keep权重仍为组内min(1,2/K)，start／stop各2；样本、标签、prompt、来源切分、轨迹内顺序和冻结数据摘要均保持。旧train基础损失质量约为keep81.28%／start12.48%／stop6.24%。

在pilot与full各自阶段，先按动作求基础质量，再将三个动作各归一化为总有效质量的1/3。目标等于三个“类内基础权重加权平均交叉熵”的均值；有效总质量为阶段窗口数、固定平均有效权重为1。保留keep内部重复控制，避免当前小批或单样本重新归一化导致权重抵消。loss_balance是训练配置，manifest内原loss_policy只描述基础权重，二者分别记录，允许复用历史冻结数据。

实测pilot1894窗各类有效质量631.3333；train9977窗各类3325.6667。全部有效权重为正，原始行内loss_weight没有改写。当前train每个start有效系数约39.59、stop约79.18，keep随基础分组变化。该方法平衡损失系数，实际梯度还受到误差、梯度裁剪和轨迹顺序影响；等份额可能提高误动作，需后续开发集检验，不能宣称消除全部keep退化。

完整公式、类的设计取舍及核心方法见[损失说明](../../../docs/archive/scripts/training/textturn_loss.md)；低门槛细节见[放行说明](../../../docs/archive/scripts/training/textturn_gate.md)。新代码均有docs对应路径说明。
