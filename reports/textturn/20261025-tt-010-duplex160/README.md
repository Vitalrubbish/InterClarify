# TT-010 回退后的160ms数据交付

按用户要求，旧TT-010两次实现已通过提交`7d70cf4`回退，工作单重开，旧v1／v2数据移至`artifacts/textturn/retired/tt-010-withdrawn`，不再作为合格交付或训练输入。此次重建使用独立版本`artifacts/textturn/tt-010-duplex160-r2`，不覆盖TT-001、旧模型或评测结果。

## 控制周期与参考适配

选择160ms默认控制窗，每次真实Nemotron名义解码完成后直接形成输入，移除480ms三步聚合等待。320ms仍需多等一个解码周期，本次不采用。控制窗口不等于模型推理或实际停播时间保证，单请求在途及最新待处理合并机制保留。旧TT-003／004回放显式固定480ms，FDB继续按其冻结配置，未热改旧评分或提交远端任务。

参考[DuplexCascade论文3.3.2节](https://arxiv.org/html/2603.09180v1#S3.SS3.SSS2)：其用户文本块后以0.10概率插入1—5个空微轮，助手期间以0.01概率插入短用户附和。新数据把句中停顿概率提高为0.20，长度1—5个160ms窗（160—800ms）；附和概率保留每个可用Speak窗0.01。0.20和160ms是本项目适配，不称论文原参数。控制更频繁时不提高文字流速：用户名义480ms发布1—2 token，助手按3／3／2 token循环，480ms共8 token。

## 资源、失败记录与边界

使用已有`interclarify-dev` conda，CPU单进程、线程1；构造地址空间2GiB、600秒timeout，新数据约254.7MiB，构造76.428秒。首轮r1还发现播放完成时多token附和需继续接收、空白片段应保留在原始前缀两个边界，修正后以r2为唯一交付。r1移入撤回目录保留；两次新增资产合计约504.2MiB，未超过512MiB。没有GPU任务或模型训练，没有修改损失函数。

这里的用户输入、停顿、播放器及80ms停播确认均为合成；不代表真实Nemotron噪声覆盖、真实播放延迟或模型质量通过。非附和首个可判定前缀仍为有限手写标注；短附和来自有限集合，不宣称开放域泛化。源隔离范围继承TT-001，不能证明全历史语义去重。新数据manifest明确training_allowed=false，后续训练须单独授权并适配新词表、嵌入及独立评分。
