# `datagen/scenarios.json`

整体功能：存储五个原创人工来源、13 个派生分支及模拟调度，作为共同轨迹与三类监督视图的唯一输入。不含实现类和方法。

| 来源 | 对话 | 分支及重点 |
| --- | --- | --- |
| scene01 | 将“谢谢”翻译成英文 | 正常交接；尾词晚提交、停顿不确定、重复 complete、无需 thinking |
| scene02 | 周五会议提醒改为周六 | 首音前取消合并用户片段；已播后取消保留历史并衔接 |
| scene03 | 整理本周安排 | 可选系统附和、重复抑制、避免错误赞同、用户非打断性附和 |
| scene04 | 依据报考类别阅读复试通知 | 自行说明、长篇相关、长篇类别未知、短篇转场、自行查找；共享前缀及晚到／过期分析 |
| scene05 | 重量及预算约束下装箱 | 上界到最优组合的递进；固定已播错误纠正；超时／失败与独立作答 |

顶层 `provenance` 显式记录没有外部教师、音频、TTS、对齐与真实前端，时序均为模拟。`sources` 保存来源分区、当时可用任务信息、共享事件和共享决策；`branches` 保存续说事件、决策及覆盖标签。同来源全部位于 `pilot`，不得因分支或切片增加就声称来源多样性增加。

事件用 `id` 和 `at_ms` 排序。`frontend` 分开记录原始状态、有效 complete、处理与观察上界；`analysis` 保留任务／版本、实际读取时间、依据快照及完成时间；`output` 保留生成全文、阶段和是否已播，精确播放前缀放在事件 `audit` 中；`task`、`runtime` 分别表达思考生命周期与取消事实；`controller` 是未来控制判断的独立模拟发布，供后续 Layer 1 输入读取；`script` 是禁止进入模型输入的隐藏审核材料。

决策通过 `read_ms`、`finish_ms`、`seen`、`target` 描述实际输入与候选输出。`rationale` 属于审核信息，不能拼入训练提示。共享决策保留统一的 `shared_prefix_group`，未分叉时目标一致。`future_cot_control`／`future_clarification` 只说明未来介入语义；没有伪造第六种用户状态或普通回答的 complete。

scene05 的错误轨迹明确为 `fixed_error_prefix` 压力样例，错误只进历史、屏蔽损失，不宣称为自然错误或主 benchmark 成绩。装箱结论可穷举核验：最多三件，唯一三件可行组合为 2A＋1B，重量 20kg、费用 80 元；A＋B 为 14kg。
