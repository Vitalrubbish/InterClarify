# NTF-013：X2教师状态退化的离线归因

2026-11-01。仅复核NTF-010 r6与NTF-012已冻结的30条回放、实际输入和官方源码，不修改模型、实现或阈值，不运行新GPU实验。

## 判断

现有证据支持**文本提交时序改变、空步规则和状态反馈共同作用**。没有发现串块、音频送错或重复文字注入；音文的语义时标是否符合训练仍未验证，不能把工程配对通过等同于训练分布对齐。

新增退化不能全部归因于当前帧的规则强制改写。打断新增3条提前complete均为该帧原始模型输出，其中2条在r6中根本没有检出nonidle；接话新增1条则对主块／观察／墙钟坐标敏感。

## 1. 已排除和尚未排除的对齐风险

两轮共同3175个主块，`audio_token_ids`逐块完全一致；X2的步序、160ms块边界、音频→文本→EOS输入顺序、实际观察边界和token前缀审计均通过。X2的EOS仅在ASR内部关闭发射组，不作为SoulX状态token输入，不直接映射成`user_complete`。

以上能排除当前证据范围内的PCM／音频编码串块和文本重复消费。它们不能证明当前的`T_n`与`A_n`具有训练时相同的语义对应关系：ASR返回时观察到哪个音频区间，不等于新增词就属于该160ms块；等待本步ASR完成也不会把晚发射的词自动重新分配回其声学块。

此前将输入顺序和覆盖审计描述为“严格对齐训练”过强，应收窄为**工程顺序／覆盖对齐通过**。目前没有词级声学强制对齐结果或训练集的词—块时标分布，无法确认或量化训练语义对齐偏差。

两ASR的观察前瞻也不同：r6文本源为主块后99ms，X2为12.5ms；SoulX自身音频前瞻仍为40ms，共同块的音频token一致。主要输入差异是可见文字、文字进入KV的位置及此前状态历史。墙钟更快本身没有作为状态模型输入。

## 2. 相同文字更早进入，但有字步骤更稀疏

对最终控制文字小写化、按词匹配，比较每个共同词首次完整出现在`committed_text`的主块时刻：642个匹配项中，X2有548个更早、82个相同、12个更晚，时差中位数为−160ms。该统计是**字符串匹配的提交时差**，不是词级声学延迟；重复词匹配和识别差异使其不能替代强制对齐。

| 指标 | r6 | X2 |
| --- | ---: | ---: |
| 全部在线帧 | 3175 | 3185 |
| 无原始ASR增量帧 | 2491（78.46%） | 2628（82.51%） |
| 实际有教师token注入的步骤 | 664 | 557 |
| 共同能量块中无ASR增量 | 658/1307 | 759/1307 |

“共同能量块”仅指同一音频块RMS≥0.001，不等同于VAD判定为语音。X2可以更早提交文字，同时产生更长的空步间隔；“更早”和“更密”并不是同一指标。

这改变了冻结SoulX看到的在线输入分布。语义相近的最终全文与更低的最终WER，也不保证每个中间前缀下的状态预测更好。大小写、缩写／分词差异仍会改变实际token；WER的小写／标点归一化不会反映所有这些差异。输入分布对退化的因果贡献仍需固定内容和时序消融验证。

## 3. 空步规则的直接放大机制

冻结[官方状态逻辑](https://github.com/Soul-AILab/SoulX-Duplug/blob/a0b9063843df69619b087b95b74597b2176910b8/service/model.py#L618-L648)在原始预测为nonidle且没有ASR增量时累加计数，达到阈值后强制在complete／incomplete中二选一。该分支没有声学静音条件。本轮保留阈值3；X2的“本步没有闭合组”因此仍被用于这一旧判据。

直接实例：接话`candor_turn_taking-3`。

| 主块截止 | X2已提交文字 | 原始状态 | 空增量nonidle计数 | 最终状态 |
| --- | --- | --- | ---: | --- |
| 0.16s | `i` | nonidle | 0 | nonidle |
| 0.32s | `i` | nonidle | 1 | nonidle |
| 0.48s | `i` | nonidle | 2 | nonidle |
| 0.64s | `i` | nonidle | 3 | **complete（规则改写）** |

标注交接边界为9.16s。0.64s的主块RMS为0.0643，原始状态仍是nonidle；规则却因三步无新字而改成complete。下一步实际反馈到模型的是complete，随后软重置又改变发声标志和计数，因此影响不会局限于这一帧。

全轮实际规则改写32→71次，RMS≥0.001块中的改写26→52次。在共同3175个主块上仍为32→70，不能由X2多出的10个EOF块解释。

| 提前complete事件数（非样本数） | r6原始／规则 | X2原始／规则 |
| --- | ---: | ---: |
| 接话 | 14／4 | 15／10 |
| 打断 | 10／2 | 12／4 |

这证明规则直接制造了部分提前complete，不能证明关闭规则后整个在线轨迹会改善多少。

## 4. 新增打断退化的具体来源

新增提前complete样本为ID136、20、9，三个当前事件均无`adjustment`，是该帧原始模型预测。

| 样本 | 主块／标注结束 | 当时控制文字尾部 | 观察／墙钟相对标注结束 |
| --- | --- | --- | --- |
| ID136 | 12.64／14.616s | `by the way do` | 提前1936／约1846ms |
| ID20 | 12.80／13.229s | `whats the weather` | 提前389／约301ms |
| ID9 | 11.68／13.037s | `whats the price` | 提前1317／约1228ms |

这些事件在实际观察和墙钟口径下仍提前，不能由20ms边界误差解释。ID20和ID9的后续限定成分分别包含`tomorrow`、`of the latest model`；更早可见的局部问句前缀可能促使模型更早结束，但这仍是待验证的机制假设。

ID136的同一12.64s块提供更直接的时序对照：

- r6本步刚注入`do`，前步反馈为idle，当前原始预测nonidle；
- X2已在12.48s注入`do`，12.64s无新增字，前步反馈为nonidle，当前原始预测complete。

同一音频块上，即使当前累计文字小写化后相同，文字进入的块位置与状态历史也不同，完整KV并不相同。

三个新增事件之前，X2都已发生过规则改写。因此“当前为原始complete”不能排除早先规则经状态反馈产生的间接影响。需要完整重放消融，事后删除规则帧不能恢复本应出现的KV。

## 5. 检出覆盖和评价坐标的混杂

ID20与ID9正好是r6没有检出nonidle、本轮新增检出的两条。原先更少的提前complete包含未识别打断这一代价。在两轮均检出的同8条上，提前complete为6/8→7/8；总计6/10→9/10由“新增覆盖的2条也提前结束”和“原共同8条新增1条提前结束”组成。新增覆盖不抵消真实提前结束，但应与固定覆盖上的退化区分。

接话7/10→8/10的唯一新增样本为ID56：主块4.000s，标注边界4.020s，实际音频观察4.040s，发布墙钟约4.130s。主块坐标早20ms，实际观察已越过边界，发布约晚110ms。提前超过160ms仍为7/10，完整观察口径的提前样本仍为7/10。因此，先前直接把接话新增1条统称为质量退化不够准确，应称为边界敏感的计数增加。

还有一个反证：全轮原始complete预测次数实际为75→62，并非全局更偏向complete；部分事件的位置与历史轨迹变差，且规则产生的complete增多。不能只用总体标签频率解释分任务结果。

## 6. 因果验证的最小后续设计

以下只是建议，没有自动提交作业：

1. 固定X2、音频与文本提交策略，仅关闭空增量强制分支，完整重放并保留状态反馈；另一条nonidle→idle规则保持，验证直接改写与历史传播的净影响。
2. 在固定同一份教师文字和规则的条件下比较两种因果提交时刻，例如原时刻与额外延后160ms，不重跑ASR或提前使用未来文字；用于区分内容变化与注入时序变化。
3. 对ID3／136／20／9补词级声学对齐，并与训练词—块分配合同核对。只有这一步能直接检查“文字属于哪个音频块”，覆盖窗口与最终WER不能代替它。

现有单次实验无法给各因素分配因果百分比，也没有保存完整logits，不能从argmax恢复决策置信度或另一轨迹。

## 2026-11-02补充：SenseVoice也会遇到空步规则风险

用户追问指出，这条规则同样作用于官方SenseVoice路径。复核冻结`_asr()`与`_state_predict()`确认：SenseVoice门控未调用识别、滑窗识别与历史相同、仅修订历史但没有新增字等情况，均可能返回空`delta_text`；之后仍进入相同的nonidle计数与complete／incomplete强制选择。同步窗口识别并不能保证每160ms都有新文字。

重新从`artifacts/soulx/20261030-delta-context-r1/evidence/replay/*.source.jsonl`仅选取`audit_kind=state_source`且`delivery_phase=online`的记录，得到269帧，9次nonidle→incomplete、2次nonidle→complete。两次complete均在`calibrated_full`／`calibrated_repeat`的4.44s且被接纳。这证明SenseVoice路径实际也触发规则；规则触发次数本身不等于误判次数。

因此，“旧空步规则与X2不匹配”应精确理解为**通用规则在本次X2接入中表现出风险**，不能解释为SenseVoice没有该问题。32→71只是r6与X2之间的比较，尚无相同FDB30、同等预热及明确控制器合同下的SenseVoice对照。历史六视图与FDB30的样本、reset及门控路径不同，不能直接比较触发率或把历史11次与当前71次作优劣排序。

现有证据能证明该规则直接制造了某些提前complete，不能证明它是X2相对SenseVoice差异的主因。相对差异取决于连续空增量、原始nonidle、状态反馈、门控和reset的联合轨迹。要验证归因，需要在每种固定ASR接入内分别开／关规则并完整重放，再比较规则效应是否随ASR变化；不能从规则的存在直接推出路线优劣。本补充未修改实现或启动实验。

## 2026-11-02补充：提交早160ms不等于相对音频错配一块

−160ms的参照是**同一个匹配词在r6与X2路径的注入步**，不是词的真实声学结束时刻，也不是训练中的词—块归属。统计使用160ms主块坐标，本来就量化为160ms的整数倍；中位数恰好一块不能单独作为索引偏一的证据，r6也不是语义对齐真值。

进一步把642个匹配项拆为：归一化ASR累计文字中首次完整出现的步，以及实际注入步。这里“ASR出现”仍在160ms RPC粒度观测，不声称是原生解码器首个子词时刻。

| 观测 | 结果 |
| --- | ---: |
| r6额外尾词保留时间中位数 | 160ms |
| X2在本步已闭合文本后的额外保留时间 | 0ms |
| r6恰好额外保留160ms的匹配项 | 531/642 |
| 两路归一化ASR中于同一步完整出现的匹配项 | 245/642 |
| 其中仅因r6额外保留而使X2早注入160ms | 221/642 |
| X2归一化ASR出现步更早／相同／更晚 | 327／245／70 |

因此，221项的“一拍”直接来自去掉尾词缓冲；其他项还混合了解码交付差异。逐项均满足“注入时差＝ASR出现时差＋X2额外保留−r6额外保留”；不能把几个分布的中位数直接相加。

同时复核worker真实读取公式：第k个160ms步骤的最后一个80ms窗，原始PCM读取上界为主块结束E＋200样本（12.5ms）；该步SoulX音频窗口上界为E＋640样本（40ms）。3185步均满足该关系。结合实际代码的有界读、连续步号及逐步文本快照，没有发现“读入后一个完整160ms块，再将其文字回填前块”的路径。该检查只约束可用输入的因果上界，不会阻止ASR依据部分语音预测一个词，也不能验证其词尾声学位置。

当前教师仍按ASR提交步把增量放到对应音频块后；“提交步”是否符合训练时的词—块归属尚未验证。这是应当继续检查的时序分布风险。若r6原本比目标晚一块，提前提交可能改善对齐；若训练要求更晚提交，同样变化也可能造成失配。两者需要词级声学时间戳和训练分块合同区分。

准确结论应为：**相对r6确实更早，尚不能判定相对音频提前错配了一块。** 统一延后160ms可以作为固定内容的时序消融，不能在没有绝对时标证据时直接当作修复。分解明细保存于NTF-013 artifact下的`timing_decomposition.json`及复核脚本；本次仍未修改实现或运行GPU实验。
