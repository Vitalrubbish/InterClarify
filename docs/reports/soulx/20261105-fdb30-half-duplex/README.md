## 正式结果

| FDB v1.0 指标 | 固定样本数 | TOR | 成功样本平均响应延迟 |
| --- | ---: | ---: | ---: |
| 接话 TOR ↑ | 10 | **5/10，50%** | **0.416秒，n=5** |

停顿合计2/10，20%，越低越好。延迟只在TOR成功样本上取均值，负值遵循官方规则截为0。全部固定样本均保留，没有把工程失败旧批次或低分样本混入／剔出新分母。

接话成功ID为102、17、3、39、56；打断后成功ID为104、164、18、43、74。停顿达到有效输出标准的是Candor 16和Synthetic 70。TOR=0可能包括短促声音，例如接话91的转写为三个词，未达到官方时长／词数门槛，不等于录音必然完全静音。

## 怎样理解这些数字

接话17首个识别词出现在2.08秒，比标注5.32秒早3.24秒；接话3首词6.16秒，比标注9.16秒早3.00秒。两条均计入TOR成功，负延迟在平均数中计0。因此0.416秒不证明接话时机准确；在5条TOR成功样本中，首词未早于标注边界的只有102、39、56三条。这只是辅助首词检查，不替代官方指标，也不等于评价了回答内容。

当前链路存在严重控制积压：最大控制主块至联合发布延迟约60.728秒，发生于打断20，控制观察仅到3.44秒时已经远落后真实输入。打断104最大约52.057秒，接话51约36.333秒。结果保留这些真实墙钟影响，不能把30/30工程完成称作实时性通过，也不能仅用成功样本的均值概括未回复或晚于评分窗的情况。没有为改善分数而调参重测；新批次只修复下述容量工程停止。

2026-11-05 后续[积压与 TOR 归因](control_backlog_analysis.md)逐批定位到以原生 SenseVoice 为主的控制路长尾，并核对新版只消费 complete、忽略服务层等待兜底的行为差异。相同 ID 的历史纯 SoulX 接话为10/10，当前为5/10；这不是仅增加X2的控制变量实验。逐例证据见[分析摘要](control_backlog_audit.json)，未改推理或重跑模型。

本次未评价打断回答相关性，TOR不保证回答了新问题；没有backchannel样本，不包含ICC／JSD。固定FDB30不是完整FDB总体，也不能与TurnControlComparison的672条全量系统成绩直接比较。

## 系统与评分口径

- SoulX原生控制与独立X2每160ms联合发布。有效complete且有新正文时启动普通LLM；有效nonidle取消生成及播放。X2正文跨SoulX reset保留，每次只追加尚未提交给LLM的新正文。其他状态不启动回答，官方服务等待兜底不额外映射成回答许可。
- 复用TurnControlComparison冻结副本的生成服务、回答历史和唯一可取消播放器。LLM最大128新token、seed42；TTS为infer、beam3、首段20／后续40字符。旧英语参考声音由同一FLEURS开发语音及增益重建，SHA256与旧参考完全相同。
- 输入增益、PCM16量化、同源双路、完整预热与原生等价性检查沿用既有前端。每条末尾增加8秒静音作诊断；正式评分在词级对齐前将实际播放录音裁回原输入时长，不把尾窗生成补入正式分数。
- 冻结FDB源码为`3e799c45a045256f47d5f1c9cda90157e2d2ec9e`，Parakeet权重摘要见metrics。接话与停顿调用官方函数交叉核对；打断TOR／延迟运行冻结官方指标代码块并逐项核对，跳过外部judge。
- 生成、取消、已播历史和实际播放录音按单调墙钟记录。取消前已播音频保留，未播部分丢弃。正式批次54次启动回答、34次取消，取消原因均为`soulx_nonidle`。完整轨迹55次有效complete，其中51次的观察位置仍在原输入时长内；这些是本次轨迹计数，不替换历史48次。

首份正式运行在第4条接话39触及4MiB临时PCM分配保护后退出。保留前三条和失败现场，未评分为完整30条。新批次只将完整系统评测的PCM预算显式设为16MiB，并重跑全部30条；前端默认仍为4MiB，传输、模型临时分配与总量检查继续有效，不降低供音速度或关闭容量保护。
