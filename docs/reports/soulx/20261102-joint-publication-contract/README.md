# NTF-029：160ms联合发布合同修订

日期：2026-11-02。用户要求相应调整NTF-017，并明确写入内容为“文本和状态token”。本次只修改任务单和设计；NTF-017仍待实施，NTF-015／016的历史交付和134项测试结果保留，不作为新合同已验收的证据。

## 最新合同

每个160ms源批次，SoulX完成本次原生调用、内部识别／反馈／reset，X2完成对应两个80ms音频步及必要的真实EOS解码后，统一将文本、五状态token及真实进度一次写入SharedContext。提交成功后才允许下一批次模型推进；两路实际采样范围仍分别记录，不因相同步号假定声学对齐。

先完成结果只留在当前批次有界暂存器，SharedContext保持上一完整快照。X2第一帧的闭合正文不提前对下游可见，WAIT无新字仍提交本批次状态／进度并保留正文时间；不保存PCM或开放组子词。available_at保留实际模型完成时刻，统一发布时间记录屏障等待后的可见时间。

撤回前端专用停止钩子，nonidle采用相同的联合提交门槛。下游统一读取本批次快照，既有唯一输出执行点、播放所有权与停止幂等保持；不新增直接连接前端的停止旁路。

complete仍需NTF-020按已提交进度检查真实观察目标和闭合正文，不能把屏障完成等同尾词齐备。候选、ready和nonidle／incomplete取消均消费已联合提交批次；交接超时只更新元数据，不提前发布当前批次文本或状态。原始可用到联合提交的等待计入同一800ms预算，不从发布时重新计时。

任一路失败、取消、缺失／重复／过期回执或Context写入失败均不提交半帧、不推进下一步；保留上一完整快照和失败诊断。独立生产者按真实时钟继续入账，原有800ms／4MiB及远端作业资源不扩大。
