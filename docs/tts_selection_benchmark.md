# 英文流式 TTS 选型与远端测试

## 范围与当前状态

本轮由用户授权：在 `feature/tts-selection` 分支调研英文、低延迟、流式 TTS，在远端测试每个入选系统 50–100 条，返回首音频包、首可听内容延迟与同文本试听音频。这里只增加独立评测工具，不替换 X-Talk 运行底座，不增加仲裁器或播放所有者，不改变 Layer 边界。

已按用户指示通过 Windows 用户目录的 RSA 密钥认证 JumpServer，并经 `guizhou` 资产进入 `d6-hpc-debuggpu-001`。使用 `vc submit` 提交计算作业；GPU 模型在 `pdgpu-4090`、CPU 模型优先在 `pdcpu` 测试。共享实验目录为 `/hpc_stor03/sjtu_home/xuan.zhang/interclarify-tts-selection-20261018`。官方来源比较见 [调研](tts_selection_research.md)。历史 MOSS 数字不填入本轮结果。最终结果、执行异常和试听入口见 [实测结论](tts_selection_results.md)。

## 固定协议

- 每个候选运行相同的 60 条原创英文文本，20 条短澄清、20 条日程确认、20 条较长回答。文本、顺序与试听子集由 `configs/tts_selection_texts.csv` 固定。
- 单请求、并发 1。候选使用与产品隔离的 conda 环境和独立服务进程，兼容依赖的轻量模型可共用锁定环境，独占相同型号资源；不在登录节点运行推理。CPU 候选记录线程数、型号和线程亲和性，不能把不同 CPU 的结果直接排名。
- 通用 HTTP 服务的模型加载和音色编码在计时外；现役 MOSS 健康检查不加载模型，其 cold 请求包含惰性加载，单独注明。首次推理另存 cold 记录，随后预热 3 条；60 条正式请求全部保留成功、失败和超时。预热数据不得进入分位数。
- 固定源码提交、权重 revision、包版本、音色、参考音频哈希、精度、设备、种子、采样参数和原生分块配置。每个请求设置进程级超时；不靠后台线程超时后继续占用 GPU。
- 本轮统一比较完整文本可用后的音频流，固定文本输入以隔离 TTS 服务差异；必须标注整句输入、分段合成和原生双向流式能力，不能混合解释。本轮没有以 LLM 词到达轨迹测试增量文本，后续接入前仍须补验该接口，不能由本轮结果推出 LLM→TTS 端到端延迟。
- 不将生成完整 WAV 后人为切块作为原生流式。保留原生音频块及客户端接收时间；如使用直接 Python 迭代器，标注为进程内交付，不称网络首包。

## 指标定义

`t0` 是客户端开始提交文本的单调时钟时刻，必须包含序列化、连接/请求和等待首个输出的成本；模型加载单列。使用常驻连接时注明连接成本不在请求内。

1. **首音频包延迟**：首个非空、可解码 PCM 音频块到达时间减 `t0`。HTTP 头、WAV 头、空消息及文本元信息不算音频包。记录该块样本数、时长和字节数。
2. **首非静音可播放延迟（首可听内容代理）**：按原始块的到达时刻模拟顺序播放，块起点为 `max(上一块播放结束, 当前块到达)`；在输出波形中以 10ms RMS 窗口、连续 30ms 超过 -45dBFS 识别首段非静音。报告其模拟播放起点，并用 -50/-40dBFS 做敏感性分析。必须跨块累计窗口，不能丢弃块尾。此值包含开头静音和到达断流，不等于声卡/扬声器实测，也不能保证噪声已构成可理解的单词。
3. **首语音/首词校验**：对试听子集人工确认开头是否为语音、是否吞字、是否有噪声；需要时离线对齐补充首词位置。离线音频起点加首包时间不能替代实际分块播放时钟。
4. **持续供音**：总音频时长、合成完成时长、RTF=`生成墙钟/音频时长`（越小越好）、预热后首音、到达间隔、播放中断次数及累计中断时长。首包快但后续供音不足实时的系统不能仅凭首包获选。

每项给出成功数/总数、失败详情、p50/p90/p95/max；60 条的尾部分位数只作描述，不据此声称稳定 SLA。不同文本长度分组报告。冷启动、预热、正式样本分开。所有原始块时间、请求结果、日志和音频保存在独立运行目录，报告附命令和环境清单。

## 人工试听

所有候选使用同样的 6 条文本（CSV 中 `listening=yes`），每条生成一段不裁剪开头的 WAV。优先各模型默认高质量英文音色，明确音色差异是评价因素；有统一合法参考音频时，可额外做克隆对照。

按 2026-10-18 用户的后续要求，试听包提供随机匿名标签、原文、播放器和评分 JSON；模型映射单独保存，避免提前暴露。用户按整体听感为每段音频填写一个 1–5 的综合分数（可填小数，越高越好），不再分别给自然度、清晰度等分项打分。JSON 按原文分组，`scores` 中 A/B/C/D 的 `null` 替换为综合分数。只由用户评价，不用自动 MOS 或 LLM 代替。保留原始音量文件，另做响度统一版本时单独标注。

## 远端任务单

1. 获得 SSH 入口，检查共享目录、GPU 配额、现有 conda 和模型缓存；不干扰正在运行的服务。
2. 固定官方来源后安装与产品隔离的 conda 环境，下载权重到共享盘，先对一条文本验证原生音频迭代、采样率和结束语义。
3. 通过集群调度提交单卡/CPU 作业，先 warmup，再跑 60 条；模型失败时保留日志，不能删除失败或换文本重试充当成功率。
4. 汇总分位数和音频时间线，生成 6 条同文本试听包，拉回本地可点击路径。
5. 形成有证据的选型建议；本轮不自动替换现役 MOSS 或修改 X-Talk 播放链路。
