# 英文 TTS 选型实测结果

2026-10-18 在 `guizhou` 入口对应的集群提交测试。四个系统各完成同一批 **60 条英文文本**，共 240 条正式请求；每模型另有 1 次首次请求和 3 条预热，均不进入正式分位数。研究范围和现役 X-Talk 播放路径未改变。

## 结果与建议

时间为毫秒，表中为 p50 / p95。完整分组、冷启动、阈值敏感性及逐请求数据见 [完整报告](../reports/tts_selection/20261018/report.md)。

| 系统与实际计算设备 | 输出方式 | 首音频包 | 首可听代理 | RTF p50 ↓ |
| --- | --- | --- | --- | --- |
| Pocket TTS 3.3.0，Xeon Gold 6330 / 2 CPU 线程 | 原生音频帧流 | 156 / 226 | 352 / 535 | 0.452 |
| Kokoro 0.9.4 / 82M，RTX 4090 | 文本段完整合成后返回 | 122 / 138 | 439 / 461 | 0.026 |
| Kyutai TTS 1.6B，RTX 4090 | 原生音频帧流 | 737 / 759 | 812 / 1128 | 0.426 |
| 现役 MOSS 配置，RTX 4090 | 原生音频帧流 | 561 / 62880 | 1809 / 63405 | 1.611 |

**优先进入人工试听的原生音频流候选是 Pocket TTS**：本轮 CPU 条件下首音延迟低、总体供音快于实时。它的 Python 接口接收完整字符串，本轮没有验证 LLM 增量文本输入或接话取消接入，因此不能据此直接宣布替换完成。若必须边收 LLM 文本边连续发声，Kyutai 的官方双向流式接口值得下一步接入验证；本轮完整文本测试的首音相对更慢。

Kokoro 的吞吐和整句可用后的首音表现很好，适合把已经形成的短句迅速播出；其首块时长中位为 **4.45 秒**，其他三者为 **80ms**。它是分段完整合成对照，不能用本表声称其支持帧级双向流式。

MOSS 当前配置不适合按本轮表现直接继续作为低延迟英文主线：60 条累计模拟断流 172.320 秒，RTF 中位数 1.611；动态文本下仍出现约一分钟的编译等待。3 条短句预热未覆盖所有形状，正式样本中的首次形状编译全部保留，不能把这组 p95 解释为“所有形状已充分预热”的稳态指标。这是当前配置与服务链路的结果，不是对 MOSS 所有实现的性能上限判断。`clarification_09` 只返回 80ms 音频，未检测到连续非静音；因此 MOSS 的首可听统计为 **59/60**，不是 60 条均成功发声。

Pocket 本轮累计断流 0.594 秒，Kyutai 与 Kokoro 为 0。以上是在首包即可播放、不额外预缓冲的模拟下计算；真实产品可通过缓冲改变首音与断流之间的取舍。

## 测量边界

- 固定完整英文文本后提交给服务，计入本机回环 HTTP/原生 WebSocket 请求、首包等待及开头静音；没有计入 ASR、LLM、远端用户网络、浏览器缓冲或声卡输出。客户端和服务均在计算节点，不是从本地电脑测公网延迟。
- 首可听代理按 10ms RMS 窗口连续 30ms 超过 -45dBFS 检测，再映射到实际分块到达的播放时钟，包含迟到包造成的等待；不保证已出现可理解的第一个词。报告给出 -50/-40dBFS 敏感性。
- GPU 为同型号独占 RTX 4090，不是同一张实体卡；CPU 均为 Xeon Gold 6330。Pocket 实际只用 CPU。`pdcpu` 持续排队后，用单 GPU 队列容器承载 CPU 测试，分配的 GPU 未用于 Pocket 推理。不能把结果当作 CPU/GPU 同算力排名。
- 模型使用默认英文音色或现役参考音色：Pocket Alba、Kokoro af_heart、Kyutai 官方 Expresso happy、MOSS 现役 reference.wav。不同音色本身会影响自然度偏好；本轮没有统一克隆同一个说话人。
- MOSS 健康检查早于模型加载，cold 首包 70.720 秒包含惰性加载；其余模型服务启动先加载模型。各模型首次请求不能直接横向排名。正式样本、预热和首次请求已分开保存。
- 本轮不测并发吞吐、真实播放设备或 LLM 增量文本。未实测的 CosyVoice3、Magpie、Qwen3-TTS、VibeVoice 及云 API 见 [调研](tts_selection_research.md)，不能声称已优于这些候选。

## 执行异常与证据

MOSS 的 60 条正式请求均已按结束协议写出完整音频块与汇总，随后包装 shell 因开发期间原地更新而退出 **127**。保留原始退出码，不将整个集群作业记为通过。收集器通过显式例外接收这批已经完成的测量，并核验 60 条无传输错误、音频长度与分块总样本数一致；非静音缺失另计。后续提交脚本已改为冻结节点入口。

Kyutai 首轮同样遇到测量后的包装错误，已排除并用冻结入口重跑，最终采用 `kyutai-r2`（退出 0）。MOSS 首次因共享环境缺 flash-attn、Pocket 首次因跨线程 inference tensor 的启动验证失败也被保留；它们没有正式样本，不混入最终分位数。具体作业 ID、排除理由及最终来源见 [执行登记](../reports/tts_selection/20261018/run_registry.json)。

逐条时间线、依赖、CPU/GPU、脚本快照与哈希均保留在 `reports/tts_selection/20261018/`。本地 9 项测量/收集门禁测试通过；另外复核了全部 240 条分块时钟与音频长度、24 个试听 WAV、汇总分位数和执行源码哈希，结果见 [核验记录](../reports/tts_selection/20261018/verification.json)。权重版本见 [manifest](../reports/tts_selection/20261018/model_manifest.json)，MOSS 沿用其目录中的 `models.lock.json`。远端完整 WAV、日志及启动失败目录保留在 `/hpc_stor03/sjtu_home/xuan.zhang/interclarify-tts-selection-20261018/`；本地只拉回固定试听子集，避免把全部音频纳入 git。
