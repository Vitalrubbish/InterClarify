# InterClarify：话轮内主动澄清的研究构想

暂定英文题目：**InterClarify: When Should a Full-Duplex Voice Agent Clarify Within a User Turn?**

## 1. 核心问题与贡献边界

用户尚未说完语音请求时，系统可能听到一个会改变任务结果的歧义。它应该继续听、趁合适的接话机会简短澄清，还是直接回答？本文研究的是：**系统能否在恰当的时刻建立共同理解，并在用户回应后继续原任务。** “真人感”由可观察的时机、问题措辞、接话与修复行为体现，不假定人会逐次计算打断的净收益。

已有全双工系统支持用户打断系统、系统提前发言或 backchannel；[duplex-dialogue-3k 所在工作](https://proceedings.neurips.cc/paper_files/paper/2024/hash/180d4373aca26bd86bf45fc50d1a709f-Abstract-Conference.html)也表明机器句中打断的时机和内容可以被判为合理。本文不主张首次实现系统打断用户。更具体的缺口是：**在持续输入的真实语音中，如何区分值得当下问清的理解分歧、暂时的 ASR 错误，以及用户即将自行说明的信息？问出后，用户能否自然接话并恢复任务？**

预期贡献集中在两点：

1. **可澄清窗口的定义与决策方法**：从当时可见的语音前缀中识别有后果的解释分歧，结合继续说话与停顿线索，决定等待、澄清或回答，并生成针对分歧的短问题。
2. **完整互动的证据**：用真实语音前缀、任务真值和真人对话共同评价时机、措辞、用户回应、任务恢复及错误打断；明确句中澄清适用的场景和边界。

系统以 X-Talk 的模块化全双工级联框架为运行底座，并把 DuplexCascade 展示的 micro-turn、backchannel、提前回答、持续监听和用户插话停播能力操作化为工程目标。论文主张聚焦 Layer 2 的澄清判断及其交互证据；补齐参考系统能力不意味着把每一层都包装成独立创新，也不要求复现 DuplexCascade 的官方源码、权重或训练流程。

## 2. 任务定义：可澄清窗口

先选择**一个有可核验结果的任务域**，例如日程安排中的时间选择，或联系人选择。每例都有对系统隐藏的用户目标、候选实体与最终动作。完整请求允许多种暂时合理的解释；只有其中一些分歧会改变任务结果。

在时刻 t，候选“可澄清窗口”需要同时满足四个可检验条件：

- **有后果的分歧**：当前前缀支持至少两个合理解释，它们导向不同的任务结果；
- **尚未解决**：最新 ASR 修订和用户已说出的补充尚未排除分歧；
- **可问可接**：能用一句具体问题指出差异，当前说话状态允许用户听到并回答；
- **可恢复**：用户的回应可以并入原任务，供系统继续执行。

这是供模型和标注者使用的操作性定义，不是自动真值，也不是“出现歧义就打断”的规则。用户可能马上自行消歧，短暂等待可以是正确动作。评测须区分**重叠插话**（用户正在发声）、**话轮内停顿接话**（用户暂歇但明显未结束）与**句末澄清**，不能把三者合并为一个命中率。

## 3. 可检验假设

**H1：语义分歧比识别不确定性更适合触发澄清。** 相比单纯 ASR 低置信度，判断不同解释是否改变任务结果，可以减少无关提问，同时保留必要澄清。

**H2：接话时机影响句中澄清的价值。** 对持续歧义且问题易回答的窗口，适时澄清可能促进确认与修复；用户即将自行说明时，等待可能更自然。人评、实际接话和任务结果须共同检验这一判断，不预设句中总优于句末。

**H3：澄清必须形成修复闭环。** 系统提出问题后让出话轮，把用户的确认、否定或补充并入原任务，再继续；只问对问题却无法恢复任务，不算成功。

## 4. 方法：在 X-Talk 上构建完整全双工参考系统

以 X-Talk 的流式 ASR、LLM agent、TTS、轮次检测、事件总线和播放管理为基础。通过短窗口调度和事件触发读取**当时已经到达**的 ASR 前缀、时间戳及可取得的修订信息；0.6 秒只作为初始实验值。系统发声时继续接收用户音频。窗口长度和底层组件选择都是实现参数，不是新颖性主张。

参考系统保留原构想的三级分工，三层共享同一可见对话前缀：

- **Layer 0：倾听反馈。** 判断 SILENCE / BACKCHANNEL，维护自然的低强度反馈；用户打断系统时的停播由播放控制执行。
- **Layer 1：常规话轮。** 判断 SILENCE / ANSWER，并决定是否请求 Layer 2。Layer 2 尚未返回时，Layer 1 继续按原有全双工策略工作，不让慢速语义分析阻塞回答与接话。
- **Layer 2：按需澄清。** 对候选窗口分析有后果的解释分歧、用户是否正在自行说明、当前能否接话及能否问出具体短问题；输出 NO_OVERRIDE 或澄清文本。它可识别歧义但选择等待。收到有效澄清结果时，Layer 2 的内容优先于 Layer 1；否则采用 Layer 1，再考虑 Layer 0，即有效覆盖时 L2 > L1 > L0。

Layer 0/1 是对 X-Talk 轮次检测与生成路径的功能划分：起步时可从同一个 turn detector、LLM agent 和结构化输出映射得到，无须先训练两套独立模型。优先复用 X-Talk 的 ASR、TTS、事件总线、用户插话停播和播放管理，只增加 micro-turn 候选、backchannel/回答分类、Layer 2 触发、有效性检查与输出选择接口。

**研究方法位于 Layer 2 的澄清决策及其触发处**：候选解释是否导向不同结果、是否仍需问、何时问、问什么；Layer 0/1 和输出优先级是参考系统的控制壳。先以提示或规则实现澄清策略，确认数据和评价可行；再根据误差分析训练澄清决策器或 LoRA 适配。强模型按需调用的收益须与直接逐窗口调用比较，不能只凭省算力宣称方法有效。

实现最小的异步有效性约束：每次 Layer 2 请求记录所依据的 ASR 前缀或版本；ASR 关键修订、用户已自行消歧或任务改变后，过时结果不得覆盖。有效覆盖到达时，停止或取消尚未播放的 Layer 1 音频；已播内容无法撤回，必要时简短修正并记录占话。用户在系统发声时插话，执行层停播并继续倾听。澄清后让出话轮，将用户的确认、否定或补充并入**同一任务**，再恢复回答或动作。这里只实现维持正确交互必需的版本检查和播放切换，不另建复杂任务编排系统。

在线模型只能看到时刻 t 以前的输入。完整录音、隐藏目标、候选实体 ID 和最终动作真值只用于数据构建与评价，不能进入在线提示。若 ASR 不提供修订事件，需诚实记录这一限制，或在固定底座后替换并对所有方法统一使用相同 ASR。

## 5. 数据与评价协议

### 5.1 场景与标注

从一个任务域开始，优先筛选具有自然停顿、补充和改口的真实语音。[SpokenWOZ](https://spokenwoz.github.io/)可用于查找逐步补全槽位的真实任务对话；是否适合所选域须先逐例试听。必要时定向采集少量语音请求。原始音频按时间回放给**实际使用的流式 ASR**，保存每次决策可见的部分转写和修订，不能用完整人工转写伪造流式输入。

每例记录任务目标、候选解释、可观察分歧出现与消失的时间、用户是否自行消歧、ASR 是否修订，以及未受系统干预时如何续说。覆盖持续歧义、自行消歧、识别修订、虽有不确定性却不改变结果四类轨迹。LLM 可用于高召回筛选与预标；训练标签须经程序检查，开发与测试样本由人审计。按说话人和场景拆分，避免同一录音的变体跨集合。

**不能自动生成唯一的“最佳打断时刻”标签。** 用户最终自行消歧，不代表系统能在更早时刻预知；用户始终未消歧，也不证明更早打断自然。标注者先只听决策时刻之前的音频，判断问题是否切中分歧、能否回答、此时发问是否得体；完整互动评价再判断用户能否顺畅接话。随机样本用于估计总体错误率，困难样本用于分析失败模式；部分样本由两人独立评审并保留分歧。先用数十例校准标准，再按观察到的分歧与置信区间决定正式样本量。

### 5.2 三种证据各回答什么问题

- **离线真实语音回放**：所有策略共用音频和 ASR，评价前缀上的候选分歧、触发位置、误触发、时间与模型开销。原录音的后半段只是“系统未插话时”的续说，不能当作插话后的反应。
- **受控任务交互**：给用户或模拟器一个系统看不到的目标；系统提问后由其确认或纠正，程序核验最终实体、槽位与动作。模拟器用于快速排错与消融；结论须检查对模拟器设定的敏感性。
- **真人互动对照**：在持续歧义、自行消歧和无需澄清的场景中，比较同一底座上的句末策略与话轮内策略；平衡顺序，避免同一参与者重复获知同一题目的答案。记录是否听清、是否被抢话、是否重复叙述、如何纠正及能否继续任务。这是“真人感”和交互收益的主要证据，不能由静态回放或 LLM 裁判代替。

### 5.3 对照、指标与分析

澄清任务至少比较：原生 X-Talk（无主动澄清）、功能对齐后的 X-Talk（有 Layer 0/1、无 Layer 2）、Wait-until-end（句末才考虑澄清）、Uncertainty-trigger（识别不确定就询问）、Direct-LLM（同一可见前缀上直接决定是否问），以及使用语义分歧与接话线索的 InterClarify。除澄清策略和必需接口外，所有方法共用 Layer 0/1、ASR、TTS、任务设置与参与者抽样。若 Layer 1 触发与 Layer 2 按需调用是最终方法，还需比较逐窗口调用强模型及同等调用预算下的触发策略；消融语义分歧、自行消歧与接话线索，说明真正发挥作用的因素。

主要指标分别报告：① 人评的时机得体性、问题相关性、可回答性及真人接话顺畅度；② 最终任务正确率与澄清后恢复原任务的比例；③ 每次请求的插话次数、用户重复或修复轮数、完成时间。区分重叠插话与停顿接话，给出不确定性区间和失败案例。按持续歧义、自行消歧、ASR 修订和无后果分歧分组分析。**不把这些量压成未经验证的单一“真人感”分数。**

**通用全双工能力是参考系统的回归门槛。** 先以固定版本的原生 X-Talk 在同一设备、音频后端和评测适配器上运行 [Full-Duplex-Bench（FDB）](https://github.com/DanielLin94144/Full-Duplex-Bench)，再运行功能对齐版本和接入 InterClarify 的版本；固定版本、数据与判分脚本，并报告绝对分数和差值。优先看 v1/v1.5 的停顿处理、backchannel、顺畅接话、用户打断及重叠语音；资源允许再使用 v2 的实时互动和 v3 的真实不流畅语音/工具任务。澄清策略应尽量保持这些能力，若有退化就定位触发、仲裁、播放或底层 ASR/TTS 的责任，不预先保证达到 DuplexCascade 论文数值。FDB 检查通用能力，不能代替本文的澄清—回应—恢复评测。duplex-dialogue-3k 是机器句中打断可以合理的邻近证据，其逐词文本模拟也不能代替真实语音互动。

## 6. 算力边界与训练选择

可申请的上限是 **8 张 RTX 4090，每张 24 GB 显存**。这足以开展 7B 级别的 LoRA 实验与多组策略对照，但不是 192 GB 统一显存；4090 不支持 NVLink。任何其他论文或系统在 H100 上报告的训练速度与显存条件都不能直接迁移到 4090。所有训练计划以固定 X-Talk 组件组合上的实际峰值显存和每步耗时短跑为准。

**资源使用顺序**：

1. 在独立的 [Vitalrubbish/xtalk](https://github.com/Vitalrubbish/xtalk) fork 中固定提交和实际启用的 ASR、TTS、LLM agent、VAD/turn detector 组件；先只完成 DuplexCascade 风格的通用 Layer 0/1 链路和 FDB smoke，记录底座事件、延迟和资源占用。
2. 在同一 X-Talk 底座上补齐 micro-turn、backchannel、提前回答、单一仲裁和单一播放所有权，再接入 Layer 2、版本检查与日志。用提示或规则建立澄清策略、任务数据和真人试验流程，立即检查是否存在足够多**人认为适合且用户能回答**的句中机会，并同步跑 FDB 回归。
3. 现象与参考系统都成立后，再训练触发或澄清决策。先冻结 ASR/TTS、X-Talk 轮次控制和通用 LLM agent，使用 BF16、gradient checkpointing、小的每卡 batch 和梯度累积做短跑；按显存选择数据并行，必要时再用参数或优化器分片。若训练直接改动 Layer 1，必须重新测 FDB 并与只增设 Layer 2 的版本比较。训练目标是关键分歧识别、接话时机和问题质量，不是重训整个语音系统。

DuplexCascade 的模型结构、控制 token、官方权重和训练流程只作为相关工作信息，**不属于 InterClarify 的实现前置条件或当前工程路线**。若所选 X-Talk ASR/TTS/LLM 组件的语言、许可或实时性能不适配目标任务，允许更换，但更换后须固定版本并由所有策略共享。

## 7. 执行顺序与继续条件

**阶段一：建立参考系统并验证现象。** 跑通固定版本的原生 X-Talk，补齐目标双工行为并建立两份 FDB 基线；保留三层全双工壳与日志，收集一个任务域的真实语音前缀，试听并审计候选澄清窗口；用句末策略和简单句中策略完成少量真人互动。若多数分歧自然消失、问题难以回答或用户普遍觉得抢话，应修正任务和方法定义。

**阶段二：验证决策方法。** 固定音频链路与 Layer 0/1，实现语义分歧和接话线索的 Layer 2 策略，完成句末、低置信度、直接 LLM 对照、真实前缀及受控交互评测；必要时训练一个 LoRA 策略。同步检查 FDB 是否退化，依据误差分析决定下一轮数据收集。

**阶段三：验证论文主张。** 预先写定真人对照的主要指标与样本选择，收集包含负例的互动，报告优势成立的场景、无效场景及不确定性；同时报告原版与最终系统的 FDB 对照。只有按需 Layer 2 的质量与延迟比较支持它时，才把触发效率写成额外贡献。

## 8. 与相关工作的关系

- [X-Talk](https://github.com/xcc-zach/xtalk)：提供模块化全双工级联底座、事件系统、轮次检测和播放管理；项目 fork 先补齐通用双工控制，再供本文的 Layer 2 研究复用。
- [DuplexCascade](https://arxiv.org/abs/2603.09180)：提供 micro-turn、backchannel、提前回答和持续双工交互的能力参照；本文不复现其官方源码，而研究其未单独回答的主动澄清问题。
- [AdaptDuplex](https://arxiv.org/abs/2609.29217)：已探索自适应窗口与异步认知动作；本文不把分层、异步或动态窗口本身当作主要新意。
- [A Full-duplex Speech Dialogue Scheme Based on Large Language Model](https://proceedings.neurips.cc/paper_files/paper/2024/hash/180d4373aca26bd86bf45fc50d1a709f-Abstract-Conference.html)：duplex-dialogue-3k 支持机器句中打断的合理性判断；本文研究特定语义功能及真实语音中的用户回应和任务恢复。
- [Interactive ASR](https://arxiv.org/abs/2604.09121)：启发了交互式 correction 与语义恢复视角；本文评价系统主动提问及其后续共同任务。
- [Clarify When Necessary](https://aclanthology.org/2025.findings-naacl.306/) 与 [AskBench](https://aclanthology.org/2026.findings-acl.845/)：已有澄清时机与问题研究；本文强调未完成的实时语音输入、可能的自行消歧，以及打断后的话轮协调。
