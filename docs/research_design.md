# 系统打断用户：研究方案

状态：正式研究方案，2026-10-22 更新。本文作为当前研究范围、数据标注、评测和系统职责的依据。标为待定的生成流程、训练细节与实施参数仍需后续确定；研究假设与设计选择的有效性由实验检验。

系统采用 X2-Turn 提供 ASR 与用户话轮状态，Layer 0 专门预测系统 backchannel 时机并开展专项训练。Layer 0 与 Layer 1 的结果进入同一个 Unified Arbiter，由 X2 user state 及实际播放状态提供仲裁依据。工程第一步只接入和测试 X2-Turn，暂不实现或训练 Layer 0；系统附和仍在总计划中，具体阶段见 [工程实施计划](engineering_implementation.md)。

## 1. 研究动机与范围

全双工系统能够在用户表达过程中持续接收信息，但“能够插话”不等于“知道什么时候插话有价值”。我们希望研究：在什么条件下，系统应提前结束倾听，主动向用户获取影响当前任务的关键信息？

目标是构建能够根据持续到来的语音、对话上下文及可用任务信息，实时选择继续倾听或主动介入的系统，并设计评价在线决策的 benchmark。初期适配 Layer 1 的调用与表达协议，Layer 2 使用冻结权重的现成模型；具体训练目标见第 5.7 节。

系统总计划保留不要求用户让出话轮的简短附和能力。其触发后续由 Layer 0 专项训练，当前步骤暂不实现；附和不等同主动澄清，不并入第 5.6 节主动澄清事件评分。

首阶段聚焦任务对话中的主动澄清：系统通过询问获取影响当前任务的缺失信息，例如确认关键指代、消除任务歧义或确认资料适用性。核心权衡是现在询问还是继续等待用户补充，而非发现信息缺口就立即提问。

系统已知用户有误时的主动纠错，以及提醒遗漏、调整任务顺序等主动引导，留作后续扩展。紧急提醒、闲聊插话、情绪支持等行为同样暂不纳入核心范围。文中的资料适用性场景仍属于澄清：系统尚不知道用户类别，通过询问确认适用部分，不预先断言用户读错。

已有工作涉及机器打断用户及其合理性评估，因此目前不能宣称该问题无人研究。候选研究贡献是：明确继续等待与提前介入之间的权衡，并以共享前缀的分支场景检验在线策略。新颖性仍需系统核查。

### 1.1 研究前提与核心目标

研究动机是：在一定条件下，提前澄清可能减少无效表达或返工，但不能预设任何提前介入都有价值。首阶段研究根据当前证据判断介入合理性的能力，不直接验证任务改善或用户接受度；有关实际收益与交互成本的验证留作后续研究，条件见第 5.4 节。

核心研究放在模型能否依据当前可用证据，自主发现影响任务的信息缺口、确定澄清目标，并判断是否及何时值得询问、何时应继续倾听，随新增信息调整决策。当前选择由模型自主完成上述过程，不以外部预先给定澄清目标为主要任务设定。研究应覆盖用户自行消解、即将结束、后续内容仍然相关等反例，检验模型是否学会等待与介入的权衡。

独立思考与表达分工是服务于该目标的系统方案，当前不以证明此架构优于其他架构为首要研究贡献。首版 benchmark 只评价决策与澄清内容，不要求真人回答澄清问题，也不要求构建用户模拟器；任务结果和实际交互成本暂不纳入评测。此范围用于控制交互采集与标注成本，不能据此声称已经证明提前介入能改善任务结果或节省用户时间。

## 2. 行为定义与统一决策视角

本文将主动插话定义为：用户尚未明确让出话轮时，系统主动发起一个要求用户暂停、让出话轮或改变当前表达方向的介入行为。

- 附和不一定要求用户停下，不能仅凭语音重叠认定为主动插话。
- 用户短暂停顿时仍可能持有话轮，因此没有语音重叠也可能构成插话。
- 系统尝试介入但用户继续说，仍属于插话尝试；取得话轮不等于介入合理。
- 用户已明确让出话轮后的询问属于轮后介入，是重要对照。

“是否插话”和“何时插话”采用统一视角。按照 micro-turn 思路，系统随信息到达持续选择继续听或介入；连续选择继续听，直到某一时刻介入，就形成了宏观插话时机。用户话轮结束前始终不介入，也是一种合法结果。这是系统级的决策视角，不要求 Layer 2 在每个 micro-turn 内完成一次推理；其异步调度见第 7.3 节。

设截至当前的信息为 H_t，每次决策比较：

> 现在介入的预期价值，与继续倾听、并在后续重新决策的预期价值。

继续听不等于承诺等到话轮结束。它保留下一时刻介入的机会，也可能带来补充信息、更自然的边界，或不断增加的无效表达与返工成本。

决策只能依赖当时可获得的信息，不能读取尚未发生的后续表达。评测可分别分析误插话、过早、过晚和合理等待，但这些是同一策略的结果，不预设“是否插话”与“何时插话”必须由两个独立模块判断。第 7.1 节的思考与表达分工属于系统职责划分，与这一统一决策视角兼容。

## 3. 主动澄清的合理性条件

用户提出的三个初始条件是：

1. 插话所询问或说明的内容，对理解整个对话具有重要性。
2. 用户没有正在澄清、解释或消除歧义的迹象。
3. 预测用户还会继续说较长时间。

这三个条件是场景设计的起点，尚不是已经验证的充分必要条件。需要进一步区分：

- 重要性：不确定性是否影响当前任务的理解、推理或行动，而非仅存在不精确的语言细节。
- 自行消解：用户尚未澄清，不代表用户短时间内不会澄清；“就是那个……”等表达可能已经给出解释即将到来的证据。
- 等待代价：预计剩余时长是一种线索，后续内容对未解决问题的依赖程度也很重要。长篇独立内容未必需要打断，短篇关键安排也可能值得及时介入。

第三条是否从“预计还会说很久”推广为“继续等待的预期代价较高”，仍是待检验的研究假设。本方案同时保留两者，不将推广后的条件视为已确定结论。

### 3.1 剩余表达时长的使用方式

当前将预计剩余表达时长作为隐式决策线索，不要求额外标注或输出剩余秒数、时长类别。Layer 2 通过 system prompt 结合截至当前的信息权衡等待与介入；Layer 1 的调用与介入时序数据覆盖相关线索。初期不以此训练 Layer 2，也不预设冻结模型已经能正确利用这些线索，具体表现由评测检验。

数据采用混合线索：既覆盖“还有十几条”“最后一句”等明确提示，也覆盖由任务规模、枚举结构和表达进度推断剩余时长的自然线索。围绕相近的信息缺口构造预计较长、预计较短的对照，同时保留“虽长但内容相关”等反例，避免将表达较长直接等同于应该插话。具体混合比例与训练方法尚未确定。

这里的剩余时长指系统继续倾听条件下的预计剩余表达。训练监督针对当前可用证据，不能仅凭完整后续实际较长就判定当前应当介入；共同前缀在尚未出现区别时应保持一致的监督。上述决定不意味着已确认剩余时长是插话的必要条件，也不意味着已确认等待代价的推广假设。

## 4. 场景分析的两个维度

每个分析针对明确观察位置、明确介入内容，并与“继续听且允许随后重新决策”比较。以下收益与负面影响是解释决策依据的定性框架，不是首版 benchmark 的两个评分轴，也不新增人工收益或成本等级标签。首版只评价决策合理性与澄清内容，见第 5.6 节；不实测确认耗时、重复表达或恢复负担。

### 4.1 主动插话获取信息的正向收益

这里评估的是现在主动获取信息的增量收益，而非该信息本身的重要程度。即使报考类别很重要，如果用户正在解释，立即追问的增量收益也可能很低。

| 等级 | 暂定含义 |
| --- | --- |
| 高 | 能及时解决关键理解障碍，明显避免后续错误、无效表达或返工；短期等待不太可能获得同样信息 |
| 中 | 能减少有意义的不确定性，但暂不阻碍后续理解，或稍后询问的损失有限 |
| 低 | 信息已经获得、与任务关系弱、正在由用户补充，或即将自然到达轮后询问机会，提前获取的额外价值很小 |

### 4.2 主动插话的负面影响

评价现在介入本身可能带来的表达与交互成本，包括截断关键补充、打乱思路、要求重复、增加恢复负担，以及削弱用户对表达进程的控制。

| 等级 | 暂定含义 |
| --- | --- |
| 高 | 截断正在发生的解释或关键表达，明显破坏连续性，容易迫使用户重述或失去思路 |
| 中 | 打断正常表达，需要一定恢复，或引入可避免的额外问答，但较容易接回原话题 |
| 低 | 在较自然的边界提出简短、具体且相关的确认，预计用户容易回答并恢复表达 |

两个分析维度分别讨论，不机械相减。高收益不自动意味着应该立即开口；低负面影响也不足以证明一次低收益插话有必要。措辞、长度、语气和实际开口位置都会改变成本，因此同一场景可以有多种不同质量的介入。

## 5. 场景举例

### 5.1 设计依据

核心场景应体现：当前缺少的信息，会决定用户接下来哪些话值得说；如果不及时确认，用户可能沿不适用的分支持续展开。

仅有关键指代歧义不足以说明现在应当介入。系统有时可以完整记住用户的话，最后确认指代，再统一处理，而无需用户重述。这里用资料适用性和诊断方向两个日常例子，说明哪些当前证据可能支持等待或提前澄清；潜在节省不是首版实测结果。

`｜` 表示当前观察位置。各分支描述可能的续说行为，不是系统能够预知的未来。同一前缀下，系统只能采用相同的信息条件和决策规则；不能因未来分支不同而要求不同反应。以下等级针对各分支新增信息后的指定位置，不给共同前缀强加唯一动作或不同评级。文中的候选问句和假设回答只帮助解释场景，不构成待标注的参考问句或必须采集的后续交互。

### 5.2 案例一

设通知明确区分学术学位与专业学位，包含共同要求及各自专属条款。用户只想了解自己报考类别的要求；系统尚不知道该类别，也无法直接读取通知，需要用户口述相关内容。

共同前缀：

> 用户：“帮我看看这个复试要求，我把通知念给你。这里先分学术学位和专业学位两部分，我先从学术学位这部分开始，里面说考核分成……”

关键确认问题是：“先确认一下，你报的是学硕还是专硕？”这个问题可能改变接下来应阅读的部分，但此时不能断言用户一定读错。

#### 分支一：用户立即自行调整

> 用户继续：“不过我报的是专硕，我直接看后面的专硕部分。｜”

理想反应：继续听，更新用户类别和阅读方向。

此时再询问报考类别，正向收益为低：信息已经给出，用户也在调整。负面影响为中：打断正在发生的调整，并可能要求重复。

#### 分支二：用户明确当前资料适用

> 用户继续：“我报的就是学硕，先说考核方式，后面还有材料和成绩计算。｜”

理想反应：继续听，收集适用条款。

再次确认类别的正向收益为低，负面影响为中：没有新增信息收益，却会打断相关内容。用户还会说很久，本身不构成插话理由。

#### 分支三：用户准备长篇展开，类别仍未明确

> 用户继续：“这一部分有十几条，我从考核方式开始，再把材料要求和成绩计算逐条念一下。｜”

理想反应倾向：在逐条展开前简短确认：“先确认一下，你报的是学硕还是专硕？”

正向收益暂定为高：一个短问答可能避免较长的不适用口述；负面影响为低至中：在枚举前的边界确认，通常比在具体条款中间开口更容易恢复。收益大小仍取决于读错类别的可能性、两类条款差异及预计口述长度，不能无条件认定每次询问都有高收益。

若用户回答“专硕”，系统可说：“那先念专硕对应的部分吧；前面如果有共同适用的要求，也一起看。”若回答“学硕”，则继续当前部分，不应断言用户原先读错。

在确实读错专属部分的情况下，轮后策略即使完整记住所有条款，仍需要用户补充适用部分；记忆与重命名不能把学硕专属条款变成专硕要求。提前确认可以避免其中尚未发生的无效口述。但这只是条件下的结果优势，在线决策仍须依据当时的信息与风险，不能用未来回答倒推系统必然应当插话。

#### 分支四：当前部分很短，即将转到另一部分

> 用户继续：“学硕部分就这一句，下面马上就是专硕要求。｜”

理想反应：继续听，不必为了提前确认而打断当前转换。

正向收益为低：很快就会进入另一部分，避免的口述有限。负面影响为低至中：虽容易恢复，但会增加一次可能不必要的问答。后续若继续展开不适用内容，应重新决策。

#### 分支五：用户正在解释自己属于哪一类

> 用户继续：“我报的类别是……我看一下报名信息，｜叫专业学位，那应该看后面那部分。”

理想反应：在用户检索、解释类别时短暂继续听；听到“专业学位”后更新理解。

在标记位置，用户已表示正在检索类别，短暂继续听可能获得答案；此时追问类别的增量收益低，负面影响可为高。标记后“专业学位”尚未到达，不能用于当前判断；实际听到后才更新类别。这里不把所有停顿都判为不能介入；若用户长时间无法确定，帮助查找类别可能更合适。

#### 分支六：长篇内容共同适用，不确定性暂不阻碍理解

> 用户继续：“前面这十几条是两类都适用的通用要求，我先念这些，分开考核的部分在后面。｜”

理想反应：继续听共同要求，在进入分类条款前或轮后再确认类别。

现在确认类别的正向收益为低：虽能补充类别信息，却不能省去本来就相关的通用内容。负面影响为中：会打断适用资料的阅读。不能把用户说得久直接算成无效表达。

#### 核心例子对照

| 已观察到的续说行为 | 候选插话 | 正向收益 | 负面影响 | 理想反应倾向 |
| --- | --- | --- | --- | --- |
| 已说明报专硕并自行切换 | 再次确认类别 | 低 | 中 | 继续听 |
| 已说明报学硕，当前部分适用 | 再次确认类别 | 低 | 中 | 继续听 |
| 类别未明，准备长篇念专属条款 | 先确认类别 | 高，需满足上述风险与长度条件 | 低至中 | 在展开前确认 |
| 当前部分很短，即将切换 | 提前确认类别 | 低 | 低至中 | 继续听 |
| 正在检索并解释类别 | 中途追问类别 | 低 | 高 | 观察解释完成 |
| 接下来是两类共同要求 | 立即确认类别 | 低 | 中 | 暂存问题，继续听 |

这些评级是待验证的定性假设，未严格控制各分支的表达成本，不作为标注真值。构造对照时可以保持信息需求接近，改变续说证据和插入位置；首版按第 5.6 节评价决策与模型实际提出的问题，不要求人工编写标准问句。

### 5.3 案例二

共同前缀：

> 用户：“打印机一直没反应。我把电脑里的打印设置都跟你说一下：首先纸张选的是 A4，方向是纵向，接下来还有页边距、缩放比例、打印范围……”

系统尚不清楚“没反应”的具体表现。候选插话是：“先确认一下，打印机屏幕或电脑上有没有错误提示？”

| 已观察到的续说行为 | 此时询问错误提示的正向收益 | 负面影响 | 理想反应倾向 |
| --- | --- | --- | --- |
| “这些设置还有很多，我逐项念给你。” | 高，提示可能改变诊断方向，避免当前不必要的设置说明 | 低至中，在设置项目边界询问较易恢复 | 优先获取关键诊断信息 |
| “对了，屏幕上写着‘缺纸’。” | 低，关键提示已经主动给出 | 中，会重复已知问题 | 继续接收提示，再决定后续问题 |
| “我先看看屏幕提示，写的是……” | 低，用户正在提供答案 | 高，可能截断关键提示 | 短暂继续听 |
| “就这两项设置，其他没改，说完了。” | 低，轮后询问已很近 | 低 | 等待轮后询问 |

在第一个分支中，若用户回答“显示缺纸”，系统可以先围绕这一提示处理，而不必让用户立即念完所有版式设置。与轮后询问相比，潜在收益是减少尚未必要的口述；并非保证这些设置永远无关。

最后一个分支若已明确以“说完了”让出话轮，其后的询问属于普通轮后询问，不计作主动打断。该分支用于对照，不能把轮后接话标为必须在轮内介入。

该例的证明力度弱于明确分开的资料条款：错误提示可能没有解释全部问题，某些打印设置随后仍需确认。因此不能把全部未念内容都计为节省，也不能预先假定每个用户都会出现足以改变诊断方向的提示。

### 5.4 后续交互验证的条件

若后续研究提前介入是否优于轮后询问，需要验证：在相同任务与完成质量下，及时澄清能避免用户沿不适用方向继续口述，而且这份收益超过插话产生的成本。以下条件保留为后续研究参考，不属于首版 benchmark 的执行或验收要求。

- 两种策略拥有相同背景信息。轮后策略允许完整记忆与推理，不能靠遗忘前文制造返工。
- 用户可以自然解释、自行调整，也可能原先就在说适用内容，不能预设其必然一路说错。
- 记录实际避免的无效口述、仍需补充的有效信息，以及确认、恢复和重复的时间；不能把所有缩短的表达都算作收益。
- 最终任务质量需相同或可比较，不能靠丢弃必要条款让提前介入显得更快。
- 同时比较在下一个自然边界介入。证明轮内介入有价值，不等于证明词语中间开口或越早开口越好。

首版 benchmark 检验模型能否根据已到达的分支证据区分等待与介入；它不执行上述交互结果验证。

### 5.5 扩展示例：边测量边口述

可保留一个较夸张的边说边做场景：用户检查柜子能否通过搬运路线上的几道门，一边测量一边报数，却量的是门框外侧宽度，而任务需要实际可通行宽度。系统若在下一次测量前确认口径，可能避免后续无效测量；等全部报完后再问，则可能需要重测。

在确认用户将持续采用不适用口径的分支，正向收益为高；若在报完一道门、转向下一道门的边界简短确认，负面影响为低至中。收益包含实际测量劳动，不能直接等同于节省口述时间。

这是语音协作任务的扩展示例，不作为当前纯口头对话的核心论据，也不据此扩展工程范围。

### 5.6 首版 benchmark 的评测范围

当前确定只评价以下两个方面：

| 方面 | 评价内容 |
| --- | --- |
| 决策合理性 | 依据截至当前的可用信息，检查思考请求位置与介入时机；介入事件按必须介入、可选介入和不得介入评价，分别识别遗漏、合理等待及误介入 |
| 澄清内容 | 实际提出的问题是否针对影响当前任务且尚未解决的信息缺口，表达是否清楚、具体，是否重复询问已知或正在解释的信息，是否包含无依据的断言 |

模型仍需自主发现信息缺口和确定澄清目标，不以外部给定目标作为主要设定。为减轻标注负担，数据不要求标注者编写参考问句；澄清内容采用 LLM judge 按当前上下文评价，并由人工抽样复核 judge 的判定。继续倾听不要求生成澄清问题，也不能因没有问句而计为内容错误。内容评价的覆盖范围与决策表现分别报告，避免一律沉默获得虚高评价。

评测不需要用户在插话后回答或恢复表达，不计任务成功率、实际节省时间、确认问答耗时、用户恢复性重复或主观负担。样本中假设的后续回答可以解释场景，但不作为已发生的交互结果或当前决策可用证据。

评价依据当前可见前缀，不用未发生的后续倒推正确动作；相同可见前缀保持一致的信息条件。不预设每个位置只有一个正确动作或唯一最佳时刻。数据规模与标注分工见第 5.7 节；具体生成方法、评分方式、统计分母与争议样本处理仍待讨论。

### 5.7 数据规模、时序标注与内容审核

当前主动澄清专项数据采用以下规模，与现有基础话轮控制训练数据分别计数。计数单位为一个背景对话及其用户续说分支；micro-turn、重叠窗口和增强视图不计作独立场景。

| 集合 | 规模 | 标注与审核 |
| --- | --- | --- |
| 试标集 | 200 条 | 逐条人工标注，完善协议并校准模型标注与 judge |
| 训练集 | 2,000—5,000 条 | AI 标注，人工抽检审核 |
| 测试集 | 300 条 | 模型标注，人工抽检审核；如实报告模型辅助标注及人工覆盖情况 |

同一场景的共享前缀分支、改写和增强不跨训练、开发与测试集合。试标集的最终归属、开发集规模、生成候选预算及人工抽检数量仍待确定，不据此启动数据生成或训练。

初期冻结 Layer 2 权重，通过 system prompt 驱动现成模型，不制作 Layer 2 思考过程或目标输出的训练文本。时序标注保留以下两类内容，暂不标注可以结束思考的观察位置或理想返回时刻：

| 内容 | 含义 |
| --- | --- |
| Layer 1 启动思考的位置 | 根据当前证据，适合生成请求 special token 并启动 Layer 2 的观察位置；请求不表示必须打断 |
| 实际打断事件窗口及类别 | 在用户尚持有话轮的语义事件区间，标注必须介入、可选介入或不得介入；标签只依据当时可用证据 |

介入类别按事件窗口定义，不要求每个 micro-turn 都执行一次动作：

| 类别 | 动作含义与评价原则 |
| --- | --- |
| 必须介入 | 根据当前证据，应在该机会的有效窗口内启动一次澄清；窗口内可继续等待更合适的位置，错过该机会仍未介入记为遗漏 |
| 可选介入 | 当前证据同时允许澄清与继续倾听，两者均可接受；未介入不记为遗漏 |
| 不得介入 | 当前证据不足以支持主动澄清，应继续倾听；此时发起澄清记为误介入 |

同一机会可能跨多个窗口；机会的归并和截止规则仍待细化，不能把连续窗口各算一次遗漏或要求重复插话。实际介入后的行为另行处理，不把固定回放中用户未被打断时的后续标签机械用于已发生插话的历史。首版不要求采集插话后的回答。思考请求位置独立判断，不从实际介入窗口机械反推一个固定提前量；不得介入时仍可能合理请求 Layer 2 判断。

上述为语义与观察位置标注，不将思考启动、返回和实际开口视为同一时刻。无需打断的场景仍可能合理请求思考，并以继续倾听结果结束。Layer 2 自行决定继续观察或结束任务；实际使用的观察位置、计算完成、结果到达、注入 Layer 1 和可听发声时间由运行时分别记录，作为诊断信息，不作为人工标注或金标监督。位置与音频时间、ASR 可见输入及 micro-turn 的映射规则仍待确定。

不设置人工参考问句标签。LLM judge 根据模型实际开口前可用的对话信息和输出问句，评价其任务相关性、是否针对未解决的信息缺口、是否重复询问，以及是否清楚、具体或包含无依据断言；不读取未来续说或隐藏答案。问句内容评价与时机评价分别报告。

人工抽样复核 judge 时，先独立判断问句，再对照 judge 的结论与依据；随机样本应覆盖判为合理和不合理的输出，疑难样本另列，避免仅查看一种判定。记录抽样方式、数量及人工与 judge 的分歧，不能将模型一致视为人工确认。judge 的具体模型、提示词、评分等级及抽检比例待试标后确定；校准使用试标数据，正式测试不用于反复调整 judge。

时序标注不等同于完整的自回归训练目标。不设置人工参考问句和采用 LLM judge 只规定标注与评价方式；训练中如何提供结果上下文和后续表达目标，参考第 5.8 节。Layer 2 的结构化结果由冻结模型实际产生，不能用未标注的理想返回位置伪造训练或评测中的结果到达时序。

### 5.8 异步调用与结果利用的训练参考

已核对 [AdaptDuplex](https://arxiv.org/html/2609.29217v3) 附录 C.4、D.1及D.4：外部结果作为工具块进入后续上下文，工具块本身屏蔽训练损失，动作与助手正文参与监督。其数据采用自动生成和人工抽检；论文没有完整公开异步返回内容的专用生成流程。该文的 Thinker/Talker 与本项目层号不能直接对应。

可借鉴的训练方案是：将冻结 Layer 2 的真实结果作为 Layer 1 的外部输入，对输入结果块屏蔽损失，并监督 Layer 1 生成思考请求 token。结果注入后的生成目标按本项目职责划分设计，不照搬论文的控制类别；基础话轮类别仍由 Layer 0 输出。若同时训练澄清正文，可由 AI 根据当时可见上下文和实际结果生成、审核目标文本，无需增加人工参考问句标签；这属于本项目的候选数据方案，不是论文已公开的具体实现。

结果自身不参与 Layer 1 的生成损失，不等于结果后的表达也不参与训练。具体是否监督正文、教师模型与生成审核流程、窗口标签到训练目标的映射及损失权重仍待定，不能把 LLM judge 的评价分数直接当作自回归正文目标。正式测试使用系统真实产生的请求、结果和问句，不提前注入理想结果或参考问题。

## 7. 系统工程架构

系统以 DuplexCascade 为运行底座，前端采用 X2-Turn 提供流式 ASR 与用户话轮状态，后接 Layer 0 系统附和时机预测、Layer 1 表达与调用、Layer 2 异步思考，以及统一仲裁和播放。相关模型与运行协议尚未完成接入。[架构图](../figures/interclarify_method_preview.pdf)展示主要模块和交互路径，[图示说明](figures/interclarify_method.md)说明绘图结构。

初期 Layer 2 使用冻结权重的现成模型，通过 system prompt 明确职责、任务状态与结构化输出，不开展 Layer 2 专项训练，也不采集其结束观察位置的监督标签。该选择不改变 Layer 2 自主发现信息缺口、持续判断介入价值与决定任务结束的职责。后续是否训练 Layer 2，根据试标阶段的判断表现、输出稳定性与运行耗时再决定。

### 7.1 思考与表达的模块关系

| 模块 | 职责 | 输出 |
| --- | --- | --- |
| X2-Turn 前端 | 流式转写并输出用户侧话轮状态，作为独立前端，不占用 Layer 0 职责 | 转写增量、原生用户状态 token/分数及对应位置 |
| Layer 0 | 小型预测器，仅判断当前是否适合发出系统 backchannel；通过专项训练获得时机预测能力 | 发出系统附和或继续等待的决策 |
| Layer 1 | 利用对话、外部话轮状态与思考结果生成表达，决定何时请求思考 | 待表达文本与思考请求 special token |
| Layer 2 | 自主发现任务信息缺口，持续判断澄清目标与介入价值 | 结构化的继续倾听或澄清结果 |
| 统一仲裁器 | 接收 Layer 0 结果与 Layer 1 待表达内容，依据 X2-Turn 用户状态及实际播放状态选择、等待或停止输出 | 单一执行路径上的动作与文本 |
| TTS 与播放 | 流式合成并播放已提交内容，回传实际播放状态 | 用户可听音频 |

用户话轮状态由 X2-Turn 输出，Layer 0 与 Layer 1 不重复预测该套类别。X2-Turn 的用户 backchannel 状态表示用户附和，不能自动触发系统附和。Layer 0 的系统附和决策为另一种来源的事件，既不负责普通接话、用户打断分类，也不判断澄清价值。Layer 2 的结果进入 Layer 1 上下文后，由 Layer 1 继续正常自回归生成，不增加独立的适用性检查、语义复核或否决流程。

本项目 special token 设计继续保留 DuplexCascade 协议；仲裁器可直接解释 X2-Turn 原生输出，仅在实际下游编码需要时适配。Layer 0 系统附和决策的具体编码在实现时冻结，不复用用户附和 token 来表达相反方向。

架构图表示完整项目模块，不标注实施阶段。Layer 0 与 Layer 1 的结果分别交给 Unified Arbiter，仲裁器根据 X2 user state、待选结果与实际播放状态决定采用、等待或停止输出。Layer 0 只向仲裁器提供抽象结果，具体字段、token 和编码尚未确定，不引入 backchannel cue 协议。Layer 2 的思考结果经 Layer 1 表达后进入仲裁，不直接播放。实施顺序见工程计划。

系统保持单一仲裁器与单一 TTS 播放所有权。控制和思考请求 token 均为内部信息，不直接送入 TTS；X2-Turn、Layer 0 和 Layer 2 不独立播放音频。用户已听到的内容不可撤销。当前架构不设独立修订层。系统 backchannel 保留在总计划，当前步骤不训练或接入；未来其正文由表达路径提供并经同一播放路径发声，具体短语方案待定，不把措辞选择扩展为 Layer 0 的训练任务。

### 7.2 思考请求与任务调度

Layer 1 长期保留会话历史与可复用状态，随新增输入窗口和事件执行推理，表达期间正常自回归生成。X2-Turn 的转写与用户状态持续送达；接话事件可立即调度空闲的 Layer 1，不额外等待固定 micro-turn。正在执行的推理在明确边界消费后续观察，不能因每帧状态取消重算。用户持续表达时，Layer 1 仍有机会处理新增信息并请求思考；Layer 0 的附和建议不是 Layer 1 唯一启动条件。没有新增信息且没有待生成内容时可以等待后续输入，不要求持续空解码。Layer 2 结果到达后的处理遵循第 7.4 节的正常边界注入规则。

Layer 1 通过独立 special token 请求异步思考，倾听或表达时均可调用，无需先开口或伴随口头回应。运行时识别该 token 并启动 Layer 2，Layer 1 继续接收输入和生成表达。

每个会话最多一个活动思考任务。同一逻辑任务可以包含多次串行短推理调用。任务活动期间，重复请求合并到现有任务，不创建并行任务或重启；新增 micro-turn 自动进入任务输入缓冲区，无需再次唤醒。

### 7.3 Layer 2 的持续输入与分步推理

Layer 2 唤醒时，在模型上下文预算内读取截至当前的完整可用对话历史，包括用户表达、系统对话记录及可用任务信息。活动期间持续接收新增 micro-turn，在每次短推理结束后的明确边界读取新观察，结合保留的紧凑任务状态更新信息缺口与澄清判断。Layer 2 维护自己的上下文与缓存，任务状态辅助分析，不替代原始历史。

处理期间累积的多个窗口可以合并读取，原始事件历史仍完整保留。推理只使用实际已到达的信息，ASR 修订按版本处理；结果记录实际依据的观察位置。输入已进入缓冲区不代表当前模型调用已经使用该输入。历史超出上下文预算时不得静默截断。

Layer 2 的处理窗口时长可配置，独立于 Layer 1 当前的 600ms micro-turn、音频传输和 ASR 分块时长。接收每个 micro-turn 不要求每个窗口都单独完成一次推理。

| 任务状态 | 行为 |
| --- | --- |
| 继续观察 | 当前不值得介入，但仍需跟踪；保留活动任务与状态，读取后续窗口，不返回任务完成结果 |
| 结束并继续倾听 | 问题已解决或无需继续跟踪；返回最终继续倾听结果，结束任务并休眠 |
| 结束并建议澄清 | 当前判断值得介入；返回结构化澄清结果，结束任务并休眠 |

任务休眠后由新的请求 token 再次唤醒。信息变化及其对澄清判断的影响由 Layer 2 持续处理。

### 7.4 Layer 2 结果的回写与表达

结构化结果包含继续倾听或建议澄清的判断、澄清目标、简短依据与有效条件。它作为外部上下文供 Layer 1 使用，问句措辞由 Layer 1 生成。

首版不为 Layer 2 返回额外新增 special token，先用结构化状态区分继续观察与逻辑任务结束。一次短推理输出结束不等于整个任务结束。结果块的来源与边界由运行时明确标识，注入内容不冒充 Layer 1 自己生成的返回事件；具体编码仍待实现。

结果到达后先暂存，在 Layer 1 下一次实际构造 micro-turn 推理输入时，与该边界可用的对话信息一起注入。若本次输入已构造，则等待后续推理边界。结果到达本身不取消当前生成、不触发重算，也不中断当前播放。回写保留既有对话与真实生成历史。

Layer 1 直接基于包含结果的上下文继续自回归。待表达文本与 X2-Turn 的用户状态、Layer 0 的附和建议进入统一仲裁器，再交给单一 TTS 播放路径。普通回答、系统附和和主动澄清具有不同用途并记录输出类型；不能仅凭用户仍持有话轮就一律禁止主动澄清。Layer 0 不承担澄清价值判断。

### 7.5 唤醒覆盖与介入频率

采用“唤醒覆盖优先、澄清介入从严”的策略。Layer 1 根据可能影响任务的信息缺口或复杂判断需求请求思考，无需先完成完整的介入价值推理。Layer 2 根据持续可见的信息权衡现在澄清与继续观察，仅在有充分依据时返回澄清建议。

初期介入频率通过 Layer 2 的 system prompt 约束，强调插话和恢复表达的交互成本，并结合近期实际介入记录判断是否值得再次询问。Layer 2 专项训练留作后续选择；本阶段不设置运行时硬性冷却时间、次数上限或频率限流。

唤醒、思考开销、澄清建议与实际可听介入分别记录。首版 benchmark 按第 5.6 节评价决策与澄清内容：思考请求行为参照启动位置标签，实际介入行为参照三类事件窗口。具体分母、机会归并等评分细节仍待确定；失败、计算开销与各阶段实际时延作为工程诊断保留，不计用户交互成本。建议生成与实际发声应分别标识。

### 7.6 任务预算与失败处理

单次 Layer 2 任务受计算预算约束。调用失败、超时或总预算耗尽后，记录原因并释放活动任务，不自动重试；Layer 1 继续正常运行。后续允许由 Layer 1 新生成的请求 token 再次唤醒。

失败和超时与正常的继续倾听结果分别记录，不作为模型已判断无需澄清的结论，也不使用未完成的中间状态作为正式澄清结果。评测保留失败与超时覆盖情况。计算资源预算与介入频率约束分别处理。

### 7.7 X2-Turn 用户状态与 Layer 0 系统附和

X2-Turn 负责转写和用户侧状态输出，原生类别与实际接话/停播动作由统一仲裁器关联系统播放状态解释。不能仅凭静音认定用户让出话轮，也不能把语义完整直接等同确定结束。保留其原生类别，不要求输出旧 Layer 0 的五类标签。其质量验证包括转写、暂停与结束、用户附和与打断、误接话、误停、漏接与时延。

停顿不直接等于 complete。已核查作者训练标签将句中/词间停顿标为 idle；其系统依赖 complete 后的静音确认，发布控制器另有纯静音兜底，因此不能仅凭模块标签宣称不会误接话。模型原始状态与控制器合成的 turn_end 必须分开记录，本项目不将上游控制器作为第二个仲裁执行者。证据、风险与检查见 [X2-Turn 停顿核查](x2_turn_pause_handling.md)。

Layer 0 只预测用户仍持有话轮时，当前是否适合系统作简短附和。输入结合截至当前的声学信息、转写、X2-Turn 状态、对话与实际播放历史；最终特征及模型待实现确定。以发出附和/继续等待为训练目标，包含不该附和的负例；X2-Turn 的用户 backchannel 不能作为系统附和正例标签。

系统附和训练是总计划中后续明确要做的工作，不以 X2-Turn 分类能力不足为触发条件，也不阻塞当前前端接入。当前不采集或训练 Layer 0；后续数据需标注系统听者附和的有效事件窗口与继续等待，区分机会与实际发声，保留无需回应、即将交接和已有输出冲突等负例。训练、开发与测试按原对话分组；FDB 测试不参与训练或阈值选择。具体数据来源、规模、标注和模型参数在实施前细化，独立于第 5.7 节主动澄清专项数据计数。

当前先验证 X2-Turn 接入、用户状态驱动的统一仲裁和基础 FDB 音频表现，不要求系统附和。后续 Layer 0 实现后，再运行系统附和评测：使用 FDB v1.0 ICC 的频率与时机分布指标并检查误抢话；用户附和/打断仍用 v1.5 相应子集。只凭频率不能证明附和合理，需独立事件集和人工抽查。这些工程结果与主动澄清 benchmark 分开报告，不引入任务结果或用户恢复成本指标。分工调整的收益由实验检验。

所有用户状态和系统附和建议保留外部来源、输入截止点和版本，不冒充 Layer 1 实际生成的历史 token。仲裁器协调同一时刻的附和、普通回答、主动澄清与停止请求，实际用户打断时能停止当前附和。已被用户听到的附和不能撤销或从历史删除。
