# 数据管线测试

`tests/test_layer1_data_pipeline.py` 用 unittest 覆盖 004 代码，无远端模型或 GPU 依赖。`CharacterTokenizer` 是可逆字符替身，用于检查原文跨度、监督和控制逻辑；另用真实 tokenizers 库构建最小 tokenizer 测试单 token/EOS/BOS 核验，不冒充发布 tokenizer 的真实数据验收。

`DataPipelineTests` 覆盖五类控制、停顿/插话/附和/思考、插话丢弃旧回答尾部、单片段插话后独立 finish、无后续轮不伪造插话、固定种子重放与 epoch 差异、跨片段时间/小数保护、评测视图冻结、三视图目标和分拍不变、user/header mask、每事件一次监督、无未来用户输入、超长事件拒收、T3 500/500、Jaccard 前缀召回、切分前去重、来源验真/未完成下载拒收、无来源审查声明拒收、配置/Unicode检查、构建/恢复及产物篡改拒收。

019增加标点独占末片段、开头片段和中间片段的语义回归：合并后不生成“no-voice配finish”的伪接话，原文跨度连续，去句读视图每个有来源事件都非空；整轮只有可删除标点则在来源过滤时排除。

本地在 conda 环境运行：`conda run -n paratalker-dev python -m unittest discover -s tests -p test_layer1_data_pipeline.py -v`。完整来源生成、发布 tokenizer 和集群测试按远端任务单执行，不由替身测试结论代替。

端到端用例另核对审计报告的来源、待完成人审/排除状态和观测采样频率，防止机器通过掩盖缺少审查。来源拒收用例检查只有排除行的中断索引也不得重用，避免恢复时重复累计过滤记录。

取消FDB转写前置后的回归：来源清点通过且可选文本覆盖不完整时，构建/审计不再pending external_exclusion_review，但仍保留最小集人审与005/007等真正门禁，不自动放行训练。

正式构建资源修正后的回归：24条完整来源只保留稳定哈希最低的6条候选，正序/逆序扫描候选ID相同，source_inventory仍登记全部24条，避免通过截取源前缀或减少扫描冒充有界抽样。

取消全库过滤后的正式路径另有回归：3个各100行的shard只读取18条完整记录，固定种子及shard遍历顺序变化时结果可复现；原字节位置可重新读出完全相同内容，绝对行号保持null，不足预算的小文件不重复填充。旧“完整扫描后候选”用例仅覆盖未配置raw预算的兼容分支，不再代表正式执行规则。

历史32条签署分支的兼容用例以32条合成fixture实际构建数据：未签署时不完成数据门禁，32条逐项签署且摘要正确时parent_issue_complete=true，但training_allowed仍false、005/007继续待验收；篡改一条摘要即撤销完成状态。r5另以用户明确豁免分支收口，实际数据没有填造逐条签署。

r5新增用户规范化先于分拍、assistant原样、替换映射、无残留数字和豁免政策回归；无明确理由不得使用豁免，数据通过不放行训练。

## Issue 040 回归

新配置下检查末文字 talking 与下一空用户拍 finish/正文的精确目标、单片段插话不额外等待、源文字一次消费、同种子新旧计划采样和正文守恒、自然停顿仍等待。三视图/跨窗口/重叠历史 mask 用例继续适用于新时序；另检查非法模式及人为错位由独立语义审计拒收。旧配置缺失字段时仍可复现历史同拍。

冻结基线端到端用例先生成旧模式，再生成新模式，校验对话身份、正文、随机事件和新增拍数；篡改基线选中对话文件必须拒收。
