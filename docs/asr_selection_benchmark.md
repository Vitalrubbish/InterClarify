## 3. 数据与输入节奏

先冻结共用 manifest：样本 ID、音频相对路径、SHA256、语言、时长、人工参考文本及来源。不得将 Qwen 或其他模型输出作为准确率真值。FDB 中预期回答／语义提示不可代用用户逐字转写；缺少真实参考时先人工校对。

冒烟至少 25 条英文，包含陈述、问句、句中长停顿、自我修正、数字日期时间、噪声和长句。正式比较建议至少 100 条、约 30 分钟，另加 10–30 分钟持续会话检查。中文作为加分集单独评价。小样本不能代表总体准确率。

句末标点参考由人工标注句型及声学结束时间；词级延迟需要人工或独立强制对齐词尾时间。对齐只用于离线评分，不进入识别。无可靠时间标注仍参与 WER，延迟记不可测。

1. 用固定非评测语音预热，等待非空输出、真实 EOF 排空及资源释放。冷启动单列。
2. 按统一 80ms 包真实时间送音频；模型自行聚合至目标 chunk，其等待计入延迟。24kHz 变体使用有状态重采样，不提前处理未来音频。
3. 输入和输出独立运行，防止同步调用拖慢送音频。记录计划／实际送入时间，积压不得靠突发追赶掩盖。
4. 记录原始 token/delta/累计文本、单调时钟、最后已接收音频位置、客户端到达时间与 EOF 状态；服务可观测时另记入队、计算及发射时间。
5. 原始累计文本逐事件检查 `current.startswith(previous)`，包含标点和空白；不先冻结最长公共前缀再报告零回写。增量接口原样拼接，并核查内部是否重识别或修订。
6. 自然停顿不触发 EOF 或重置状态。仅真实文件结束排空；补零长度和目的记录，EOF 后文字／标点单列，不算在线能力。长会话中验证句末标点。

每配置至少重复 3 次、轮换顺序，在同型号单 GPU 串行测试，避免竞争。保存 JSONL 原始事件、逐样本 JSON/CSV 和中文汇总。空输出、超时和异常保留在总分母中。

## 4. 指标

| 指标 | 定义与约束 |
| --- | --- |
| WER | 同一冻结规范去标点／大小写后，总 S+D+I 除总参考词数；另保留原始转写。空输出计删除错误 |
| CER | 中文加分集单列，不与英文 WER 平均 |
| 实体正确率 | 日期、时间、数字及关键名词的正确数／总数 |
| 回写 | 原始输出前缀违例次数及样本数；任一次即契约失败 |
| 首文本延迟 | 首非空输出到达减首音频输入，含前导静音及上下文等待，不叫逐词延迟 |
| 词级交付延迟 | 正确匹配词到达减声学词尾，P50/P95；全句编辑对齐处理重复词，报告匹配覆盖率和识别失败 |
| 标点质量 | 词对齐后按词间边界及标点类别算 precision/recall/F1，不可对齐项单列 |
| 句末标点延迟 | 正确句末标点到达减对应句声学结束，P50/P95与可测分母；误提前、缺失及 EOF 才出现分别统计 |
| 尾词及 EOF | EOF 前／后转写、漏尾词和排空耗时；缺词计入 WER |
| 资源与积压 | 峰值显存、长会话趋势、音频实际送入偏差、可观测排队／计算耗时 |

chunk 设置、配置中的 delay、RTF、raw→committed 等待差和 lag growth 均不能替代交付延迟。不可测项记 null 并说明原因；只报成功词延迟时必须同时给失败覆盖率。

## 5. 决策与第二阶段

硬门禁：真实增量输入输出、原始可见文本零回写。句末标点不作淘汰条件；最终看官方模型能否在用户结束后及时生成回复正文。不能以偶尔出一个标点宣布适配成功，也不能给每个 chunk 强补句号。当前未设项目认可的 WER／P95 数值上限，不能事后声称通过预设阈值。

冒烟后冻结选择口径，再在正式集上选取准确率与延迟的 Pareto 配置，同时检查实体及标点错误，保留 1–2 个进入系统回归。正式测试集不用于反复调参。

第二阶段固定 Layer 1 权重、micro-turn 时钟、TTS、数据和 judge，仅替换 ASR。测正常接话、用户插话、停顿和用户附和，分别报告停旧回答、新回答启动、有声覆盖及各失败分母。禁止利用隐藏录音终点强制让轮。

最终报告附版本、环境、实际命令、原始日志路径和失败案例；两阶段完成后才冻结最终选型。本轮不删除 Qwen／X2，也不声称新模型已经改善接话。
