# Layer 1 数据生成配置

`configs/layer1_data.yaml` 固定 UltraChat 来源、对话级切分、过滤/去重、事件采样、句读增强、资源限额及发布 token ID，无类或方法。构建入口校验配置后保存原文结构和摘要；正式训练不由此配置放行。

`sampling.raw_source_dialogues=6000`限定实际解析/过滤的原始对话总数；固定种子跨shard定位完整JSONL窗口，只抽取该部分。candidate_pool_dialogues=6000是过滤后候选上限；候选分组后选1000/200/300。保留原始字节位置，不伪造绝对行号。它是可复现的有限窗口抽样，不声称全库逐对话等概率；用户已取消全库过滤，不为未抽取对话建立ID/近重复索引。

来源为 `stingning/ultrachat` 固定 revision，原始 `id/data` 字段。默认 train/dev/test 为 1000/200/300 条，T3 每个训练 epoch 恰好 500/500。32/100 子集从已切分 train 的稳定顺序取出，不借用 dev/test。

过滤要求交替成对、无空文本/保留标记、总长 20–12000 字符；字母中 ASCII 比例至少 0.95。这是可审计的英文启发式，不能准确识别全部语言，排除原因落盘。近重复按 NFKC、小写、词归一化后的 5-gram Jaccard≥0.85，短文本以全文作一个 shingle。候选池先分组、后选代表与切分，不将句读变体拆进不同集合；最终跨集合另做逐对检查。

生成参数对应[论文 3.3 节](https://arxiv.org/html/2603.09180v1#S3.SS3)：用户 1–7 token、assistant 内容每拍 10 token、自然停顿 0.10/1–5 拍、有效插话每个可插话回答 0.30、用户附和每个回答续写拍 0.01、回答后思考 1–20 拍。首个回答片段与最后用户片段配对，非末用户片段监督 talking；插话用下一原始用户轮，首片段 interruption，后续 talking，结束后 finish 加新回答。有效插话仅在至少两片段且有后续用户轮时抽样，截断点在非末回答片段之后，防止把已完成回答误标为插话。自然停顿只在非末用户片段后采样，保持等待。附和仅替换实际续写拍的 no-voice，不覆盖新回答启动或插话。这些冲突/末尾规则是本项目明确实现选择，不声称取得作者完整生成代码。

019修复后，1–7 token 只指初始随机抽样；去句读后为空的标点独占片段在生成事件前合并至相邻片段，故最终少数用户片段超过7个基础token。r4统计为合并2355次、超过7个基础token片段336个，全部有来源的用户微轮在两种视图均非空。完整用户轮去句读后为空时，来源过滤将排除该对话；当前r4未触发此排除原因。这一例外用于避免 no-voice 被错误监督为接话或续说，并在机器报告中单列。

系统附和固定关闭；无 72B 标注。user 普通句读删除集合显式登记，保护特殊 token、词内撇号/连字符、数字小数/时间；assistant 不变。最长序列通过构建参数显式传入，005 实测前只用于数据审计，不等于训练长度已冻结。

数据目录上限 100GiB、可用磁盘保留 5GiB；SQLite cache 为 32MiB。远端脚本另限制主存、线程和时长。超限明确失败，不减少来源覆盖或静默抽取 shard 前缀。

r5默认启用english_numeric_v1：完整用户长轮先转换数值为英文读法再分拍。原样视图为该共同处理后保留句读的视图；歧义数值上下文按预登记规则排除并报告。
