# NTF-015：保留原生协议的 SoulX 状态控制封装

日期：2026-11-02。状态：待实施。本轮仅按用户指令建单；依赖无。

## 目标与依据

从重新克隆的官方源码建立可审查的状态控制入口，保留内部SenseVoice教师链路，外部流式转写不进入状态KV。当前设计见[独立流式前端](../dev/SoulX-Duplug/independent_streaming_frontend.md)，历史改造差异见[归因](../reports/soulx/20261101-ntf012-x2-teacher-fdb30/regression_analysis.md)。

## 工作范围

1. 冻结官方子模块提交、核心源码摘要、SoulX／SenseVoice权重和英文配置，不依赖已删除的comparison加载器。
2. 保留音频编码、文字门控、滑窗识别、归一化、KV修订、状态规则、反馈及完成分支的内部识别；不套用旧Nemotron／X2教师适配。
3. 在只读采集点取得原始五状态、规则调整、有效性、外层服务状态及完成来源，不把外层speak冒充原生complete。内部ASR文字只作控制与诊断。
4. 明确原生reset的KV、回看、padding与输入消费语义。未读PCM由外部账本保全，不将整个旧model.buffer写回；主块与回看／前瞻重叠分别计账。
5. 保留有效nonidle的即时停止钩子及每个output_id去重；不等待独立ASR或日志。

## 交付与验收

- 提供原生控制封装及相应配置；新增／修改代码、配置、必要测试同步更新docs同路径中文说明，解释类和核心方法。
- 必要契约检查覆盖内部调用顺序、控制文字来源、reset期间PCM无静默丢失、状态采集先于清理、服务状态不混写和停止回调去重。
- 相同PCM、种子和配置下，以未插桩官方调用为参考核对封装前后的内部调用、实际音频／文本输入及状态轨迹；不能只凭源码摘要宣称等价。真实模型对照纳入NTF-018／019远端作业。
- 官方子模块保持干净，项目封装diff独立可审查；如果无法兼容原生reset，先更新设计解释所需变化，再实现。

## 边界与后续

本地使用既有conda进行轻量检查，不在本单独立申请GPU。不改变状态阈值或训练权重，不切换下游。之后由[NTF-016](NTF-016.md)提供另一条独立正文路径。
