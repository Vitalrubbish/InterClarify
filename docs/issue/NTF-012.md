# NTF-012：X2 整词提交适配与固定 FDB30 同卡对照

日期：2026-11-01。状态：实施中。前置：NTF-011 r2四条通过、退出0。用户已确认以 X2Streaming-ASR 替换 Nemotron 作为教师文本源。

## 背景

NTF-011 只证明“X2 能实时跑”；本单把它接成教师文本，并与 r6 做唯一变量对照。切换的实质不是换一个识别器，而是**换掉“词何时算完整”的判定权**：

- Nemotron：模型每步只给子词增量，词边界靠空格推断，尾词靠“一次空步”补提交 → r6 因此多注入 17 个尾词；
- X2：模型显式给出 `[W]` 发射信号，随后连续文本解码至EOS闭合发射组，闭合即可用 → 不需要尾词缓冲，也不需要空步判据。

因此本单同时删除三处为 Nemotron 碎片输出而存在的机制：`pending_text` 尾词缓冲、`commit_pending` 空步判据、`post_pause_extension` 退化追加。删除后教师文本的语义变成一句话：**每 160ms 取一次，有闭合组就追加，没有就只跑音频。**

## 设计

### 文本源

X2 worker 与 SoulX 主进程分离，沿用既有 Unix socket RPC 协议和发布屏障，避免 4B 模型的显存与崩溃影响主进程。worker 内部把两个 80ms 帧聚合为一个 160ms 步，返回**只含已闭合组**的累计文本，于是主进程的 `TeacherCursor` 契约不变：文本只追加、不跳过步。

这样 X2 的 80ms 粒度与 SoulX 的 160ms 块正好 2:1 对齐：第 k 步覆盖样本 `[k×2560, (k+1)×2560)`，不需要 `AudioProgressPairing` 的窗口牵引逻辑。合成左填充的预热不参与主块对齐，但**帧号到音频时间的偏移必须实测标定**，不能由 delay=6 直接推出。

### 前端

`TeacherTextBuffer` 已有“全部提交”分支：`commit_pending=True` 时 `stable_text = control_text`，不做尾词缓冲。因此：

- `TeacherTextBuffer` 不改判定逻辑，只在 X2 路径恒定传 `commit_pending=True`；
- 规范分词、历史前缀校验、`_extension` 兜底全部保留——若 X2 真的只追加，`_extension` 不应触发，触发即缺陷，必须报错并保留证据；
- 审计字段 `pending_text`、`pending_ids`、`tail_reencode_count`、`tail_replace_tokens`、`post_pause_extension` **保留键位但固化取值**（空／0／false），使既有分析脚本无需改动即可读 r6 与 X2 两批帧。

### 归因字段

r6 的 `empty_nonidle_rule` 只是开关位（3175 帧全为真），无法区分“规则是否真的改写了状态”。X2 的空步频率与 Nemotron 不同，若不拆分，状态指标的变化分不清是文本变了还是规则触发变了。本单新增：

- `empty_run_length`：当前连续空步数；
- `rule_applied`：本步状态是否被规则改写；
- `chunk_rms`：本块音频 RMS，用于把规则触发点分成静音段与语音段；
- `x2_closed_groups`：本步闭合的组数；
- `x2_open_group_tokens`：尚未闭合组的 token 数（应为 0 注入，仅审计）；
- `x2_frames_consumed`：本步消费的 80ms 帧数（应为 2，EOF 部分块除外）。

## 范围

1. `scripts/remote/x2_teacher_worker.py`：按 NTF-011 验证过的喂法，把两帧聚合成一 RPC 步，输出累计闭合文本与帧级审计；沿用 `BarrierSession` 式的有界前瞻与取消语义。
2. `scripts/runtime/x2_teacher_frontend.py`：以最小子类方式复用 `NemotronTeacherFrontend`，只改文本提交策略与审计字段，不复制 `process_step` 的主体逻辑。
3. `scripts/remote/x2_teacher_fdb.py`：复用 `nemotron_teacher_fdb.py` 的配对、发布顺序校验、800ms 停线和 `analyze` 口径；单独成文件以保证 r6 基线文件逐字节不变。
4. `scripts/remote/run_x2_teacher_fdb.sh`：同卡双进程（X2 + SoulX）、同一冻结清单、同一预热合同、同一显存停止线。
5. `configs/x2_teacher_append_only.json`：冻结模型 revision／sha256、`frame_ms=80`、`block_ms=160`、`wait_token_id=32`、`word_token_id=33`、`commit_unit=eos_closed_emit`、`last_word_commit=closed_group_only`。
6. 本地用例：组闭合才注入、未闭合组永不注入、两帧聚合顺序不变、空步不追加、历史前缀不变量、`_extension` 触发即失败、审计字段语义。
7. 远端固定 FDB30 对照，run `ntf012-x2-teacher-fdb30-20261101-r1`。

## 非范围

- 不改 SoulX 源码、状态 token、阈值、`empty_nonidle` 与 `nonidle_to_idle` 规则；
- 不做 complete 后整句重识别，不恢复 `_revise()`／KV 检查点／输入账本；
- 不训练、不量化、不调 delay token；
- 不删除 Nemotron 实现与 r6 证据，它作为冻结基线保留；
- 不使用 X2-Turn 权重；它的转回状态头若另测，必须单独立项。

## 验收标准

1. 固定 30 条完整率、退出码、主块与完整观察发布延迟、800ms 触发情况，按 r6 同口径并列。
2. **整词提交**：`post_pause_extension` 恒为 0；`x2_open_group_tokens` 在注入帧上恒为 0；历史 token 逐字节不变（前缀校验零失败）。
3. **规范性**：每帧累计注入 token 等于当前已闭合文本的规范分词，给出 30 条的分子／分母。
4. **归因**：`empty_run_length`、`rule_applied`、`chunk_rms` 的分布给出；规则触发次数拆分为静音段与语音段，与 r6 并列。
5. **实时**：同卡共存下 `x2_rtf`、`backlog_ms` P95/max、双进程显存合计给出；超 22GiB 或 800ms 停线即如实记录退出。
6. **识别质量**：20 条带参考文本的用例给出同口径 WER，与 Nemotron 的 12.5% 并列。
7. **状态三轴**：与 NTF-004／009／010 同口径并列；单次运行不做显著性结论。
8. 若状态指标仍无整体改善，如实写为结论，不得改用其他口径或继续调 ASR 来掩盖。
