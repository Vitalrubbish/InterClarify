# NTF-016：同源音频分发与 X2 完整词流式转写

日期：2026-11-02。状态：待实施。依赖：[NTF-015](NTF-015.md)的控制输入合同。

## 目标

用户进一步指定X2Streaming-ASR，使Context正文以完整词追加。同一持续音频分别驱动SoulX原生控制和X2原生流式解码；只有EOS闭合组进入共享正文，生成中的子词留在ASR内部，不受SoulX文字门控、complete或reset影响。此修订替代原先拟用Nemotron的选型，合同见[独立流式前端](../dev/SoulX-Duplug/independent_streaming_frontend.md)。

## 工作范围

1. 建立16kHz单声道PCM统一采样账本和两路有界输入，各路串行消费；冻结转换、增益、传输包与实际模型窗口边界。一路未就绪不阻塞另一路的正常计算。
2. 复用 `x-square-robot/X2Streaming-ASR-4B-1009` revision `4c8df16`、官方源码 `0aca80597bb1399c0be4002de5bc62c0a779c542`、BF16与英文language-tag；按[既有配置](../../configs/x2_streaming_probe.json)核验摘要、首块／增量形状及80ms LISTEN／DECODE／EOS协议，不下载新候选或恢复comparison旧入口。
3. 以EOS闭合发射组为提交单位，使用官方join规则形成只追加完整词正文；一个组可含多个词。组内子词有界缓冲，沿用64 token解码上限，超限失败，不截断后伪造EOS。不以WORD、空步、空格或静音阈值判定闭合；无新闭合组与尚在解码分别记账。
4. 输入EOF、关闭、取消与SoulX内部reset分别管理。complete不结束ASR，不触发额外整段正文识别；不将无新增token解释为静音或尾词已齐。
5. 每个80ms帧内的闭合组完成后即可通知Context，不等待第二帧、SoulX主块或消费者释放。可复用X2Engine因果解码，不照搬旧教师worker的两帧聚合、发布屏障或教师注入封装。
6. 任一路出错或触及有界输入上限时显式停止样本并保存两路进度，不静默丢帧、切换正文来源或降低真实送音速度。EOF保留未闭合组和尾词诊断，不强制提交或回填在线正文。
7. 独立上报每个80ms整步完成后的asr_processed_until／asr_observed_until和可用时间，含WAIT无新字步骤；不能用收包或预取进度代替。进度与闭合正文分别提交，不刷新未改变正文的可用时间，为[NTF-020](NTF-020.md)仅complete同步提供依据，不能等complete才开始解码。

## 交付与验收

- 提供音频分发／独立ASR适配与本地必要契约检查，docs按实现路径配套说明。
- 检查两路收到的真实PCM摘要与采样区间一致，回看、前瞻和合成padding可区分，不按相同步号假定观察相同。
- 检查两路先后完成、多个子词组成一词后闭合、多词组、WAIT与WORD不提交、开放组EOF保留、前缀不回改、reset后正文连续、取消清理和迟到回调；无跨路屏障或两帧强制聚合。
- 闭合组完成后无需等待SoulX即可交付，available_at取实际EOS闭合及拼接完成时间；对外原子更新由[NTF-017](NTF-017.md)完成。不承诺一组恰好一词或组内每词有独立声学时标，识别质量仍需实测。
- WAIT无新文字仍有可核查的整步完成通知；正文观察范围、实际解码进度和输入预取位置不混写，跨进程结果与进度顺序可追溯。

## 执行边界

本地使用conda，仅运行轻量契约检查。真实解码、资源和实时性验证统一纳入NTF-018／019，不在本单独立启动远端实验。保持每路未读PCM≤800ms及总PCM≤4MiB，具体停止线按设计执行。
