# NTF-017：160ms双路完成后的文本／状态联合写入

日期：2026-11-02。状态：待实施，已按用户最新指令修订。依赖：[NTF-015／016已交付](../reports/soulx/20261102-native-independent-frontend/README.md)。本次只改合同，不把任务单修订记为实现完成。

## 目标与变更原因

每个160ms源音频批次，等待SoulX完成本次原生调用（含SenseVoice、规则反馈、完成服务及reset），X2完成对应两个80ms LISTEN／DECODE步后，一次性向SharedContext写入已闭合正文、五状态token及真实进度。用户已明确澄清：写入内容为文本和状态token，不保存原始PCM。

此合同替代原先两路各自立即写Context以及nonidle专用停止钩子的安排。模型内部仍各自计算并记录实际可用时间，但先完成侧的结果只暂存本批次，不能提前对下游可见。停止与其他状态统一经过同一份已提交快照，不增加绕过联合写入的前端执行路径。正文仍只使用X2真实EOS闭合组，完整合同见[前端设计](../dev/SoulX-Duplug/independent_streaming_frontend.md)及[Context接口](../dev/SoulX-Duplug/shared_context_interface.md)。

## 工作范围

1. 以session_id／turn_id／全局step_id关联一个160ms批次，暂存一条控制回执、两条80ms进度及至多两组闭合正文；EOF终止批次按实际存在帧数核对。设备实际结束、结果拼接和本次原生reset结束后才接受完成回执，不把收包／入队当作完成。
2. 两路均完成后，通过单个联合入口，在短锁中原子写入本批次累计正文、状态token／有效性、原生代次、服务来源、各路真实采样范围与进度、已提交组数和统一batch_published_at。读取者只能看到上一完整批次或当前完整批次，不能看到单侧更新。
3. X2仍按80ms原生协议运行，WORD组内连续解码到真实EOS，最多64 token；第一帧闭合组暂存到本160ms批次结束后才写Context。WAIT无新字也算步完成，无需等待新词／下个EOS；正文保留原值和text_available_at，只推进本批次状态及实际进度。
4. 保留各自state_available_at、text_available_at和asr_progress_available_at，联合提交时记录相同的发布时间；不能用屏障释放／写入时刻覆盖真实可用时间，也不因相同步号宣称真实窗口、词尾或尾词完整。
5. 移除现有前端active_output／stop_output的专用停止接入与相关探针要求；控制回调及X2正文／进度回调只送本批次暂存器，不直接写Context或操作输出。下游从联合快照读取状态后按既有输出生命周期处理，唯一播放所有权与幂等仍保留；本单不接真实LLM／TTS。
6. 调整DualAudioFrontend，使顺序固定为两路完成→联合提交成功→允许下一批次推进。推理、网络、日志、消费者及complete ready不占Context锁、不成为提交或推进的等待条件；输入生产者始终按真实时钟继续入账。
7. reset不清正文、不创建新逻辑话轮、不重置step_id；关闭、取消、任一路异常、缺失／过期／重复回执或Context容量／校验失败时，不提交半帧、不推进下一批，保留上一完整快照和失败诊断。EOF、开放组与未处理真实PCM分别记录，不伪造EOS、状态或ready。
8. 为NTF-020预留单条当前交接记录。complete、nonidle和incomplete均以已联合提交状态为消费边界；complete额外放行条件由NTF-020负责，不能用屏障完成替代真实观察覆盖或尾词保证。
9. 更新SharedContext、dual_audio、native_soulx、independent_x2及受影响调用方／必要测试的同路径中文说明；替换015／016旧的“首帧提前发布／独立停止”验收口径。同步架构图和绘图说明，删除前端停止旁路，保留内部SenseVoice与外部X2分工。

## 验收标准

- 两种先后完成顺序都只提交一次；任一路未完成、WORD仍DECODE或设备未完成时，读取仍为上一批次。
- 第一帧已闭合正文在第二帧／控制完成前不可见；两步WAIT仍可完整提交，正文及其可用时间不变，不需要一批一词。
- 状态token和正文同时可见，真实可用时间分别保留，统一发布时间不早于两路完成；下一批模型开始不早于本次提交成功。
- 不再触发独立停止回调；nonidle经相同联合快照交付，不能在X2尚未完成时提前执行前端停止。
- 并发读取、生命周期和交接更新不覆盖较新批次；错误／重复／过期回执、取消、关闭和写入失败均不产生半帧或复活旧结果。
- reset后PCM／正文连续，EOF部分批次显式标注；子词泄漏和正文前缀回改为0，实际采样范围不靠相同步号推定。
- 收音不因推理／屏障停止，800ms及4MiB上限保持；模型计算、屏障等待、联合提交和消费者读取分别计时。
- 读取返回副本，仍只有每话轮一份当前值，不增加正文历史、版本查询、patch、消费ack或无界待发布队列。
