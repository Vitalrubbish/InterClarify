# NTF-017：正文与状态独立更新的 SharedContext

日期：2026-11-02。状态：待实施。依赖：[NTF-015](NTF-015.md)、[NTF-016](NTF-016.md)。

## 目标与合同变更

以两路各自就绪的时刻更新Context，替代历史“对应音频块配齐后联合发布”。正文只接收X2的EOS闭合组，以完整词追加，不暴露开放组子词；多词组可同次写入。保留单份当前全文／原始状态和原子读取，不恢复正文历史、patch或版本查询。用户确认仅complete回答交接需要同步，因此预留一条当前交接记录，其等待／取消规则由[NTF-020](NTF-020.md)实现。字段及边界见[设计第3／4节](../dev/SoulX-Duplug/independent_streaming_frontend.md)。

## 工作范围

1. 为正文和状态提供独立字段更新入口，在锁内读取最新记录并只合并本路字段，避免旧快照覆盖另一路新结果；推理、网络和落盘不持锁。
2. 分别保存正文、原始状态和解码进度的真实观察上界、可用与发布时间。WAIT无文字时允许只更新ASR进度，不刷新正文时间；旧processed_until若保留，只指SoulX主块截止，其他更新不要求它增长。
3. 保留稳定session_id／turn_id与正文来源 `x2_streaming_asr`；只接受已闭合累计正文并检查追加前缀，不接收子词草稿。状态尚未到达可未初始化，尚无闭合正文可为空，不能伪造配齐；无需额外等待下一词或标点。
4. SoulX内部reset只更新控制代次，不清空正文、不创建新逻辑话轮。显式关闭后拒绝迟到结果，EOF和drain文字单列诊断。
5. 有效nonidle仍直接走唯一停止钩子；原始complete立即记录但不直接许可回答，交接ready的原子字段接口供NTF-020使用。本单不接下游模型，四类非complete状态及正文无跨路等待。

## 验收标准

- 必要检查覆盖正文先到、状态先到、状态连续变化但无新字、文字更新时状态不变，以及两线程交错写入无丢失更新。
- 完成进度与正文分开推进，WAIT不改文字时间；预留交接更新不能覆盖较新的原始状态或正文。complete生成边界、取消和超时检查由NTF-020补齐。
- 子词草稿对Context不可见，EOS闭合后完整词／多词组一次可见；后续追加不回改已有正文。组内每词不伪造单独可用时标，LLM仍使用其自己的tokenizer。
- 每组时间／采样位置只由所属路推进；原子快照允许两路进度不同，不冒充同块对齐或尾词完整。
- 空结果、识别异常和reset不意外清空正文；关闭后两路回调均不能重开或修改话轮。
- 读取返回副本；同一话轮仍只有一份当前值，覆盖不重复触发直接停止，不增加历史事件投递承诺。
- 同步更新SharedContext实现、受影响调用方、必要测试的docs同路径说明，以及[接口合同](../dev/SoulX-Duplug/shared_context_interface.md)的实现状态。
- 同步架构图前端部分及绘图说明，明确内部SenseVoice教师和外部X2Streaming-ASR正文的独立用途；保留下游模块分工。
