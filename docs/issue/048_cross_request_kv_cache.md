# Issue 048：跨 micro-turn 请求复用 KV cache

状态：进行中，2026-10-21。用户已授权实现及远端延迟对照测试，执行由 Issue 049 跟踪。

## 目标与依据

当前模型服务每拍重建完整 token 历史并重新调用 generate，没有跨请求保留 KV cache。本任务按会话复用完全匹配的历史前缀，减少重复预填充计算，测量首控制标记、首正文与整拍耗时的改善；不预先承诺具体收益。

主要入口：[模型服务](../../scripts/remote/duplex_model_service.py)、[模型客户端](../../xtalk/src/xtalk/duplex_control/model_client.py)、[运行适配器](../../xtalk/src/xtalk/duplex_control/runtime_adapter.py)。缓存位置和 attention mask 处理参考[当前依赖版本文档](https://huggingface.co/docs/transformers/v4.46.3/en/kv_cache)。

## 工作范围

- [ ] 提供显式会话身份与可关闭的缓存路径，保留无缓存基线；缓存按会话及模型/适配权重身份隔离，沿用当前推理串行所有权。
- [ ] 以完整输入 token ID 与实际已缓存前缀匹配，正确处理消息头、控制标记、EOS、位置、attention mask 及生成结束时尚未进入缓存的 token；不通过重新编码生成文本替代原始生成 ID。
- [ ] ASR rewrite 修改历史时，仅复用仍完全一致的前缀；失效后缀重算，必要时清空缓存回退。保持完整历史和既有上下文长度检查，不引入历史裁剪或滑窗。
- [ ] 处理取消、断连、生成异常、会话结束和缓存淘汰；缓存必须对应下一次实际接受的历史，无法确认时清空重建。停播不自动撤销模型历史或用户已听内容。
- [ ] 限制缓存会话数、token 数和显存预算，提供命中、失效、淘汰及占用诊断；不在本任务引入新推理框架、量化、并发批处理或重新训练。
- [ ] 修改代码前同步相关中文设计说明，并更新每个实现/配置/测试的同路径文档。保持 Layer 动作边界、单一仲裁器和单一 TTS 播放所有权。

## 验证与交付

- [ ] 必要测试覆盖追加、静音拍、ASR rewrite、EOS/长度终止、取消后续请求、多会话隔离及淘汰后重建，检查实际缓存长度与历史对齐。
- [ ] 固定权重、精度、贪心生成、64-token 预算、600ms micro-turn 和 TTS 参数，远端以相同输入进行有/无缓存比较；先用固定历史请求隔离计算收益，再观察完整链路效果。
- [ ] 分短/中/长历史报告预填充与请求到首控制/首正文、整拍耗时、实际拍间隔、峰值显存和常驻缓存占用；区分首次冷请求、缓存命中与失效重建，不混合统计。
- [ ] 核对缓存路径与完整历史基线的生成 token ID。若存在数值差异，保留首次分歧及对应前缀并排查，不直接宣称行为等价；补充漏答、提前开口、插话停播与协议错误回归。
- [ ] 远端使用 conda 和调度作业；执行前冻结计算、内存/显存、磁盘、时长和并发上限，串行比较，记录源码、资产、输入、退出码及逐例结果。
- [ ] 交付收益、资源代价、正确性证据及采用/回退结论，完成后归档。尚未执行的测量保持未执行。

与 [047](047_tts_first_segment_latency.md) 分别验证，缓存比较期间 TTS 参数一致。缩短 micro-turn 为后续独立讨论，不纳入本任务；本任务也不重启已关闭的训练阶段。建单不代表已启动远端作业。
