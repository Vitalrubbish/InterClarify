# Issue 047：首段 TTS 文本聚合期限降至 300ms

状态：进行中，2026-10-21。用户已授权实现及远端延迟对照测试，执行由 Issue 049 跟踪。

## 目标与依据

当前 LLM 正文已增量送入 KokoroSegmented，同一回答可跨 micro-turn 连续合成；首段仍通常聚合 600ms，后续段期限为 1,200ms。将首段期限降至 300ms，验证首可听延迟与听感、播放连续性的变化，不预先承诺端到端节省 300ms。

## 工作范围

- [ ] 在现有客户端中独立配置首段和后续段聚合期限，支持复现 600/1,200ms 基线及 300/1,200ms 候选；维护克隆与配置加载的一致性。
- [ ] 保持完整词边界、句界提前提交、160 字符上限及结束 flush；300ms 是聚合期限，不是残词必须提交或用户必须听到声音的硬时限。`min_chars=12` 仍为句界触发条件，不改成字符数到阈值立即提交。
- [ ] 固定现有权重、Nemotron/Kokoro、600ms micro-turn、正文过滤和单一播放所有权；本任务不恢复句点、不改变后续段期限、不重新训练。
- [ ] 同步客户端、配置及相关测试的同路径中文文档，补充首段/后续段期限独立生效、词边界与取消隔离的必要回归验证。

主要入口：[KokoroSegmented](../../xtalk/src/xtalk/models/tts/kokoro_segmented.py)、[英文运行配置](../../configs/xtalk_duplex_english_runtime.json)。依据见 [TTS 报告](../tts_selection_report.md)。

## 验证与交付

- [ ] 用固定文本增量轨迹比较基线与候选，覆盖短确认、澄清、长回答与慢供给；再以同一真实链路输入验证，避免把脚本供给结果当作端到端结果。
- [ ] 记录首正文到达、首段提交、PCM 到达与客户端首可听代理，分别报告聚合和合成耗时；保留断流次数/时长、取消后过期音频隔离及人工复听结果。首包、TTSStarted 不替代首可听。
- [ ] 远端使用 conda 和调度作业；执行前在任务单冻结 GPU/CPU/内存、磁盘、时长及并发上限，串行比较条件，保存源码、资产、输入轨迹与退出码。
- [ ] 交付逐例比较及采用/保留基线的结论，不以加快开头但损害连续性作为自动通过。实现、验证和结果交付后归档。
