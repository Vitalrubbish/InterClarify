# NTF-019：独立流式正文与原生状态的固定 FDB30 验收

日期：2026-11-02。状态：待实施。依赖：[NTF-018](NTF-018.md)完整预热与实时门槛通过。

## 目标

在固定英文三轴各10条样本上验证：保留原生控制协议后，独立流式正文能持续可读，状态发布无需配对等待，完整预热后同卡运行无过载。工程完整性与状态／转写质量分别报告，不把本实验扩大为下游Agent验收。

## 固定条件与工作范围

1. 沿用既有FDB30 manifest，SHA256 `403be34448e0b011fa0b6a26216c0390ea3ed46ce77335e4bbe7a20cde4f3c07`；冻结顺序、音频转换／增益、模型／源码摘要、种子及评分坐标，不换样本或用失败结果调阈值。
2. 两个固定实验臂分别为SoulX原生单路和SoulX原生控制＋独立Nemotron正文，均按NTF-018完成完整预热。模型配置、reset语义和输入相同；单路只作为状态与调度参考，不将其内部窗口文字当作新方案权威正文。
3. 每臂独立进程、每个固定样本独立会话；模型在本臂30条间常驻，只清理会话状态，不逐例重载或给失败样本补做预热。
4. 对照真实状态产生、状态发布与正文发布时刻；同一PCM区间核对音频token、内部实际控制文字、规则调整和状态轨迹。差异先查输入／reset／来源，不拿历史r6当协议真值。
5. 分别统计接话提前／结束后complete、停顿区间内complete、打断有效nonidle及结束后complete；主块、实际观察和墙钟口径并列。输出为停止回调探针，不冒充物理停播。
6. 正文只评价Nemotron在线已可见内容，报告有参考样本的在线WER、首字可见、结果可用至发布的延迟、complete时正文及之后实际到达的尾词。无可靠词级时标时不宣称逐词延迟；EOF后drain不得回填在线分数。

## 验收标准

- 双路正式30/30完整、退出0、无800ms触发、无PCM静默丢失／越界；失败样本计入固定分母，不能只报告共同成功子集。
- 在非空正文的样本中展示完成状态之前已有正文可读的实际轨迹；不得等待SoulX配齐、complete或整轮重识别才发布。
- 每次更新的来源、采样上界、可用／发布时间正确，单路更新不覆盖另一路较新字段；reset不丢正文，关闭后不再写入，未完整尾词不假定final。
- 提供两臂状态质量、各路延迟P50/P95/max、未读PCM与积压曲线、首帧／稳定阶段及资源对照。工程通过不要求虚构质量改善，状态差异和未通过项逐例解释。
- 中文报告、配置和必要分析脚本及其docs同路径说明齐备，工作单按实际交付归档；没有下游切换或全量benchmark结论。

## 资源与停止边界

远端conda、单并发；最多2个串行作业，每臂一次，各≤1800秒、结果≤128MiB，1×4090、4CPU、32GiB RAM、显存22GiB停止线。每路worker各1、CPU线程各≤2；每路未读PCM≤800ms、PCM合计≤4MiB，送音迟到和发布延迟执行既定800ms停止线。与NTF-018累计GPU预算≤2小时、结果≤512MiB，启动空闲盘≥10GiB；触限保留失败，不自动筛选重跑、放宽限制或扩容。不训练、不接LLM／CoT／TTS，本轮只建单。
