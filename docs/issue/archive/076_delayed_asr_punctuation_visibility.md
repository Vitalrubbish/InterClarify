# Issue 076：明确ASR延后补点的训练可见性

状态：已完成并归档，2026-10-21。本单已核对已有探针并修订073结论、074计划及ASR说明，不修改实现或训练数据、不运行新模型。

## 用户观察与已有证据

用户检查疑问句后补充：当前ASR在一句话结束时通常不立即输出句末标点，待下一句开始时才输出上一句的标点；User Interruption启动时也能观察到这一现象。这意味着需要适配标点的到达顺序，不能仅依据最终文本决定每拍可见内容。

读取已存`reports/asr_text_surface/20261019/report.json`：`contractions`的第28个更新（从0计）为`Don't stop.`，此前为`Don't stop`，新增`.`；随后更新为`Don't stop. I`。`year`的第29个更新新增逗号，随后出现`the`。这支持标点可独立于后续文字增量到达，不要求与下一句首词同一个decoder更新。旧探针没有逐更新声学位置，不证明补点相对下一句发声的精确时延；用户的实际疑问/插话观察与旧朗读探针分别记录。

探针JSON文件SHA256为`e8d0ba05a3bf935c59a5202ff7783b5bec0e322e04dd69aa864313b1c8abbccb`，本次只读，未改写。

## 需要落实到074的约束

- 同一ASR连续识别上下文内，区分原文中句界位置与标点实际可见时机。当前句结束、后续尚未到达时，不因离线已知下一句而提前发放句末标点。
- 后续句/用户再次开口时，按模拟的ASR到达顺序，把上一句迟到标点追加到后续增量；不回写模型已经消费的旧micro-turn，不删除或重建既有assistant生成历史来伪造当时可见内容。
- 允许底层出现独立标点增量；是否形成独立600ms micro-turn由落窗决定，不能机械固定为“下一句首词同拍”，也不能人为额外制造一拍。停顿/插话控制监督继续遵循事件计划，补点本身不等同于当前用户让轮。
- 最后一句后没有后续输入时，以现役ASR稀少末尾标点的形式为主要拟合目标，同时记录已观察到的少量末尾点号/EOF补点；不写成所有样本永不补点的断言。ASR上下文重置时不跨会话搬运待补标点。
- 074冻结实现前，核查连续两句、较长停顿后续说、系统回答期间用户再次开口、识别上下文重置和EOF等场景的到达记录，明确问号/感叹号及600ms落窗；不把FDB未来续说或结束标注作为模型输入。
