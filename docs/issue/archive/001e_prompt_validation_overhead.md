# Issue 001e：修复输入校验反复计算词表大小导致掉拍

状态：完成，2026-10-18。父任务001。用户指出600ms节拍下8秒应有十余拍，复核发现不能仅解释末尾8/7差异：两路完整请求耗时随历史增加，由约0.18秒增长到2.07秒，GPU生成本身仍约0.04–0.24秒。

根因证据：stream_ids在每个prompt token的范围检查中调用len(tokenizer)。远端transformers4.46.3/tokenizers0.20.3的该方法计算包含新增token的词表大小；真实发布tokenizer上9次约0.138秒、23次0.352秒、49次0.814秒、90次1.502秒、130次2.117秒。它在GPU生成计时之前，旧日志只报生成时间而漏掉了这部分CPU开销。新本地tokenizers0.23.2无同样明显开销，不能据本地版本推断远端性能。

修复为每次请求只计算一次词表大小，再逐token验证范围。保持实际tokenizer、权重、IDs、严格校验、串行调度、600ms间隔与观察窗不变，不通过修改验收门槛制造通过。新增带调用计数的回归，核验正常与越界ID；在同一远端tokenizer上复测校验耗时，并以新快照重跑raw/完整词两条件的真实权重协议轨迹。完成后回填结果并归档，001其他缺口仍独立保留。
