# TT-003：接入 Nemotron 与 Shared Context

状态：已完成并归档（2026-10-25真实链路核查）。依赖：[TT-002](tt_002_training.md)形成可继续验证的候选。依据：[训练方案第 1、5 节](../../../archive/dev/TextTurn/training_plan.md)。

## 目标

让候选读取 Nemotron 在线输出，在同一条路径上完成动作判断及每个用户 turn 的下游转写交付。

## 工作

2026-10-25核查：候选已通过TT-002开发集gate并实际运行Nemotron链路；3来源／12条真实冒烟运行和Context均一致，正式1200例Context写入／读取全部一致，存在4例在线步骤或控制运行失败，详见[结果核查](../../../../reports/textturn/20261025-tt-004-results/README.md)。接口交付完成不表示语音模型质量达标。真实步骤采用固定Nemotron实现的编码帧耗尽边界，等待相应streamer交付最后token后发布；每三个完成事件聚合，不从音频接收进度推断。Shared Context及步骤游标均有界，关闭与EOF分离；本项不启动第二个并行GPU作业。

1. 适配现有 Nemotron EN160，在每个解码步骤完成时交付新增文本或 `no-voice`，包括无字输出步骤；不能用音频接收／读取进度冒充解码完成。步骤事件适配与实际接入一起交付，不另起协议研究任务。
2. 转写先按稳定 `turn_id` 和版本写入 Shared Context，提供最新话轮快照与按游标读取更新；控制器和只读消费者从同一来源消费，不等 start 才交付文本。
3. 每三个解码完成步骤聚合为480ms控制窗，累计新增文字或整窗no-voice后触发控制；EOF不足三步的尾窗记录实际覆盖范围。最多一个在途请求和一个待处理最新快照；合并未启动观察时保留累计文本和合并记录，480ms聚合之外不追加固定等待、不每步取消重算。
4. 对接 Listen/Speak 及模拟输出生命周期；stop 只记录用户打断意图，正常结束通过播放完成事件转换状态。少量样本直接跑通流式输入、动作返回与下游读取。

## 交付与验收

- 一个可用于 TT-004 的远端影子回放入口、Context 写入／读取接口及对应中文说明。
- 文本单次消费、同 turn 连续更新、重复／乱序、空步骤、错误和关闭／EOF 分离得到必要测试；当前 ASR 不支持的回写明确失败，不静默丢词。
- 保存解码步骤、480ms窗覆盖范围与聚合等待、转写版本、Context可见时刻、控制返回及合并数，足以测量实际延迟；真实步骤事件无法取得时交付具体缺口，不改用独立 600ms 计时器顶替。

本项不加载下游 LLM、不接入真实 TTS／播放器、不切换现役运行时；共享接口由只读消费者验证，控制动作不执行播放。
