# TT-009：重测效果不佳后的条件性训练数据重构

状态：已按用户指令终止并归档，未实施，不计为完成。2026-10-25用户明确要求直接归档，由[TT-010](tt_010_asr_update_yield_dataset.md)替代；新数据改造不再以TT-008结果不佳为启动前提。原条件性方案保留作历史，以下内容不再代表当前授权合同。

## 目标与假设边界

若正确注入助手正文仍不能可靠输出stop，重构控制训练数据中的轮次、生命周期和用户接管覆盖。缺少正常结束的状态边界、stop监督范围过窄、时序捷径和配比失衡均作为待检查原因，不提前宣布其中某项已被证明。

当前合同明确：start开始表达，stop专用于用户打断；回答自然完成由生成／播放结束转Listen，不产生stop标签。两者不要求逐次配对。已有构造包含generation、playback_tail、playback_complete与轮后Listen等待；需要检查这些状态转换是否完整进入可学习的输入与监督，不能把“没有正常结束stop标签”直接等同遗漏标注。

若用户后续明确选择让stop同时表示正常结束，则先更新研究设计、训练合同、标签语义、动作执行与评分文档，再据此实施；本工作单当前不预先授权这一合同变更，也不新增动作或扩大MVP。

## 工作

1. 依据TT-008的480ms（8 token／周期）、160ms（3 token／周期）注入正文重测结果和现有[数据审核](../../../archive/dev/TextTurn/data_review.md)，核查历史／轮次错误、自然完成输入缺失和真实stop监督不足。TT-008已按用户要求取消空正文对照，不能把结果写成已隔离正文因果作用的证据。只用训练及开发来源构造或选参，UltraChat测试与FDB文本／trace不得回灌训练。
2. 重建有因果顺序的完整轨迹：用户输入→start→助手已发布前缀→用户接管或自然完成→Listen及下一轮；记录动作前输入和动作后状态。区分正文生成完成、待播放尾窗及播放完成，未知未来正文和未来结束时刻不能进入当前快照。
3. 自然完成路径显式记录完成事件、结束前Speak／keep及结束后Listen／keep，核对助手正文提交历史和当前用户段重置；用户打断路径保留Speak／stop及停止后已到达用户内容，不把两条路径压成同一标签。覆盖尾窗内打断与自然完成相邻的边界。
4. 扩展当前仅少量Stop／Wait／Please stop前缀的监督，构造需要让轮的普通续说／接管、纠正和请求变更；配套短附和、词内ASR补全、含义未明前缀及无用户输入的keep对照。新标签只依据当时可见训练场景与事件，不据测试错误倒推标签；必要的训练标签核查不变成重新要求本轮行为测试补语义金标。
5. 降低生命周期及重复keep的无信息占比，按来源和独立机会分层，限制重复窗口。既有30／20／20／20／10类别预算只是开发集验证起点，不强行三动作等量，不为凑足10000窗复制数据或牺牲因果上下文。保留来源／近重复组隔离。
6. 固定160ms／480ms的时间单位与助手发布时序，避免用“每周期几个token”在更换周期时隐式改变生成速度；训练周期默认仍按已有480ms合同，修改前明确更新相应方案。保留no-voice约定，不增加VAD、固定等待或ASR延迟补偿。

## 交付与完成条件

- 版本化数据重构说明、来源及切分清单、完整轨迹样例、动作／状态边界统计、正式快照和输入摘要；旧TT-001冻结数据保留，不原地覆盖。
- 分别给出自然完成、用户打断、附和及新输入的覆盖，检查start后的状态、用户轮迁移、助手角色和正文前缀是否一致；说明每项修改解决哪类已有证据支持的问题。
- 少量必要测试覆盖动作合法性、正常结束不用stop、打断stop、尾窗、字段与角色分离、时间单位和数据切分；代码与docs对应路径同步维护。
- 文本数据构造和核查使用本地／远端已有conda，设置工作数、内存、磁盘及超时；不加载GPU模型。正式规模仍不超过原1000训练对话和10000快照上限，实际不足如实披露，不自动扩容。
- 交付给用户检查并满足数据一致性要求后归档。重构完成不等于stop能力已改善，必须由后续训练与独立评估验证；本项不自动训练、不调参、不替换现役候选，也不自动解除原累计GPU预算。

维持Layer职责、单一仲裁器及单一TTS播放所有权。已听内容不可撤销；本项仅重构普通控制数据，不训练表达正文、ASR、CoT或Layer 0／1／2。
