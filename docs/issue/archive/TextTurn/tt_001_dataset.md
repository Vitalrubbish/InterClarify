## 目标

把旧 UltraChat 对话和事件计划直接转换为可训练的 TextTurn 数据，覆盖正常接话、用户打断、用户附和和停顿处理。

## 工作

2026-10-25 用户明确要求继续完成并启动训练及评估。本次补齐正式构建：完整校验同一 revision 的 train_0 分片；从 Git 历史索引排除已用来源，并排除首批 review 来源。旧事件产物仍未恢复，因此新时序明确记为合成。正式候选仅选取可用语义规则明确审核的完整英文请求、陈述及不完整前缀，不把随机截断直接标 keep；标签来源为规则辅助审核与代理抽检，不能称作逐例人工审核。去重先于切分；训练窗口分层抽样，完整轨迹另存，目标上限与缺口照实报告。若来源隔离或语义条件不能满足则不放行训练。

用户检查后的修订：User Backchannel 以 `Hmm.`、`I see.`、`Right.` 这类短促回应为主，移除首批附和样例中为明确标签而追加的继续指令。短回应依据当前可见上下文标 keep，后续明确打断再标 stop，不使用未来内容提前改写标签；歧义仍保留未知。该调整仍在本工作单内，不新增 issue。

2026-10-24 历史修订：按用户进一步指令，逐条复核剩余七个未标注快照：六个 Listen 快照仍在接收新增文字，尚无当前表达结束后的让轮观察，标 keep；一个 Speak 快照仅出现 `Please`，没有足够的停止依据，标 keep。补标依据只取当前可见内容，不把所有缺失标签自动填为 keep，也不新增固定静音等待时长。

2026-10-24 历史修订：用户指出旧实现已支持 Assistant 每窗 10 token 推进，首批固定前缀遗漏了这一机制。本轮在本工作单内恢复双向文本时间线，Assistant 改为每个 160ms 步骤 2 token，只累加当前已发布片段；附和和打断到达时助手继续推进，自然完成仍由单独的播放完成事件结束，不新增训练或执行路径。

2026-10-25 用户进一步确认：控制窗改为480ms，User非空输入随机1—2 token／窗，Assistant改为8 token／窗模拟生成。增加随机播放尾窗与下一轮开口等待，生成结束不退出Speak，播放完成才转Listen；重建全部观察窗监督和逐窗阅读表，不新增issue。此前160ms／2 token方案保留为Git历史，不再作为当前合同。

本轮按用户要求，将分离的阶段片段替换为六个来源各一条连续综合轨迹：Listen用户输入及停顿→start→Speak生成和附和／打断→播放完成或stop→Listen等待或续说→再次start并回复。模拟执行事件与动作监督分开，保留打断前已生成前缀和当前用户文字，不泄漏未生成回答；类别在轨迹内按阶段统计，不把窗口数当作独立对话数。不新增issue，不执行真实播放或模型训练。

1. 从既有资产或固定来源恢复旧对话与分组；复用有效来源和切分，不恢复整套旧训练框架。旧测试如已被调参使用，保留为回归材料并补充未用来源。
2. 按480ms重建控制窗：User每个非空窗随机1—2 token，Assistant每窗8 token模拟生成；空窗输入no-voice并保留连续空窗数。随机话中停顿、生成后的剩余播放尾窗和播放完成后的下一轮等待分开构造。用Qwen3 tokenizer编码，仅监督合法动作。
3. 生成 Listen 下 keep/start、Speak 下 keep/stop 的决策快照，只保留当前可见历史；自然说完不标 stop。start 中完整陈述／陈述式回答至少占三分之一，补足附和与真实打断的上下文对照。
4. 产出最多 2,000 个机制试训快照，以及最多 1,000 对话／10,000 快照的完整训练候选；目标开发 200、独立测试 300 对话，测试四类各覆盖至少 100 个不同场景组。去重、标签抽查和损失 mask 检查与构建一起完成，未知标签不强行填充。

## 交付与验收

- 数据构建入口、配置、对应中文说明，以及来源／切分／审核清单和可读取数据。
- 四类数据和陈述句数量可直接统计；同源派生不跨集合，测试资料不进入训练；只监督动作，旧 token ID 和回答正文目标已移除。
- 保存完整目标及实际数量、超长／歧义／不可用记录。数量或来源不足明确报告，不能用重复窗口补足；不将存在缺口的材料标成已满足正式训练／独立测试条件。

本项不加载模型训练，不安排大规模人工审核或单独探针项目；只做能支持标签和切分正确性的必要检查，少量测试随构建入口交付。
