# TT-005：统计 FDB 50 条录音在ASR停止更新后的Speak／start比例与start等待拍数

状态：已完成并归档（2026-10-25结果核查）。依赖：[TT-002](tt_002_training.md)、[TT-003](tt_003_streaming_context.md)。依据：[FDB 跨数据集计划](../../../dev/TextTurn/fdb_cross_dataset_plan.md)。

2026-10-25交付核查：480ms正式100条均运行成功、无未知。接话50条中，最后ASR更新后Speak为44/50、start为21/50；仅这21条的首次start平均等待1.5896拍、763.00ms。逐例CSV、汇总JSON及trace已核对，见[联合结果](../../../../reports/textturn/20261025-fdb-action-only/README.md)。本项工作完成不代表完整四类验收通过。

2026-10-25按用户最新纠正：本测试只监控TextTurn，移除模拟回答及其生成／播放生命周期。原r1—r3保留为撤回记录，新480ms结果按相同样本重提，不能沿用旧协议成绩。

## 目标

直接交付50条真实录音在ASR转写不再更新后，系统处于控制器Speak状态的样本比例、系统输出start的样本比例，以及其中输出start样本的平均等待拍数。三项分别统计，不以FDB参考后1000ms覆盖替代。

## 工作

1. 按计划的固定种子和排序规则，从 `candor_turn_taking` 取50条有效且音频不重复的录音，保留候选、排除理由、资产摘要和已知历史使用；候选不足时交付原因，不换来源或缩小分母。FDB标注仅作辅助分析。
2. 使用固定候选 `tt-002-20261025-r1/best` 和真实Nemotron EN160，80ms包实时回放，每三个真实解码完成步骤形成480ms控制周期。每条从Listen开始，仅start进入Speak、stop返回Listen、keep维持状态，不模拟回答、生成或播放，不自动复位。
3. 使用测试流程已经自动拼接的5秒静音，不重复拼接，也不在音频结束后额外人工输入 `<no voice>`。这5秒经过ASR后，自然无新增转写的完整周期仍正常形成no-voice输入；实际输入结束后不再补控制周期，EOF排空单列。
4. 离线确定在线ASR转写最后一次实际变化并发布到Shared Context的时刻 `t_last_asr_update`；重复文本不算更新，无有效转写时标未知。按计划记录该时刻之后的Speak状态、start动作、首次start完整返回时刻及等待拍数，以及未命中或失败的原因，不用音频结束、EOF或整段参考匹配替代边界。

## 交付与完成条件

- 50条冻结清单、ASR／控制／控制器状态trace、逐录音CSV、汇总JSON及中文结果。
- **ASR停止更新后Speak样本比例**：最后更新之后至少一个完整控制周期的动作应用后状态为Speak的录音数／50。
- **ASR停止更新后start样本比例**：最后更新之后至少一次控制输出为start的录音数／50，按动作完整返回时刻归属。同一录音重复命中只计一次；更新前已经进入Speak并持续至更新后，可只命中Speak项而不命中start项。
- **输出start样本的平均等待拍数**：仅对最后更新之后输出过start的录音，取其之后首次start完整返回时刻，逐例计算 `(t_first_start - t_last_asr_update) / 480ms`，再求算术平均；一拍为480ms，允许小数，包含聚合、排队及返回等待。重复start不重复参与平均，同时报告有效样本数和逐例等待拍数。
- 未输出start的样本不参与等待拍数均值，不填0；计时缺失单列未知，没有有效样本时均值为null。等待拍数均值的分母为符合条件且计时有效的start样本数，不是50条计划录音数，也不是start调用次数。
- 观察包含已有5秒静音对应的正常在线周期，不追加观察。两项分别列命中、已确认未命中和未知，保留50条计划分母及保守上下界；可判定比例列分子／分母和Wilson95%区间。不得以运行失败或没有ASR转写冒充正常未命中。
- 另报控制耗时P95、聚合等待、状态转移及EOF情况；这些是控制器状态和动作统计，不称为实际开口延迟或官方TOR。
- 接话好坏均可完成本项；缺失和运行失败必须如实交付，不能换样本补成成功。结果用于跨集诊断，不等同完整四类验收。
