状态：待办。优先级：P0。依赖：001；文本训练集不依赖 002，真实 ASR 迁移评测数据依赖 002。

## 目标

训练模型适应无标点及真实流式 ASR，同时保留等待、附和与打断能力。数据必须区分“完整文字的合成 micro-turn”与“真实 Nemotron 在线轨迹”，不将前者冒充后者。

## 首轮主线：复用文本数据与论文生成方法

2026-10-18 根据用户建议，优先使用 DuplexCascade 所采用的 UltraChat 数据来源与 micro-turn 构造方法，先做用户侧含句读/去句读的混合继续训练。不将上一轮讨论的“先采集 400 条真实轨迹”作为开训门槛；真实 Nemotron 轨迹优先用于独立迁移评测，后续有必要再纳入适配训练。

公开性核对：截至本次检查，[官方 GitHub](https://github.com/sbintuitions/DuplexCascade) 主要提供推理代码；[论文 3.3 节](https://arxiv.org/html/2603.09180v1#S3.SS3) 说明从 UltraChat 抽取 50k 对话并动态构造训练序列。目前未找到作者精确的 50k 样本清单或完整生成/训练管线。因此优先复用可取得的官方资产；不足部分按论文重建并明确标注，不能称为已取得完整官方管线。[UltraChat 来源](https://github.com/thunlp/ultrachat) 的具体发布版本仍需核验。

首轮准备 1,000 条原始文本对话用于训练、200 条用于文本开发、300 条用于内部文本测试，先从训练集合抽 32/100 条检查与短跑。每条对话可生成多个 micro-turn，独立对话数、生成序列数与有效 token 数分别记录。混合组以对话为单位 50% 保留用户普通句读、50% 去句读，每次曝光只选择一个视图，首轮不搜索比例。该 50/50 为实验起点，不宣称最优。

文本集合先按原始对话划分，再构造 micro-turn 和增强。由于作者原训的精确样本清单不可得，不能保证文本保留集没被官方模型训练见过，只能称其未参与本次继续训练；真实 Nemotron 独立评测承担迁移验收。

构造顺序：先在原文上冻结相同的微轮边界、停顿、插话与附和事件及控制监督，再变换用户普通句读，避免去标点改变 tokenizer 后重新分拍而混入另一变量。记录 token 预算可能变化的事实。保留论文中的自然停顿、用户插话、用户附和和回答后思考；按项目无系统附和范围关闭 system backchannel 生成，不需要为此调用 72B 模型标注系统附和。
