# Issue 004：使用 UltraChat 自行实现 micro-turn 数据生成管线

状态：待办。优先级：P0。依赖：001；文本训练集不依赖 002，真实 ASR 迁移评测数据依赖 002。

## 已确定的实现路线

使用 DuplexCascade 官方论文采用的 **UltraChat 原始对话数据集**，由本项目自行实现数据生成管线，从普通文本对话构造双工 micro-turn、控制监督和用户句读增强视图。首轮不以自行采集音频或生成新的基础对话语料替代 UltraChat。

[论文 3.3 节](https://arxiv.org/html/2603.09180v1#S3.SS3) 说明从 UltraChat 抽取 50k 对话并动态构造训练序列；[UltraChat 官方来源](https://github.com/thunlp/ultrachat) 的具体发布版本、split 和字段在下载前冻结。作者精确 50k 清单和完整生成代码目前未取得，本项目不声称使用同一批 50k 样本或直接复用官方生成程序。版本无法确认时记录证据与选择依据，不静默换成名称相近的清洗变体。

真实 Nemotron 轨迹优先用于独立迁移评测，不要求先采集 400 条才能开训。合成序列和真实轨迹使用不同 source_type；文本生成器不伪造音频、说话人或真实到达时间。

## 样本与切分

首轮准备 1,000 条原始对话用于训练、200 条用于文本开发、300 条用于内部文本测试；先从训练集合抽 32/100 条检查与短跑。独立对话数、派生序列数、micro-turn 数及有效监督 token 数分别报告。失败或不合格对话按预登记规则补选，保留排除原因，不按模型结果挑样本。

先按原始对话 ID 与近重复组切分，再生成事件和增强；同一对话全部种子变体、片段和句读视图只能进入一个集合。UltraChat 没有真实说话人时不伪造 speaker 分组；真实录音按对话和说话人分组。完整 FDB、已有五例、FLEURS 100 条不进入训练或 checkpoint 选择。

作者原训样本清单不可得，文本保留集只能称未参与本次继续训练，不能保证官方 checkpoint 从未见过。真实 Nemotron 独立评测承担迁移验收。

## 自行实现的生成步骤

1. **读取与过滤。** 固定来源 revision、split、字段、语言和长度规则，保存原始 ID、摘要及排除原因，保留原始文本。
2. **构造基础事件。** 按论文方法拆分用户/assistant 微轮，构造等待、接话、自然停顿、有效插话、用户附和与回答后思考。固定 tokenizer、种子与事件计划；合成时钟只表示模拟窗口，不宣称真实 ASR 到达时间。
3. **生成监督。** 使用发布 checkpoint 的实际五类控制 token ID、ChatML、no-voice、结束 ID 与 assistant 文本；控制名称到 wire token 的映射必须显式核验。loss 只覆盖合法 assistant 目标，不训练 user/padding。关闭 system backchannel。
4. **构造句读视图。** 先冻结基础微轮边界、控制事件及目标，再只变换用户普通句读；不因去标点后 tokenizer 长度变化重新分拍。保护特殊 token、撇号、连字符、小数与时间格式，assistant 标点保留。
5. **混合与序列化。** 生成原样、去句读和混合视图。混合按原始对话、每个 epoch 以固定种子平衡分配 50%/50%；1,000 条时为 500 条原样、500 条去句读，每条每次曝光只选一个视图。新 epoch 可重新分配，保存分配表，不能数据翻倍而不记录预算。
6. **长度与审计。** 最长序列按 005 实测冻结。分段/截断须保留合法消息与控制边界、必要上下文，不把截断位置标成真实用户结束。保留生成器版本、参数、事件计划、增强映射与摘要。

论文参数作为首轮生成配置的起点：用户微轮随机 1–7 token、assistant 微轮 10 token；自然停顿概率 0.10、增加 1–5 空拍；每个系统长轮模拟插话概率 0.30；系统微轮中的用户附和概率 0.01；回答后思考增加 1–20 空拍。实现时逐项核对采样单位、触发顺序和控制监督，记录任何偏离与原因。系统附和步骤关闭，不进行 72B 系统附和标注。自然停顿不能统一监督成接话，用户附和不能统一监督成插话。

## 工作项

- [ ] 交付 UltraChat 来源清单：仓库/数据集 ID、revision、split、许可、字段映射、获取方式与原始文件摘要。
- [ ] 自行实现读取、过滤、切分、基础事件生成、句读变换、混合采样、序列化和审计；不把官方推理脚本或仅删除标点的脚本当作完整生成管线。
- [ ] 用配置表达论文生成参数和本项目关闭系统附和的差异，锁定 tokenizer 与实际 token IDs。
- [ ] 保存原始对话到派生序列/事件/增强视图的映射，保证三训练组使用同一基础事件计划。
- [ ] 区分可复现的动态生成与冻结评测序列；训练恢复时能恢复采样/生成状态或从可验证位置重放。
- [ ] 最小审计集供 005 短跑，完整数据与报告供 006；真实前缀标注另用于 007，完整录音和未来边界不进入在线输入。

## 测试与完成标准

- [ ] 实际可读取官方采用的 UltraChat 数据来源，版本、字段和摘要齐全；不把未知的作者精确 50k 清单作为已完成资产。
- [ ] 1,000/200/300 条原始对话切分完整，分组泄漏和跨集合近重复为零；过滤、补选、派生序列数量可追溯。
- [ ] 相同来源、tokenizer、配置和种子重复生成的事件/序列摘要相同；不同种子改变允许的随机选择而保持协议合法。动态生成保存/恢复后顺序可核对。
- [ ] 确定性测试覆盖继续说话、句末接话、句中空窗、用户插话、用户附和和思考；实际 token ID、目标 mask、消息边界正确，不出现系统附和目标。
- [ ] 原样与去句读视图的基础事件、控制监督及分拍一致；保护字符测试通过，允许的用户 token 长度变化被记录。混合组每轮 500/500 且没有重复曝光造成的隐藏翻倍。
- [ ] 最小集全部人工审查；扩充数据按行为类别抽查并双人复核一部分。生成事件计数、观测频率和采样单位有报告，不要求小样本频率精确等于理论概率。
- [ ] 报告对话/序列/micro-turn/有效 token 数、控制类别覆盖、长度、排除原因、合成/真实来源区别；没有未来文本泄漏、伪造真实时间戳或截断伪边界。
- [ ] 提供一条可执行的远端生成与审计命令、conda 环境及产物路径；完成数据交付才能运行 006，文本保留集不能代替真实 ASR 验收。
