# NTF-018：全链路预热与远端积压归因

日期：2026-11-02。状态：待实施。依赖：[NTF-015](NTF-015.md)—[NTF-017](NTF-017.md)及[NTF-020](NTF-020.md)。优先级：正式FDB30之前。

## 假设与已有证据

用户认为此前积压大概率来自预热不足。历史双ASR报告确认旧SoulX仅三块状态前向及一次3.36秒静音识别，没有复用更完整的非静音、多长度预热；SenseVoice同长度调用出现过约1.3秒长尾。该差异支持优先排查，但尚无隔离对照证明全部积压由此造成，见[追加审计](../../reports/soulx/20261031-dual-asr-publication/README.md#原始soulx配置差异追加审计)。

## 工作范围

1. 实现正式ready之前的完整预热：同一常驻模型和双路拓扑，覆盖音频编码、状态前向、真实语音门控与SenseVoice、多种窗口／整轮长度、文字修订、完成分支，以及X2首块／增量编码、LISTEN等待、DECODE多token和EOS闭合后完整词发布。冻结输入摘要、长度清单和覆盖项，不能只用静音。
2. 两轮固定完整预热均须有实际转写、覆盖记录和清理证据；未覆盖路径明确报告处理。就绪前等待异步工作及设备计算完成，清空预热会话KV／PCM／文字／计数／回调，保留常驻权重和内核缓存。正式会话统一重置随机数状态，避免预热次数改变原生reset的随机padding。
3. 提供受限远端脚本与同路径中文说明。冻结三种条件：双路既有有限预热、双路完整预热、SoulX单路完整预热；各条件从新进程开始，固定同一三轴预检音频、波形、种子、线程、规则和到达时钟。双路两臂只改变预热覆盖，单路臂仅作资源争用参考。
4. 每条件只执行一次固定三轴预检，清单不因结果替换。有限预热臂参考历史SoulX控制支路覆盖，仅用于诊断；双路两臂的X2均保留相同的两次真实语音预热，不通过关闭X2预热制造差异。完整预热后再启动正式到达时钟，加载、预热与在线耗时分列。更换ASR后该对照不属于旧Nemotron双路实验的单变量复现。
5. 记录每路未读PCM、送音迟到、排队、音频编码／ASR／状态计算、组内DECODE／EOS闭合、闭合至发布等待及积压曲线。分别报告第一帧、首个完整词、首遇长度／分支与后续帧P50/P95/max，不仅汇总均值；没有新闭合组不算漏发布。
6. 预热覆盖complete交接的进度追齐、无新字WAIT、正文提交和ready路径，正式会话清空预热交接记录。双路两臂使用相同NTF-020策略；拆分原始状态计算延迟与complete交接等待，取消／超时单列。单路参考只评价原始状态，不伪造无X2的ready对照。

## 验收与结论规则

- 预热结果不进入正式Context、模型缓存或话轮；两路均就绪才开始真实时钟回放。
- 双路完整预热预检3/3完整、退出0，无800ms过载触发，音频／来源／生命周期检查通过，才进入NTF-019。
- 交接等待不造成两路收音／计算暂停或其他状态发布阻塞；未就绪到期明确失败，交接deadline与既有800ms总线取更早者，不增加额外800ms预算。
- 对首遇路径长尾与稳定阶段积压分别下结论。完整预热后仍有持续积压，应报告该假设未充分解释问题及实际耗时来源，不能自动提高上限、加卡或换ASR。
- 单次小样本对照只支持该配置下的观察，不据此为所有历史失败分配因果比例。旧预热臂触限的样本同样保留，不通过筛除首帧美化结果。
- 中文报告保存配置、预热覆盖、逐阶段计时、资源、失败轨迹和退出码；工作单完成后归档，实时门槛未过则后续正式实验不启动。

## 资源与执行边界

真实模型仅在远端conda调度作业运行，复用既有模型／环境。最多2个串行作业，各≤1800秒、结果≤128MiB；1×4090、4CPU、32GiB RAM、显存22GiB停止线、每路worker各1及CPU线程各≤2。每路未读PCM、送音迟到和各路在线发布延迟按设计执行800ms停止线，PCM总量≤4MiB；空闲盘≥10GiB。不自动重复运行或扩大矩阵。本轮只建单，不提交作业。

## 160ms推进屏障纳入预检

双路有限／完整预热使用相同160ms推进屏障，每周期X2两个80ms原生步、SoulX一个160ms原生调用；不新增无屏障对照臂或作业。预热覆盖两侧先后完成、WAIT、WORD多token至EOS、reset、complete pending跨周期及关闭。单路参考只有SoulX，不伪造另一侧完成。

计时额外拆分本步输入就绪、两侧完成、先完成侧等待和屏障释放；验收确认下一步开始不早于上一步释放。正式音频持续按真实时钟到达，屏障期间积压和未读PCM照计，不能暂停送音隐藏吞吐不足。complete交接pending不得额外阻止已满足两侧完成条件的屏障释放，防止真实前瞻需要下一步才能处理时形成死锁。
