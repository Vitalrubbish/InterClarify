# 085：独立 Layer 0 与统一仲裁接入

状态：待执行，依赖 084；完整五类验收必要时还依赖 086。

## 目标与工作

按 [工程计划第 4、7 节](../engineering_implementation.md#4-layer-0-的输入输出与执行协议)实现独立 Layer 0 后端、服务和会话控制器。音频/ASR/播放事件组成因果观察快照，输出带来源和版本的外部状态，每会话一个推理在途，处理过期、超时和断连。

候选可返回自己的原生 token、类 ID 或分数，由唯一仲裁器直接解释；仅在下游确实要求 DuplexCascade 编码时转换。模型原始状态、服务平滑/回退与实际动作分开记录，不为 token 拼写不同改词表或训练。

在现有 `DuplexRuntimeAdapter` 的统一执行位置接入。先影子记录，再启用 Layer 0 作为唯一基础控制来源；不恢复被双工路径替换的第二套控制管理器。由实际播放反馈区分生成与已听内容，停止操作关联具体响应并去重。

过渡模式保留旧 Layer 1 真实生成历史，其基础控制 token 只作诊断；分别报告分类正确与表达是否产生。不得伪造 Layer 1 生成 token，也不得将控制 token 送入 TTS。

## 交付与验收

- 工程计划列出的 Layer 0 实现、配置及同路径中文说明；修改 X-Talk 文件同步更新其中文页。
- 覆盖暂停、让出话轮、附和、真实打断、ASR 修订、播放响应切换、过期结果、故障与重复事件的协议检查。
- 一个仲裁器、一个播放所有者；已播内容不撤销，分类器不独立播放；Layer 0 不判断主动澄清价值。
- 记录独立分类器结果与系统控制结果，完整五类缺口不得隐藏。后续 Layer 1 外部状态训练另立单。

采用新 X-Talk 提交后同步本项目源码指针与运行配置说明。
