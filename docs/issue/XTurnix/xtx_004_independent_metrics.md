# XTX-004：实现末端 start 延迟、覆盖与链路估计评分

状态：待实施。依赖：[XTX-001](xtx_001_fleurs_data.md)、[XTX-003](xtx_003_streaming_replay.md)。依据：[质量测试计划第 4、5 节](../../dev/XTurnix/quality_test_on_fleurs.md)。

## 目标

离线从原始 trace 独立计算“最后 ASR 词汇增量 → 有效 start”的延迟与覆盖，再生成采用历史 ASR 开销的链路估计。

## 工作内容

- `t_asr_last` 取在线阶段最后一次词汇增加或词内补全的客户端接收时刻；忽略仅标点、空白、EOS 或 EOF 排空变化。无可靠锚点时不回退文件末端。
- `t_start_after_last` 为锚点后首次有效 start 返回，请求输入必须已包含末次词汇前缀版本；旧前缀迟到结果不能计为末端命中。
- 在 `[t_asr_last, t_asr_last+5s]` 内按事件序号评分，并受实际在线截止/EOF 限制；窗口不完整、窗外和 EOF 后命中分开记录。
- 保存首次原始 start 的有符号相对时间，单列提前 start、过期输入、回写、空转写、超时及其他失败，不通过归零或丢弃掩盖。
- 输出全部 100 条的主覆盖分母，以及命中条件下延迟均值、P50/P95、最大值与样本数；缺失为 null，不填 0 或 5,000ms。
- 辅助计算语料 WER：固定 `whisper-normalizer==0.1.12`，正常空假设计删除，运行失败另报覆盖，在线文本与 EOF 最终文本分开。
- 仅对有效延迟生成 `L_chain_estimated=413.582852ms+L_control`，保留历史来源。不得称为实测音频末词到 start，不把两个 P95 相加冒称整体 P95。

## 交付

在 `scripts/remote/xturnix_fleurs_test.py` 中提供 score 入口，既能独立读取保存的 trace，又不访问模型；更新对应实现说明。使用现有 `tests/test_xturnix_fleurs_test.py` 补少量可手算边界案例，不另建大量镜像测试。

## 验收

- [ ] 词内补全、多 token 同批、仅标点变化与同时间戳事件序号均可手算复核。
- [ ] 提前/过期 start、窗口两端、窗外/EOF 后结果与不完整窗口处理符合计划。
- [ ] 空转写、回写、运行失败、无 start 和零命中均保留完整分母与 null。
- [ ] 参考词数及 WER 标准化口径可复核，参考文本不进入在线回放。
- [ ] 原始实测增量与历史常数组合估计分栏输出，534ms 示例计算及历史常数正确。

## 资源与边界

本地/远端均使用 conda，评分最多 4 CPU、8GiB RAM、worker≤2。评分不加载模型，不新增声学末词对齐，不把本项覆盖率称为话轮准确率或 FDB TOR。
