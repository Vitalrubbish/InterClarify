# XTX-001：冻结 FLEURS 输入与历史 ASR 基线

状态：待实施。依赖：无。依据：[质量测试计划第 2、5 节](../../dev/XTurnix/quality_test_on_fleurs.md)。

## 目标

固定本轮 100 条正式输入、1 条 dev 预热输入，以及后续组合估计采用的历史 Nemotron 延迟，保证回放和评分使用同一份数据清单。

## 工作内容

- 只读核查已有 FLEURS 数据；缺失时按固定 revision `70bb2e84b976b7e960aa89f1c648e09c59f894dd` 恢复 `en_us/test` 文件名 SHA256 升序前 100 条，dev 同规则另取 1 条。
- 保存输入 manifest、文件哈希、来源 revision、参考文本、时长、采样率和声道。原始音频不裁剪、不改写；PCM16 传输转换另记。
- 核对 test 总时长 969.26 秒、标准化参考 2,162 词、首末文件及 dev 文件；存在差异时停止冻结并记录原因，不改抽样规则凑数。
- 从固定历史提交 `f6ad9d9ba04e4e046dcfcdd480b5343165466046` 复核 EN160 逐词延迟 P50 413.582852ms、P95 1,032.668798ms、可测词 3,068/4,324，保存来源和指标定义。
- 明确历史 P50 是典型估计常数，不是均值、末词专项实测或新的端到端成绩；数据不用于调参。

## 交付

在拟建的 `scripts/remote/xturnix_fleurs_test.py` 中提供 prepare-data/verify-data 入口；对应 `docs/scripts/remote/xturnix_fleurs_test.md` 解释数据处理职责和核心方法。远端保存 manifest、数据锁、核验结果与历史基线来源，Git 只收简明证据，不收音频。

## 验收

- [ ] 100 test＋1 dev 可追溯且集合无交集，所有文件均有独立哈希。
- [ ] 固定规则、输入摘要和历史汇总逐项核对，不冒称与失踪的旧 manifest 已逐文件验同。
- [ ] 历史 ASR 常数来源及统计覆盖可复核，正确区分逐词延迟和文件末端差值。
- [ ] 缺失或不匹配显式失败，不以替换样本绕过。

## 资源与边界

数据准备在远端 conda 环境进行；最多 4 CPU、8GiB RAM、下载并发≤2、单作业 1 小时，新增资产累计≤10GiB、启动空闲盘≥30GiB。不加载 GPU 模型、不启动回放，不恢复旧专用测试脚本。
