# NTF-008：方案 A 的单块缓冲与训练序列对齐

日期：2026-11-01。状态：已建单，待实施。

工作单元：把运行时每一帧的模型输入严格对齐训练格式 `A_n T_n <|end_of_sentence|> → S_n`，用整块缓冲换取分布一致；状态发布不再等待覆盖配对。

## 背景与证据

冻结权重下，官方 0.6B 的训练序列是 `A_n T_n <|end_of_sentence|> S_n`，注意力因果。文本必须排在它所属音频之后、结束符之前。

两条时钟的实测关系（NTF-003／005）：

- 音频主块固定 160ms；
- Nemotron 首步约 92.5ms，之后等待完整输入窗口中位 134.7ms、P95 138.9ms；
- 文本覆盖到主块截止的解码步骤，典型比主块晚约 99ms（配对 160→259ms、320→419ms）；
- 计入解码与 SoulX 前向后，状态相对主块起点约 340ms、相对主块截止约 180ms。

如果不等文本（文本晚一块注入），模型会在停顿处看到“静音 + 空文本”，系统性偏向过早 `complete`，且偏在最关键的边界。因此用户已确认采用方案 A：音频也延后一整块，保证序列与训练完全一致。

## 范围

### 本单包含

1. 音频 embedding 进入有界缓冲（默认 4 块），不再直接推进下一步。
2. 配对规则沿用 NTF-003 已实现的“第一个覆盖到主块截止的完成步骤”，把该步增量直接作为 `T_n` 与 `A_n` 一起输入。不追踪文本覆盖范围，不特判首块，不判文本是否迟到。
3. 删除 `scripts/runtime/dual_asr_frontend.py` 的 `PairedPublisher` 与双路覆盖配对，状态改为即时发布。
4. 缓冲溢出规则：超过上限丢弃最旧的一对，记 `buffer_overflow` 并保留原始证据。
5. EOF：最后一个块用已到达文本排出并标记 `eof_partial`，不补静音、不回填。
6. 官方外层 `speak` 在新链路下的含义改为“flush 已到达教师文本”，不再触发整轮重识别。
7. 保留 NTF-006 新增字段的发布与只读语义。

### 本单不包含

- 教师文本路径改造（NTF-007）。
- 调度、分卡、CPU 配额（用户确认只测同卡）。
- `_reset_controller()` 的 buffer 策略、输入增益、远场阈值。
- 阈值与状态规则的修改。
- 任何训练。

## 接口与数据合同

- 每帧输入顺序必须是 `A_n → T_n → <|end_of_sentence|>`，审计逐帧核对，不允许例外。
- `T_n` 为该配对步骤的全部增量，允许为空；文本窗口相对音频窗口整体后移约 96ms，因此模型在块 `n` 上的实际观察上界为 `主块截止 + 99ms`。该上界必须逐帧记录，不得用主块口径冒充。
- 文本未到属于该配对步骤尚未完成，由缓冲吸收，不以空文本替代。
- 状态发布延迟相对主块截止约 180ms，且为固定偏移，不随文本量变化。
- `buffer_overflow`、`eof_partial`、`text_missing` 三类降级必须显式记录，不能与正常帧混计。
- SharedContext 仍保持单一当前值与单写者发布，不新增历史接口。

## 预热合同

预热在所有模型加载完成之后、开放回放之前执行，不计入正式计时，不写入正式指标。目的在于覆盖非静音特征路径，避免把“预热不足”误判成模型或链路问题。

1. **SoulX／SenseVoice 路径**：多种长度静音预热，另加至少 3.36 秒、3.36 秒、10.08 秒三段非静音合成信号。历史 SoulX 完整系统使用过这套组合；NTF-005 只做了三块状态前向和一次 3.36 秒静音识别，属于已确认的运行配置差异。
2. **Nemotron 服务**：要求两次真实语音输出成功并完成会话清理后才算就绪；未完成预热不得当作就绪。
3. 预热使用与正式回放相同的加载器、权重、精度和线程配置，不单独调参。
4. 记录每段预热输入的来源、采样数、摘要、首字延迟与计算耗时，随作业证据一并保存。
5. 预热失败或超时即作业失败并保留证据，不允许跳过预热进入正式回放。

## 验收标准

1. 逐帧审计证明每帧输入顺序严格为音频 → 文本 → 结束符，0 例外。
2. 主块截止到发布的延迟如实报告，目标 P95 ≤ 250ms；同时按 `主块截止 + 99ms` 的完整观察口径重算延迟，两种口径并列，不混用。
3. 固定 30 条内不触发 800ms 停止线。
4. 三轴预检 3/3 结构通过，`buffer_overflow` 与 `eof_partial` 计数为 0。
5. NTF-006 新增字段在发布后未被改写。
6. 打断 `nonidle` 检出时间单独列表；预期比 NTF-004 晚约 180ms，该代价必须可见，不得藏进总体指标。
7. `docs/scripts/runtime/dual_asr_frontend.md` 改为历史说明并归档，`soulx_frontend.md` 与 `nemotron_teacher_forcing.md` 同步改写。

## 资源与执行边界

远端真实模型仅在既有 conda 调度作业运行：单并发、1×RTX 4090、4 CPU、32 GiB RAM、显存 22 GiB 停止线、每作业最多 1800 秒、结果上限 128 MiB。本单只做三轴预检与结构验收，完整 30 条对照在 NTF-009。
