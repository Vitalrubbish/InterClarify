# TT-006：测出 FDB 50 条真实录音的停顿介入率并解释误介入

状态：待实施。依赖：[TT-002](../archive/TextTurn/tt_002_training.md)、[TT-003](../archive/TextTurn/tt_003_streaming_context.md)。依据：[FDB 跨数据集计划](../../dev/TextTurn/fdb_cross_dataset_plan.md)。

## 目标

回答当前控制器在真实用户停顿中是否保持倾听，以及发生介入时，是明显未完成表达、完整语义后的短暂停顿，还是 ASR／运行问题。直接交付 50 条录音的逐录音、逐区间成绩和中文归因。

## 工作

1. 按计划的固定种子和排序规则，从 `candor_pause_handling` 取 50 条有效且音频不重复的录音，保存资产摘要、全部候选、排除理由和已知历史使用。保留每条 `pause.json` 的全部区间，不挑容易通过的区间；候选不足时交付原因，不以 synthetic 子集补位。
2. 使用与 [TT-005](tt_005_fdb_turn_taking.md) 相同的固定候选、真实 ASR、80ms 实时音频包和 480ms 控制窗，固定 Listen 观察全部停顿。每条录音追加 5 秒在线静音后再 EOF；必要的实现与边界测试并入实际测试，不单列环境、探针或接口确认任务。
3. 对每个半开区间 `[start,end)` 统计 start，并同时记录动作返回时刻和该调用依据的控制窗覆盖范围，区分停顿中决策但续说后返回，以及已读取续说后的决策。另列区间长度、观察窗数量、合并／积压及缺失情况，不能丢掉中间区间换取正确保持。
4. 对全部标注持轮区间中的介入，核查当时可见前缀、空窗与上下文，给出语义及运行归因。完整句不自动等于让轮，后续还有内容也不单独证明当时不能接话；当前候选的 start 不能解释为未训练的系统附和。

## 交付与完成条件

- 50 条冻结清单、原始 ASR／控制 trace、逐录音和逐区间 CSV、汇总 JSON，以及联合报告中的 Pause 结果和介入归因。
- 按录音报告 FDB 规则介入率：任一区间出现介入即计一条；全部区间充分观察且无介入才算正确保持。另报逐区间结果及区间总数，不能把区间数当成独立录音数。
- 短于 480ms 且没有控制观察落入的区间、无调用、超时、异常和缺文件分别保留；缺少观察既不算误 start，也不算成功等待。报告已判定结果、未知数量及 50 条计划分母上的保守上下界，比例列分子／分母和 Wilson 95% 区间。
- FDB 规则介入与语义归因分列，归因不改主分母。单列控制耗时 P95、观察覆盖、队列合并及尾窗／EOF 状态；不给出实际音频输出 TOR 或闭环对话结论。
- 结果好坏均可完成本项；不改阈值、不重训、不换样本补失败，也不由本项宣称用户打断、附和或 system backchannel 已通过。

与 TT-005 共用一次远端串行作业及一份联合报告，两项没有先后完成依赖。资源合计受[共同约定](README.md#fdb-跨数据集测试共同约定)约束；完成各自结果即可分别归档，不要求另一项先完成。
