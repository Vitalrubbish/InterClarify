# TT-011：修复外部测试管线并在训练完成后串行测试

状态：实施中。2026-10-26用户明确启动；新候选身份、UltraChat生命周期、语义审核和串行续接实现中。当前尚未部署续接、未提交测试。原训练保持只读监控。

依赖：[TT-010](tt_010_asr_update_yield_dataset.md)完整轨迹训练；训练run为`tt-010-fulltraj-20261025-r1`，调度ID为`job-179293824747465991917-xuan-zhang`。研究与生命周期边界遵循[研究设计](../../research_design.md)及[架构合同](../../research_design/architecture.md)。

## 目标与范围

先修复UltraChat正文注入回放和FDB真实录音动作监控，使其兼容TT-010候选；核查通过后部署等待续接，训练成功并满足开发集放行条件后自动启动测试，无需再次请求用户确认。先运行160ms UltraChat，再运行160ms FDB；保持一个活动GPU作业。

两项均为已有资产上的回归测试，不称全新盲测。不接入或训练Layer 1/2，不执行真实助手TTS播放，不恢复480ms对照、旧完整合成语音验收或已取消的完整FDB任务；不根据测试表现重训、调阈值或重选候选。

## 一、修复候选加载与运行入口

- 参数化训练run、数据manifest、训练配置及候选摘要，移除对TT-002路径与旧adapter摘要的强绑定；不能只替换模型路径而继续加载旧四token注册表。
- 使用TT-010的五token注册信息，核验`<finish>`为151673、动作ID与保存权重一致；检查候选放行、adapter摘要及保存重载验证。
- 新配置、冻结清单和输出使用独立路径，不覆盖旧清单、脚本冻结快照、trace与报告；保留原样本身份及历史使用说明。
- 所有代码、配置和必要脚本在`docs`下维护对应路径的中文说明，代码注释及文件名使用英文。

## 二、UltraChat主测试

- 复用TT-008既有30来源：30个完整干净文本会话与120个已录制在线ASR场景，共150例；核对资产摘要，缺失保留原计划分母，不换样。仅执行160ms，正文按原160ms配置每周期3 token发布，记录其与训练生成节奏的差异。
- 干净文本与已录制ASR分别报告；后者不冒充本次重新执行Nemotron。正文按独立时钟推进，不因模型调用次数变化而追加未来内容。
- 对齐TT-010可见输入字段，包括输出ID、已生成／模拟已播内容、生成结束、运行时事件和最近终态。模拟播放完成后才注入`<finish>`；打断输出的迟到完成不能再产生finish，重复回调不重复闭合。
- stop主评分改为当前因果前缀首次可判定为非附和式有效更新后的及时覆盖，目标时限1000ms；停止词统计仅作辅助诊断。冻结标注依据、可见输入摘要及规则后再执行候选；不能用未来全文、模型输出、固定词表或任意用户更新自动充当语义金标。必要审核随本单完成，不能可靠判定的机会列为unknown。
- 分列短附和误stop、无更新误stop、停顿误start、正常接话与陈述接话、正常结束后再次接话、播放尾窗打断；覆盖不足明确列出。保留连续Speak与首末有效用户更新区间重叠严格大于960ms的行为抢话统计，与1000ms及时动作指标分开。
- 同时报告动作输出与实际影子生效、自然提前结束、未处于Speak及观察缺失，不能以正常完成替代stop成功。输出逐例trace、CSV、汇总与失败原因；给定状态诊断不替代自由运行结果。

## 三、FDB外部回归

- 复用TT-005／006／007固定的Smooth Turn Taking与Pause Handling各50条录音，沿用160ms与真实Nemotron输入，保留原音频及样本摘要。
- 严格保持`action_only`：start切Speak、stop回Listen、keep维持，不模拟助手正文、回答完成、finish或计时复位。此测试与UltraChat生命周期管线不同，空助手输入的分布差异须解释。
- 沿用原两臂行为指标：ASR更新后Speak／start覆盖及start等待时间、更新前连续至少3周期Speak；辅助报告新转写后的stop和严格大于960ms的持续抢话。固定周期的拍数和实际毫秒分别呈现。
- 新旧候选按相同样本与行为口径比较，说明历史运行及ASR差异；行为统计不自动等于语义质量通过。

## 四、等待与自动续接

1. 修复后做少量必要契约检查，覆盖新token加载、finish／stop闭合、过期结果、候选身份和串行提交；真实模型检查仅在远端调度节点现有conda环境执行。
2. 在独立冻结源码中部署有日志、有状态文件、可重复检查但不可重复提交的续接器；只读等待原训练，不修改或终止其作业。绑定训练run和候选，不能因目录或best提前存在就启动。
3. 训练退出码0、候选文件完整、开发集gate放行、学习及重载核查通过，且调度器确认训练结束、无其他活动作业后，冻结候选与两项测试清单。先做不计入正式分母的接口冒烟，再执行UltraChat正式测试。
4. UltraChat成功执行并释放资源后，重新核对无活动作业，再提交FDB；不能仅以服务退出或日志静止推断GPU已释放。接口或运行失败时停止续接并保留证据；质量未达标仍交付报告，若运行成功且候选有效则继续FDB，不按测试成绩挑选或修改模型。
5. 训练失败、超时、gate未放行或重载核查失败时，记录明确原因且不启动测试，不自动改用pilot中间权重或旧模型。等待、已提交、运行、失败、完成状态分别记录；续接部署后验证其存活及实际提交回执。

## 资源与交付

- 两项测试串行，最多1×24GiB GPU、8CPU、32GiB RAM、worker≤2，单录音流、单控制推理worker；显存22GiB停止线。每项外部测试最多2小时，保留清理余量；启动可用盘≥30GiB、资产≤10GiB、报告≤2GiB，复用权重和音频。
- 本次沿用用户已取消旧累计GPU剩余预算限制的授权，不再用旧3991秒或旧8GPU小时累计限制阻止续接；保留实际GPU占用记录及全部单作业资源上限。禁止修改正在训练的冻结源码。
- 训练完成与测试启动之间允许为审核、冻结和接口核查等待，缺条件时如实记录，不把自动等待写为已提交。
- 提交源码与文档，记录远端冻结提交、候选／数据／协议摘要、conda环境、作业ID、资源采样、进度和退出码。原有用户未提交修改不纳入本单提交。
- 最终交付中文联合报告，分开列UltraChat与FDB结果、实际分母、缺失、质量结论及输入分布限制。不得据此宣称真实Layer 1／TTS闭环或TT-004完整语义验收已通过。
