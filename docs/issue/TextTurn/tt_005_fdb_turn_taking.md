# TT-005：测出 FDB 50 条真实录音的接话覆盖与延迟

状态：待实施。依赖：[TT-002](../archive/TextTurn/tt_002_training.md)、[TT-003](../archive/TextTurn/tt_003_streaming_context.md)。依据：[FDB 跨数据集计划](../../dev/TextTurn/fdb_cross_dataset_plan.md)。

## 目标

回答当前 UltraChat 派生数据训练出的控制器，在外部真实录音中能否及时接话，以及早接话、晚接话和遗漏各有多少。直接交付 50 条录音的逐例结果和中文结论。

## 工作

1. 按计划的固定种子和排序规则，从 `candor_turn_taking` 取 50 条有效且音频不重复的录音，保留全部候选、排除理由、资产摘要和已知历史使用。将 `turn_taking.json` 第一项区间起点固定为交接参考；标注定义及作者评分代码的核对随评分实现完成，不单设确认任务。候选不足时交付原因，不换来源或缩小分母。
2. 使用 `tt-002-20261025-r1/best` 和真实 Nemotron EN160，按 80ms 包实时回放，每三个真实解码完成步骤形成 480ms 控制窗。转写持续写入 Shared Context，固定 Listen、助手表达为空，只记录动作；原音频结束后追加 5 秒在线静音，再发送 EOF。必要的入口适配和少量边界测试直接服务于本次测试。
3. 按实际音频包发送时钟评分，记录首个 start、参考前介入、参考后 start、未接话及运行失败。保留负延迟，重复 start 不增加成功数；语音依据未可靠对齐时留空，不用整段 ASR 逐字匹配替代 FDB 事件。
4. 分析早接话、晚接话和遗漏的代表案例，结合当时可见的 ASR 前缀、空窗与排队情况解释原因。FDB 规则成绩和当前语义策略分开陈述，不用结果调整候选或评分参考点。

## 交付与完成条件

- 50 条冻结清单、原始 ASR／控制 trace、逐录音 CSV、汇总 JSON，以及联合报告中的 Smooth 结果和案例分析。
- 报告参考后 1000ms 内及时 start 覆盖、整个观察期内 start 覆盖、参考前介入率和延迟 P50／P95。及时命中要求此前没有 FDB 规则介入；失败及未命中保留在 50 条计划分母，比例列分子／分母及 Wilson 95% 区间。原音频与追加尾窗结果分别列出。
- 说明 ASR 延迟、480ms 聚合等待、调度滞后与包粒度；另报输入就绪至控制返回的 P95。相对音频参考的 1000ms 指标不替代 TT-004 的语义依据可见后指标，也不称为实际开口延迟或官方 TOR。
- 接话好坏均可完成本项；缺失和运行失败必须如实交付，不能换样本补成成功。结果用于跨集诊断，不等同完整四类验收。

与 [TT-006](tt_006_fdb_pause_handling.md) 共用回放与评分入口、一次远端串行作业及一份联合报告；两项没有先后完成依赖，资源合计受[共同约定](README.md#fdb-跨数据集测试共同约定)约束，不因拆单增加预算。达到交付条件即归档，不以模型达到质量门槛作为归档条件。
