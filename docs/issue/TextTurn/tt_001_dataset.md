# TT-001：重建四类控制数据

状态：待实施。依赖：无。依据：[训练方案第 2 节](../../dev/TextTurn/training_plan.md#2-训练数据如何构造)。

## 目标

把旧 UltraChat 对话和事件计划直接转换为可训练的 TextTurn 数据，覆盖正常接话、用户打断、用户附和和停顿处理。

## 工作

1. 从既有资产或固定来源恢复旧对话与分组；复用有效来源和切分，不恢复整套旧训练框架。旧测试如已被调参使用，保留为回归材料并补充未用来源。
2. 按 160ms 重建事件：非空片段约 1—2 token，保留完整字符；静音用 `no-voice`，停顿按原持续时长换算，不将 600ms 窗直接改名。用 Qwen3 tokenizer 重新编码，注册动作及 `no-voice` token。
3. 生成 Listen 下 keep/start、Speak 下 keep/stop 的决策快照，只保留当前可见历史；自然说完不标 stop。start 中完整陈述／陈述式回答至少占三分之一，补足附和与真实打断的上下文对照。
4. 产出最多 2,000 个机制试训快照，以及最多 1,000 对话／10,000 快照的完整训练候选；目标开发 200、独立测试 300 对话，测试四类各覆盖至少 100 个不同场景组。去重、标签抽查和损失 mask 检查与构建一起完成，未知标签不强行填充。

## 交付与验收

- 数据构建入口、配置、对应中文说明，以及来源／切分／审核清单和可读取数据。
- 四类数据和陈述句数量可直接统计；同源派生不跨集合，测试资料不进入训练；只监督动作，旧 token ID 和回答正文目标已移除。
- 保存完整目标及实际数量、超长／歧义／不可用记录。数量或来源不足明确报告，不能用重复窗口补足；不将存在缺口的材料标成已满足正式训练／独立测试条件。

本项不加载模型训练，不安排大规模人工审核或单独探针项目；只做能支持标签和切分正确性的必要检查，少量测试随构建入口交付。
