# TT-001：重建四类控制数据

状态：实施中（2026-10-24 按用户指令启动）。依赖：无。依据：[训练方案第 2 节](../../dev/TextTurn/training_plan.md#2-训练数据如何构造)。

启动交付：[首批检查材料](../../../reports/textturn/20261024-tt-001-preview/README.md)、[中文逐例样例](../../../reports/textturn/20261024-tt-001-preview/samples.md)和[构建入口说明](../../scripts/training/build_textturn_dataset.md)。已从同一固定 revision 恢复六个原始来源对话，按用户短促附和反馈修订后为 14 个合成场景、24 个快照；剩余七个空标签逐条审核补为 keep，现 24 个均有动作标签，keep/start/stop 为 17/4/3，正常 start 中 2/4 为完整陈述。所有记录属于 review 集合，不进入正式训练或独立测试。

已检查的远端旧训练与归档位置未找到旧对话／600ms 事件产物，旧切分及事件位置未恢复；当前数据使用显式新增的合成时序。完整分片 LFS 校验、历史来源隔离、正式规模和全量标签审核仍有缺口，因此本项不归档，不放行 TT-002。首次样例供用户检查，不把检查批次当成正式数据冻结。

## 目标

把旧 UltraChat 对话和事件计划直接转换为可训练的 TextTurn 数据，覆盖正常接话、用户打断、用户附和和停顿处理。

## 工作

用户检查后的修订：User Backchannel 以 `Hmm.`、`I see.`、`Right.` 这类短促回应为主，移除首批附和样例中为明确标签而追加的继续指令。短回应依据当前可见上下文标 keep，后续明确打断再标 stop，不使用未来内容提前改写标签；歧义仍保留未知。该调整仍在本工作单内，不新增 issue。

按用户进一步指令，逐条复核剩余七个未标注快照：六个 Listen 快照仍在接收新增文字，尚无当前表达结束后的让轮观察，标 keep；一个 Speak 快照仅出现 `Please`，没有足够的停止依据，标 keep。补标依据只取当前可见内容，不把所有缺失标签自动填为 keep，也不新增固定静音等待时长。

1. 从既有资产或固定来源恢复旧对话与分组；复用有效来源和切分，不恢复整套旧训练框架。旧测试如已被调参使用，保留为回归材料并补充未用来源。
2. 按 160ms 重建事件：非空片段约 1—2 token，保留完整字符；静音用 `no-voice`，停顿按原持续时长换算，不将 600ms 窗直接改名。用 Qwen3 tokenizer 重新编码，注册动作及 `no-voice` token。
3. 生成 Listen 下 keep/start、Speak 下 keep/stop 的决策快照，只保留当前可见历史；自然说完不标 stop。start 中完整陈述／陈述式回答至少占三分之一，补足附和与真实打断的上下文对照。
4. 产出最多 2,000 个机制试训快照，以及最多 1,000 对话／10,000 快照的完整训练候选；目标开发 200、独立测试 300 对话，测试四类各覆盖至少 100 个不同场景组。去重、标签抽查和损失 mask 检查与构建一起完成，未知标签不强行填充。

## 交付与验收

- 数据构建入口、配置、对应中文说明，以及来源／切分／审核清单和可读取数据。
- 四类数据和陈述句数量可直接统计；同源派生不跨集合，测试资料不进入训练；只监督动作，旧 token ID 和回答正文目标已移除。
- 保存完整目标及实际数量、超长／歧义／不可用记录。数量或来源不足明确报告，不能用重复窗口补足；不将存在缺口的材料标成已满足正式训练／独立测试条件。

本项不加载模型训练，不安排大规模人工审核或单独探针项目；只做能支持标签和切分正确性的必要检查，少量测试随构建入口交付。
