# TT-008：UltraChat助手正文对照重测stop

状态：待实施。2026-10-25用户明确要求提出本工作单。依赖TT-002固定候选、TT-003输入接口及TT-004既有UltraChat测试资产。只建立工作单，本次不启动重测、训练或GPU作业。

## 目标与待验证假设

检查FDB测试中不输出stop，是否与Speak时缺少助手回答正文有关。固定候选、输入和事件时序，比较有／无助手正文的stop行为；不能把更换数据来源、修复轮次结构和加入助手正文同时发生后的改善全部归因于正文。

训练已通过user_text、assistant_visible及history.role区分双方。待验证的是assistant_visible的正文内容，不是缺少角色标记。依据见[现有诊断](../../../reports/textturn/20261025-fdb-start-stop-audit/README.md)。

## 工作

1. 优先复用TT-001冻结test中的UltraChat来源、TT-004语音及已保存的Nemotron在线转写，不将test或FDB资料用于训练。固定来源ID、样本清单、文本／音频／ASR摘要、历史使用和实际场景分母，保留无ASR、超长及失败，不按stop结果挑选或补位。已有测试已用于诊断，称回归重测，不宣称新盲测。
2. 先修正共同的输入合同：正确的history.role、已提交用户轮与当前用户段分离、Speak状态及生成完成标志。助手自然完成与用户下一轮等待按已有事件记录处理，不把用户原轮全文不断累积成新的打断输入。角色格式两组相同。
3. 在完全相同的Speak可见快照上做成对对照：A为assistant_visible空，B为截至当前时刻的UltraChat助手回答前缀；两组history、用户输入、状态、生成完成标志、控制周期和就绪时刻一致。原始完整回答可作为前缀来源，但未来未到达文本不能提前可见；不让TextTurn生成回答，不调用回答模型或TTS。此前FDB输入的空history和null状态作为已知差异披露，不把A组伪称逐字段复现FDB。
4. 先对固定共同快照比较合法keep／stop及其分数；再以同一事件流运行各自状态轨迹，区分成对决策效果与动作导致的后续状态差异。正常完成只由既有生命周期转Listen，不自动制造stop；被自然完成提前关闭、未到Speak或缺有效后续观察的机会单列，不能借自然完成充当及时stop。
5. 保留明确停止词、普通用户续说／接管、短附和、无用户输入及生成完成后的尾窗对照。若冻结测试缺某类，报告覆盖不足，不在本项补造训练标签。先用已有文本事件与真实ASR转写分别检查；干净文本不能替代真实ASR结论，已记录转写的时间戳回放与新在线ASR执行分别披露。
6. 主对照先用训练合同的480ms；若做160ms复核，沿用同一来源与名义助手发布时序，分开报告，不能把周期改变混作注入正文的效果。配置、时序、候选和评分规则在看重测输出前冻结，不选检查点、不调阈值或改动作约束。

## 评分与交付

- 按用户确认的行为口径，在有效在线ASR首次至末次更新区间内，连续Speak的实际重叠时长严格>960ms记抢话；不要求新增语义补标，不换成固定周期数，不用末次更新后的尾静音凑时长。原始start、短暂start→stop和自然完成另列，不删除机会来改变分母。
- 报告每组stop总次数、发生过stop的独立机会数、Speak下新增用户输入后的960ms内stop覆盖、延迟分布及观察不足。已有明确打断锚点可另报原合同1000ms及时率；行为960ms与既有1000ms指标保持各自名称和分母。
- 成对快照列A／B均stop、仅B stop、仅A stop、均keep；附和／无输入的误stop也比较，不能只看stop数量上升。不能把“用户继续说”自动称为已有语义打断金标。
- 逐例保留输入字段摘要、已发布助手前缀、ASR版本、状态／动作、完整返回时刻、stop前后960ms及自然完成事件。交付清单、逐例CSV、汇总JSON、中文结果和可复核trace；数据与原始产物位置明确，Git仅收录审阅摘要。
- 输出结论为“正文注入有帮助／未观察到帮助／证据不足”，写明改善适用的输入和场景；最终效果是否足够由用户判定，不以单一总分自行触发重构。

## 资源与边界

真实模型执行走远端调度及已有conda。最多1×24GiB GPU、8CPU、32GiB、worker≤2、单活动作业，显存22GiB停止线。单作业最多2小时，并先从实际调度核查原累计8GPU小时剩余；最后已知为7549秒，非可直接重复分配额度。新运行、重提和清理均计入，额度不足则缩短或停止。

沿用新增资产≤10GiB、报告≤2GiB、可用盘≥30GiB，不复制模型或重合成已具备的语音。源码、清单和配置冻结在独立目录，不覆盖已有报告。必要实现／测试并入本项，代码和docs同路径同步维护；完成交付后归档，本项不自动完成TT-004。

本项不重训、不更换候选、不修改stop含义，不部署现役播放器或控制路径。重测后仅在用户明确判定效果不好并指令启动时进入[TT-009](tt_009_conditional_data_rebuild.md)。
