# NTF-006：SoulX 官方服务状态兜底与 complete 门控对齐

日期：2026-11-01。状态：本地实现完成；远端验收并入 NTF-007／008 新教师链路。

工作单元：把官方外层 `state_predict()` 的 `speak` 语义显式带入前端 frame，区分直接 `model_complete` 与 `wait_fallback`，并补齐 `speech_detected` 门控和审计；不改变原生五状态 token 的含义，不把服务 `speak` 反写成原生 `user_complete`。

## 背景与证据

官方 `a0b9063843df69619b087b95b74597b2176910b8` 的 `config/config.yaml` 设置 `max_wait_num=8`、`max_mistake_num=3`、`far_field_threshold=0.02`。我们的 `soulx_config.yaml` 与官方逐项一致，只有模型路径和英文 ASR 选择不同；8/3 是官方 YAML 覆盖值，不是我们擅自修改，也不是 `config.py` 中 10/5 的类默认值。

当前问题在运行时消费，不在 YAML：

- `scripts/runtime/soulx_frontend.py` 的 `observe_state()` 挂在内部 `_state_predict` 上，只取得原始状态 token；官方外层 `state_predict()` 才会在 `incomplete` 后连续 8 个 `idle` 块时返回 `speak`，执行整轮识别并 reset。该 `speak` 当前只作为 `feed_audio()` 的返回值存在，调用方没有把它写入 Context，也没有形成完成事件。
- `artifacts/soulx/20261030-current-context-r1` 回放中，官方外层 `speak` 6 次，前端原生 `user_complete` 5 次。`sensevoice_english` 用例在 `processed_until=88960` 出现 `incomplete`，第 8 个 `idle` 块（`processed_until=109440`，约 1.28 秒）官方返回 `speak`，前端仍发布 `user_idle`，该用例 `user_complete` 计数为 0，随后 `controller_reset`。若下游只认 `user_complete`，这类样本不会接话。
- 官方外层只在 `speech_detected=True` 时把 `user_complete` 转成 `speak`；当前前端发布原始 `user_complete` 时没有这个门控，远场过滤也只覆盖 `nonidle`。30 条双 ASR 实验未观察到“无前置 nonidle 的 accepted complete”，属于潜在边界风险而非本轮已发生主因。

本单只处理上述 `speak`/`speech_detected` 语义。`_reset_controller()` 保留整个旧 `model.buffer`、输入增益与 `far_field_threshold` 耦合、预热/调度/800ms 停止线差异，均不在本单范围，另行拆单验证。

## 范围

### 本单包含

1. 捕获官方外层 `state_predict()` 返回值，在每一帧增加可审计字段：
   - `service_state`：`idle`、`nonidle`、`speak`、`blank` 或 `None`。
   - `service_completion_source`：`model_complete`、`wait_fallback` 或 `None`。
   - `speech_detected`：状态产生时官方 `speech_detected` 的快照。
   - `service_text`：官方 `speak` 返回的整轮识别文本，仅作诊断，不覆盖 SharedContext 正文。
2. 明确完成语义：
   - 外层 `speak` 且原生状态为 `user_complete`、`speech_detected=True`：`service_completion_source='model_complete'`，保持现有 `state_accepted=True`。
   - 外层 `speak` 且原生状态不是 `user_complete`：`service_completion_source='wait_fallback'`；原生 `state_token`、`state_accepted` 保持原值，不伪造 `user_complete`。
   - 原生 `user_complete` 但 `speech_detected=False`：`state_accepted=False`，`rejection_reason='no_speech'`，不产生完成信号。
   - 其他状态：`service_completion_source=None`。
3. 让下游可读取 `wait_fallback`：
   - `SharedContext.open_user_turn()` 初始化新字段；`publish_user_frame()` 保留并校验新字段。
   - `PairedPublisher` 的状态缓存和联合发布帧携带新字段；配对审计同时核对它们未被后续步骤改写。该项暂按现状实施，配对器本身将在 NTF-008 中删除，届时同步移除此要求。
   - Layer 1 的读取合同只需能区分 `model_complete` 与 `wait_fallback`；本单不实现 Layer 1 行为。
4. 本地回归测试：
   - `incomplete` 后连续 8 个 `idle`，外层返回 `speak` 时产生 `wait_fallback`，原生 `state_token` 仍为 `idle`。
   - 直接 `complete` 且 `speech_detected=True` 时产生 `model_complete`。
   - 原始 `complete` 且 `speech_detected=False` 时不接受、不产生完成信号。
   - `wait_fallback` 的 `service_text` 不覆盖 SenseVoice/Nemotron 正文。
   - YAML 有效值仍为 `max_wait_num=8`、`max_mistake_num=3`，并覆盖 `config.py` 默认值差异。
5. 远端验证并入新链路：
   - Nemotron 已确定为唯一教师文本，不再使用 SenseVoice 滑窗，也不再运行双 ASR 配对预检；本单不单独提交 SenseVoice 单例或三轴双 ASR 作业。
   - 字段与门控在 NTF-007／008 的教师链路预检中一并核对：`wait_fallback`保留原生`idle`、`model_complete`只在直接complete时出现、无语音complete被拒绝、诊断文字不覆盖正文。
   - 本单不重跑完整 FDB30；完整延迟与状态对照由 NTF-009 承担。

### 本单不包含

- `_reset_controller()` 的 buffer 保留策略与官方 reset 的 A/B。
- 输入增益归一化与 `far_field_threshold` 的重新标定。
- 预热、双卡/CPU 调度、800ms 停止线的调整。
- 修改 `max_wait_num`、`max_mistake_num`、`far_field_threshold` 的数值。
- 把 `wait_fallback` 当作原生 `user_complete`，或新增历史正文版本。
- Layer 1/2 行为、CoT、TTS、真实播放和下游 Agent 切换。

## 接口与数据合同

新增字段只描述“官方服务层”的结果，不改变原生五状态：

- `state_token` / `state_token_id` / `state_accepted` / `rejection_reason` 仍表示模型原生状态及其接纳性。
- `service_completion_source` 表示官方外层是否给出接话许可，以及来源是直接完成还是等待兜底。
- `service_text` 只用于诊断和人工核查；新教师链路正文来自 Nemotron，不再依赖 SenseVoice 整理器。
- `wait_fallback` 不应被下游解释成“语义完整”；它只是官方在 `incomplete` 后等待 8 个 160ms 块没有新增语音时的接话兜底。
- 新字段必须参与帧快照上限和审计，不新增历史接口或事件游标。

## 验收标准

   - 下游测试消费者能读到该完成信号

3. 原始 `complete` 且 `speech_detected=False` 时不产生完成信号，并记录拒绝原因。
4. 现有本地测试全部通过；新增用例覆盖上述三条路径。
5. 新链路预检结构通过，新增字段在发布后未被改写，nonidle 停止和 EOF 诊断不回归。
