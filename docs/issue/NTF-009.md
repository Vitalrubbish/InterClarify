# NTF-009：固定 FDB30 同卡对照与延迟验收

日期：2026-11-01。状态：已建单，待实施。

工作单元：在只使用同一张卡的条件下，用固定 30 条清单验收 NTF-007／008 的完整链路，报告完整性、延迟分布与三轴状态指标。本单只做同卡，不设分卡臂。

## 背景与证据

- 历史 SoulX 完整系统跑同 30 条全部完成，最大输入滞后 742.4ms，无超 800ms 条目；当时使用双卡、12 CPU。
- NTF-004 同卡 25/30 完整，5 条触 800ms；NTF-005 同卡 18/30，12 条触线。
- NTF-005 的分段耗时显示长尾来自调度与争用，不是 ASR 算力：同一 53760 采样 SenseVoice 调用预检 80.3ms、正式 1303.3ms。
- 用户已确认本轮只测同卡，因此分卡对照不再作为验收项，剩余长尾在报告中如实保留为同卡条件下的已知限制。

## 范围

### 本单包含

1. 冻结输入清单，沿用 SHA256 `403be34448e0b011fa0b6a26216c0390ea3ed46ce77335e4bbe7a20cde4f3c07`。
2. 执行 [NTF-008 预热合同](NTF-008.md#预热合同)：多种长度静音 + 至少 3.36／3.36／10.08 秒非静音合成信号，Nemotron 完成两次真实语音预热与清理；预热完成且记录摘要后才允许开始正式回放。
3. 资源合同保持与 NTF-004／005 相同：单并发、1×RTX 4090、4 CPU、32 GiB RAM、显存 22 GiB 停止线、每作业 1800 秒、结果 128 MiB。
4. 报告完整率、主块截止到发布的延迟 P50／P95、状态产生与注入分段耗时、三轴状态指标。
5. 与 NTF-004、NTF-005 按同口径并列比较；样本可配对时用共同完整样本，不拼接不同分母。
6. 失败样本保留原始证据与失败原因，不通过重试筛选成功批次。

### 本单不包含

- 分卡或增加 CPU 配额的对照（用户已确认只测同卡）。
- 训练、阈值调整、状态规则修改、清单变更。
- Layer 1／Layer 2 行为、CoT、TTS、真实播放与下游 Agent 切换。

## 验收标准

1. 预热按合同完整执行并留证；预热失败或跳过即本轮作废，不得进入正式分母。
2. 30/30 完整，且无 800ms 触发。
3. 主块截止到发布延迟 P95 ≤ 250ms，P50 与分布如实报告。
4. 三轴状态指标与 NTF-004／005 同口径并列，样本不足时明确说明不做显著性结论。
5. 打断 `nonidle` 检出延迟单独列出，与方案 A 预期增加的约 180ms 对照。
6. 若仍触发 800ms：保留失败帧，给出长尾分解（SoulX 计算、注入、排队），并明确同卡条件下不追加分卡臂。
7. 新增对照报告写入 `reports/soulx/`，更新 `docs/dev/SoulX-Duplug/README.md` 与工作单索引。

## 资源与执行边界

单并发、1×RTX 4090、4 CPU、32 GiB RAM、显存 22 GiB 停止线、每作业最多 1800 秒、结果上限 128 MiB。启动前重查队列与磁盘，模型与源码只读复用，不新增下载。超出即失败并保留证据，不自动扩容。
