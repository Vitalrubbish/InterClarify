# NTF-023：原生基线与最小 X2 教师替换的小样本对照

日期：2026-11-02。状态：待调研。依赖：[NTF-021](NTF-021.md)、[NTF-022](NTF-022.md)。本轮仅建单。

## 目标

从干净官方源码建立SenseVoice状态基线，尽量保持原生协议接入X2教师，识别此前状态退化是否仍存在。不能复用旧教师适配后将结果称为“只换ASR”。

## 工作范围

1. 在相同PCM、种子、预热及配置下对照未插桩官方入口与采集入口，核对模型实际输入、ASR调用、状态反馈与reset轨迹，确认采集不改变行为；明确数值容差和首个差异。
2. 实施前写清X2适配合同：持续解码的文字如何对应原生查询窗口、门控未调用时如何保留结果、窗口裁剪／历史差分／KV修订如何执行、原生reset后源文字如何定位、完成分支整轮识别如何处理。无法等价的职责列出原因与影响，不删除分支掩盖差异。
3. 尽量共用原生门控策略、归一化、差分／KV修订、状态规则、反馈和reset实现，仅更换教师来源。策略相同不要求两臂产生相同门控与状态结果。任何必要的额外改动先补设计，不混入软reset、无门控或只追加等历史改造。
4. 对固定6条样本记录ASR可用假设、实际查询、采用的文字／token、KV修订、音频块、原始预测、规则改写、反馈状态及reset；逐步定位两臂首个分歧与历史错误事件。
5. 核对真实输入范围和因果性，完整记录EOF。原生完成后的整轮识别发生在状态预测之后，不得反过来计为该帧模型已经看见的文字。

## 交付与验收

- 原生采集入口的等价性结果、最小可审查diff及全部协议差异清单。
- 原生SenseVoice／最小X2两臂的小样本状态、教师消费和返回时间对照，区分原始预测与规则后结果。
- 两臂6/6完整、退出0、输入与因果审计通过且无800ms过载，才作为后续消融底座；若适配不能保持必要协议，则交付失败原因与进一步设计需求，不能假定兼容。
- 不以X2的EOS代替user_complete，不以较晚发布掩盖原始提前预测；采集历史仅保存为诊断产物，不改造SharedContext。
- 所有实现及必要检查配套docs同路径中文说明。
