# 任务单：首轮审查后的 A0 接入与基线冻结

## 1. 当前结论与任务边界

2026-10-10 已审查 InterClarify `f21ac63` 的配置、执行脚本和 [首轮结果报告](xtalk_round1_baseline_results.md)。模型服务和独立增量 TTS 已有运行记录；原始远端日志、模型锁定文件和音频尚未在本次审查中取得，性能数字仍待独立核验。当前为 **继续 A0 接入，暂不冻结底座**。

候选组合保持 Qwen3-ASR 1.7B、Qwen3-8B-AWQ（关闭 thinking）、MOSS-TTS-Realtime + codec、XTurnix-ZH Base；不同时更换模型与控制策略。首轮目标保持无 System Backchannel，Layer 0 移除，Layer 2/3 尚不启用。单一仲裁器、单一 TTS 播放所有权和已播内容不可撤销的边界继续生效。

本任务单安排后续工作，不表示下列代码已经实现或远端测试已经完成。工程总门禁见 [../engineering_implementation.md](../engineering_implementation.md)，控制层顺序见 [../xtalk_modification_plan.md](../xtalk_modification_plan.md)。

## 3. F1：先修复复现入口与失败判据

### 必须完成

1. `tests/test_xtalk_round1.py` 的 TTS 参数补齐 `stream_chunk_words`，保留原有并发收音测试，并增加分块模式的覆盖。本次审查结果为 14 项中 13 项通过、1 项因缺字段报错；不能用上游 X-Talk 的 87 passed / 3 skipped 替代项目回归。
2. `submit_xtalk_round1_job.sh` 默认镜像与 `flash_attention_2` 配置统一。当前入口默认 v0.2，配置要求 v0.3 的依赖。核验 v0.3 实际 digest，并将 tag、digest、配置摘要写入每个作业的记录；缺少 flash-attn 或版本不匹配时在预检查阶段失败。
3. 让 XTurnix probe 对预期行为执行断言；增加完整请求应接话、未完成前缀应等待、用户短附和应继续、有效插话应停止的正负例。只输出合法枚举不算行为正确。
4. `chain_report` 缺少必需报告、LLM 为空或流式 TTS 未通过时返回非零；分别记录执行完成、内容正确、性能达标和交互正确。`content_ok` 当前只检查非空，须改为准确的完整性字段或增加独立内容验收。
5. 检查并行模型下载器的锁定写入：当前多个 worker 可同时写 `models.lock.json`，与其单写者说明不符。先解析并持久化全部 revision，再并行下载，由一个写者更新结果；锁定文件不得截断，已有 snapshot 路径须核验存在，版本不一致须拒绝。
6. 核验环境准备脚本的并行安装退出码，分别等待并检查每个进程；清理服务仅限本作业记录的进程组，去掉可能匹配其他作业的宽泛 `pkill`，异常退出也要清理本作业服务。

### 验收与产物

在本地 conda 环境完成项目回归、Shell 语法检查；用失败注入证明无效 probe、缺报告、安装失败和缺模型均不能得到 PASS。归档测试结果及修改文件对应文档。远端执行前确认资源、实际镜像和配置一致。

入口修复后再使用原任务单的提交脚本。当前尚未修复时，如需复核旧模型服务，必须显式指定已核验的 v0.3 镜像；现有 `chain` 仅用于顺序测量，不能当成在线全双工验收命令。

## 4. F2：取回证据并修正测量口径

### 归档清单

取回首轮 asr/services 作业，以及 `20261010T025525Z`、`20261010T102317Z`、`20261010T104729Z` 对应的实际产物目录。每份记录至少包含：

- `models.lock.json`、输入配置、源码提交及 dirty 状态、镜像 digest、各 conda/pip 环境版本；
- `steps.jsonl`、作业退出码、`chain_report.json`、ASR 原始事件与报告、LLM 增量响应、TTS 报告；
- 服务日志、GPU 采样、输入与参考音色校验值、可试听的输出音频；
- 冷启动、预热步骤、warm 测量分别使用的输入与参数。

体积大的权重、原始音频和完整日志留在共享存储或 Git 忽略目录；提交可复核的摘要、相对产物路径与校验值清单。最新 v0.3 每个作业都要登记自己的提交和 digest，不能复用报告开头 v0.1 的来源标识。

### 结论校正

1. TTS 的 0.72 秒保留为“完整回复经人为 6 词分块回放的独立首音频时间”；它证明增量输入可出音频，尚未证明实际 LLM → TTS 在线延迟。分段计时不能相加或组合成端到端亚秒结论。
2. ASR 同时报告 `first_partial_seconds`（墙钟到达）和 `first_partial_audio_seconds`（输入音频进度）；预热后的 1.2 秒目前是后者。结合事件差值检查排队与落后情况，重新分析早期高延迟中的初始化开销。
3. 初次 TTS 表格的 cold 项没有在 flush 前出音频，正文“三次均在 flush 前出音频”与表格不符。按各运行实际结果说明。
4. 对 17 秒整段输入结果保留真实观测，不称为测量假象；标明输入方式和适用场景。免编译、稳态吞吐和长回复可用性分别由源码路径、运行日志与多长度测试支持。
5. GPU 占用区分权重、框架预分配的 KV cache、运行峰值与剩余空间。vLLM 高占用不能直接证明 8B 权重撑满显存；10 秒采样也不能当作精确瞬时峰值。

产物为补充审查记录与修正后的结果解释。历史数值保留，不用新结果覆盖旧输入的测量。

## 5. F3：补中文测试，确定可冻结的参数

### 小样本设置

准备至少 30 条真人中文语音，覆盖日期/时间、人名或实体、自然停顿、自行补充、改口、中英混说六类，每类至少 5 条，可以交叉标记。至少 3 名说话人，保留人工文本、关键槽位与采集条件；它是工程 smoke 集，不是正式研究评测集。另准备一份有来源记录的中文参考音色，并固定校验值。

ASR 在同一音频上比较 0.6 / 1.2 / 2.0 秒窗口，区分冷态与预热后测量。记录累计前缀、修订、最终转写、字符错误率及关键槽位错误，统计墙钟首 partial、输入进度、解码 RTF、最长积压。窗口选择依据质量与延迟的实际折中，不保证 0.6 秒输入窗口必然实现 0.6 秒首字。

TTS 固定 flash-attn 与模型 revision，测试中文日期时间、数字、人名、短句、较长回复和中英混说。中文没有天然空格，分块不得直接照搬英语 `split()` 的“6 词”策略；独立测试可按明确文本边界发送，F5 必须使用真实 LLM delta。分别记录首音频、持续吞吐、音频块间隙、停播和试听问题。

### 预算和验收

对代表性输入至少重复 3 次，保存全部观测；报告样本数和 p50/p95，不把单次最优值作为稳定结论。本轮先取得证据，在进入 F5 前把 ASR 墙钟延迟、LLM 首个可朗读文本、TTS 首音频、用户插话到停播及队列积压的预算写入验收配置或报告，说明选择依据。数值预算尚待实测，不在本任务单虚构已达标阈值。

关键条件：ASR/TTS 稳态无持续积压；关键日期时间与改口可核验；TTS 无明显漏读、重复、长停顿；每个失败有样本和原因。持续吞吐不足或严重内容错误时给出 revise，调整组件参数后重跑共享基线。

## 6. F4：在 X-Talk fork 完成 Qwen ASR 接入

先在 fork 文档中写清 ASR 接入设计及服务协议，再实现代码。保持 Qwen 的 vLLM 0.14.0 与 X-Talk 客户端依赖隔离，优先独立模型服务加异步客户端；不能假定普通 OpenAI 文本流接口即为持续音频流式协议。

适配须满足当前 X-Talk ASR 契约：

- 输入为 16 kHz 单声道 PCM16，返回当前累计文本，显式保留修订，不仅返回新增 delta；
- 每个会话维护独立解码状态；`clone` 共享可共享资源但隔离缓存，`reset` 清理该会话；
- 区分临时解码 flush、真实输入结束和话轮控制。上游 `is_final` 提示不能擅自销毁仍需继续接收的会话，官方 finish API 若终止状态须明确适配办法；
- 同会话推理顺序可控，慢调用在音频事件链外运行；超时、取消、断线和 shutdown 有可检查的资源回收；
- 原生 DefaultService / DefaultAgent 及原有轮次逻辑继续使用；系统附和显式关闭，LLM 请求层显式关闭 thinking；
- 提供完整可实例化的 X-Talk 服务配置与启动入口，保持准备 YAML 与运行时配置职责清晰。

单元与确定性集成覆盖两会话隔离、append/rewrite、临时 flush 后续说、结束/reset、超时取消、断线和无音频。远端模型 smoke 与接口测试分开登记；InterClarify 记录 fork 的实际新提交及配置，不复制运行时源码。

## 7. F5：真实流式与全双工交互验收

### 在线链路

从同一个原生 X-Talk 会话接入真实音频，ASR 事件驱动原有轮次控制，LLM delta 到达后直接交给现有 StreamingTextTTS 链路。不得先收集完整回复再按固定速度回放。保留原来的顺序和人为分块测试作为独立对照，名称与结论分别标注。

时间线使用单调时钟，绑定 session/turn/response/chunk 标识，至少记录音频到达、用户末次发声、ASR partial/final、生成请求、首个可朗读文本、TTS 请求/首音频、播放提交/客户端起播、实际已播前缀、插话与停止确认。跨进程记录时钟来源；实际声卡起播不可取得时报告“客户端交付/播放确认”，不冒称用户已听到。

分别报告音频起点到首 partial、用户末次发声到起播、提前接话的位置、LLM/TTS 分段延迟及用户有效插话到停播。首 token 与首个可朗读文本不是同一指标。

### 交互矩阵

| 场景 | 需要确认的行为 |
| --- | --- |
| 用户句中短暂停顿、思考后续说 | 记录原生行为与误接话；不把 pause 自动判为说完 |
| 系统回答时用户继续输入 | 音频与 ASR 仍接收，没有关闭输入 |
| 系统说话时用户短附和 | 正常继续，不误停播；记录上下文相关的失败 |
| 系统说话时有效用户插话 | 停止剩余生成/合成/播放，保存已播文本并继续同一会话 |
| 取消后立即重新生成 | 旧响应音频不能串入新响应 |
| 连续多轮、不同回复长度 | 无编译长卡顿、持续队列积压或状态泄漏 |

至少完成一段 10 分钟连续会话，保存队列/资源趋势；首轮可顺序使用多个会话验证隔离，不新增多用户并发 MVP。自然语音场景允许失败，但必须形成差距表：原生缺失的双工策略记为 ADAPT/PATCH，基础链路丢音频、取消失效、已播历史错误属于接入阻塞。

原生基线不要求预先完成 DuplexCascade 的 micro-turn 或提前回答策略；这些在冻结之后的 A1–A4 中改造。此处先证明输入、输出、事件与取消机制可支撑后续改造，并记录原生策略表现。

## 8. F6：FDB smoke 与冻结决策

固定 FDB 提交、数据、评测适配器与判分脚本，先运行原生基线 smoke，保留用户附和抗误打断、停顿、接话及用户打断相关项目；System Backchannel 输出项目注明范围外。受语言、数据访问或评测接口限制时写明具体阻塞、已做检查与解除条件，不能把未运行写成通过。

冻结报告至少包含组件 revision、fork 提交、镜像 digest、完整环境与配置摘要、输入与音色校验值、测试结果、延迟分布、资源、差距表、FDB 结果或具体阻塞，以及 go / revise / stop：

- **go**：F1 入口可信，F2 来源可追溯，中文质量与预算可接受，F4 接口通过，F5 基础在线链路与取消/已播边界有证据，FDB 已运行或具体阻塞明确；冻结底座，按既有方案开始 A1。
- **revise**：已有服务可运行，但质量、预算、适配或证据仍有缺口；保持 candidate，先修复并复测。
- **stop**：现有组合在已尝试的参数下仍无法满足基本吞吐或交互约束；停止扩大实验，先更新组件路线和基线记录。

冻结后依次实施 A1 可观测性、A2 micro-turn 与等待、A3 Layer 1 和单一仲裁、A4 功能验收。阶段 A 通过后才进入 InterClarify Layer 2，不借此次任务扩大研究范围。
