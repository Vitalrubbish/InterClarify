# 前端执行线程、CPU 预算与 complete 交接修订

2026-11-05，NTF-052／053。已完成实现与本地验证。本文件先于代码更新建立合同，用于替代此前“批次间临时线程／保留complete整段识别”的实现合同。

## 执行线程与资源

SoulX始终由回放调用线程执行。双路并发仅将X2的两个80ms步放入该前端生命周期内的单个常驻辅助线程；两路收尾后才联合发布。顺序参数只影响串行模式，不再通过交换并发模型所属线程来覆盖完成顺序。前端第一次实际推进绑定回放线程，之后拒绝迁移；取消阻止新任务，关闭等待辅助线程结束，失败返回前仍等待当前批次收尾。

直接长度预热、两轮联合预热及正式回放在同一回放线程执行SoulX，实际模型调用线程内启用inference_mode。前端、SenseVoice、X2、Qwen和TTS的intra-op均为2、interop为1；SenseVoice显式传ncpu=2，加载后再次检查并保存实际预算。完整系统四个模型进程的计算线程预算为8，保留12CPU作业内的调度余量。容量、显存和真实供音时钟沿用原合同。

## complete 后的识别

保留官方状态预测前的短窗SenseVoice识别、文字修订、规则反馈及KV顺序。有效complete到来后，原有服务分支仍整理缓冲并执行reset，但不再调用整段SenseVoice；服务状态仍为speak，服务文字为空，并显式记录complete_recognition_skipped事件。下游继续消费同一批次X2正文。无有效语音的complete仍按官方逻辑拒绝。

wait_fallback分支和取消后已播尾音的历史识别不属于本次删除范围；complete-only回答触发、空正文处理及nonidle取消保持。此次没有恢复等待兜底回答许可、增加pending_handoff或调整缓存释放／dtype。

固定子模块不修改。观察适配器必须只匹配complete服务分支中唯一的整段识别位置，并校验冻结源码摘要和替换计数。保留显式原生兼容模式供严格对照使用，正常前端默认跳过complete重识别。
