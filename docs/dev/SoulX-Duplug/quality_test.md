# SoulX-Duplug 英文话轮能力与延迟测试计划

更新：2026-10-24。状态：方案，未实施。入口见[候选路线](README.md)。本文件定义首轮可复核的组件测试；样本、环境和评分配置尚未实际冻结，文中的数量是计划值，质量预算是执行前待冻结的初筛标准。

## 1. 要回答的问题与范围

本轮检验公开权重能否成为第一阶段控制器候选，重点回答：

1. 完整英文陈述、问句、请求和对上一轮问题的回答，是否能及时接话？
2. 句内停顿和语义尚未完成时，是否会误抢话？
3. 系统表达期间，能否区分用户附和和要求获得话轮的发声？
4. 从用户音频事件到控制结果返回需要多久，时间花在 ASR、模型还是排队上？

主测为 SoulX-Duplug＋官方 SenseVoiceSmall 英文路径，使用原生五类用户状态，不训练、不加入 CoT、不替换 Nemotron，不运行自由回答、在线 TTS 或真实播放器。Speak 场景使用离线固定的参考输出时间轴，所有控制仅作影子记录；本轮无法报告实际可听开口或停播延迟。

旧 XTurnix 结果只用于说明历史问题，不参与本轮胜负判定。两路线输入、状态标签和延迟锚点不同；不把历史 Nemotron 逐词延迟与本轮结果相加。此前取消的 FDB、FLEURS 作业保持原状态，本方案不恢复它们。

### 2.2 原生状态、服务结果与影子动作

原生状态定义依据[论文第 3 节](https://arxiv.org/html/2603.14877v1#S3)。必须分别记录模型预测、服务包装结果和运行时映射，不能将三者混成同一个标签。

| 原生状态 | 含义 | 本轮解释 |
| --- | --- | --- |
| `user_idle` | 静音或噪声 | 保持当前行为；不能自动认定用户让轮 |
| `user_nonidle` | 有意义的用户发声 | Listen 下继续观察；Speak 下按官方示例作为停止候选 |
| `user_backchannel` | 用户附和 | Speak 下继续参考输出；不触发系统附和 |
| `user_complete` | 用户表达语义完整 | 记录原生完成判断，检查其是否形成服务接话结果 |
| `user_incomplete` | 暂停但语义未完成 | 记录等待判断，继续观察后续发声及兜底行为 |

[官方服务](https://github.com/Soul-AILab/SoulX-Duplug/blob/main/service/model.py)将部分原生状态合并为 `idle`，并返回 `nonidle`、`speak`；`blank` 表示音频尚不足一块，不是用户状态类别。Listen 下 `speak` 记接话候选，Speak 下 `nonidle` 或 `speak` 均记停止候选，其余保持；Speak 下的 `speak` 还表示新用户话语已完成，不能直接启动第二路输出。参考状态由测试驱动依据预设输出生命周期维护，不由模型自报；首次停止候选后关闭该影子输出，后续结果不能再当作同一 Speak 机会。

Speak 下 `nonidle` 到停止的映射采用[官方客户端策略](https://github.com/Soul-AILab/SoulX-Duplug/blob/dialogue-system/dialogue_system/clients/vad_client.py)；官方[回答执行路径](https://github.com/Soul-AILab/SoulX-Duplug/blob/dialogue-system/dialogue_system/app.py)也会在 `speak` 启动新回答前停止旧输出。这不是“有意义发声必然是打断”的金标。用户附和是否被误判、普通短确认是否造成误停，正是本轮要测的问题。

服务在 `user_incomplete` 后持续静音时可能由 `max_wait_num` 触发 `speak`。每个接话结果必须记录 `model_complete` 或 `wait_fallback` 来源，以及 RMS 过滤、强制 complete/incomplete 分支；不改变默认值做主测。兜底触发比例单列，不能只报最后接上话的总数。

## 3. 数据与标注

### 3.1 公开英文完成/未完成集：200 条

使用 [SoulX-Duplug-Eval](https://huggingface.co/datasets/Soul-AILab/SoulX-Duplug-Eval) 的 `Easy-Turn-Testset-en.zip`。核查到的数据 revision 为 `f6e50e8f07f3d33d8b2e77b14df986d14c817ef2`，归档大小 56,893,309 B，SHA256 为 `6c045b9543c6f6f5188a5134923b50f96705c609a2c80b3582aafedeb9907387`。上游说明包含 Complete 318 条、Incomplete 299 条；本轮只读清点后再确认类别与文件数量，不把 HF 自动显示的 train split 当成可训练授权。

按类别将归档内相对路径的 SHA256 升序排序，各取前 100 条，共 200 条。先核查重复及类别冲突；若需剔除，保留剔除清单并按同一顺序补足，选择不得参考模型分数。保存全部候选及最终 manifest，解压前核对空间和成员路径。

此集只提供完成/未完成的公开诊断，不能独自证明真实让轮、附和或打断能力。完整音频逐条流式回放；Incomplete 后的尾部静音不将其变成 Complete，兜底误接话仍计错误。本项目选定的在线窗口指标不是作者的原始 ACC，不宣称直接复现论文。

### 3.2 独立受控英文场景：100 条

另建与公开集、旧 FLEURS/FDB 和训练素材隔离的小型事件集，提供清晰的交互目标和音频事件窗口。先定义语义与时序，再取得音频；优先使用有来源的英文原声，不足时可使用现役 Kokoro 离线合成，标明合成音色和局限，不把单一 TTS 声音的结果推广至自然多说话人对话。

| 场景 | 计划数 | 必须覆盖的内容 |
| --- | ---: | --- |
| 正常接话 | 25 | 至少 15 个完整陈述/陈述式回答，另含问句、请求、短回答；均有明确让轮意图 |
| 持轮与停顿 | 25 | 悬空条件、列表续项、犹豫、自我修正；覆盖 0.3/0.8/1.5/2.5 秒停顿，不改变默认兜底 |
| 用户附和 | 25 | 参考输出期间的理解应声、同意、短确认；与同词不同语境的轮后回答区分 |
| 用户打断 | 25 | 明确停止、纠正条件、改变请求及要求重新说明；在参考输出仍有效时出现 |

每个独立场景只进入一个正式主分母。配对、重复音频和同模板改写标记为同组，不增加独立场景数；数量不足如实报缺口，不通过重复窗口补齐。数据范围是用户附和和用户打断，不训练或评估 Layer 0 系统附和。

另备 20 条独立开发场景，每类 5 条，与正式集按源会话和模板分组隔离；音源及说话人重叠单列，单音色合成不声称说话人隔离。开发集用于预热、协议和音量合理性核查，不按其结果搜索阈值。正式 300 条输入在看模型结果前冻结；本轮不批量生成 UltraChat 训练数据，不调用未经授权的收费生成服务。

### 3.3 金标与来源

每例保存任务背景、音频和脚本摘要、真实/合成来源、音源与模板组、预期系统状态、发声起止、允许接话窗口、持轮区间、附和或打断起点，以及语义完整性判断。Speak 场景额外记录参考输出文本、参考时间轴和用户事件发生时参考输出仍有效的证据。

输入音频只有用户侧音轨；助手参考音轨不混入识别音频。本轮不覆盖真实回声消除或远场串音，不能据此声称已验证真实双工声学环境。原版模型不读取额外任务背景或助手文本，背景仅用于独立标注和复核，报告说明其上下文限制。

正式评分前至少完成一次独立于模型输出的听审，记录审核者是人工还是辅助模型、时间锚点置信度和分歧。无法确定的语义或声学事件标为未知，保留数量和原因；不根据模型预测反向修改金标。不把文件末端当作真实发声终点；合成时序也须对齐到最终波形，无法可靠定位则延迟为 null。

## 4. 在线回放协议

1. 在远端隔离 conda 环境加载固定资产，保存启动及权重加载证据；预热不计正式结果。
2. 使用独立开发集，再做四类各 1 条的冒烟。只核查会话隔离、状态记录、时间、资源和输出契约；失败则停在冒烟，不边改边跑正式集。
3. 逐条建立全新会话，按真实时钟的 80ms 包末采样时刻持续发送，不等音频识别完才发送下一包。录制用户流不因影子接话或停止候选而提前截断，以保留后续错误证据。
4. 发送器与接收器解耦，单会话仅 1 个在途处理请求；待发送/待处理队列合计最多 10 个传输包（800ms）。超过上限结束该例并记过载，不突发追赶、不静默丢帧、不通过减慢音频隐藏处理不足。
5. 保留源录音静音，所有样本统一追加 5 秒在线静音。之后才结束会话；不得以 EOF、类别或最后词标签通知模型结束。尾窗结束后另记会话排空，排空结果不并入在线指标。源录音与尾窗已含的静音分别记录。
6. 40ms 前瞻只能等待真实已发送音频提供，不能偷读下一未发送包。在线 ASR 不读取脚本或参考转写。
7. 固定参考输出时间轴只用于维护测试的 Listen/Speak 和影子输出标识。接话候选不自动形成真实发声；用户打断后也只记录停止决定，不能伪造播放器确认。

需要最少量观测代码暴露原始状态、服务分支、ASR 调用和排队时间，观测不能改变判定、归一化或兜底策略。开发阶段核对观测开销；若原始状态仅在最终响应中附带，客户端只能得到服务返回上界，原生判定的在线可见延迟不得倒推。

## 5. 话轮质量评分

以独立事件为主，不用大量 idle/keep 帧稀释错误。原始五类状态可另报有可靠标签窗口的混淆矩阵和覆盖，不能给整段音频强贴单一逐帧金标。

| 指标 | 评分规则 |
| --- | --- |
| 正常接话 | 首个服务接话候选位于允许窗口内才算有效；分别报 1 秒内及时接话和 5 秒内最终覆盖。此前出现误接话，则该机会判失败，后续命中仅作诊断 |
| 陈述句接话 | 单独报告完整陈述与陈述式回答的计划数、覆盖、误接话、兜底依赖和延迟，不用问句成绩代替 |
| 持轮误抢话 | 任一标注持轮区间内出现服务接话候选即记该机会失败；模型完成判断与计时兜底分别计数 |
| 用户附和误停 | 在参考 Speak 及附和机会内，出现任一停止候选即记失败；结束后的正常接话另记，不混入附和 |
| 用户打断 | 记录打断起点后的首个有效停止候选、600ms 内及时覆盖及 5 秒内最终覆盖；起点前误停记失败，不将其负延迟截为 0 |
| 公开完成集 | Complete 报接话覆盖与提前候选，Incomplete 报观察窗内误接话；保留原生完成与服务接话两个口径，禁止合成一个未经定义的 ACC |
| 运行可靠性 | 失败、空转写、过载、超时、观察不完整分别计数，并保留全部计划分母 |

原生完成率、服务接话率及 `wait_fallback` 依赖同时报告。若总接话提高主要来自兜底，不能据此声称已解决语义完成判断。准确的用户附和识别也不等于系统已会主动附和。

## 6. 延迟、吞吐与时钟

### 6.1 音频到服务决定

客户端使用同一单调时钟记录回放起点 `t0`、每包计划/实际发送及结果接收。金标音频事件映射为 `t_event = t0 + sample_offset / sample_rate`。发送偏差、服务器排队和返回网络耗时保留在端到端测量中；不能将服务器墙上时钟直接与客户端时刻相减。

| 量 | 定义及用途 |
| --- | --- |
| `L_take` | 首个有效服务接话结果收到时间减用户真实发声结束时刻；只在允许窗口内计有效命中 |
| `L_stop_decision` | 首个有效停止候选收到时间减打断起点；是影子控制延迟，不是实际停播延迟 |
| `L_complete_native` | 仅在有立即发出的原生事件、且锚点可在同一客户端时钟测量时，计算原生完成事件可见延迟；否则为 null 或明确标服务返回上界 |
| `L_wrapper_gap` | 同一服务进程内，从原生判断完成到服务结果就绪的时间，包含可能的整轮二次 ASR；与客户端端到端延迟分开 |

源音频中用户已停止后的静音也计入等待。允许窗口、声学锚点和统计排除规则在正式评分前冻结；保留提前、过期、窗外及未命中结果。命中条件下报告均值、P50、P95、最大值和样本数；失败或未命中填 null，不填 0 或窗口上限。

### 6.2 ASR 与模型耗时

在同一服务进程的单调时钟记录：包/块入队、处理开始、音频编码、ASR 门控、外部识别开始/结束、文本差分和缓存修订、状态预测、服务包装与返回。ASR 的滚动窗口调用与生成完整回合文本的调用分开统计，保存输入音频时长、调用次数和耗时分布。

CUDA 耗时采用正确同步的计时方式；若为避免扰动主路径采用异步事件或 profiler，记录计时方法和额外开销，不能把异步 kernel 发射时间当作执行时间。各阶段分位数不能相加冒充端到端 P95。

滚动窗口 ASR 的单次耗时不是新词稳定到达延迟。若有可信词级参考对齐，可另报正确可对齐词的首次交付、修订次数及覆盖；本轮不以未验证的逐词时间替代控制锚点。WER 仅作辅助，按在线转写和会话结束转写分别保存；标准化规则实施前冻结，空转写计删除，运行失败另报覆盖。

同时报告单次 ASR 调用 RTF（调用耗时/该窗口音频时长），以及整个控制路径处理总耗时/新输入音频时长、每块处理耗时与队列深度。重叠窗口会重复处理音频，ASR 窗口 RTF 小于 1 不代表整个系统能跟上实时输入。

### 6.3 公开数字的比较边界

[论文](https://arxiv.org/html/2603.14877v1#S6)的英文模块延迟约 205ms，是从整链路减去回答 LLM/TTS 首包耗时估算；240ms 是理论分块延迟。英文正常接话约 511ms、打断停播约 450ms 来自作者完整系统，包含本轮未运行的环节。本轮直接计时与这些数字分别列出，不能宣称严格复现，也不能用 160ms 块长代替实测延迟。

## 7. 初筛标准与结论

以下为本方案提出的首轮候选筛选预算，尚非用户已确认的部署标准。正式执行前将最终值与数据 manifest 一并冻结；正式测试结果不得用于修改预算、参数或选择检查点。

| 项目 | 建议初筛预算 |
| --- | --- |
| 受控正常接话 | 1 秒内有效服务接话覆盖≥90%，同时报告模型完成与兜底贡献 |
| 陈述句 | 独立报告；1 秒内有效接话覆盖≥90%，不能由其他句型补偿 |
| 句内停顿误抢话 | 独立机会错误率≤5% |
| 用户附和误停 | 独立机会错误率≤5% |
| 用户打断 | 600ms 内有效停止候选覆盖≥90% |
| 服务接话延迟 | 有效命中条件下 P50≤500ms、P95≤1,000ms |
| 停止决策延迟 | 有效命中条件下 P50≤300ms、P95≤600ms |
| 稳定性 | 无持续积压；运行失败率≤1%，所有失败留在计划分母 |

公开 200 条集只作固定外部诊断，不设根据论文数字倒推的通过线；逐类别成绩必须披露。受控集才用于本方案的机会级初筛，不能将两集拼接成单一准确率。

同时给出分子/分母与 Wilson 95% 区间，相关改写按场景组处理。每类约 25 个事件、陈述句更少，点估计满足预算也不能证明真实错误率已低于 5%；需要将结论限定为“值得进入下一轮验证”。任何类别、标注或有效样本不足时写证据不足，不以总体平均掩盖。

最终结论采用：可继续验证、需要针对性适配、当前不满足、证据不足。基础控制通过也不证明 CoT 条件化、自然对话泛化或真实播放链可靠。若收益依赖等待兜底、误抢话/误停越线或处理持续落后，先定位原因，不直接进入训练或替换现役控制器。
