## 1. 测什么

本轮只回答：用户音频经 Nemotron 在线转写后，SoulX-Duplug 对英文完整／未完整表达判断得怎样，返回完成判断需要多久。

采用公开权重、不训练、不加入 CoT，全程 Listen 影子观察，不运行 Layer 1/2、TTS 或播放器。保留原生五类状态，但本轮只评价 `user_complete` 与继续等待的区分；用户附和、用户打断、自然多轮让轮和实际可听延迟不在本数据集的结论范围内。

### 单一转写与输入时序

同一条音频流送入 Nemotron 和 SoulX 音频路径。Nemotron 按自身流式节奏持续处理，不受 SoulX 的 ASR 门控或完成判断暂停；原始累计转写和修订保留，控制输入的归一化副本另记，后续供 Layer 1/2 使用的权威文本仍来自 Nemotron。

Nemotron 更新必须按逻辑用户 `turn_id` 写入 Shared Context，并向下游暴露最新转写快照及更新读取接口；写入不等待 SoulX 完成判断或音频／文本对齐处理。具体规则见[Shared Context 接口合同](shared_context_interface.md)。本轮使用最小 Context 存储与只读消费者替身验收数据链路，不加载真实下游 LLM。

官方[推理代码](https://github.com/Soul-AILab/SoulX-Duplug/blob/main/service/model.py)同步调用外部 ASR，并处理文本差分和缓存修订；替换为 Nemotron 需要实现适配，不能只改模型名称。实施前固定以下合同：

1. 每次 ASR 处理完成记录会话、实际使用的音频截止点、前缀版本、原文、增量／修订及真实可用时间；音频仅已送达，不等于已被 ASR 处理。
2. 以确认处理过对应音频观察的 ASR 快照作为文本就绪依据，尚未返回时有界缓冲等待；ASR 确实完成且没有新字词时才使用空增量，不把 ASR 落后解释为静音。
3. 按观察顺序把缓存音频块与可用文本送入 SoulX。保留每次模型输入实际使用的音频范围和 ASR 版本，不将较晚音频产生的文本伪装成较早块的转写，也不要求每个词精确归属一个 160ms 块。
4. 新增文本只消费一次。现有 Nemotron 服务对已交付原文回写明确失败；词内追加引起的控制文本归一化变化也须处理，不能自行插空格或重复前缀。需修正已注入控制文本时，从有记录的有效检查点有界重放受影响输入；超出可保留范围则明确失败，不静默拼接或舍弃修订，也不把重放结果回填成过去已经发生的判断。
5. 原生状态和服务分支分别记录。完成回合文本直接取 Nemotron 的对应版本；删除官方整轮二次识别调用，不能通过 EOF 提前取得最终转写后补回在线输入。

缺少可靠的观察截止点或无法验证上述顺序时，先修复协议，不以估计时间戳冒充适配完成。本轮记录这套适配组合的表现，不作为官方 SenseVoice 配置的直接复现。

## 4. 怎么跑

1. 远端 conda 隔离环境加载固定资产，只读复用现有 Nemotron。先验证模型加载、空增量、音频／文本对应、会话隔离和资源上限。
2. 每类按归档相对路径 SHA256 排序取首条，共 2 条做协议冒烟，只检查契约，不调参。正式 run 使用冻结代码与配置重新回放全部 617 条，记录冒烟接触过的样本，不声称完全盲测；若冒烟修复行为逻辑，先更新版本再正式运行。
3. 每条全新会话，逐包真实时钟回放，独立发送和接收。单会话只允许一个在途 SoulX 请求，待处理音频队列≤800ms；超过上限结束该例并记过载，不减慢音频或无限并发掩盖处理不足。
4. 保留源录音头尾静音，所有音频统一追加 5 秒在线静音，再结束会话做独立排空。期间不向模型发送文件末端、类别或“用户说完”提示，右前瞻只读取真实已到达音频。
5. 完成候选仅记录，不关闭 Nemotron、切换 Speak 或启动播放，完整采集观察窗内的判断。文件发送结束、在线静音截止和 EOF 排空分别标记，排空结果不计在线命中。

## 5. 只报告三组结果

### 5.1 完整性判断

原生判断和服务接话分别评分，观察窗为整条源音频与统一的 5 秒在线静音。原生完成事件指上游状态预测流程返回 `user_complete`，同时保留是否来自直接预测、状态切换分支或无文本强制分支。

- **Complete 完成召回**：观察窗内至少出现一次原生完成判断的样本数／318。
- **Incomplete 误完成率**：观察窗内至少出现一次原生完成判断的样本数／299；未完成正确率为完整观察且没有误完成的样本数／299。
- **总体与平衡准确率**：Complete 检出及 Incomplete 正确等待计正确；总体用全部 617 条为分母，平衡准确率为两类正确率平均。失败、超时或观察不足记预测 null，均不算正确，另列数量。
- **服务接话与兜底**：用相同规则对服务 `speak` 另报完成召回和误接话率，区分 `model_complete` 与 `wait_fallback`；Incomplete 上计时兜底接话仍是错误。

这是本项目定义的在线整条音频判定，不等同于作者特定时点的 ACC，也不证明语音中途开口时机正确。单条完整性标签不足以给每个中间帧贴金标；完整音频中途出现的完成候选全部保留，不只展示末端命中。

### 5.2 延迟

| 指标 | 记录方式 |
| --- | --- |
| 组合处理耗时 | 记录一次状态请求实际发送至结果收到的耗时；在服务同一时钟内分列等待 ASR、音频编码、文本注入及状态预测 |
| Context 可见耗时 | 在同一适配进程时钟内，记录收到 ASR 更新至 Shared Context 提交可读的耗时；单列，不算作下游 LLM 响应时间 |
| 相对文件结束的完成时间 | 首个在线原生完成结果或服务 `speak` 的客户端接收时间，减源音频最后一包实际发送完成时间，两种结果分别报告 |
| 接话覆盖与长尾 | 同时报完成命中数、仅兜底、窗外、未命中、过载和失败；延迟报样本数、均值、P50、P95、最大值 |

使用同一客户端单调时钟计算在线相对时间；服务端只计算内部阶段耗时，不能跨机器直接相减。ASR 等待、音频分块、40ms 前瞻、排队和传输均计入实际路径，不与历史 Nemotron 常数拼接。

公开集没有已验证的声学终点，本轮把“相对文件结束”明确标为代理量，不能冒称从最后一个实际发声词到决定的延迟。源录音可能含尾部静音，负值原样保留，不归零，也不自动判误抢话；没有完成判断的延迟为 null。若缺少可独立观测的原生事件返回，只能报告服务返回时间，不能倒推出原生判断可见时间。

### 5.3 输入与运行诊断

保存 Nemotron 原始转写、版本、消费截止点和在线到达时间，统计空转写、修订、ASR 等待、队列积压及 CPU/GPU 峰值。仅在原数据确有可用参考转写时附加 WER，固定 `whisper-normalizer==0.1.12`，空假设按删除计；没有参考时不生成伪参考，也不因此扩大测试范围。

在同一次回放中检查每个非重复 ASR 文本版本的 Context 写入与读取结果：保持 `session_id`、`turn_id`、来源、版本和文本一致，确认重复不重入、旧版不覆盖新版、关闭时仍保留最后在线文本。写入失败和读取差异单列，不能只用 trace 中有文本证明下游接口可用；空转写样本保留空记录及原因，不能从接口分母消失。

本轮建立未训练组合基线，不做参数扫描或预设复杂的四类能力通过门槛。报告判断是可继续验证、需要适配、当前不满足或证据不足；结合两类错误与延迟作结论，不只看进程成功或平均准确率。

## 6. 资源与交付

真实模型仅在远端调度作业执行，遵守[远端目录约定](../../remote_workspace.md)。继续使用独立根目录 `~/parathink-soulx-duplug/`，Nemotron 资产与现役服务环境只读复用，不改当前运行时。

上限保持：1×24GiB GPU、8 CPU、32GiB RAM、batch=1、1 个活动作业；GPU 显存停止线 22GiB，下载并发≤2、CPU worker≤2。单作业≤4 小时，本轮冒烟及正式运行累计≤4 GPU 小时。启动可用盘≥30GiB，新增环境、模型、数据、缓存与结果累计≤10GiB，其中 trace/报告≤2GiB；触限停止，不自动扩容。

交付控制在：冻结配置与版本、数据 manifest、逐例 trace/CSV、汇总 JSON、资源记录和一份中文报告。每例保留标签、原生及服务结果、首个完成时间、兜底来源、输入版本和失败原因；附上对应 turn 的 Context 快照及写入／读取核验结果，不复制第二套音频或启动 LLM。
