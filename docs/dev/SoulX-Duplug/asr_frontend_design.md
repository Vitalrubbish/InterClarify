# ASR 前端：160ms 全文与状态联合覆盖

2026-10-30，按用户指令撤下Nemotron＋SoulX专用适配和探针，采用官方SoulX＋SenseVoice。每处理一个160ms音频块，前端将最新话轮全文与本块状态原子覆盖到SharedContext，后续识别修订直接替换旧正文。不保存历史正文版本、patch或事件游标，不增加320ms定时器。

当前代码已实现，并通过本地契约检查和远端六视图当前值写入检查；下游Layer1／2、CoT与真实播放尚未接入。完整验证状态见[远端报告](../../../reports/soulx/20261030-current-context-test/README.md)。本次不新建issue，不恢复旧训练或FDB评测。

## 1. 组件与处理顺序

| 组件 | 职责 |
| --- | --- |
| `SoulXFrontend` | 采集SenseVoice原始结果、维护音频账本、取得原生五状态，每块联合发布 |
| `SenseVoiceObservation` | 分离已知ASR标签，保留原文字和字符映射 |
| `TurnTranscriptAssembler` | 将窗口识别整理为当前话轮全文，处理尾部修订及覆盖缺口 |
| `SharedContext` | 每个话轮只保留最新整组数据，短锁内替换并返回读取副本 |

音频按80ms包接收，满足完整输入后调用官方160ms步骤。识别仍受原生门控控制，没有新字的块继续预测状态。新文字先更新前端当前草稿，不立刻单独写入Context；状态回调先暂存本块结果，待官方外层状态处理结束后，将最终草稿和本块状态一次发布。

此顺序包含complete／等待兜底分支额外进行的整段SenseVoice识别。官方内部reset发生在返回前时，前端仍保留该块预测及逻辑话轮正文，避免把完成状态配成下一generation的空文本。不把服务`speak`反推成原生complete。

## 2. 文字与修订

在SenseVoice富转写后处理之前采集原始结果，保留数字、标点、空格、大小写和附和。语言、情绪等标签独立解析，不作为用户正文或控制状态。官方归一化、去标点及去附和只用于SoulX自身输入，不覆盖Context正文。

同起点窗口重新识别可替换旧词、增加或删除尾部。滑窗移动需要唯一词锚点；reset后的相邻片段只在音频范围连续且旧尾有词句界时拼合。不直接累计`asr_segment`，也不把最近窗口当完整话轮覆盖。

无法可靠拼合时保留最后可重建正文，标记`assembly_status=gap`、`coverage_complete=false`。识别错误或普通空返回不清空已有正文。正文覆盖正确不表示识别正确或所有音频已覆盖；旧六视图中仍有拼合gap，不宣称本次存储改造已修复该质量问题。

## 3. 当前值与状态

`SharedContext.open_user_turn()`创建空记录；`publish_user_frame()`联合替换当前全文与当前状态；`get_user_turn()`返回同一组副本。逻辑话轮标识稳定，不因每块更新、内部reset或complete重复预测而新建用户消息。

帧包含`text`、`state_token`、`state_token_id`、`state_accepted`、真实处理截止、观察上界、覆盖标志及必要来源信息。只允许SenseVoice来源；不要求正文版本、历史查询或事件流。无新正文仍提交本块状态。

原始argmax与规则调整后的有效状态分别记录，五类token与冻结词表ID核对。远场拒绝、未知状态、合成音频和排空阶段不作为有效控制输入；排空结果只进Context之外的诊断记录，不替换在线当前值。

## 4. reset、关闭与并发

模型计算由单写者串行执行，前端拒绝并发feed或计算期间关闭。Context读写只用短锁，读者可以并发取得整组副本，不会看到新正文与旧状态拆开的中间值。

内部reset仅重建官方模型缓存及状态，保留已到达未处理PCM、采样账本、逻辑话轮和正文整理器。真实处理位置检查不能跳过、重复或倒退。逻辑关闭保留最后已发布正文和状态，关闭后不再接受在线帧。

EOF不等于语义完成。最后不足块的真实采样单独报告；额外合成尾部标记drain，后到识别不回填在线结果。

## 5. 直接打断与Layer1

活动输出期间，有效nonidle在状态钩子中直接执行匹配输出的停止回调，然后做诊断及后续发布，不等待下游读取或日志落盘。对同一output_id成功投递一次；回调仅是停止请求，不代表物理停播已完成。

其余状态只供Layer1读取，不映射成运行时start／keep。Layer1／2在合法输入边界读取最新值，更新不自动修改在途推理或KV。慢消费者可能错过被覆盖的短暂complete；本轮遵循用户确认的当前值读取，不另加历史队列或锁存，后续接入需验证响应行为。
