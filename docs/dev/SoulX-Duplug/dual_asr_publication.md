# 双ASR独立计算与缓存状态配对发布

2026-10-31用户确认的下一步方案，见[NTF-005](../../issue/NTF-005.md)。设计已记录，代码尚未切换。原因是NTF-004将Nemotron文字适配进0.6B后未见整体改善；本方案恢复原生控制输入，把Nemotron留作下游正文来源。

## 两路计算

同一份PCM使用会话内统一采样时间轴。SoulX保留音频回看/前瞻，SenseVoice按原生门控识别滑窗、整理控制文字并写入0.6B上下文；每160ms处理一步状态。状态完成后缓存该块的状态、接纳标志、controller generation、主块采样截止、实际观察上界和产生时刻。

Nemotron独立流式识别，保留原生RNNT缓存。每个真正完成的解码步骤保存当时原始累计正文、实际读取范围和完成时间，允许无新增文字。SenseVoice正文不写SharedContext，Nemotron正文不注入0.6B。恢复官方controller reset不重启Nemotron、不清空逻辑话轮正文。

## 配对与发布

```text
共同PCM ──→ SoulX音频＋SenseVoice → 0.6B状态 → 有界状态队列 ──┐
        └─→ Nemotron原生解码 → 对应步骤正文/覆盖/完成快照 ──┤
                                                         ↓
                                          按音频顺序配对，单写者联合发布
                                                         ↓
                                          SharedContext：Nemotron正文＋状态
```

两路独立推进，发布屏障不阻塞另一模型下一步计算；单模型内部仍串行，状态不因Nemotron迟到重新推断。某块发布时刻不早于该状态完成和对应Nemotron解码完成两者中的较晚者，另加配对/提交开销；避免把两路计算人为串成耗时相加。

“同段”按真实采样覆盖定义：对每个SoulX状态，选择实际窗口截止首次覆盖其主块及真实前瞻上界的Nemotron完成步骤。两路步号独立，启动短ASR块不伪装成首个160ms状态的完成依据。以既有原生窗口为例，SoulX主块截止160ms、前瞻至200ms，对应Nemotron首个充分覆盖窗口截止259ms；这99ms观察前移应如实记录，不通过改名隐藏。

配对使用所选步骤完成时冻结的Nemotron正文，不使用发布线程稍后看到的最新全文。Nemotron先完成则缓存正文快照，SoulX先完成则缓存状态；二者都完成后按主块先后发布，旧块不能覆盖已发布新块。两路恢复计算与发布线程不可共用一个会阻塞计算的长锁。

配齐但本步Nemotron无新字时，仍发布该步状态与原始累计正文；“没完成”“完成但无新字”“已完成待另一路”分别审计。解码完成只证明该窗口已处理，不保证该范围内所有词已经交付，更不保证两个ASR的文字或语义一致。缓存状态可以延迟发布，不能在Nemotron尾词后来到达时倒填旧帧。

## 可见性与边界

SharedContext仍只保存一个逻辑话轮的当前原子快照，不增加历史正文版本或事件游标。160ms表示音频步长，发布墙钟周期取决于较慢一路；积压后多个已配齐帧可能紧邻发布，慢消费者可能漏读短暂状态，当前值接口本身不保证逐帧送达。

complete到达后保留原生SoulX内部行为，但不结束独立Nemotron会话、不强制整段Nemotron重识别或将尾词补齐当作发布条件。EOF前到达的音频在明确配对规则内处理；EOF不足下一完整窗口的状态记未发布，排空仅诊断，不补静音、不新增在线状态、不回填SharedContext。

本次只延后SharedContext联合发布。既有有效nonidle直接停止活动输出的路径仍在状态有效产生时调用唯一执行点，不额外等待Nemotron；其后同状态仍通过配对写入SharedContext。该独立路径与正文发布分开计时，当前研究探针不接真实播放。

## 有界与验收

缓存是内部未配对工作队列，不是无限状态历史。实现时设明确条数/字节上限及取消、异常、关闭清理；保留原800ms积压要求，测量真正未读PCM和未发布状态跨度，历史回看窗口单独计量。主块到发布延迟、完整观察截止到发布延迟和两路计算/排队分别记录；不拿一项代替另一项。

先验证配对、队列和两路计算确实解耦，再在远端比较原生状态质量与配对发布后的延迟。双ASR同卡可能争用，原生SenseVoice仍可能提前complete；本设计不预先宣称解决吞吐或状态质量问题。Layer 0/1/2/3职责、单一仲裁器、单一TTS所有权及已听内容不可撤销的边界保持。
