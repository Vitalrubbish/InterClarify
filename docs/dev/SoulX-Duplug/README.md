# SoulX-Duplug 候选路线

更新：2026-10-24。状态：按用户指令新建路线，当前交付质量测试方案；尚未创建环境、准备音频、运行模型或训练。

本路线先验证 SoulX-Duplug 的英文普通接话、停顿处理、用户附和和用户打断能力，以及对应控制延迟。首轮采用公开权重、官方配套的 SenseVoiceSmall 英文 ASR，保留原生五类用户状态；状态到系统行为的适配在同一个输出运行时完成。

## 路线边界

- 本次授权为撰写方案，不代表已授权远端测试、训练或部署；不创建未经用户明确指令的 issue。
- 这是新增候选研究路线，不修改[研究主文档](../../research_design.md)、[现役配置](../../runtime_baseline.md)或 XTurnix 实现，不自动恢复此前取消的 FDB、FLEURS 正式作业。
- 第一阶段允许保留 `user_idle`、`user_nonidle`、`user_backchannel`、`user_complete`、`user_incomplete`；它们描述用户状态，不是原生的 start/keep/stop。
- 本轮不接入 Layer 0/1/2、CoT 或完整播放链。采用参考播放时间轴的控制测试只能说明影子决策，不能证明真实停播时间。
- 后续若进入 CoT 阶段，需要另行设计分析文本输入、异步事件与决策监督。基础话轮测试通过不能证明模型已能利用 CoT。
- 继续保持[架构设计](../../research_design/architecture.md)中的单一仲裁执行点、单一 TTS 播放所有权和已听内容不可撤销的边界。

## 后续推进顺序

质量方案审阅 → 按明确指令建立实施工作单 → 冻结资产与输入、预检资源 → 独立开发集与冒烟 → 正式回放和报告 → 决定是否继续适配或训练。

实施时，脚本、配置及少量关键契约测试分别维护 `docs` 下同路径中文说明；本次不预先创建实现空壳。
