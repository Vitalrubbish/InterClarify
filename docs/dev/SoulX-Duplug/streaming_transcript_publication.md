# SoulX＋SenseVoice：160ms 文本与状态联合更新

2026-10-30，用户确认取消此前 320ms 正文周期方案：每处理完一个 160ms 音频块，将最新话轮全文和本块状态一起写入 SharedContext；后续识别修订直接覆盖旧正文，不保留历史正文版本。原因是让正文与状态按同一个处理步骤交付，简化下游读取。

本文记录已确认设计，替代此前周期合并建议。用户已授权撤下 Nemotron＋SoulX 适配并实现本合同。旧版本化接口已替换，当前值写入和本地检查已完成；远端真实模型验证待资源，进展见[报告](../../../reports/soulx/20261030-current-context/README.md)，两者分别报告，不以旧实测替代新合同验收。不新建 issue。

## 1. 更新单位

采用官方 SoulX＋SenseVoice 组合，保留音频编码、ASR 门控、窗口识别和状态预测。每处理完一个 160ms 音频块，原子写入一份最新用户观察，包含当前话轮全文与本次原生状态 token。这里是音频处理步长，不承诺墙钟上严格每 160ms 返回，也不要求每块重新调用 SenseVoice。

```text
音频块 → SoulX＋SenseVoice → 整理当前话轮全文和本块状态
                                 ↓
                    原子替换 SharedContext 当前观察
                                 ↓
                  Layer 1／2 在输入边界读取最新值
```

本块无新文字时，沿用当前正文并更新状态。识别错误或空返回不自动清空正文；只有成功整理出的修订才能替换全文。不增加独立的 320ms 定时器，不等待 complete 或多次一致确认。

## 2. 覆盖范围

SharedContext 每个话轮只保留一份当前转写与当前状态，不保存历史全文、正文版本、修订 patch 或正文事件游标。后续文字发生变化时，以整理后的完整话轮文本替换旧值，允许修改、增加或删除旧字词。

SenseVoice 单次返回通常是窗口文字，必须先处理窗口重叠和修订，不能把最近窗口直接覆盖为话轮全文，也不能逐次追加 `asr_segment`。无法可靠拼合时保留最后可重建正文并标记覆盖缺口，不猜测缺失文字。

controller reset 不清空当前话轮正文，也不创建新 `turn_id`。真正关闭话轮时保留最后可用全文；EOF 后识别结果仍单独作为排空诊断，不倒填在线结果。

## 3. 最小观察与并发

下游读取的概念结构为：

```json
{
  "session_id": "s1",
  "turn_id": "u1",
  "text": "我想订明天去上海的机票",
  "state_token": "<|user_nonidle|>",
  "state_accepted": true,
  "processed_until": 5120,
  "coverage_complete": true,
  "status": "open"
}
```

`processed_until` 是真实已处理音频采样位置，不是文本版本，也不是识别覆盖保证。来源、观察上界及发布时间作为必要运行元数据按需补充，不要求作为 LLM 正文。

采用单写者和短锁，写入时整组替换，读取时返回同组数据副本，避免新正文与旧状态被分开读取。单写者串行处理模型与关闭操作，不需要通过历史正文版本来解决并发。

状态可能因远场等原因不被接纳，因此保留 `state_accepted`；下游不将拒绝状态当成有效用户状态。是否完整覆盖已接收语音由覆盖字段表达，不能把同组写入理解成文字与音频逐词精确对齐。

## 4. Layer 1 与直接打断

Layer 1 在正常输入边界读取最新 text 和有效状态，正文与状态分开编码，不把状态标签拼入用户自然语言。每次覆盖不是一条新用户消息，也不要求每 160ms 启动或取消一次 LLM 推理。

SharedContext 覆盖不能自动更改在途模型已经读取的内容。后续输入边界使用最新全文；若保留 LLM KV，需要另行处理正文修订，不能把所有新全文反复追加成重复消息。当前已生成或已播放的历史不因 ASR 更正被改写。

当前值读取不保证慢消费者读到每个中间状态。例如 complete 下一块被 idle 覆盖时，尚未读取的 Layer 1 不再取得那个 complete；本方案不为此增加历史队列或锁存旧 complete。后续 Layer 1 接入需验证该读取方式下的完成响应，不能把快照读取当成逐事件可靠投递。

活动输出期间有效 nonidle 仍在预测与过滤完成后直接触发停止，不依赖 Layer 1 是否及时读取当前值。其余状态不新增运行时动作映射。

## 5. 实施边界与检查

详细合同见[共享接口](shared_context_interface.md)和[前端设计](asr_frontend_design.md)。已同步改造 SharedContext、SoulXFrontend 与回放读取方式，后续Layer1／2接入使用当前值接口，不能只把原事件协议中的正文替换后就宣称已去掉版本历史。Nemotron 独立探针的冻结运行和历史报告保留，不将其只追加协议强套在 SenseVoice 修订上。

少量检查覆盖：旧词改写、删除修订、无新增文字但状态变化、整组原子读取、reset 不丢正文、覆盖缺口、关闭与排空分离，以及覆盖不会重复触发直接停止。真实模型在远端 conda 受限作业内验证，另报告计算和排队导致的实际返回间隔。
