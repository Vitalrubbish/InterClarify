# 每个用户话轮的转写与 Shared Context 接口

2026-10-29 当前选型：用户确认首版采用 SoulX-Duplug＋SenseVoiceSmall 语音前端，先打通链路，后续再评估 Nemotron，见[选型说明](asr_adapter_assessment.md)。本接口按版本化话轮快照组织，不预设文本只能追加；尚未实现。TextTurn 的 `no-voice` 不属于本接口正文，也不能代替 SoulX 音频判断。

适用于 [SoulX-Duplug 路线](README.md)；Shared Context 即架构中的共享 Context，不另设第二份权威转写。

本轮已完成[ASR 前端设计](asr_frontend_design.md)：明确原始识别／标签与五状态的采集位置、保守窗口对齐、统一事件事务及延迟观测。本文维护下游接口，详细源头和算法以该设计为准。项目已有 `scripts/runtime/textturn_context.py` 仍是仅接受 Nemotron 及前缀追加的历史实现，不能据此声称本接口已实现。

## 1. 写入时机与话轮标识

首版唯一转写来源为 SenseVoiceSmall。语音前端取得在线识别结果后，将窗口重叠、差分与修订整理为当前话轮快照，先写入 Shared Context，再发布可读更新通知，供 Layer 1/2 在各自输入边界消费。SoulX 在前端内部使用同一来源的对应文本，状态记录关联版本；Context 发布不等待状态预测完成。文本写入不等待 `user_complete`、服务 `speak` 或播放启动，已可用文字不应被后续控制处理阻塞。

实施前冻结来源标识 `sensevoice_small`、识别调用和修订合同，验证窗口转写向同一话轮快照的映射。不能直接拼接相邻窗口、重复注入整个前缀，或将控制器重置当成用户话轮关闭；整轮重识别若修订文本，按新版本记录其实际可见时间。每个运行和活动话轮只采用一个权威来源，不混合两套文字，也不在话轮中热切换。后续 Nemotron 替换需单独适配，其原文前缀及回写失败行为不套用到 SenseVoice。

用户话轮使用稳定的 `turn_id`，它与 ASR 会话／generation 标识分别记录。同一用户话轮内的多次 ASR 更新、80ms 音频包、160ms 音频块及表达 micro-turn 均不创建新的用户消息。用户话轮由运行时管理，不能每次状态模型输出 complete 就重新分配标识；模型重复预测不能导致文本重复入库。

数据流为：用户音频 → SoulX-Duplug＋SenseVoiceSmall 语音前端 → Shared Context 中的版本化用户转写与状态 → Layer 0/1/2。有效用户打断额外直接到达输出运行时；后续 CoT 从 Context 反馈至前端，当前不实现条件化扩展。SoulX 控制专用归一化只生成派生副本，不覆盖 Context 中的来源转写，不调用第二个 ASR。

SoulX 原生五类用户状态另外作为状态 token 送入 Layer 1，保留其所依据的音频观察范围、ASR 版本及实际可见顺序，不拼入 ASR 转写正文。Layer 1 在自己的正常输入边界读取转写与状态：当前 turn 看到有效 `user_complete` 后才开始生成普通正式回答，状态已写入 Context 不代表在途模型已经读取。模型读取状态不创建新用户消息或独立回答调用，具体输入封装与 token 编码待后续实现时冻结。

状态输入路径与直接打断路径分开。只有活动输出期间的有效用户打断额外提交给唯一输出执行点；其他状态不进入输出运行时，不映射成 start/keep。本文的转写快照及读取方法不扩展成运行时动作接口；状态协议与输出生命周期按[架构第 2.2 节](../../research_design/architecture.md#22-前端状态与系统附和)维护。

## 2. 最小转写快照

每个版本以当前话轮的完整文本快照为准；增量仅作为优化，不能由下游把多个完整快照拼成重复文字。

| 字段 | 含义 |
| --- | --- |
| `session_id`、`turn_id` | 会话与逻辑用户话轮的稳定标识 |
| `source`、`asr_generation` | 首版来源为 `sensevoice_small`，关联前端识别生命周期；单次窗口调用另记标识，后续候选来源为 `nemotron`，同一活动话轮不切换 |
| `version`、`asr_version` | 当前话轮快照版本及所依据的前端文本版本；包含追加与修订，生命周期更新也可产生新快照版本。Nemotron 的 `asr_prefix_version` 在后续适配中映射到来源版本 |
| `text` | 当前话轮截至本版本的完整转写，保留 ASR 清理后可用文字的空格、大小写和标点，不预设版本之间满足前缀追加 |
| `assembly_status`、`coverage_complete` | 正文是否存在未对齐缺口、来源是否连续覆盖；`text` 是当前可重建假设，缺口时不能声称覆盖最新音频 |
| `asr_call_ids`、`audio_spans` | 来源调用和实际识别输入的有序音频片段，区分真实音频、填充和历史回补；不以一个首尾范围掩盖中间缺口 |
| `event_seq` | Context 的有序事件位置，供各消费者保存自己的读取游标 |
| `audio_observed_until` | 上游实际已处理音频的采样截止点；缺失时明确标缺失，不以已发送长度代替 |
| `received_at`、`published_at` | 接收更新及写入可见的单调时钟时间；记录所在时钟域，跨机不直接相减 |
| `status`、`close_reason` | `open`／`closed` 与运行时关闭原因，和语义是否完整分别记录 |

`source`、版本和时间等为运行元数据，不要求原样作为 LLM 正文。下游模型输入主要是角色为 user 的文本及必要上下文；数据来源与观察边界供运行时组装、追溯和判断过期使用。

`text` 从原始结果中分离已识别标签后整理，不经过 SoulX 专用的去附和、去标点或字符过滤；纯数字同样保留。`raw_text` 和有序标签保存在来源观察，`control_text` 是同次识别的派生副本。三种视图通过调用 ID 关联，不引入第二个权威 ASR。

## 3. 对外方法与更新规则

以下是拟实现的逻辑接口，不代表已有函数、HTTP 服务或网络协议。

| 接口 | 核心作用 |
| --- | --- |
| `publish_user_transcript(snapshot)` | 校验来源与版本，原子写入当前话轮快照及有序更新记录，返回提交位置 |
| `get_user_turn(session_id, turn_id)` | 读取该话轮最新快照及状态，支持下游取得当前完整文本 |
| `read_user_transcript_updates(session_id, after_event_seq)` | 按游标读取后续有序版本，供消费者在自己的输入边界增量消费 |
| `commit_frontend_events(events)` | 原子提交来源观察、正文更新及依赖记录，提交后通知；统一分配前端事件位置 |
| `publish_user_state(event)` | 保存原生五状态、接纳结果和实际依据，不将状态拼入正文 |
| `read_frontend_updates(session_id, after_event_seq)` | 按统一游标读取来源、正文、状态及生命周期；只读转写接口不能替代此方法 |

Shared Context 同时维护当前视图和有界可追溯记录，ASR 改写不覆盖既有事件，记录只按显式保留水位回收。转写以会话、话轮与快照版本校验，统一事件以稳定 `event_id` 幂等；同 ID 异载荷报冲突。重复投递不重复写入，旧版本迟到不覆盖新版本，新的修订事件通过更高版本发布。纯音频处理进度另记，不重复发布没有文本或生命周期变化的用户消息。

SenseVoice 窗口识别及整轮重识别可能修订文字，不满足前缀追加关系时发布完整新快照，消费者不能强行计算追加 delta。前端须记录实际使用的窗口范围与修订依据；无法可靠拼合时，将原始窗口立即写入来源观察、标记 `assembly_status=gap` 并保留最后可重建正文，不以猜测文本替代。无新增文字、未调用、未就绪与识别错误分别记录，空值不抹掉既有正文。后续 Nemotron 的现役服务对已交付前缀回写报错，替换时仍须沿用其明确失败行为，或先单独验证修订支持。

消费者分别保存游标和实际读取版本。同一版本不在同一个消费者的历史里重复注入；正在推理的调用保留自己的输入事实，后续修订在下一个输入边界可见，不回滚已经生成、提交或播放的内容。消费者暂时落后时可重新取得最新快照；若更新记录已超出有界保留范围，明确返回游标缺口并重新同步，不静默伪装为连续 delta。

## 3.1 状态事件与因果顺序

五类状态保存精确 token 字符串、源 token ID、词表 revision、原始预测和规则调整后的有效状态，以及 `accepted` 与过滤原因。源 ID 不直接作为 Layer 1 的 token ID；目标 tokenizer 须独立检查。ASR 标签与正文中的相似字符串均不具有控制权限，KV 修订中人为注入的 nonidle 不发布为新预测。

状态的 `basis` 引用已提交的来源调用、正文版本、`control_revision` 和实际音频观察边界，不能简单关联“提交时最新文字”。状态先于整轮转写返回时，立即发布状态，较晚正文另增版本，既有状态引用不倒改。Context 与直接打断使用同一事件 ID，但直接停止不等待下游读取、最终识别或日志落盘；仅有效 nonidle 进入输出执行点，完整规则见[前端设计第 8 节](asr_frontend_design.md#8-下游读取与直接打断)。

正文、状态与来源共用 `event_seq`，各消费者以一致水位读取。游标缺口后可以重取正文快照，不能仅凭最新状态补造丢失的历史 complete／打断事件。状态依据和来源记录一同按水位保留，超出保留范围明确标记，不返回悬空引用冒充完整证据。

## 4. 用户话轮结束

运行时在确认话轮交接或会话结束后关闭当前话轮，写入关闭时实际可用的最后版本，保留既有历史。`closed` 只描述该话轮记录的生命周期，不等于 ASR 文本绝对正确或用户语义完整；公开 Incomplete 音频结束后同样可以关闭测试记录，但不能因此生成 complete 金标或控制事件。

话轮关闭、ASR EOF 排空和后到转写分别记录。EOF 后结果只进入明确标注的离线／排空记录，不能回填到主在线快照冒充较早已经可见；不得丢掉关闭前已有的未完整文本。测试中的每条录音对应一个测试用户话轮，标签不参与话轮 ID 分配或在线写入。

## 5. 本轮验收与结论边界

[原质量测试](quality_test.md)保留为 617 条公开音频的 Nemotron 历史设计，首版执行配置须另行冻结。后续接口验证必须接入最小 Shared Context 存储及只读消费者替身，逐例验证写入和读取，而非只将转写写入 trace 文件。记录每个非重复 ASR 文本版本是否提交成功、消费者读到的文本是否一致、关闭快照是否保留最后在线版本，以及接收至 Context 可见的耗时；特别核查未完成话轮已有中间转写可读。

少量契约测试覆盖同 turn 多次更新、重复／乱序事件、修订或明确失败、消费者读取与重新同步、空文本以及关闭／EOF 分离。测试不加载下游 LLM，不新增语料、CoT 或播放测试；只能证明接口的数据与时序合同，不能证明模型已正确利用转写。
