# 用户话轮的 SharedContext 联合快照接口

当前阶段补充（2026-11-03）：019已由用户审核归档，030已取消原生前端800ms时长停止条件，容量与作业资源保护保持。用户已明确暂不推进后续LLM接入，031—035草案未实施归档；本文下述联合提交接口没有因归档新增状态或等待条件。

2026-11-04。NTF-017已完成本地联合提交实现与契约验收。每160ms批次在SoulX与X2均处理完成后，统一写入文本和状态token；不写原始PCM。NTF-015／016内部回调只送批次暂存器，下游读取共同快照处理五状态。[联合提交交付](../../reports/soulx/20261102-ntf017-joint-publication/README.md)和[前端设计](independent_streaming_frontend.md)为实施依据。

## 1. 每160ms联合提交

同一逻辑用户话轮以稳定session_id／turn_id定位一份当前记录，step_id标记160ms源音频批次。SoulX完成本次原生调用及其反馈、服务／reset，X2顺序完成两个80ms音频步及可能的DECODE至真实EOS，才允许一次联合写入。两路可以串行计算；任何先完成结果均只留在本批次有界暂存器。

写入内容为本批次最新X2闭合组累计正文、SoulX状态token／有效性、控制代次、服务来源及两路真实进度。Context不保存PCM、开放组子词或两路计算中的半帧。X2第一帧产生的文字等本160ms批次完成后可见；WAIT无新字仍完成本步，联合提交保留原正文，不等新词、下一组EOS或整轮识别。

联合入口在短锁内校验身份、当前批次、两侧完成及追加前缀，保留当前话轮开闭状态，再一次替换当前前端观察。读取返回完整副本，只能看到上一个或当前完整批次。不能把工作线程此前读取的整份快照回写覆盖较新生命周期或元数据。推理、网络、日志和消费者不持该锁。

严格顺序为两路完成→联合提交成功→允许下一批次模型推进；写入失败即终止样本，不释放下一步。输入生产者持续按真实时钟到达。所有状态提交后均可供下游读取；消费者无需ack。仍不增加历史正文、版本查询、patch或无界待发布队列。

## 2. 当前记录与时间边界

| 字段组 | 含义 |
| --- | --- |
| session_id／turn_id／status | 稳定身份与open／closed，内部reset不创建新话轮 |
| step_id／batch_published_at | 最新已联合提交的源批次和原子写入时间，不是历史正文版本 |
| source／text／committed_groups | 来源固定x2_streaming_asr、EOS闭合组累计全文及已提交组数，不含子词草稿 |
| text_observed_until／text_available_at／text_published_at | 产生当前正文的真实观察上界、实际闭合拼接时间和首次联合发布该正文的时间；无新字时不刷新 |
| state_token／state_accepted／controller_generation | 本批次原生五状态、有效性与控制代次；service_state和完成来源分别记录 |
| state_processed_until／state_observed_until／state_available_at／state_published_at | 本批次状态的真实主块、观察边界、原始可用时间及联合发布时间，padding另计 |
| asr_processed_until／asr_observed_until／asr_progress_available_at | X2本批次最后实际完成80ms步的真实处理／观察边界及实际可用时间；WAIT也推进 |
| 完整性 | 传输／整理缺口、后端明确尾部状态；缺乏可靠尾词信号时为unknown |

有新正文时，text_published_at与本批次state_published_at均取batch_published_at；各自available_at保留模型实际完成时刻。正文不变时保留此前text_observed_until、text_available_at和text_published_at，继续推进当前批次、状态及ASR进度。可用到发布的等待必须包含本160ms屏障，不能回填成提前可见。

processed_until表示SoulX真实主块截止。两侧同一step_id不证明实际观察范围相同：startup／reset padding、回看及前瞻沿用[采样映射](independent_streaming_frontend.md#22-ntf-015016采样映射与实现冻结)。ASR处理／观察范围不保证此前所有词已发射，WAIT不等于静音或句子结束。

## 3. 生命周期与失败

模型侧只保存当前批次的一条控制回执、两条80ms进度和至多两组闭合正文。X2每步进度仍在内部诊断中分别记录，供后续联合提交校验；收包、特征预取不算解码完成。

reset不结束X2、不清空正文、不改变全局step_id；原生SenseVoice整轮识别仍属控制诊断，不覆盖正文。complete不触发ASR结束、额外重识别或final标记。EOF只按实际存在的终止帧验收完整批次，不补造状态或EOS；开放组、未处理PCM和drain保留在诊断中，不回填在线正文。

任一路错误、缺失／重复／过期回执、Context校验／容量失败或关闭／取消均不得提交半帧，上一完整快照保留，失败样本显式停止。关闭后拒绝迟到回调，旧结果不能重开话轮。原子关闭可更新生命周期元数据，但不能在两路未完成时单独刷新文本、状态token或ASR进度。

## 4. 下游消费与complete

Layer 1在合法输入边界读取已联合提交的文本和状态；Layer 2从同一快照取得正文，与真实对话历史及上一轮analysis组成[文本输入](../layer2/protocol.md#2-每周期接收什么)，不带入独立任务资料、SoulX或助手输出状态。后续思考反馈仅注入正常结束时的result，中间analysis留在Layer 2。五状态统一采用本160ms批次两路完成及联合提交门槛；已提交的有效complete携当前正文直接供Layer 1在当前turn使用。

后续 [Layer 1 持久 Context](../layer1/protocol.md)需要逐批接收新增正文与新发布状态，生成后将实际输出 token 保留在自己的模型 Context。新增正文从累计 X2 文本中按已消费位置取得；同一批不重复注入，同值状态若属于新批次仍保留批次身份。该持久 token 历史与本接口的最新联合快照分开，不能把累计全文每周期重新追加。

Layer 1 首轮常规周期为三拍 480ms，在消费侧按顺序读入三个完整前端输入块后解码，保留组内全部状态。前端联合发布和唯一输出执行点对有效打断的消费仍以 160ms 批次为粒度，不等待三拍；Layer 1 分组不改变本接口的两路推进屏障。

当前冻结映射下，X2完成本批次两个80ms步时，其真实处理截止覆盖SoulX状态观察截止，现有DECODE已解至EOS，闭合组正文也在同次提交。真实范围继续分别记录，018／019核对该关系，不按相同步号推定对齐；若后续模型或采样映射改变，先修订并验证合同。

一次联合写入不创建新用户消息，不自动回改在途输入、KV、生成历史或已听内容。前端不直接操作输出，下游从共同快照处理有效打断，保留唯一输出执行点、停止幂等和实际停播确认。尚未发布的原始complete不能供下游提前使用。

后续Layer 1接入须增加有界逐批交付与消费位置，处理慢读遗漏、过期complete及重复回答；当前接口仍未实现可靠事件投递，也未新增队列或ack。本次只更新合同，不修改前端实现。同步完成不能证明尾词齐备；尾部保持unknown，记录complete联合发布后才到达的文字，不增加空步、固定延时或强制EOS规则。EOF padding不能冒充真实覆盖。

官方取消与历史整理案例见[运行时分析](completion_runtime_analysis.md#4-取消后怎样处理-context)。前端联合快照与下游真实生成／已播账本分开：首音前取消按同一用户片段恢复，实际播放后按已播事实处理续说；不得把累计X2全文重复追加，或将未播助手生成写成已说事实。该分组与输出层仍待接入，不是本接口已实现的能力。

## 5. 验收与迁移

NTF-017覆盖两种完成顺序、暂存不可见、一次联合提交、WAIT不刷新正文时间、提交成功后才推进、并发读取／关闭和失败无半帧。NTF-018／019记录原始计算、屏障等待、联合发布时间及读取时间，不用发布延迟伪装原始状态改善。

NTF-017已迁移SharedContext及三份适配模块、必要测试与同路径说明，未运行真实模型。X2开轮固定为joint发布，话轮内不能切换模式。Context仅保存当前联合快照和话轮开闭状态。X2正文只向Context提交，两路音频对齐按实际采样窗口核验。
