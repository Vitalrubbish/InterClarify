# TextTurn：FDB 两臂各50条跨数据集测试计划

更新：2026-10-25。状态：计划已交付，尚未抽样冻结、实现新入口或提交作业。按用户最新要求，将两臂结果分别列为[TT-005 接话覆盖与延迟](../../issue/TextTurn/tt_005_fdb_turn_taking.md)和[TT-006 停顿介入与归因](../../issue/TextTurn/tt_006_fdb_pause_handling.md)，替代此前仅归入 TT-004 的安排；测试范围、协议与预算不变。两项直接交付实验结果，必要工程工作并入实施，不单列确认任务。

## 1. 目的与结论边界

使用FDB的Smooth Turn Taking与Pause Handling各50条录音，检查当前UltraChat派生数据训练出的控制器在外部录音上的接话与停顿表现。用FDB已提供的时间标注建立可核验的行为评分，避免再次用“ASR整段逐字匹配”代替事件边界，也不将整类样本统一记为未知。

本轮评价真实Nemotron ASR与真实控制器的影子动作，不生成回答、不运行TTS或播放器。由此可以报告接话决策覆盖和延迟，不能报告官方音频输出TOR、回答质量或实际开口延迟。

用户已明确：完整语义后出现一个空窗可以接话，短促系统附和可能更合适。因此FDB标注区间内的start首先记作“FDB持轮规则下的介入”，不能未经分析便称为语义判断错误；完整句不自动等于用户让轮，原始录音后面还有内容也不能单独否定当前接话。FDB规则成绩与当前交互策略的解释分开保留。

## 3. 历史使用与模型冻结

FDB并非项目从未使用的测试集：[历史两轴评测](../../../reports/fdb/20261021-full-two-axes-r4/README.md)已运行全部119条Smooth，历史25条子集也涉及Pause。因此本轮定位为**当前TextTurn候选的跨数据集测试**，不称项目级全新盲测。逐条记录已知历史使用，无法恢复的标为未知；不按历史成功／失败挑录音。

只使用 `tt-002-20261025-r1/best`：Qwen3-0.6B、full第2轮，adapter SHA256为 `32f5493835a1b21294a3b862e38da85f7d052bbc93dbf12a81c42436e144b5d17`。冻结基模、tokenizer、Nemotron、依赖、源码、清单和评分规则。现有候选未训练system backchannel，start不能解释为系统附和。

本轮不更换检查点、不调阈值、不调整训练配比。FDB音频、正文、标注和ASR trace不进入训练；结果用于归因和回归，后续参数选择仍依赖开发集，不能反复用这100条挑最优候选。

## 4. 运行协议

原录音按80ms包、真实时钟发送给Nemotron EN160；转写变化立即写Shared Context，每三个真实解码完成步骤形成480ms控制窗，整窗无新增文字才输入no-voice。保持现有归一化规则，不新增VAD、固定等待或ASR延迟补偿，标注和参考转写不传给控制器。

两臂采用固定Listen影子观察：保留实际ASR累积文本，助手当前表达为空；记录start但不执行、不切换Speak、不伪造助手回复。这样可以完整观察同一录音的多个持轮区间，避免一次start后的模拟播放掩盖后续机会。此模式只评价Listen下的动作判断，不冒称闭环对话测试。每条录音独立会话，控制请求至多一个在途、一个待处理快照，合并范围和输入缺口显式记录。

每条原音频后统一追加5秒在线静音观察，随后才发送EOF。录音时长内结果与尾窗结果分别列出；尾窗允许观察文件末尾之后的动作，但不是原录音内容，也不把EOF或解码排空当成让轮信号。主报告明确控制器的观察范围包含这段尾窗，不能混同历史严格等长输出的官方评测。

## 5. 评分：先固定事件，再运行模型

### Smooth Turn Taking

实施冻结前核对所用FDB版本的事件定义及作者评分代码。现有历史规则采用`turn_taking.json`第一项时间区间的起点作为交接参考；本轮按该规则冻结，不在看到结果后改用另一端点。

- 每条录音统计首个start、参考前介入、参考后start及未接话。首个start早于参考时刻时保留有符号负延迟，不能归零掩盖；后续重复start不增加独立成功数。
- 主时序指标是相对FDB音频参考的决策延迟：`动作完整返回时刻－参考点所在音频包的实际发送时刻`。以实测发送时钟映射标注时间，保存调度滞后和80ms包粒度的量化范围，不伪造包内真实到达时间，也不把名义160ms进度当成真实音频时钟。
- 报告参考后1000ms内start覆盖、整个观察期内start覆盖、参考前介入率，以及延迟P50/P95。及时命中要求没有此前的FDB规则介入，失败及未命中保留在50条分母中。
- 此1000ms包含ASR延迟，是外部音频参考下的链路诊断，与原方案“动作依据已可见后1000ms”的指标分别命名，不能相互替代。ASR语义依据首次可见若尚无可靠对齐，则该项填null，不影响已有FDB事件时序的逐例评分。

### Pause Handling

按`pause.json`的每个半开区间`[start,end)`统计是否出现start。每条录音任一区间发生介入，即计为一条FDB规则介入；全部区间都被充分观察且没有介入才算正确保持。另报逐区间结果、区间长度和落入区间的控制窗数量。

同时记录返回时刻所在的实际音频区间，以及该调用所依据控制窗覆盖的音频区间，区分“停顿中做出的决定、续说后才返回”和“当前用户已经续说的输入”。队列积压和合并不能通过丢掉中间区间换取正确保持。

不足480ms的停顿仍保留在计划分母，单列“没有控制观察落入该区间”；这类缺少观察不是误start，也不能当成功等待。无调用、异常、缺文件和缺失区间分别计数，报告已判定结果及计划分母上的保守上下界。

### 语义解释与运行指标

全部评分保留两层事实：FDB预设事件下的时序符合情况，以及当前ASR输入是否足以支持动作归因。对标注持轮区间中的介入，核查当前前缀、空窗和上下文，区分明显未完成表达、完整语义后的短暂停顿、ASR缺失及其他情形。核查不改FDB主分母，不把后续续说直接当作当前语义不完整的证据，也不修改模型重新跑到通过。

控制耗时独立报告输入就绪至返回的P95，包含排队与HTTP；另列480ms聚合等待、转写发布及Context读取时刻、合并比例、超时和尾窗／EOF状态。原始音频参考延迟不能称为单纯模型耗时，控制返回不能称为扬声器开口。

各臂给出分子／分母和Wilson95%区间。50条属于小规模跨集诊断，不能替代原计划每类至少100个独立场景组的完整验收，更不能由这两臂宣称附和、用户打断或system backchannel已通过。

## 6. 实施步骤与预算

1. 在远端只读核查资产、标注定义、历史来源和剩余预算，冻结50＋50清单与规则；实现少量边界测试，覆盖负延迟、多个停顿、短区间无观察、超时及分母保留。
2. 固定当前候选与服务，先用不计入100条的录音做最少量接口冒烟，只按运行及Context一致性核查，不按模型质量换样本或改规则。
3. 单作业串行回放100条，逐例落盘；失败不删除、不用新录音补位。确需修复运行错误时保留原结果、说明修复并单独编号，不静默覆盖。
4. 服务停止后离线评分、核对所有计划分母，交付中文结果与逐例证据；保留早接话、晚接话、遗漏和运行失败。

全部模型执行走远端调度和已有conda环境。最多1×24GiB GPU、8CPU、32GiB RAM、worker≤2、一个活动作业，显存22GiB停止线。本次最多2小时；启动前从实际作业记录核对本轮累计8GPU小时的剩余额度，若不足则缩短作业上限或不启动，不自动扩容。新增资产沿用10GiB上限、报告2GiB上限、启动可用盘至少30GiB；尽量只读引用现有音频，不复制模型。触限停止并保留证据。
