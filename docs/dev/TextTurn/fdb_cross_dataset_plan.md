# TextTurn：FDB 两臂各50条跨数据集测试计划

更新：2026-10-25。状态：计划及工作单已交付，尚未抽样冻结、实现新入口或提交作业。按用户最新要求，[TT-005](../../issue/TextTurn/tt_005_fdb_turn_taking.md)统计ASR停止更新后的模拟Speak及start样本比例，[TT-006](../../issue/TextTurn/tt_006_fdb_pause_handling.md)统计ASR停止更新前连续至少3周期Speak的样本比例。为支持这些指标，原固定Listen方案改为模拟Listen/Speak状态转移；Turn Taking使用测试流程自动拼接的5秒静音，不重复添加，Pause Handling不拼接静音。数据规模、候选与预算不变，必要工程工作仍并入结果交付。

## 1. 目的与结论边界

使用FDB的Smooth Turn Taking与Pause Handling各50条录音，检查当前UltraChat派生数据训练出的控制器在外部录音上的接话与停顿表现。主指标以实际ASR转写最后一次更新及模拟Speak状态为依据，不再以FDB标注区间内是否start或参考后1000ms覆盖作为本轮主评分。FDB时间标注保留用于辅助解释。

本轮使用真实Nemotron ASR与真实控制器，执行模拟Listen/Speak状态转移及既有模拟生成／播放生命周期，不调用回答模型、TTS或真实播放器。统计结果描述影子状态和控制动作，不能报告官方音频输出TOR、回答质量或实际开口延迟。

用户已明确：完整语义后出现一个空窗可以接话，短促系统附和可能更合适。因此FDB标注区间内的start首先记作“FDB持轮规则下的介入”，不能未经分析便称为语义判断错误；完整句不自动等于用户让轮，原始录音后面还有内容也不能单独否定当前接话。FDB规则成绩与当前交互策略的解释分开保留。

本轮不更换检查点、不调阈值、不调整训练配比。FDB音频、正文、标注和ASR trace不进入训练；结果用于归因和回归，后续参数选择仍依赖开发集，不能反复用这100条挑最优候选。

## 4. 运行协议

原录音按80ms包、真实时钟发送给Nemotron EN160；转写变化立即写Shared Context，每三个真实解码完成步骤形成480ms控制窗，整窗无新增文字才输入no-voice。保持现有归一化规则，不新增VAD、固定等待或ASR延迟补偿，标注和参考转写不传给控制器。

两臂每条录音从Listen开始，start切换到模拟Speak，stop或模拟播放完成后回到Listen，keep维持当前状态。沿用现有每480ms模拟生成8 token、生成完成与播放完成分离的生命周期；模拟助手内容及播放参数在运行前固定，不从FDB参考转写或标注生成，也不为了满足连续3周期而强制维持Speak。记录每个控制周期的输入状态、返回动作、应用后状态及生命周期变化。每条录音独立会话，控制请求至多一个在途、一个待处理快照，合并范围和输入缺口显式记录。

两臂的音频结束方式不同：

- **Turn Taking**：测试流程已经自动在原音频后拼接5秒静音，直接消费这段静音，不再追加第二段静音或音频结束后的人工 `<no voice>` 控制周期。拼接静音仍经过Nemotron，正常无新增转写的完整控制窗按既有规则形成no-voice输入；5秒发送完成后结束输入。
- **Pause Handling**：关闭末尾静音拼接，只发送原始录音；原音频结束即结束输入，不额外补静音、no-voice或用于凑满连续周期的观察。

两臂均记录原音频结束、实际输入结束及EOF时刻。EOF／解码排空不当作正常静音，不额外制造控制周期；在途调用保留真实完成时刻，不按文件结束时间提前截断或伪造返回。Turn Taking的5秒静音是测试附加观察，Pause中的原始停顿保持不变。

## 5. 评分：ASR更新边界与模拟Speak

### 共同统计口径

每条录音记录在线ASR转写实际变化并发布到Shared Context的时刻；相同文本的重复推送不算更新。以本次有效在线观察中最后一次转写变化时刻为 `t_last_asr_update`，包含正常在线转写修订，不以原音频结束、FDB时间标注或EOF替代。该边界只在离线统计时确定，不作为控制器输入或运行中的让轮信号。

一个周期指三个真实Nemotron解码完成步骤聚合的完整480ms控制周期。Speak按该周期控制动作应用后的模拟状态统计，使用实际时刻判断其位于最后更新之前或之后；同时保留输入状态和动作，方便复核。EOF不足三步的残窗单列，不计为完整周期。合并窗不拆成多个已观察周期，控制缺失或无法恢复的状态缺口不能跨越后拼成连续序列。

各比例按录音计数，每条最多贡献一次，计划分母每臂50条。无有效ASR转写、运行失败或关键trace缺失时标为未知，不能当作正常未命中；报告命中／已确认未命中／未知、计划分母上的保守上下界，并对可判定样本比例给出分子／分母及Wilson95%区间。无ASR文本的样本不能把启动时刻冒充最后更新时刻。

### Smooth Turn Taking

主指标为ASR不再更新之后：

1. **模拟Speak样本比例**：`t_last_asr_update`之后，至少一个完整控制周期处于模拟Speak的录音数／50。
2. **start样本比例**：`t_last_asr_update`之后，至少一次控制输出为start的录音数／50，按动作完整返回时刻归属；重复start只计一条录音。

统计截止到本次输入对应的在线控制观察完成，包含已自动拼接的5秒静音所产生的正常周期，不在截止后额外补no-voice。最后一次ASR更新前已经进入Speak、之后仍处于Speak，可以命中第一项；若之后没有新的start，则不命中第二项。两项分别报告，不混成一个接话成功率。

### Pause Handling

主指标为**ASR不再更新前连续至少3周期Speak的样本比例**：在 `t_last_asr_update`之前，出现过连续3个及以上完整控制周期均为模拟Speak的录音数／50。序列中所有计入周期的状态记录时刻都须严格早于最后更新时刻；跨越该边界的部分不能补足3周期。

每条录音另存最后更新前的最长连续Speak周期数及命中序列的起止时刻。连续1或2周期不命中，任一Listen状态或不可恢复的观察缺口中断连续计数；同一录音多次命中只计一次。只使用原始录音产生的在线观察，不拼接5秒静音，也不将末尾排空或额外no-voice计入。该指标统计持续Speak行为，不直接把每个命中都称为语义错误。

`pause.json`的区间、区间长度及观察覆盖仅用于解释命中序列；不再以“任一区间出现一次start”代替本项主指标。

### 语义解释与运行指标

主表使用上述三个样本比例。FDB时间标注、当前ASR前缀、空窗及上下文作为辅助证据，解释明显未完成表达、完整语义后的短暂停顿、ASR缺失及其他情形。语义解释不改变主指标或50条计划分母，不把后续续说直接当作当前语义不完整的证据，也不修改模型重新跑到通过。

控制耗时独立报告输入就绪至返回的P95，包含排队与HTTP；另列480ms聚合等待、转写发布及Context读取时刻、合并比例、超时和尾窗／EOF状态。原始音频参考延迟不能称为单纯模型耗时，控制返回不能称为扬声器开口。

50条属于小规模跨集诊断，不能替代原计划每类至少100个独立场景组的完整验收，更不能由这两臂宣称附和、用户打断或system backchannel已通过。

## 6. 实施步骤与预算

1. 在远端核查资产、历史来源和剩余预算，冻结50＋50清单、模拟生命周期及上述评分规则；少量边界测试覆盖最后ASR更新前后、Speak与start分离、连续2／3周期、跨边界序列、两臂静音配置及未知分母。
2. 固定当前候选与服务，先用不计入100条的录音做最少量接口冒烟，只按运行及Context一致性核查，不按模型质量换样本或改规则。
3. 单作业串行回放100条，逐例落盘；失败不删除、不用新录音补位。确需修复运行错误时保留原结果、说明修复并单独编号，不静默覆盖。
4. 服务停止后离线评分、核对所有计划分母，交付三项主比例、中文结果与逐例证据；保留未命中、未知及运行失败。

全部模型执行走远端调度和已有conda环境。最多1×24GiB GPU、8CPU、32GiB RAM、worker≤2、一个活动作业，显存22GiB停止线。本次最多2小时；启动前从实际作业记录核对本轮累计8GPU小时的剩余额度，若不足则缩短作业上限或不启动，不自动扩容。新增资产沿用10GiB上限、报告2GiB上限、启动可用盘至少30GiB；尽量只读引用现有音频，不复制模型。触限停止并保留证据。
