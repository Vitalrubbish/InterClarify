# TextTurn 第一阶段：训练与验收方案

更新：2026-10-24。状态：设计方案，尚未训练。目标是得到一个独立的文本话轮控制器，先解决普通接话、用户打断、用户附和及停顿处理，后续再学习结合 Layer 2 的 CoT 决策。

本次按用户修订：stop 只表示用户打断系统；观察粒度由 600ms 改为匹配 Nemotron EN160 的 160ms 解码步骤；通过门槛放宽为首轮可行性筛选，不作为部署保证。

## 1. 基模与输入输出

首轮使用 **[Qwen/Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B)**，采用通用后训练权重，不使用 `-Base` 或 XTurnix 的专项权重。关闭模型自身 thinking，保留对话理解能力，只训练控制动作。0.6B 优先考虑高频调用成本；1.7B 留作数据可靠但复杂上下文能力不足时的后续候选，不在首轮同时训练。

输入为当前可见对话、累计用户转写、当前助手表达与真实 Listen/Speak 状态，以及本观察窗的新增文本或 `no-voice`。第一阶段 CoT 为空；模板固定保留分析输入位置，第二阶段填入实际已发布的 CoT，不要求控制器生成推理正文。

| 系统状态 | 可选动作 | 含义 |
| --- | --- | --- |
| Listen | keep / start | 继续等待／开始一轮表达 |
| Speak | keep / stop | 继续表达／因用户打断而停止并让用户说 |

**stop 仅用于用户打断系统。** 系统自然说完由 Layer 1 的生成结束、队列排空和真实播放结束事件驱动运行时返回 Listen，不产生 stop 训练标签，也不计用户打断成功。生成结束而缓冲音频尚在播放时仍保持 Speak，用户此时打断仍可输出 stop。

新增三个独立动作 token，使用新 tokenizer 编码，不复用旧 DuplexCascade 的数值 ID；`no-voice` 也按新 tokenizer 注册并初始化。推理只比较当前状态的两个合法动作分数，取最高值，不生成回答或解释；运行时是唯一执行点，模型输出不等于已经开口或停播。

**观察节奏：**匹配现有 Nemotron EN160，每个名义 160ms 解码步骤完成后立即发布本步新增文本或 `no-voice`，写入 Context 后触发判断；不再等独立的 600ms 窗口，也不额外攒满 160ms 才处理已经返回的结果。80ms 音频传输包与 160ms 解码块分开记录，启动缓冲、lookahead 和实际解码耗时仍按实测计入。分块依据为[已锁定模型的配置说明](https://huggingface.co/nvidia/nemotron-speech-streaming-en-0.6b/blob/ebe59e5a817142986528bbbee5dba8db7b38ed50/README.md)：`[70,1]` 使用两个 80ms 帧，即 160ms。

**静音约定：**每步没有新增 ASR 文本就输入 `no-voice`，作为带 ASR 延迟的静音；不额外增加 VAD、词稳定等待或延迟补偿。静音不直接固定为 start，模型依据已有内容和状态选择动作。ASR 报错或连接失败单独记录，不伪装成正常静音。

当前服务主要在文本变化时通知；后续适配要暴露包括空文本在内的解码步骤完成事件。不能把音频已接收或已读取当作解码完成。160ms 是名义观察粒度，不保证文字每 160ms 都返回；该事件接口需先核验，再冻结训练／在线协议。单会话最多一个在途控制请求和一个待处理最新快照，来不及处理时合并尚未开始的观察，保留累计文本、覆盖步骤和合并数，不无限排队、不强制每步取消在途推理。

## 2. 训练数据如何构造

### 先复用旧 UltraChat 素材

旧 Git 配置记录了 `stingning/ultrachat@f220fe796ce3ed62fbe1681b45ce6cbc9c6cabe0` 的 1,000 条训练、200 条开发和 300 条测试对话，以及 600ms 事件计划。历史实现可从 `38315aa` 的父提交追溯；当前只有代码／报告证据，原始产物、来源清单和审核结果需要重新验真，不假定已完整恢复。当前上游别名跳转到 [openbmb/UltraChat](https://huggingface.co/datasets/openbmb/UltraChat)，不能因名称变化悄悄更换数据版本。

复用原始对话、来源 ID、去重组与语义事件位置；重新构造 160ms 时序、控制标签、模型输入和 tokenizer 编码，删除旧回答正文的训练目标。旧 `no-voice` 含义保留，但不能原样沿用 600ms 分块。

首轮模拟数据将非空片段改为每步约 1—2 个当前 tokenizer 的 token，保留完整字符边界，不额外等完整单词；没有文字的步骤为 `no-voice`。这是构造起点，不冒称真实发射规律，有 Nemotron trace 时按实际增量和返回步骤构造。旧停顿先还原为持续时长，再换算成 160ms 步数，原 600ms 停顿约对应 4 步，不能简单将一个旧窗口改名为 160ms。换粒度后只重新采样必要快照，避免等待样本成倍支配训练。

| 场景 | 样本构造与动作 |
| --- | --- |
| Smooth Turn Taking | 保留用户请求、陈述和回答；表达未完成时 Listen/keep，内容已完整且让轮后的静音窗 Listen/start |
| Interruption | 在助手表达期间加入相关的用户打断；前缀已经表达停止、纠正条件或改变请求时 Speak/stop；尚不足以判断的前缀继续 keep 或标未知 |
| 用户 backchannel | 在助手表达期间加入允许其继续的理解、同意及短确认，标 Speak/keep；补充同一词语在不同历史下需要让轮的对照 |
| Pause Handling | 在用户表达内部插入一个或多个 `no-voice` 窗，持轮期间 Listen/keep；保留后续续说，与真正让轮的 start 对照 |

额外保留系统自然完成的负例：无用户打断时，最后仍在播放的步骤标 keep，真实播放结束后由运行状态变更为 Listen。旧事件中若把回答结束与用户打断混用，重建时分开。

每条训练样本是一个决策快照：来源与事件 ID、可见历史、用户文本、助手可见表达、Listen/Speak、当前窗输入、目标动作。训练控制器看不到未来用户续说、尚未生成的助手回答或未来 CoT。Speak 状态与播放历史在合成素材中明确标为模拟。

完整陈述／陈述式回答至少占训练 start 机会的三分之一。附和扩充上下文和表达，不能只重复 `yes/okay/right/I see`。截断位置、原文最后一个词或下一条用户消息，均不能单独决定 keep/start/stop；审核只依据当时可见内容，歧义保留为未知，不强行凑标签。人工／辅助审核及其范围分别记录。

### 规模、文本处理与隔离

先从旧训练对话抽取最多 2,000 个快照做机制试训；方向成立后，首轮完整候选仍限于 1,000 个训练对话、最多 10,000 个审核快照，不自动扩到全量 UltraChat。训练按四类场景分层采样，控制长对话和重复等待窗口的占比，不把帧数当成独立场景数。

对最后可见用户文本统一移除末尾句读，所有类别用同一规则；保留内部标点、小数和缩写，禁止用有无句号提示标签。后续验证使用 Nemotron 实际文本，原始转写保留，控制输入处理另记。

先按原始对话及近重复／模板组划分，再构造分块、改写和停顿。同源派生不跨 train/dev/test。旧测试若已用于调参，则从未使用来源补足独立测试；旧材料只能作回归集。目标保留 200 个开发、300 个独立测试对话，四类测试各至少覆盖 100 个不同场景组；同组在每类只计一次，跨类数量不相加冒充更多独立对话，不足则报告证据不足。FDB、FLEURS、公开 Easy Turn 测试资料不进入训练或标签生成。

## 3. 怎么训练

采用监督微调，只监督当前动作 token；历史、状态、用户正文、`no-voice` 和将来的 CoT 输入不计算预测损失。首轮不联合训练 Layer 1/2，不优化回答质量或训练 ASR。

| 配置 | 首轮起点 |
| --- | --- |
| 参数更新 | 冻结基模，LoRA rank=16、alpha=32；同时训练新动作 token 的嵌入及输出参数，以及新增 `no-voice` 的输入嵌入 |
| 优化 | AdamW，学习率 `1e-4`，warmup 5%，最多 2 epoch，开发集选最佳一次候选 |
| 序列与批次 | 最大 2,048 token，micro-batch=1，梯度累积 16，BF16、梯度检查点 |
| 超长与保存 | 超长单例明确排除并计数，不静默删掉关键历史；最多保存最佳及最终两个 adapter，不复制基模 |

这些是拟用起点，资源探针后在正式训练前冻结，同时锁定模型 revision、tokenizer、依赖和随机种子；不在独立测试上挑参数、阈值或模型。先核验极小批次能正确学习动作、输入损失已屏蔽和保存重载一致，再受限试训；不把小批次拟合当作质量通过。新增 token 的保存／加载和状态内合法动作约束必须核验。

机制试训后，仅在开发集同条件比较优于未专项训练模型、且没有明显误抢话／误停回归时，才考虑完整候选。独立测试前冻结一个候选和全部评分规则，不因测试不佳自动再训。

## 4. 通过门槛

先做独立文本事件回放，再在同一批可获取语音的测试场景上运行 Nemotron＋控制器影子回放。没有语音的合成场景只能证明文本阶段结果，不能宣称在线门槛通过；本轮不恢复已取消的旧评测作业。

质量按独立机会计算，正常接话／用户打断在允许动作依据的输入已可见时刻后 1,000ms 内返回才算及时命中；合成轨迹使用明确记录的发布时刻，在线轨迹使用实际 ASR／Context 可见时刻。该锚点先于后续控制排队，不能移到请求开始后隐藏等待。任一禁止区间出现错误动作，则该机会失败；大量正确 keep 不稀释一次误抢话或误停。

| 项目 | 第一阶段通过线 |
| --- | --- |
| 正常接话 | 及时 start 机会覆盖≥80%；完整陈述／陈述式回答单独覆盖≥80% |
| 停顿处理 | 持轮停顿机会中，任一次误 start 的比例≤15% |
| 用户附和 | 附和机会中，任一次误 stop 的比例≤15% |
| 用户打断 | 及时 stop 机会覆盖≥80%，自然完成不计入分母或成功数 |
| 控制耗时 | 同一硬件、输入≤2,048 token 时，从输入就绪到动作完整返回的 P95≤500ms，包含排队、调度和传输 |
| Context 接口 | 所有非重复转写版本正确写入并可读；同 turn 不重复入库、旧版不覆盖新版，空文本及关闭事件不丢失 |
| 运行可靠性 | 正式计划样本处理成功率≥95%，队列有界；报告合并比例及延迟，不以丢词换取速度 |

1,000ms 的及时覆盖与 500ms 的控制 P95 是放宽后的首轮预算，均不是实际停播或可听回复保证。160ms 观察按解码完成触发，不另外叠加固定观察等待；ASR 本身的延迟接受且不补偿，单列测量。不得把未计 ASR 的控制耗时称为音频端到端延迟；允许动作窗口只供离线评分，不作为在线输入。

四类质量线必须分别满足，同时报告分子／分母、95% 区间、陈述句数量和失败／未命中。失败不算命中，未完整观察的样本不算正确等待，缺失延迟为 null。满足点估计且样本充足记“第一阶段初筛通过”，不据有限样本保证部署错误率；任一项未达标或测试来源不独立，记录未通过／证据不足，不用平均准确率代替。

公开英文 Easy Turn 的 617 条可另报完成／未完成诊断，但它不能替代四类场景验收，不据其结果调参。训练 loss 下降、合成集高分或更频繁 start，都不足以通过。

## 5. Shared Context、第二阶段与执行边界

Nemotron 每次文本更新先按稳定的 `turn_id` 写入 Shared Context；下游取得最新快照或按游标读取更新，无需等 start。同一轮多个快照不能重复追加为正文。`no-voice` 是控制观察事件，不向用户转写文本填入虚构词语。转写版本、消费者实际读取版本、关闭及 EOF 分别记录；沿用旧[接口设计](../SoulX-Duplug/shared_context_interface.md)中的版本与读取原则，但不依赖 SoulX 音频同步或完整实现任意 ASR 回写。

第一阶段通过后，从同一检查点训练 ASR＋CoT 控制，混入普通控制样本防止退化。Layer 2 只发布分析，等待与介入仍由控制器学习；CoT 缺失时继续处理接话与用户打断。本轮不预设第二阶段已通过。

本地与远端均用 conda，真实训练和模型测试只在远端执行。最多 1×24GiB GPU、8 CPU、32GiB RAM、1 个活动作业、worker≤2，显存停止线 22GiB；单作业≤4 小时，首轮累计≤8 GPU 小时，新增资产≤10GiB、报告≤2GiB、启动可用盘≥30GiB。触限停止，不自动扩容或增加试验。

交付保持精简：数据来源／切分和审核清单、训练配置与模型版本、adapter、逐例结果和一份中文报告。后续依次核对旧数据 → 重建控制样本 → 受限试训 → 独立验收；实施按用户明确指令建立工作单，代码、配置和少量必要契约测试配套同路径中文说明。本次仅撰写方案，不启动训练。
