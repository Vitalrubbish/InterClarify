# TextTurn 第一阶段：训练与验收方案

更新：2026-10-25。状态：TT-001正式文本数据已冻结归档，TT-002训练及TT-003接口已交付归档，TT-004评分v2已修复并重评，接话语义标注覆盖不足，整体证据不足。目标是得到一个独立的文本话轮控制器，处理普通接话、用户打断、用户附和及停顿；后续再学习 Layer 2 的 CoT。工作仍按 [TT-001—004](../../issue/TextTurn/README.md)推进。

2026-10-25新一轮改造合同见[TT-010](../../issue/TextTurn/tt_010_asr_update_yield_dataset.md)：Speak下首个可判定为非backchannel的有效ASR更新监督stop，不等待停止词或完整句；短附和keep、歧义前缀保留未知，禁止用未来全文反推当前标签。同步论证音频播放完成后由运行时注入finish输入标记及start输出生命周期闭环。下方数据构造和token集合描述已冻结旧版本，不代表新数据已实施；TT-008已按其旧合同完成并归档。

本次按用户修订，将控制观察窗改为 **480ms**；User 非空片段每窗随机 1—2 token，Assistant 按文本生成设置为每窗 8 token。生成完成、音频播放完成及用户下一轮开口前等待分开模拟。此前 160ms 控制窗约定被本次替代，底层 Nemotron EN160 解码配置保留。

## 1. 基模与输入输出

首轮使用 **[Qwen/Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B)**，采用通用后训练权重，不使用 `-Base` 或 XTurnix 的专项权重。关闭模型自身 thinking，保留对话理解能力，只训练控制动作。0.6B 优先考虑高频调用成本；1.7B 留作数据可靠但复杂上下文能力不足时的后续候选，不在首轮同时训练。

输入为当前可见对话、累计用户转写、当前助手已生成文本、Listen/Speak、本窗新增用户文字或 `no-voice`、连续空观察窗数和当前助手生成完成状态。第一阶段 CoT 为空。已生成正文不等于已播放正文；播放是否完成由运行状态决定。

| 系统状态 | 可选动作 | 含义 |
| --- | --- | --- |
| Listen | keep / start | 继续等待／开始一轮表达 |
| Speak | keep / stop | 继续表达／因用户打断而停止并让用户说 |

**stop 仅用于用户打断系统。** 系统自然说完由 Layer 1 的生成结束、队列排空和真实播放结束事件驱动运行时返回 Listen，不产生 stop 训练标签，也不计用户打断成功。生成结束而缓冲音频尚在播放时仍保持 Speak，用户此时打断仍可输出 stop。

新增三个独立动作 token，使用新 tokenizer 编码，不复用旧 DuplexCascade 的数值 ID；`no-voice` 也按新 tokenizer 注册并初始化。推理只比较当前状态的两个合法动作分数，取最高值，不生成回答或解释；运行时是唯一执行点，模型输出不等于已经开口或停播。

**观察节奏：**控制器使用名义 480ms 窗口，聚合 Nemotron EN160 的三个解码完成步骤；ASR 每次新增转写仍立即写 Shared Context，不等控制窗关闭。窗内累计新增文字，整窗无新增文字才输入 `no-voice`；控制窗关闭后触发判断。80ms 音频传输、160ms 解码和480ms控制窗分别记录。480ms 带来的窗内等待是新增控制延迟，必须实测，不能声称保持原来每160ms即判断的延迟。EOF 不足三步的尾窗单独关闭并记录覆盖范围。

**静音约定：**无新增 ASR 文本直接作为带 ASR 延迟的空观察，不新增 VAD、词稳定等待或延迟补偿。连续空窗数作为可见观察历史进入输入，不暴露未来静音时长。`no-voice` 不固定映射 start；ASR 报错或断连不伪装成正常空窗。

原 ASR 服务主要在文本变化时通知；TT-003已补齐真实空解码完成事件及三步聚合，实际链路已核查，不能用音频接收进度替代解码完成。480ms 是控制观察粒度，不保证每窗有字。单会话最多一个在途请求和一个待处理最新快照；来不及时合并尚未开始的控制窗，保留累计转写及覆盖范围。

## 2. 训练数据如何构造

### 先复用旧 UltraChat 素材

旧 Git 配置记录了 `stingning/ultrachat@f220fe796ce3ed62fbe1681b45ce6cbc9c6cabe0` 的 1,000 条训练、200 条开发和 300 条测试对话，以及 600ms 事件计划。历史实现可从 `38315aa` 的父提交追溯；当前只有代码／报告证据，原始产物、来源清单和审核结果需要重新验真，不假定已完整恢复。当前上游别名跳转到 [openbmb/UltraChat](https://huggingface.co/datasets/openbmb/UltraChat)，不能因名称变化悄悄更换数据版本。

复用原始对话、来源 ID、去重组与语义事件位置；按 480ms 控制窗重新构造时序、动作及 Qwen3 编码，旧回答正文不作为训练目标。旧停顿先恢复持续时长，再按 ceil(duration/480) 换算；600ms 对应两窗960ms，并记录量化误差。

首轮 User 非空片段按固定种子随机分为每窗1—2个当前 tokenizer 的 token；保留完整字符，字符重叠和末尾孤立句读合并可偶尔超过预算。话中停顿在已审核的不完整表达位置插入随机1—3个480ms空窗；本批不把随机位置直接当作可靠 keep 标签。完整用户表达后的首个允许让轮空窗标 start，不能只在任意停顿末窗标动作。当前使用合成调度，真实空窗与突发分布仍待 Nemotron trace 核验。

Assistant 模拟每480ms发布8个token，末块可更短；该参数描述 LLM 文本生成，不按语速解释，也不是实测吞吐。仅把截至当前窗已生成的前缀放入输入。生成结束后随机插入1—3窗剩余播放尾巴：Assistant无新增，状态仍为Speak，空用户观察标keep，用户明确打断仍可stop。随后 playback_complete 转Listen，不产生stop标签；再随机插入1—5窗用户下一轮开口前等待，标Listen/keep。尾窗只模拟剩余待播放时间，不再追加一整段音频时长。随机数可复现，未来等待时长不进入模型输入。

| 场景 | 样本构造与动作 |
| --- | --- |
| Smooth Turn Taking | 保留用户请求、陈述和回答；表达未完成时 Listen/keep，内容已完整且让轮后的静音窗 Listen/start |
| Interruption | 在助手表达期间加入相关的用户打断；前缀已经表达停止、纠正条件或改变请求时 Speak/stop；尚不足以判断的前缀继续 keep 或标未知 |
| 用户 backchannel | 在助手表达期间加入短促的倾听、理解或确认回应，如 `Hmm.`、`I see.`、`Mm-hm.`，标 Speak/keep；结合可见上下文区分需要让轮的表达，含义不明确时保留未知 |
| Pause Handling | 在用户表达内部插入一个或多个 `no-voice` 窗，持轮期间 Listen/keep；保留后续续说，与真正让轮的 start 对照 |

额外保留生成完成但音频尚在播放的负例和打断对照。正常播放结束后关闭当前助手表达，已完成正文写入历史；用户下一轮尚未开口时 User 当前文本为空，继续 Listen/keep。此处模拟下一轮开口等待，不据此推断真实认知时间。

每条训练样本是一个决策快照：来源与事件 ID、可见历史、用户文本、助手可见表达、Listen/Speak、当前窗输入、目标动作。训练控制器看不到未来用户续说、尚未生成的助手回答或未来 CoT。Speak 状态与播放历史在合成素材中明确标为模拟。

按用户2026-10-25反馈，检查片段改为连续的综合话轮，不能全部是纯Listen或纯Speak。每条从Listen接收用户表达，经start后模拟仲裁接受、转Speak并逐窗生成；包含短附和、播放尾窗或用户打断，之后继续Listen中的续说或下一轮表达，再次start并完成回复。start/stop监督快照保留动作执行前的状态，随后的模拟执行事件才切换状态，不跳过中间上下文。打断后仅把已生成前缀以generated_only/interrupted标记保留，不当作已完整播放或已完整回答；用户已到达的打断文本保留并可续说。纯阶段可以作为对照，但本批交付以综合轨迹为单位，来源及去重组不变，不把同一轨迹窗口计作多个独立场景。

完整陈述／陈述式回答至少占训练 start 机会的三分之一。按用户对首批样例的反馈，附和保持短促，以 `Hmm.`、`I see.`、`Right.` 等为主，通过不同对话上下文增加多样性，不用追加 `please continue/keep going` 来代替自然附和。短回应本身没有接管依据时可保持 keep，之后若出现明确打断再标 stop；不能用未来的打断倒推当前应当停止。截断位置、原文最后一个词或下一条用户消息，均不能单独决定 keep/start/stop；审核只依据当时可见内容，歧义保留为未知，不强行凑标签。人工／辅助审核及其范围分别记录。

### 规模、文本处理与隔离

2026-10-25 实施说明：用户已授权继续完成 TT-001、训练和后续评估。旧事件产物未恢复，正式构建改用固定来源上的显式合成事件计划；完整分片 LFS 校验、历史来源排除及候选组去重后再切分。审核采用保守语义规则和代理抽检，分别记录覆盖，不冒称逐例人工审核。训练快照从完整轨迹按动作与场景分层取样，开发／测试保留完整可用观察；语音来源、在线接口或数量不足时必须保留缺口，不用文本成绩代替在线通过。这样补齐可复现输入，同时保留原规模、预算及开发集放行条件。

先从旧训练对话抽取最多 2,000 个快照做机制试训；方向成立后，首轮完整候选仍限于 1,000 个训练对话、最多 10,000 个审核快照，不自动扩到全量 UltraChat。训练按四类场景分层采样，控制长对话和重复等待窗口的占比，不把帧数当成独立场景数。

对最后可见用户文本统一移除末尾句读，所有类别用同一规则；保留内部标点、小数和缩写，禁止用有无句号提示标签。后续验证使用 Nemotron 实际文本，原始转写保留，控制输入处理另记。

先按原始对话及近重复／模板组划分，再构造分块、改写和停顿。同源派生不跨 train/dev/test。旧测试若已用于调参，则从未使用来源补足独立测试；旧材料只能作回归集。目标保留 200 个开发、300 个独立测试对话，四类测试各至少覆盖 100 个不同场景组；同组在每类只计一次，跨类数量不相加冒充更多独立对话，不足则报告证据不足。FDB、FLEURS、公开 Easy Turn 测试资料不进入训练或标签生成。

## 3. 怎么训练

采用监督微调，只监督当前动作 token；历史、状态、用户正文、`no-voice` 和将来的 CoT 输入不计算预测损失。首轮不联合训练 Layer 1/2，不优化回答质量或训练 ASR。

| 配置 | 首轮起点 |
| --- | --- |
| 参数更新 | 冻结基模，LoRA rank=16、alpha=32；同时训练新动作 token 的嵌入及输出参数，以及新增 `no-voice` 的输入嵌入 |
| 优化 | AdamW，学习率 `1e-4`，warmup 5%，最多 2 epoch，开发集选最佳一次候选 |
| 序列与批次 | 最大 2,048 token，micro-batch=1，梯度累积 16，BF16、梯度检查点 |
| 超长与保存 | 超长单例明确排除并计数，不静默删掉关键历史；最多保存最佳及最终两个 adapter，不复制基模 |

这些是拟用起点，资源探针后在正式训练前冻结，同时锁定模型 revision、tokenizer、依赖和随机种子；不在独立测试上挑参数、阈值或模型。先核验极小批次能正确学习动作、输入损失已屏蔽和保存重载一致，再受限试训；不把小批次拟合当作质量通过。新增 token 的保存／加载和状态内合法动作约束必须核验。

机制试训后，仅在开发集同条件比较优于未专项训练模型、且没有明显误抢话／误停回归时，才考虑完整候选。独立测试前冻结一个候选和全部评分规则，不因测试不佳自动再训。

## 4. 通过门槛

2026-10-25评分修正：经用户授权，修复v1将未知／缺失混入误动作率、完整参考匹配代替语义锚点的问题。保留原始报告，v2同时给出计划分母、可判定覆盖、成功／失败／未知、Wilson区间及计划分母上的上下界；缺失不算成功，实际错误另列。接话语义锚点及禁止区间须绑定已审核的当前可见输入，参考文本匹配仅作ASR诊断，不自动给之前的start判错。原始trace缺少标注时交付证据不足，不能据测试结果寻找宽松阈值或改选模型。本次先离线重评及审计训练构造／配比，不改已冻结数据或启动训练；测试来源不得进入新的训练材料。

先做独立文本事件回放，再在同一批可获取语音的测试场景上运行 Nemotron＋控制器影子回放。没有语音的合成场景只能证明文本阶段结果，不能宣称在线门槛通过；本轮不恢复已取消的旧评测作业。

质量按独立机会计算，正常接话／用户打断在允许动作依据的输入已可见时刻后 1,000ms 内返回才算及时命中；合成轨迹使用明确记录的发布时刻，在线轨迹使用实际 ASR／Context 可见时刻。该锚点先于后续控制排队，不能移到请求开始后隐藏等待。任一禁止区间出现错误动作，则该机会失败；大量正确 keep 不稀释一次误抢话或误停。

| 项目 | 第一阶段通过线 |
| --- | --- |
| 正常接话 | 及时 start 机会覆盖≥80%；完整陈述／陈述式回答单独覆盖≥80% |
| 停顿处理 | 持轮停顿机会中，任一次误 start 的比例≤15% |
| 用户附和 | 附和机会中，任一次误 stop 的比例≤15% |
| 用户打断 | 及时 stop 机会覆盖≥80%，自然完成不计入分母或成功数 |
| 控制耗时 | 同一硬件、输入≤2,048 token 时，从输入就绪到动作完整返回的 P95≤500ms，包含排队、调度和传输 |
| Context 接口 | 所有非重复转写版本正确写入并可读；同 turn 不重复入库、旧版不覆盖新版，空文本及关闭事件不丢失 |
| 运行可靠性 | 正式计划样本处理成功率≥95%，队列有界；报告合并比例及延迟，不以丢词换取速度 |

1,000ms 的及时覆盖与500ms的控制P95仍是首轮预算。480ms聚合等待单列，并计入从允许动作依据首次可见到动作返回的及时性判断；不能把锚点后移到窗关闭来隐藏等待。ASR本身延迟单列且不补偿，控制耗时不冒称音频端到端延迟。

四类质量线必须分别满足，同时报告分子／分母、95% 区间、陈述句数量和失败／未命中。失败不算命中，未完整观察的样本不算正确等待，缺失延迟为 null。满足点估计且样本充足记“第一阶段初筛通过”，不据有限样本保证部署错误率；任一项未达标或测试来源不独立，记录未通过／证据不足，不用平均准确率代替。

公开英文 Easy Turn 的 617 条可另报完成／未完成诊断，但它不能替代四类场景验收，不据其结果调参。训练 loss 下降、合成集高分或更频繁 start，都不足以通过。

2026-10-25用户另行要求先制定[FDB Smooth Turn Taking与Pause Handling各50条测试计划](fdb_cross_dataset_plan.md)。使用固定候选、已有录音和FDB时间标注做外部动作诊断，音频参考延迟与本节ASR依据可见延迟分列，不能称官方音频输出TOR或完整四类通过。当前仅交付计划，未启动新作业。

## 5. Shared Context、第二阶段与执行边界

Nemotron 每次文本更新先按稳定的 `turn_id` 写入 Shared Context；下游取得最新快照或按游标读取更新，无需等 start。同一轮多个快照不能重复追加为正文。`no-voice` 是控制观察事件，不向用户转写文本填入虚构词语。转写版本、消费者实际读取版本、关闭及 EOF 分别记录；沿用旧[接口设计](../SoulX-Duplug/shared_context_interface.md)中的版本与读取原则，但不依赖 SoulX 音频同步或完整实现任意 ASR 回写。

第一阶段通过后，从同一检查点训练 ASR＋CoT 控制，混入普通控制样本防止退化。Layer 2 只发布分析，等待与介入仍由控制器学习；CoT 缺失时继续处理接话与用户打断。本轮不预设第二阶段已通过。

本地与远端均用 conda，真实训练和模型测试只在远端执行。最多 1×24GiB GPU、8 CPU、32GiB RAM、1 个活动作业、worker≤2，显存停止线 22GiB；单作业≤4 小时，首轮累计≤8 GPU 小时，新增资产≤10GiB、报告≤2GiB、启动可用盘≥30GiB。触限停止，不自动扩容或增加试验。

交付保持精简：数据来源／切分和审核清单、训练配置与模型版本、adapter、逐例结果和一份中文报告。实施按已建立的 TT-001—004 推进，核对旧数据、环境准备、小批次学习和少量契约测试均随对应实现完成，不另立确认任务。代码、配置和少量必要测试配套同路径中文说明。用户2026-10-25已授权继续实现、训练和后续评估，实际状态以工作单与run记录为准。
