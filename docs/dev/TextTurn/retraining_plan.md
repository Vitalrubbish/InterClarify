## 固定内容

保持Qwen3-0.6B原revision、LoRA rank16／alpha32及现有目标模块；学习新增五个token行，动作仍只有keep／start／stop，finish只作输入。保持单一仲裁器和TTS所有权，不训练ASR、正文、CoT或其他Layer。

原冻结数据保留为机制对照：pilot4来源／1894窗、full21来源／9977窗、dev200来源／88947窗。任何新数据使用独立版本，不覆盖原产物；所有选中轨迹每窗都参与监督，不删keep、不复制正例，轨迹内时序保留。来源／近重复组隔离不变，外部测试不回灌。

保留AdamW、学习率1e-4、weight decay0.01、BF16基模、FP32可训练adapter及token行、长度2048和梯度检查点；改变逻辑更新分组后按真实更新数重算warmup与余弦日程，不能继续照搬累积16窗和两轮238步。正式训练无应用层时间上限的既有授权保持。

## 数据构造优先改什么

1. **打断后的接话闭环。** 当前42条含stop轨迹在stop后均无start，包括用户已完整提出例子、重述或解释请求的情况。新构造需区分明确停止、尚未表达完、完整后续请求：前两者可keep，最后一类按当前可见语义让轮后start，接续回复直到finish或再次被打断。不能把所有打断后静默机械改start，也不修改已经听到的内容。
2. **明确自动边界。** 普通start按用户指定句末标点弱监督，不把源文本最后一块当作唯一完整点，也不将所有中途空拍一律keep。识别依据限定于当时已到达前缀，模型不读取边界标签字段，保留句末仍有续说的弱监督限制。stop的自动可判定点还需核对，不能从普通start的句读代理推导全部其他动作。
3. **成对困难负例。** 相同或相近上下文中同时覆盖未完成／已完成表达、附和／补充请求、无新增／真实新增／重复旧转写；在生成中和播放尾窗均覆盖。增加真实语义的非停止词打断，不只扩充8个模板的词面改写；不要仅依赖固定附和词表。每个对照保留完整轨迹和单一输入来源。
4. **预算关注来源和动作机会。** 1894窗中只有24个正例，无法代表充分覆盖。下一版先确定来源与语义机会覆盖，再在2000／10000窗上限内构造完整轨迹；可使用短而完整的模拟回复减少重复Speak窗，不能截断旧回答后伪造finish。无法容纳目标覆盖时报告预算冲突，不自行扩窗或删拍。接话覆盖疑问、陈述、补充请求及打断后重启，陈述最低比例保持。

新版本先交付少量连续轨迹供用户核对时序与自动标签规则，不将逐拍人工语义标注作为冻结前置条件。数据修改和优化修改分开做对照，避免同时改变后无法归因。

## 参数更新怎样改变

以同一来源、同一表达形式的normal完整轨迹和interrupt完整轨迹组成一个逻辑批次。原pilot有8组，每组自然包含2个start、1个stop及全部keep。逐窗独立前向并累积梯度，保留各自因果快照；先算组内三类基础权重加权平均CE，再对三类等权平均。窗口权重分母在组开始时固定，全部窗口反传后只统一裁剪一次norm=1，再执行一次AdamW，组内不提前更新或清梯度。

这样裁剪对已经合并的三类梯度使用同一个系数，消除正例更新组与仅keep更新组被分别缩放的结构；仍不能保证误差梯度及最终参数位移相等。组内归一化会改变原全阶段目标及来源权重，需在损失文档和manifest明确说明，不宣称与旧损失完全等价。

保持完整词表CE：本轮合法动作CE并未显示更好的正负例折中。不改运行时argmax阈值，不直接取消裁剪，不据外部测试选类别份额。

## 执行与检查

先在原冻结pilot上检查更新组织，再在审核后的数据版本上复现，均从固定基模开始，不从全keep权重续训。原pilot8组配对可预定最多40次逻辑更新（5次完整遍历）、前2步warmup，每8步评估一次；这是下一次机制验证的建议上限，未验证最优，尚未启动。新数据的逻辑组数及完整遍历上限在冻结时重新核对，不默默沿用旧scheduler。

每轮记录三类召回、完整词表及合法动作CE、动作相对keep的margin，以及每次更新的梯度范数与实际裁剪系数；保留非有限检查。全部pilot正例及相邻负例必须可追溯，平均loss下降不能代替这些检查。训练检查与开发集泛化分别报告。

建议在长开发评估前保存该轮权重，避免评估期间中断造成已训练参数丢失；选模仍须等待完整dev，不以部分结果选择best。选定权重后重复新token、动作分数及保存重载核查。

正常接话、陈述接话和打断的既有1%最低开发覆盖率及误动作回归约束保持；该低门槛只排除零能力，不代表达到研究质量线。完整机会成功、停顿误start、附和误stop和延迟按原研究口径另报，不以窗口准确率代替。

最多一个活动作业，远端已有conda、1×24GiB GPU／8CPU／32GiB RAM、worker≤2，显存22GiB、资产10GiB／报告2GiB及空盘30GiB停止线保留。本轮仅交付测试证据和方案，不恢复TT-011或直接提交正式full训练。

## 验证和停止条件

逐组检查三类有效质量各1/3、全部窗口参与、梯度有限、裁剪作用于合并梯度。先要求恢复训练及开发start／stop，并满足探针keep至少85%，再单列Listen误start、Speak误stop、停顿／附和和打断后接话，不允许总keep准确率掩盖分组失败。

初筛合格才固定一个候选，用预留20开发来源完整8607窗及全量pilot确认，再跑200来源完整开发gate。四臂均不合格，因此本次尚未使用该确认集。语义数据版本改变时对应评估标注也需独立审核、版本化，不悄悄改旧成绩。

只有受限pilot及完整开发gate通过，才确定full的逻辑更新数和轮数并安排正式训练；当前未得到可用模型，不自动进入full或恢复TT-011。若失败，保留原因，不靠无限加轮或放宽门槛通过。
