# TextTurn数据修复推荐配置

2026-10-27。按用户要求集中给出剩余六组配置建议。已确认参数以[配置记录](dataset_repair_configuration.md)为准；本文所有新增取值及规模调整均是待确认建议，不据此修改生成器、正式配置或冻结数据，不启动训练。沿用TT-010，不新增issue。

## 1. 已确认设置的基线

| 项目 | 配置 |
| --- | --- |
| 用户观察与增量 | 160ms；有字拍1／2 Qwen token各50% |
| 用户连续发布 | 1—8拍等概率；随后选择短空串90%、长空串10% |
| 短／长空串 | 短1—3拍等概率；长4—16拍，权重`0.8 ** (k - 4)`归一化 |
| 插入位置与开头 | 允许在未完整成词的片段后插入；首字前0—3拍等概率 |
| 普通接话 | 当前前缀句末标点作为弱完成依据，首个合格空观察start；句末不强补空拍 |
| 续说与过渡文本 | 保留原续说时钟；中途开口使用8—20 token完整过渡句，原文全部到齐后复用对应UltraChat回复 |
| 助手生成／播放 | 生成每拍3／3／2 token循环；独立播放每拍最多1 token |
| 首包／停止确认 | 首个助手片段后等1—3拍再开播；停止确认80ms |
| 正常结束 | 生成结束且播放排空才finish，不追加旧960ms尾窗 |
| 控制与真实播放 | 活动输出即Speak控制模式，准备／播放阶段单独记录；准备阶段可keep／stop |
| 泛化检查 | 未见过渡句式与真实回复背景独立报告；来源及句式族隔离 |

所有选中轨迹的每个观察均监督，不回滚已播内容，只有一个仲裁执行点和一个TTS播放所有者。本轮不增加CoT训练、VAD、教师调用或表达模型训练。

## 2. 第一组：句读和轨迹收尾

**保持原始发布事件与模型文本编码分开。** 原始句读用于离线弱标签，模型仍去用户末尾句读。若新增片段仅为标点，保留真实user-update事件，并在输入中用普通事件类型区分text-update／empty-observation，不将去标点后的空字符串伪装成一个无更新拍。标点拍不start；其后真正无更新的拍才满足空观察条件。不移动标点、不强制并入上一拍，也不为了分块方便悄悄突破每拍1—2 token预算。

**句末检测限定于当前前缀。** 使用`.?!`及对应全角句读，允许其后的闭引号／右括号；常见缩写、数字后孤立点号和省略号按保守不确定处理，不依赖未来字符判断。缩写例外表和算法版本冻结。普通无标点段不因文件结束补句号或强标start；单列无完成标记的观察，不算正常接话正例。

**用户文字结束后继续观察8拍，即1280ms。** 如果输出仍在准备／播放，继续正常发布真实模拟状态直至输出关闭；否则结束该观察段。这里是离线回放的观察覆盖，不是线上必须等8拍。下一完整用户段的首字前等待只使用已确认0—3拍，不再额外重复加入一份随机轮间等待。异常／不完整片段明确标记，不能伪造finish。

**建立已提交用户前缀游标。** 已被start消费的文字不在finish后再次触发start；没有新用户内容就keep。stop后保留当次接管的用户新段，等待其句末和空观察重新接话，不自动恢复旧输出。句末后若新词先到达，按最新前缀判断，不沿用更早句号的完成状态。

## 3. 第二组：打断与附和构造

**每个活动输出最多安排一次额外合成用户事件。** 先采用下表的机会级分配，保留原始自然续说作为独立输入；若自然续说已占用相同时段，不叠加另一条用户流。准备、生成中、生成完成后仍播放等阶段分层选取；不按每个Speak窗口重复抽样，避免长回复自动拥有更多附和／打断。

| 机会类型 | 初始比例 | 处理 |
| --- | --- | --- |
| 不额外插入 | 40% | 只保留原续说和正常生命周期 |
| 单纯附和 | 30% | keep，不生成新的回答 |
| 直接接管 | 20% | 首个可判定非附和增量stop |
| 附和后转接管 | 10% | 同一用户流先keep，出现接管内容后stop |

比例用于合成机会选择，不是动作比例或线上发生频率。原始自然续说可能额外产生stop，统计时分开报告实际计数。所有用户事件使用同一发布器和已确认节奏，不给附和单独加速。

**自动stop边界用语义功能明确的短语族，拒绝字符数阈值。** 例如接管族中的完整词组`I meant`、`could you explain`与明确停止族中的`stop speaking`作为弱锚点；锚点匹配只用当前用户前缀及实际新增文字，不能由未来完整模板倒推当前动作。未达到锚点、词内片段和有歧义的短词keep。此规则只给合成数据自动标签，不是线上停止词过滤器，也不声称开放域语义金标。

**接管内容包含80%后续请求、20%明确停止。** 后续请求覆盖解释、补例子、纠正条件、改变关注点等。明确停止后没有新请求则保持Listen／keep；完整后续请求按句末＋空观察重新start。没有现成因果参考回复的合成新请求，继续用已确认过渡句模拟一次新输出，不把原答案冒充新请求答案。

**闭环对照必须存在。** 成对生成相同附和开头后的停止续写、非附和续写和结束；测试重复／旧版本时先经过唯一转写入口，重复内容不重新算有效增量。模板族与阶段独立选择，核对可达性和交叉表。阶段不可达时记录缺口，不延长回复强凑覆盖。

## 4. 第三组：来源与覆盖

**先复用原160个训练来源池与200个dev来源，不读test正文构造。** 扩展所使用的训练来源数，先不下载新语料。pilot从训练池选取，必须与dev隔离；同源变体不当独立来源。保留既有历史排除与词面近重复去重限制。

**解除句式与历史位置的绑定，但不伪造独立上下文。** 从原始完整对话中选取不同位置的有效用户—助手对；问句、陈述各目标50%，并要求两种句式在同一类历史位置均有覆盖。不把依赖上文的陈述剪成无历史首轮，也不拼接无关历史。若160个来源不能提供交叉覆盖，先列出缺口和候选新增来源规模，再决定是否扩展训练池，不用改写冒充新来源。

**过渡文本库建议24条训练、8条开发。** 每条8—20 Qwen token，按句式族隔离，开发句不只是训练句替换同义词；长度和生成速率不绑定动作类型。完整UltraChat回复背景按来源隔离。具体32条内容及分词长度在实现前作为可审阅清单交付，不调用额外模型生成。

**保留两类dev报告。** 第一类是同生成规则的新来源，检验内容泛化；第二类固定未见过渡句式、未见接管表达和真实回复背景，检验输入背景变化。两者都只属于开发诊断，不包装成项目级新盲测，FDB仍保持外部历史回归用途。

## 5. 第四组：规模与模型输入

**建议提高快照预算：train上限100000，pilot上限10000。** 这超出旧10000／2000上限，需用户明确采纳后更新合同；当前文件和配置均不生效。目标train至少100个独立来源、pilot至少20个，仍守住原1000来源总上限。dev保持200来源，窗口数按完整轨迹实计。

提高预算的原因是完整原回复可达数百token，独立播放游标每160ms消费1 token，单个回复就可能占用数百观察拍。继续使用旧1万窗可能再次只容纳少量来源。目标来源数与窗口上限是否能同时满足，必须先做一次只读／CPU构造规模预估；达不到时报告冲突，不删空拍、不复制正例、不裁剪原回复伪造finish，也不继续自动加预算。

本次本地conda只读计数原160个训练来源的320条对应完整回复：固定Qwen tokenizer下均值137.02 token、中位119、最大317。按已确认播放代理，每个来源的两条回复平均仅正文消费就需约274.04拍，尚未计用户输入、准备、其他变体与恢复。这支持提高预算的必要性，但不是新版轨迹的完整规模预估，不能据此保证100000窗一定容纳100来源。

**只选择完整、分层的来源组。** 不再优先固定某个演示来源；在固定seed下按句式、历史位置和动作机会覆盖选择。原始完整回复优先选择自然较短且仍完整的来源，保持长回复在dev单列，以免为快照预算牺牲全部正文多样性。

**模型输入只保留可在线得到的事实。** 建议包括角色历史、当前用户前缀及增量、text-update／empty-observation、控制模式、播放阶段、已生成／已播放前缀、生成完成、实际空观察计数及最近关闭事件。source_id、scenario_id、normal／interrupt、计划阶段、句末弱标签、预选空串长度、未来时长全部只在审核元数据中。

**输出ID和原始时间戳留在运行时关联层。** 模型不需要知道全局标识字面量，历史关闭事件保留类型和因果顺序即可。运行时照常使用output_id、状态版本和输入版本做去重、迟到结果失效及唯一输出管理。输入映射必须训练／回放一致，不只修改训练生成器。

输入长度继续2048 token，不静默截断；任一必需快照超限则在来源组选取前整组排除并报告原因。固定seed建议20261027，新数据另存版本，旧集和旧报告保留。

## 6. 第五组：损失权重与优化验证

**每窗保留正损失，平衡在一次逻辑更新内部完成。** 基础keep权重沿用按轨迹／状态／类别封顶2，start／stop基础权重各2。将同源、同句式的普通和接管完整轨迹组成含三类动作的逻辑组；若二轨迹不足，再在该来源组中加入必要对照，不强行伪造stop。组内每类先算加权平均CE，再三类各1/3合并，全部窗口反传后只裁剪一次norm=1、更新一次。没有stop的独立场景可与其他同源场景共同分组，不能除以零或丢弃keep。

完整词表CE、Qwen3-0.6B固定revision、LoRA rank16／alpha32、AdamW及学习率1e-4先保持。分组改变后重算真实逻辑更新数和学习率日程，不沿用16窗一次更新的旧scheduler。组内按快照独立前向，不把完整轨迹误写成跨窗口KV训练。

**先验证优化，再比较数据。** 在旧pilot上做一次组内平衡／统一裁剪的受限对照，再从同一基模在新pilot验证；两者训练预算按逻辑更新数、总窗口暴露与耗时分别报告，不能声称数据规模不同仍是严格单因素比较。最多5次完整pilot遍历，评估和保存检查点，均为有限试训，不自动进入full。

记录每类召回、相对keep的margin、裁剪前范数和系数、各类有效损失及保存重载一致性。候选若只能全keep或大量误动作，停止扩大训练，不靠放松门槛或无限加轮通过。

## 7. 第六组：验收与执行范围

**数据交付先过硬性完整性检查。** 文件摘要、来源组隔离、逐拍完整、可见因果前缀、无计划泄露、模板全可达、独立时钟、生成／播放游标、准备阶段取消、start终态配对、stop／finish去重及防重复接话全部通过。按句读规则重算自动标签一致率要求100%，这个一致率不称语义正确率。

**机会级开发质量线建议沿用既有研究目标。** 正常接话、陈述接话、打断及打断后恢复分别及时覆盖至少80%；持轮停顿误start、附和误stop各不超过15%。未见句式和真实回复背景各自执行同一质量线，不合并平均掩盖失败。每类至少30个有效机会才作初筛，低于30报告证据不足；给出分子／分母和95%区间，不保证部署误差率。

已有1%门槛只保留为排除零能力的诊断线，不用它自动放行正式质量。合成接话锚点按已确认句读＋首空观察定义，打断按冻结的首个可判定前缀定义；1000ms内返回计及时命中，排队不可从计时中删除。控制返回P95先保留500ms预算，实际停播确认和首个可听音频分别记录，合成时钟不能冒充硬件端到端延迟。独立语音验证仍需真实ASR和可信语义标注，弱标签不能证明该阶段通过。

**实施分两段交付。** 先实现数据修复、输入契约同步、少量必要边界测试及CPU规模预估，再交付冻结清单和连续样例；模型训练另行按确定的pilot范围启动，不因同意本文自动恢复TT-011或提交外部测试。用户可选择在批准整套配置时一并明确启动范围，避免事后重复询问已有授权。

本地及远端均用conda。远端最多1活动作业、1张24GiB GPU、8CPU／32GiB RAM、worker≤2，显存22GiB、资产10GiB／报告2GiB、空盘30GiB停止线保持。CPU构造以单线程、2GiB地址空间为起点，按规模预估核对磁盘与运行时限，不能照搬旧512MiB资产上限后删除数据求通过。正式训练无应用层时间上限的旧授权保留；受限pilot以有限遍历自然结束，不新增无限训练。

## 8. 需要用户集中确认的变更

最主要的新增选择是train／pilot窗口上限提高至100000／10000，及先实现数据与规模预估、训练另定启动。其余六组均为本文集中推荐，等待用户整体采纳或指出修改部分，不逐个数字再次询问。确认前不把本文写入正式JSON、不覆盖旧数据，也不把推荐比例记成已执行结果。
