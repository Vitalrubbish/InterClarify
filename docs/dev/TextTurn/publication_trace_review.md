## 1. 样本与统计边界

主样本为旧TT-007的100条FDB真实录音回放，包含50条Turn Taking和50条Pause Handling。另查TT-004本地保留的6条合成语音例子：只有`19244-smooth_declarative`具有可分析的非空在线转写；3条没有在线解码记录，2条在线解码始终无字。这5条不能充当正常发布节奏的证据，不混入统计。

以每次`asr_online/decode_step`形成的原生160ms观察为单位，使用当前累计文本与前一拍的差获得增量。原始transcript事件可能在同一次解码中连续发布多个片段，不将每个片段当作额外160ms观察；也不使用控制请求合并后的结果倒推ASR节奏。

“主体区间”只指首个至最后一个非空在线文字更新之间，包含两端。开头等待、末尾空拍和EOF排空分别统计；它不是人工标注的真实有声区间，也不表示最后在线文本已经完整。no-voice只表示该解码周期无新增文字，不推断真实静音或用户是否让轮。

全部100条共8774个在线解码周期，与8774个原生control_window逐一核对，文本和增量一致；实际控制调用8715次，59个合并窗口不作为丢失ASR拍。所有文本保持追加前缀，周期内原始转写事件计数与版本变化一致。1436条EOF排空事件单列，未并入在线窗口；18条录音在EOF阶段还有新增文字，不能把这些文字提前放入线上观察。

这些记录来自已经使用过的外部评测，当前只做机制诊断与形态展示，不用其正文构造训练样本，也不拟合训练分布、选动作阈值或声明新的盲测成绩。后续精确时序参数需由训练／开发来源的trace确定；本次没有为此启动新采集。

## 4. 发布设计的建议

1. **保留160ms观察时钟，独立定义文本发布。** 每次观察可以无新增，也可以有一段新增文字，允许多个连续非空拍；取消“每块后必补两空拍”的固定形式。发布结构已获用户确认，具体参数仍待讨论。
2. **联合生成连续发布段与变长空串。** 每拍独立随机丢字只控制总体比例，未必保留连续结构。可以自动构造连续发布段、短空串和较长空串，再核对整体文字速率；当前已确认的初始分布见配置记录，没有直接复制本报告统计值。
3. **统一普通续说、附和和打断的基础发布机制。** 文本内容和持续时长可以不同，不能仅因类别不同就固定使用480ms与160ms两套文字速率，否则到达节奏可能代替语义区分。
4. **支持跨周期词内续写。** 保持同一文本的字符前缀一致，避免只模拟完整词或固定Qwen token宽度；同解码内的原始片段仍先合并为当前观察。
5. **分别生成开头、内部和末尾观察。** 额外模拟停顿需要与基础ASR无更新分开记账，防止重复叠加；末尾空窗不固定成第一拍必start，也不通过EOF或原文剩余长度决定标签。
6. **发布节奏与动作监督分开。** 发布器负责何时可见多少文字；标签依据当时可见语义、状态和既定策略。空串长、短本身均不决定start／keep，也不直接从历史控制动作复制标签。

先前“每480ms还是每160ms发布1—2 token”的二选一不足以描述这些trace。用户现已分步确认基础发布参数，后续继续讨论空串位置、词内跨度、起止时序及自动语义标签；决策记录见[配置讨论](dataset_repair_configuration.md)。
