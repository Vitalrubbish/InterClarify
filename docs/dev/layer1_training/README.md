# Layer 1 训练数据构造与分阶段时长评估

更新：2026-11-05。工作单：NTF-049。

本文将[训练设计](../../research_design/layer1_training.md)细化为可试标、可核算的训练准备方案。建议先用 **300—500 个独立来源、约 1,000 条决策样本**验证协议和标注，再按学习曲线扩展到 **10 万条决策样本**。基础交互占 70%，两项 thinking 任务合计占 30%；训练按协议、含噪与恢复、附和、thinking 四阶段推进。

以历史讨论中的 **8×RTX 4090** 为预算场景，一次四阶段顺序训练暂估 **55—147 小时，中档约 85 小时**，包含 20% 的训练外开销；前三阶段约 **16—40 小时**。这些数字来自下文的吞吐假设，尚无本项目训练实测。数据准备、评测和多组消融另计，不能据此承诺完整研究交付时间。

本文提出的配比、规模和资源配置是试验起点，试标后再冻结；不改变普通回答的 complete 边界，也不表示已完成语料生成、模型适配或训练。

## 1. 训练对象与数据计数

首轮采用官方 Qwen2.5-7B-Instruct，固定 SoulX、X2 与 TTS，只更新 Layer 1 的参数高效适配参数。官方模型卡给出的总参数量为 7.61B；底座与 chat template 以[官方模型卡](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct)为准。Qwen3 留作后续候选，切换后须重新测量 token 长度、显存和吞吐，不能直接沿用本预算。

以下数量分别记录：

| 单位 | 定义与用途 |
| --- | --- |
| 独立来源 | 原始对话、独立任务或场景家族；同题换数字、共享前缀分支与语音变体归同一组 |
| 分支轨迹 | 一个来源按时间展开的具体对话及运行事件序列 |
| 决策样本 | 某一合法读取边界的可见上下文，以及下一段 Layer 1 动作／正文目标；允许由同一轨迹产生多个样本 |
| 训练曝光 | 样本被实际送入训练的次数，包含重复采样和多轮训练 |
| token | 分别统计完整序列 token 与参与损失的目标 token；训练成本按完整序列计算 |

10 万条是**去重后的决策样本规划量**，不是 10 万段独立对话。暂按 2 万—3 万个来源、平均每来源约 3—5 条样本预算；来源数须与实际清单一起验收，不能靠每 160ms 切一份样本凑量。后续阶段复习已有能力，优先使用同类的新样本；若重复使用同一条记录，去重计数只算一次，额外曝光单独加入成本。

## 2. 数据如何构造

### 2.1 先试标，再形成来源池

先选约 400 个来源，覆盖协议、含噪与恢复、附和，以及 thinking 的代表场景，产生约 1,000 条高质量决策样本。优先确认三件事：当前输入是否足够判断、教师目标是否一致、模型能否同时学会等待与回答。

扩展阶段采用三种来源：

1. **可核验任务与受控对话**：构造查询、计算、约束规划、信息缺口、续说和改口等场景，准备答案或必要信息清单，再生成自然说法与语音变体。
2. **允许用于训练的自然对话**：保留自然停顿、口语不流畅、附和和纠正，补充合成语料较难覆盖的节奏；记录来源与使用条件。
3. **训练分区的模型失败回放**：收集提前回答、重复回答、漏用新条件、无效思考和错误附和等失败，只从训练来源补样，经审核生成正确目标。

来源结构先不设硬性比例，以试标中自然节奏覆盖和标注可靠性决定；下一节的行为类型比例才是训练采样配额。首轮以现有英文前端链路为主，语言扩展须单列语种及前端表现，不能将未知的识别质量当作已验证条件。

### 2.2 按来源分组隔离，然后回放冻结前端

按场景家族先划分训练／开发／内部测试，建议比例为 **90%／5%／5%**，再生成各组的分支、音频和切片。10 万条预算只计算训练分区，开发与测试额外准备；FDB、SoulX-Eval 及其改写均不进入训练、教师筛选或阈值选择。

将录音或合成音频送入冻结的 SoulX＋X2 前端，按真实流式顺序记录 160ms 联合提交轨迹。保留两侧实际观察范围、原始可用时间、联合发布时间、X2 当前闭合正文和 SoulX 状态；EOF、完整转写或未来续说都不能成为当前模型提前可见的信息。

不能将 SoulX 预测改成事后金标再声称模型适应了真实噪声。金标可用于审核和单独诊断；正式训练输入保留实际前端预测。人工构造状态抖动、ASR 延迟或延迟注入时，记录合成来源，并由真实轨迹支持其合理范围。

### 2.3 从事件轨迹选择决策样本

重点抽取用户开始表达、信息显著增加、完整快照首次提供有效 complete、用户续说／改口、输出取消、停播确认、附和机会和分析结果实际到达后的合法读取边界。补充相邻的正常等待与无需额外思考样本，避免数据只包含异常和应当开口的时刻。

每条样本至少保留以下信息，具体字段名在实施时冻结：

| 信息组 | 保存内容 |
| --- | --- |
| 来源与隔离 | 场景、对话、分支、样本标识，数据分区，主类别与辅助标签 |
| 模型可见输入 | 当前已提交转写、状态、必要历史、实际读取位置及可见事件；CoT 仅在到达并被读取后加入 |
| 输出与播放事实 | 生成、提交、实际播放的分别记录，`output_id`／`chunk_id`，取消请求及确认、是否已有真实已播采样 |
| 监督目标 | 自身动作、下一段表达或思考请求，目标损失掩码，允许动作集合及标注置信度 |
| 审核元数据 | 教师与版本、答案／信息清单、模拟延迟来源、拒绝原因及人工审核结果 |

完整后续转写、未来音频、最终答案及事后原因保存在审核侧，不拼入当前教师或学生输入。用于生成表达目标的教师只获得学生当时可见的材料；离线审核器可以使用完整材料检查因果性，但不能把未来答案回填成当前目标。

普通回答目标只能放在模型实际读取当前话轮有效 `user_complete` 之后。同一 complete 的重复观察包含“已经消费、不重复回答”的目标；没有 complete 的等待样本监督内部等待动作及结束边界，不能用空标签代替等待训练，也不把“请稍等”当作每次等待的口头目标。

### 2.4 取消恢复、附和与 thinking 的构造要点

**取消恢复**同时覆盖首音前与已播后两种轨迹。首音前取消，用户续说与此前正文仍作为同一片段，未播生成保留为内部历史，不冒充助手已说内容；已有实际已播采样时，保留已听事实及新用户片段，必要时明确纠正。旧输出作废、迟到文本／音频丢弃由运行时保证，模型监督聚焦依据最新条件组织下一次表达。首次 complete 后当时合理的回答不会因为未来取消而被追溯标成错误。

**附和**按事件窗口标注“适合但可不发”“不应发”“不确定”，同时审核措辞是否形成错误赞同。可选窗口允许等待和合适短回应，不把实际未发声直接视为负例；不确定样本不强行监督精确时机。用户 `user_backchannel` 是外部状态，系统附和是模型自身行为，二者分开记录。

**thinking**使用按当前前缀生成的分析轨迹。Layer 2 仅提供事实、缺口、推导与变化依据，不能直接提供“现在插话”或候选问句；Layer 1 学习请求、利用已到达结果及继续表达。训练可使用明确标记的模拟延迟，但返回次序必须可实现；正式评测使用真实推理与播放时序。

边说边想需包含开口后仍在进行的分析，不能先求出完整答案再切成几个片段。自然发生的错误可作为带标记的已听上下文，先前错误正文屏蔽损失，只监督后续可靠表达与纠正。不得通过奖励“先错后改”制造修正能力。

### 2.5 审核、监督与扩展条件

- 对全量样本执行来源隔离、时间因果、目标边界、重复与完整性检查；计算和约束题尽量程序核验。
- 试标集全部人工审核；扩展阶段每类至少分层抽查 200 条，兼顾通过、拒绝、真实与合成来源。恢复、附和及修正样本前 500 条加强复核；发现系统性错误先修标注流程，再扩量。
- 用户文本、状态、外部事件、CoT 及 padding 屏蔽预测损失；Layer 1 的合法动作、请求和可靠正文参与监督。不训练 Layer 1 复现 SoulX 状态，也不将 CoT 文本变成助手应播放内容。
- 同时报告各类样本数、目标 token 量和损失贡献。短等待不能因正文 token 少而被长回答淹没；先采用动作／正文分组归一化的候选方案，权重通过开发集决定，并在所有对比中固定。

先用 1,000 条样本验证，再按约 1 万、3 万、10 万条逐步扩展。是否扩量依据各类学习曲线与失败覆盖，不能仅因总 loss 下降就进入下一阶段；数据生成、切片和训练代码另建实施工作单。

## 3. 数据分为哪几类，各占多少

### 3.1 全部训练阶段合计的建议配比

以下按 10 万条去重决策样本计数，每条只分配一个**主要监督类别**。恢复时存在 ASR 噪声等情况用辅助标签记录，不重复加入分母。分类优先看该条的主要目标：thinking、附和、取消恢复、含噪交接、干净协议或普通回答；场景相同但监督目标不同的决策样本可以归不同类。

| 类别 | 主要学习内容 | 占比 | 10 万条中的数量 |
| --- | --- | ---: | ---: |
| A：干净协议与等待 | 理解外部状态，未 complete 时等待，已消费事件不重复回答，区分内部动作与正文 | 15% | 15,000 |
| B：普通任务回答保持 | 在合法 complete 后准确回答，覆盖直接回答、必要轮后询问、多轮条件与不同长度 | 20% | 20,000 |
| C：含噪状态与交接 | 短暂／重复 complete、ASR 滞后、正文不变状态变化、尚未取消时的续说分支 | 10% | 10,000 |
| D：取消与恢复 | 首音前取消、已播后取消、用户改条件与旧结果仍依据旧条件等恢复场景 | 15% | 15,000 |
| E：系统附和 | 可选短回应、不应回应、错误赞同、近期已回应及用户附和方向区分 | 10% | 10,000 |
| F：边听边想 | 思考请求、分析利用、合理等待、缺口消解与后续条件满足时的澄清表达 | 15% | 15,000 |
| G：边说边想 | 可靠早期表达、回答递进、自我修正，以及简单任务无需继续分析的对照 | 15% | 15,000 |
| **合计** | **基础交互 70%，thinking 30%** | **100%** | **100,000** |

这组比例先保证普通回答与基础交互，再给两项研究任务各保留 15%。它不是对线上事件频率的估计；开发和测试需另报自然分布结果，以及恢复、错误附和等专项压力结果。来源、语种、语音合成方式和难度是正交标签，不额外叠加占比。

### 3.2 需要控制的类内结构

| 类别 | 首轮建议 |
| --- | --- |
| A | 约 2/3 为尚未到达回答边界的等待，1/3 为重复事件／输出阶段识别；配合 B 检查是否学成一味沉默 |
| C | 真实前端轨迹不少于 70%，有来源标记的扰动不超过 30%；覆盖正确 complete 后及时回答，防止统一增加等待 |
| D | 首音前取消与已播后取消约 1:1；在已播后样本中兼顾需纠正与无需重复道歉的正常更新 |
| E | 可选附和窗口与明确不应附和约 1:1；不确定标签留在审核池，不计入强时机监督配额 |
| F | 值得澄清的情形与等待／自行消解／无需思考的对照约 1:1；共享前缀未分化前保持相同监督 |
| G | 可靠递进约 50%，直接正确且无需追加思考约 30%，经过审核的修正约 20%；不得为凑修正比例奖励错误前缀 |

F、G 中分别留出约 20% 的延迟、过期结果、无结果或无需调用对照作为交叉标签，不另外加到 100%。若可用的自然修正样本不足，G 的修正额度让给可靠递进并登记实际比例，不用低质量造错补齐。

## 4. 分阶段怎么混合、何时进入下一阶段

各阶段继续同一底座与适配器，保存阶段检查点；跨阶段固定协议、tokenizer 和输入模板。思考请求使用架构约定的专用 token；在试标时统一确定词表，新增 token 的相关输入与输出参数须可训练、可保存并通过重载验证，不能只添加字符串就假定模型理解。

下面给出能与总体比例逐项核对的样本分配。后续阶段复习前面的行为类别；表内样本不重复计数。两轮训练产生的曝光量在第五节另乘轮次。

| 阶段 | A | B | C | D | E | F | G | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| S1：协议适配 | 5,000 | 5,000 | 0 | 0 | 0 | 0 | 0 | 10,000 |
| S2：含噪与取消恢复 | 2,000 | 4,000 | 6,000 | 8,000 | 0 | 0 | 0 | 20,000 |
| S3：系统附和 | 3,000 | 4,000 | 2,000 | 3,000 | 8,000 | 0 | 0 | 20,000 |
| S4：thinking 适配 | 5,000 | 7,000 | 2,000 | 4,000 | 2,000 | 15,000 | 15,000 | 50,000 |
| **合计** | **15,000** | **20,000** | **10,000** | **15,000** | **10,000** | **15,000** | **15,000** | **100,000** |

因此，S1 的 A/B 为 50%/50%；S2 为 A/B/C/D＝10%/20%/30%/40%；S3 为 A/B/C/D/E＝15%/20%/10%/15%/40%；S4 为 A/B/C/D/E/F/G＝10%/14%/4%/8%/4%/30%/30%。训练初期不按全局 30% 的 thinking 配比混入尚未建立的复杂协议。

| 阶段 | 进入下一阶段前重点检查 |
| --- | --- |
| 试标与小训 | 目标可由当前输入支持，损失掩码正确；协议、新 token、保存重载与可取消轨迹可用 |
| S1 | 等待／回答边界、普通回答质量、重复回答；不能靠整体减少开口换取低违规率 |
| S2 | 同前缀续说、首音前后取消、新条件采用、恢复后的合法回答，以及实际停止和旧输出隔离 |
| S3 | 附和机会与误发分开评分，错误赞同、近期重复及实际抢话受控；普通回答和恢复不退化 |
| S4 | 请求有依据、已到达分析被利用、递进和纠正有实际信息价值；分别检验两项研究收益及基础能力保持 |

阈值由试标和独立开发集确定后冻结，不能用正式测试结果调参。S1—S3 可先形成基础交互版本。**S4 的完整边听边想及轮内主动澄清，还依赖后续 SoulX CoT 条件化控制与独立生成边界设计**；在该条件满足前，只可先做请求／结果利用和表达子任务，不将其记为完整 S4 验收。本预算只计算 Layer 1，Layer 2 与 SoulX 后续训练费用另计。

阶段检查点用于观察能力变化；要归因于某类数据，还需同初始化、相近训练 token 预算的移除该类数据实验。顺序检查点本身不能排除额外训练量的影响。

## 5. 分阶段训练需要多久

### 5.1 预算配置与测量口径

使用以下配置做容量和时长规划，最终以远端预检冻结版本为准：

- Qwen2.5-7B-Instruct，4-bit NF4 底座、BF16 计算的 QLoRA，候选 LoRA rank 为 16，覆盖 Transformer 线性层；只训练适配参数及必要的新词表参数。该方法的加载与训练方式参考 [PEFT 官方量化说明](https://huggingface.co/docs/peft/v0.21.0/developer_guides/quantization)，线性层适配参考 [LoRA 官方说明](https://huggingface.co/docs/peft/v0.21.0/package_reference/lora)。文档示例不代表本仓库依赖已支持，实施前验证兼容性。
- 8 张 24GiB 4090 数据并行，每卡 micro-batch＝1、梯度累积＝4，有效 batch＝32 条；启用梯度检查点及经验证的节省显存注意力实现。每卡须独立满足显存限制，不能将多卡总显存直接视为单个模型可用容量。
- S1—S3 最大完整序列 2,048 token，S4 为 4,096；下表采用较短的实际平均长度。必要历史、状态、外部 CoT、目标及模板均计入完整序列。超长轨迹在因果边界构造局部样本，关键已听事实或条件放不下时排除该样本，不直接截掉关键历史。
- 各阶段先预算 2 轮，以开发集早停；若需更多轮或新增失败补样，按实际曝光重新计算。

吞吐 `Q` 定义为**全部训练卡合计、每秒处理的非 padding 完整序列 token**，包括被损失屏蔽的输入。分子不是只数助手正文，也不是模型推理生成速度；分母包括稳态训练中的数据加载、重计算、梯度累积与通信，排除单独的加载、评测及保存区间。

尚无远端实测，因此短序列采用 **1,200／2,000／3,000 token/s**，长序列采用 **800／1,400／2,200 token/s** 三档情景。它们是用于敏感性分析的工作假设，不是官方 benchmark 或八倍单卡性能。序列变长、padding、跨卡通信及训练词表参数都会改变实际吞吐，实测值可能低于这三档。

### 5.2 可复算公式与阶段结果

对于阶段 `i`：

```text
训练 token_i = 样本数_i × 平均完整序列长度_i × 轮次_i
纯训练小时_i = 训练 token_i / 实测或假设的全卡吞吐_i / 3600
阶段预算小时_i = 纯训练小时_i × 1.20
GPU 小时 = 使用卡数 × 墙钟小时
```

额外 20% 暂用于模型加载、少量阶段内开发集检查、保存与恢复，不含完整语音闭环评测、数据生成、排队及失败重跑。测量吞吐时已经计入的 padding 和重计算不再重复乘系数。

下表三档依次为低吞吐／中档／高吞吐；M 表示百万 token，小时保留一位小数。

| 阶段 | 样本数 | 平均长度／最大长度 | 轮次 | 训练 token | 纯训练小时，低／中／高吞吐 | 含 20% 开销的小时，低／中／高吞吐 |
| --- | ---: | --- | ---: | ---: | --- | --- |
| S1：协议适配 | 10,000 | 1,024／2,048 | 2 | 20.48M | 4.7／2.8／1.9 | 5.7／3.4／2.3 |
| S2：含噪与取消恢复 | 20,000 | 1,536／2,048 | 2 | 61.44M | 14.2／8.5／5.7 | 17.1／10.2／6.8 |
| S3：系统附和 | 20,000 | 1,536／2,048 | 2 | 61.44M | 14.2／8.5／5.7 | 17.1／10.2／6.8 |
| S4：thinking 适配 | 50,000 | 2,560／4,096 | 2 | 256.00M | 88.9／50.8／32.3 | 106.7／61.0／38.8 |
| **合计** | **100,000** | **完整输入与目标** | **2** | **399.36M** | **122.1／70.7／45.6** | **146.5／84.8／54.7** |

总计约 **2.3—6.1 天连续占用 8 卡**，中档约 **3.5 天**，对应约 **438—1,172 GPU 小时**，中档约 679 GPU 小时。S1—S3 中档约 23.9 小时，S4 约 61.0 小时；长上下文与 thinking 数据是主要成本。

试标小训另计：1,000 条、平均 1,024 token、2 轮约 2.048M token。若单卡稳态吞吐为 100—250 token/s，含 20% 开销约 **3—7 小时，1 卡**。随后预留 **2—4 小时、8 卡**做长短序列校准、显存检查和断点恢复验证；这些同样是假设预算，不包含训练器开发时间。

### 5.3 如何把假设换成可信的远端预算

远端先完成单卡加载、前后向、目标掩码与保存重载预检，再用同一真实样本分布执行 8 卡校准。短、长序列分别覆盖热身和至少 100 个稳态优化步骤，记录实际非 padding token 总量、步骤墙钟、各卡峰值显存、RSS 与通信情况。

将测得的长度分布与 `Q` 代回公式；如使用分桶或打包，要验证样本间注意力隔离和损失掩码，并重新测量。若只测了短序列，不能据此签发完整 S4 的时长估计。所有超长、资源超限和慢步骤都保留在报告中，不以丢掉困难样本制造较高吞吐。

8 卡并行并不保证 8 倍加速。若后续只有 4 卡或 1 卡，须测该卡数下的全局吞吐重新计算；在相近吞吐下，样本数、平均长度或轮次翻倍会使成本近似翻倍，改变最大序列长度还可能进一步降低吞吐。

## 6. 数据准备、评测和完整实验日历

训练时长与项目历时分别预算：

| 环节 | 首轮预算方法 | 当前可给出的范围 |
| --- | --- | --- |
| 试标与规则修订 | 400 个来源，每个审核 5—10 分钟 | 约 33—67 人时，另计争议复核与规则修订 |
| 扩展语料生成与标注 | 若接受率为 70%，得到 10 万条需生成约 14.3 万候选；按每候选 500—1,500 个教师输出 token | 约 71—214M 教师输出 token，另计输入；无教师选型及实测吞吐前不换算成天数 |
| 全量语音／前端回放 | 2 万—3 万个来源、每来源平均 60 秒 | 基础音频约 333—500 小时；单流水线实时率为 1 时需约 14—21 天，另乘变体量，并按允许的并发和实测实时率调整 |
| 分层人工抽查 | 每类至少 200 条，加恢复、附和、修正等专项复核 | 抽查数量随缺陷率增加，不计入 GPU 训练小时 |
| 一次四阶段训练 | 第五节的完整输入 token 与稳态吞吐 | 含常规开销约 55—147 小时、8 卡 |
| 阶段语音闭环评测 | 例如每阶段 300 条、平均 60 秒，共四阶段 | 1,200 条约 20 小时音频；单流水线按实时播放约 20 小时，再加评分与异常分析；使用独立开发数据 |
| 消融、多种子与规模实验 | 根据需要重训的阶段计算，不把已有检查点重复计训练 | 在主线基础上单列新增 GPU 小时；不包含在 55—147 小时内 |

例如，若只额外做两次 S4 重训消融，中档增加约 `2 × 61.0＝122.0` 个 8 卡墙钟小时；连同主线约 **207 小时，即 8.6 天连续占用 8 卡**，仍未包括造数和评测。仅倾听、仅表达、联合训练以及规模实验的具体矩阵待首轮结果确定，不能直接把所有实验压进一次训练预算。

因此，当前能合理预算的是：数据已准备好、运行环境可用且前置条件满足时，一次完整 Layer 1 顺序训练约需数天；如果从零制作语音与审核数据，准备环节可能比训练更长。应先完成试标、实测前端回放速度与训练吞吐，再排正式日历。

## 7. 远端执行与资源边界

本次只编写方案，不启动作业。后续训练与集群测试在远端 conda 环境执行，另立实施工作单；下列是拟议的训练专用上限，不能覆盖现役前端任务的单卡、时长及磁盘限制：

- 同时最多 **1 个训练作业、8 个 GPU rank**；数据加载每 rank 最多 1 个 worker，合计最多 8 个；CPU 分配不超过 32 核，主进程计算线程每 rank 至多 2 个。不同时另跑造数、教师或语音闭环任务。
- 主机 RSS 总量上限 **128GiB**，每卡峰值显存控制在 **22GiB**。若 4,096 长度或词表训练超限，停止并记录；调整后重新校准，不静默截掉关键上下文或扩大资源。
- 新增数据及产物总预算 **200GiB**：音频最多 120GiB、文本与缓存 32GiB、adapter／优化器检查点 24GiB、日志 2GiB，其余留作余量。权重只读复用；检查点只保留当前、最佳与阶段末必要版本，禁止每个检查点复制完整底座。
- 16kHz、单声道、16-bit PCM 每小时约 0.1152GB，333—500 小时约 38.4—57.6GB；多语音变体、双声道或高采样率另算。启动前要求可用盘覆盖剩余预计新增量并额外留 20GiB，日志与缓存设置硬上限。
- 单个调度子作业最多 **24 小时**，长阶段通过已验证检查点续接。记录训练清单摘要、代码与模型版本、实际曝光、完整／目标 token、吞吐、资源峰值与退出原因；资源触限不自动扩卡或无界重试。
