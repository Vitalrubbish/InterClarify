# Listen 下 start/keep 校准协议

更新：2026-10-23。对应 XTX-010，用户已明确同意先验证 Listen 校准，Speak 校准后置。本文在模型打分前冻结数据与决策规则；结果写入独立报告，不根据留出成绩更换阈值、输入或数据。

## 目的与边界

验证未训练 XTurnix-PT 的默认决策是否过于保守，以及仅调整阈值能否在受控误抢话预算下改善接话。固定 `xcczach/xturnix-pt@d4b0403e5a6744b46fa7602b6d77bbac2768d5b5`、官方输入预处理、FP32、关闭 thinking、上限 2,048 token，状态由本实验显式设为 Listen。只做影子离线推理，不安装新训练环境或更新参数。

原审核中“四类在线金标尚不可用”的结论不作为本实验前置门槛。此次使用来源原生停顿标签和固定 Listen 条件，不将候选语义标签强行转换为四类动作，不要求先取得真实机器人播放轨迹。Speak/stop 数据缺口不阻塞 Listen 校准。

## 数据与隔离

来源为 `livekit/eot-bench-data@ca9d98a9686b920a2d8c9eb984224ba9be74e4dd`，英文 `validation` 子集共 400 个用户话轮。只读取文本、词时间、对话历史和停顿元数据，不下载音频。官方定义每个话轮的末次停顿为 eot，之前的停顿为 hold；这是离线标签依据，文件长度、最终标签和停顿时长不进入模型输入。[数据来源](https://huggingface.co/datasets/livekit/eot-bench-data)与[官方说明](https://github.com/livekit/eot-bench)。

从 ID 的 `__user_turn_` 前缀提取原会话分组。两个已用于源格式检查的会话 `en__875_82`、`en__977_89` 在模型打分前排除。其余会话用 `SHA256("xtx010-listen-v1:" + conversation_id)` 的整数奇偶确定 dev/test；同会话所有话轮与停顿只能进入一个集合。源数据的 validation 在本项目重新分组，结果不能称为官方完整 benchmark 成绩。原 48 会话审核素材不用于此次留出测试，FLEURS/FDB 不参与校准。

观察点固定为停顿开始后 100ms，只取词结束时间不晚于该点的当前用户文字，并附来源提供的此前对话。没有未来当前轮词、标签、EOF 或合成 pause。历史空文本剔除、连续同角色消息合并并留记录；独立开场 assistant 问候移除，使历史从完整 user/assistant 对开始。原因是固定官方管线只会移除从 user 开始的完整历史对，保留开场 assistant 会导致部分长历史不能按该规则缩减。本规则在打分前统一应用并记录，未根据动作分数选择历史；之后由官方管线按 2,048 token 移除最旧完整对，移除数保留。官方末条去尾标点照常执行。源参考转写与对齐不是实际在线 ASR 到达，结果只支持离线文本条件下的校准判断。

原始资料与请求保留本地忽略目录；远端保存冻结推理输入、摘要和逐例分数。Git 只保存不含正文的清单、汇总和必要证据。空前缀、异常时间、角色和超长失败均保留原因，不为提高成绩而替换话轮。

打分前核查发现 dev/test 各有 2 个观察点尚无任何已结束词，均为句中停顿。固定处理为不发模型请求并保持 Listen，记录 `abstain_empty_text`、分数 null；计入计划观察，不计入模型混淆矩阵或伪造 p_start=0。这与没有当前文本时不触发文本控制请求一致，不使用该点标签决定行为。后续真正推理失败仍单列，不能与空文本 abstain 混淆。

## 阈值与指标

分数为官方合法动作对 softmax 后的 `p_start`。默认规则为 `p_start >= 0.5`；校准规则为 `p_start >= threshold`，不改变权重或提示词。

开发集按完整话轮归并：任一句中停顿被判 start，就记一次误抢话；分母为全部计划用户话轮，并另报具有句中停顿的风险话轮分母。末次停顿 start 为末端接话命中，失败与漏接话仍占原计划分母。快照级混淆矩阵及 PR 曲线另列，不能用多个 keep 稀释一次误抢话。

在开发集全部可区分阈值上，先约束话轮级误抢话率≤5%，再最大化末端接话召回；并列时选误抢话更低者，再选更高阈值。5% 是本次探索工作点，不默认放行生产。默认阈值结果完整保留，不能仅报告校准后的 start 比例。

先完成 dev 打分与阈值文件，再读取 test 输入和打分；test 只使用已冻结阈值，不重新选工作点。按原会话聚类，对默认/校准差值做固定种子的 1,000 次配对 bootstrap，报告 95% 区间及真实分母；样本少或区间宽时只报告探索性结果。若开发或测试有推理失败，单列计划/成功覆盖，失败末端计漏接话，带失败的句中判断不宣称安全通过。

留出集重点看末端召回是否改善及误抢话是否仍受控；超出 5% 或差值区间不足以支持收益时如实记录。阈值校准不改变排序能力，不因不成功就自动进入训练。

## 资源与交付

真实模型只在远端调度作业执行，复用已存在的 XTurnix conda 和只读权重。最多 1×24 GiB GPU、8 CPU、32 GiB RAM、batch=1、1 个作业，限时 30 分钟；启动空闲盘≥30 GiB，本次输入/trace/报告≤100 MiB，累计资产仍遵守既有 10 GiB 上限。记录 GPU 显存、RSS、版本、源码/输入摘要、加载与推理耗时及退出码。

不运行 Nemotron、TTS、播放器或 Speak 决策。推理服务时间只作计算成本，不称为端到端接话延迟；此次不报告 FDB TOR、VAD 等待或实际停播时间。
