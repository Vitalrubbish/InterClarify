## 1. 分析要回答什么

当前最直接的问题是：XTurnix-PT 在英文完整陈述句后经常继续等待。训练可行性分析应分别回答：

1. 补足真实对话历史、校准动作阈值后，是否仍有明显漏接话？
2. 少量监督微调能否改善完整陈述句的接话，同时保留句内等待和用户打断能力？
3. 剩余错误是否依赖文本之外的语调、节奏或停顿？若是，继续微调纯文本模型的收益可能有限。
4. 训练能否在现有单卡、内存、磁盘和时间预算内完成，并导出可复核的控制模型？

先验证普通话轮控制，随后再分析 CoT 条件化主动介入。两者分别报告：普通接话改善不等于已经学会主动澄清，程序能完成反向传播也不等于模型有效。

本阶段不训练 Nemotron、Layer 0/1/2，不接入新的播放路径。系统附和机会仍属于 Layer 0；XTurnix 只负责状态条件下的控制动作，保持单一仲裁执行点和单一 TTS 播放所有权。

### 1.1 候选路线与前置讨论

此前建议优先探索“因果 VAD 观测辅助的 XTurnix 小规模微调”，是候选研发方向，不代表已经证明需要训练或能够获益。当前先分析模型偏好、输入、数据与成本，再与用户讨论是否进入后续范围；允许选择只校准、先补证据、不训练或调整路线，不能以已有选择跳过分析。

该候选方向保留独立控制策略，拟补足真实发声、静音和 ASR 到达状态，再训练四类动作。其考虑是控制请求需要在 Layer 1 正文生成期间独立受理，后续还需学习 CoT 条件下的等待与介入；独立进程不等于没有共卡排队，这些预期仍需证据支持。

VAD 只提供当时可获得的语音活动与时间观测，不把用户发声直接映射为 stop，也不把静音直接映射为 start。Nemotron 继续提供原始在线转写；XTurnix 独立选择合法动作；输出运行时仍是唯一执行点。VAD 不提供语调或完整的声学语义表示，不能据此声称已解决纯文本模型的全部信息缺口。

具体输入格式在实施前另行冻结，区分实际语音活动、静音持续时间、转写尚未到达与真实 Listen/Speak 状态；不能把无 ASR 增量当成静音，也不能把 EOF 当停顿。新增观测使用单独版本的预处理与训练样本，不能把字段直接塞进原版管线后假定模型已理解。只有 ASR、VAD 状态或已定义的时间观测发生变化时才触发重判，不以不变文本的重复调用表示时间。

现役 DuplexCascade 控制作为基线保留，不与未来 XTurnix 同时执行动作。当前围绕已交付的实际分析报告与用户讨论；只有明确进入实施后，才开展协议实现、数据准备、校准或资源探针，更不能提前执行第 6 节的微量优化。后续若在相同误抢话和误停预算下没有独立数据收益，停止扩大训练。

## 2. 已有证据与待验证假设

| 证据 | 可以支持的判断 | 尚不能支持的判断 |
| --- | --- | --- |
| [XTX-005 冒烟](../../../reports/xturnix_fleurs/20261023-xtx-005-smoke-a10/README.md)为 0/5 start，窗口覆盖 5/5 | 当前冻结配置下存在持续等待现象 | 自然对话中陈述句的让轮召回率为零 |
| [pause 探针](../../../reports/xturnix_fleurs/20261023-pause-token-probe/README.md)中，干净参考文本仅 1/100 start | ASR 错误不是低输出率的唯一解释 | FLEURS 具备可直接用于训练的话轮标签 |
| 同一探针的中英文问句可以 start，句末追加 pause 后被压成 keep | start 路径可用，合成 pause 会改变动作分数 | 所有调用条件均正确，或真实停顿必然抑制接话 |
| [官方论文第 5.3 节与附录](https://arxiv.org/html/2610.04400v1)报告 PT 偏向 keep；英文 Smart-Turn 无 endfiller 子集的 start 召回为 3.47%，ROC-AUC 为 86.44% | 有必要先区分动作偏好与区分能力，并验证校准收益 | 上述数字可以直接换算成本项目的效果 |

原探针报告将陈述句 keep 概括为合理行为，解释偏强。本文保留其原始数值，只把低接话率作为诊断线索；陈述句也可以结束话轮，不能按句型直接认定正确动作。

需要检验三种解释：默认边界过于保守、目标领域数据不匹配、必要声学信息缺失。对同一转写和状态，纯文本模型无法因真实语调不同而改变输出；未编码的静音时长也不会因重复推理自动成为新信息。

## 3. 当前分析与后续条件性验证

XTX-007 已以已有结果、源码、公开资料和少量数据样例形成实际报告，并完成“先审核监督”的路线讨论。XTX-009 首轮来源审核先于输入环境实施，原因是它只检查监督可获得性，不需要生成部署训练样本；正式数据冻结仍依赖 XTX-008。以下 A—F 继续作为条件性验证设计，不因首轮审核完成而自动推进训练。

| 步骤 | 具体检查 | 应留下的产物与继续条件 |
| --- | --- | --- |
| A：资产与协议核对 | 源码、权重、tokenizer、动作 ID、聊天模板、上下文上限、精度 | 版本锁与实际输入示例；先排除模板和目标位置错误 |
| B：数据可用性分析 | 来源、当前可见信息、标签依据、四类覆盖、分歧与泄漏 | 数据清单、试标报告、分组切分与缺口；标签不可靠时先修数据 |
| B 的输入核验 | 因果 VAD 的语音活动、静音时间与 ASR 到达时序，新增观测的版本化输入 | 对齐后的少量轨迹与输入合同；冻结 VAD 参数，确认无 EOF 补点及未来泄漏 |
| C：未训练基线 | 单句与真实多轮输入对照，默认决策与开发集校准对照 | 分数分布、PR 曲线与错误分类；确定微调还需解决什么 |
| D：训练机制与资源探针 | 少量样本前后向、损失掩码、梯度、显存、步耗时、保存重载 | 训练机制与资源记录；通过后才进行小规模试训 |
| E：试训与独立验证 | 相同输入、同等校准条件下比较训练前后表现 | 四类动作、事件级错误和延迟；区分有效、无效与证据不足 |
| F：决策 | 汇总收益、回归、标注成本与声学错误 | 决定继续文本适配、补数据，或转向音频控制模型 |

每一步保留失败原因。方法文档不能替代 XTX-007 的实际报告和讨论；后续探针能做反向传播也不能倒推训练必要性已得到论证。

## 4. 数据与监督是否可获得

### 4.1 首轮覆盖

首轮以现役 Nemotron 的英文场景为主。中文可作为独立诊断切片，不能用中文改善替代英文验收。动作仍为以下四种状态与动作组合：

| 当前状态 | 目标动作 | 必须覆盖的情况 |
| --- | --- | --- |
| Listen | keep | 未完表达、句内停顿、列举或解释仍在继续、完整短句后仍持有话轮 |
| Listen | start | 用户明确让轮后的陈述、请求、问题，以及对前一轮提问的完整回答 |
| Speak | keep | 不要求系统停下的用户短确认或附和 |
| Speak | stop | 用户提出真实打断、纠正或新的对话要求，需要系统让轮 |

句型和动作交叉覆盖，避免形成“问句=start、陈述句=keep”的新捷径。Speak/keep 只表示继续说，不据此触发系统附和。

优先使用成对样本：同一上下文下的未完成前缀与已让轮表达；相同短确认在回答问题和随声附和中的不同含义。还要保留困难负例，例如用户说完一个语义完整的分句后继续列举。不能只用随机截断制造所有 keep 样本。

### 4.2 来源与规模核查

先检查现有资产中是否确实存在可用训练语料。当前 FLEURS 与 FDB 证据属于评测资产，不作为训练或阈值选择来源；不假定官方 550 万预训练样本或合成微调语料可以直接获取。

可核查的补充来源之一是 [Easy-Turn-Trainset](https://huggingface.co/datasets/ASLP-lab/Easy-Turn-Trainset)：公开训练集带转写及 complete、incomplete、backchannel、wait 标签。但必须逐项核对语言、上下文和标签含义，尤其不能把 wait 直接等同于 Speak/stop，或把孤立 backchannel 强行补成某个播放状态。它只能补充部分监督，不能直接覆盖四类控制合同。

先读取元数据并估算可筛选数量、下载粒度和成本。该数据页列出的全量文件约 97.3 GB，超过本轮新增资产预算，不全量下载；若存储格式无法低成本筛选，记录为当前不可用，不绕过预算。

建议先试标约 200 个独立对话或场景，检查标签可判定性和主要错误；试标样本只进入训练或开发，不并入独立测试。随后才确定试训清单，首轮训练动作快照不超过 2,000 条。开发与测试分别争取至少 100 个独立对话或场景，并报告每类的实际事件数；这些是分析预算，不是已获得的数据量，也不是后续大规模训练的总量上限。覆盖不足时只能报告探索性结果。

真实对话不足时，可构造明确标注来源的用户—助手对话及前缀对照，但测试需保留独立真实来源，不能仅用同一生成模板证明泛化。人工审核覆盖通过与拒绝、正例与负例；生成模型和审核模型一致不代替人工核查。

### 4.3 因果性、记录与切分

每条样本至少记录以下信息；元数据与送入模型的内容分别保存。

| 信息 | 建议字段 | 用途 |
| --- | --- | --- |
| 来源与分组 | `source_id`、`conversation_id`、`scenario_id`、`pair_id` | 追溯、去重与分组切分 |
| 当前观察 | `messages`、`input_version`、`observed_until` | 确认当时实际可见的历史和前缀 |
| 状态与动作 | `state`、`target_action`、`event_id` | 合法动作监督与事件归并 |
| 标注依据 | `label_source`、`review_status`、`ambiguity` | 区分录制事件、合成目标、审核与分歧 |
| 时间与停顿 | `event_window`、`pause_source` | 离线时间核对，不作为隐藏结束提示 |

模型和动作审核只看当前可见信息。后续录音可用于离线确认实际事件边界与续说事实，不能混入输入或教师提示，不能通过未来结局强行消除当前歧义。相同归一化输入和状态若存在冲突标签，应追查来源并标记歧义，不简单多数投票或把冲突 keep 全部删掉。

按原对话、场景和模板族分组，再切 train/dev/test；配对样本、同一录音的窗口、ASR 版本及改写不得跨集合。先冻结分组清单，再生成派生视图。所有视图另计，不能充作新的独立对话。

参考转写可以用于离线分析；拟用于部署的效果必须在实际在线 ASR 前缀上验证。未来词汇、最终全文和录音 EOF 不进入模型输入，不用离线末词位置生成 pause。VAD 辅助样本必须保留同一时刻的真实音频观测或明确标记的因果模拟来源；仅有文本的样本不编造精确静音时长，不将模拟数据效果冒充真实在线效果。

## 5. 先测不训练能改善多少

完整方案可比较单句 PT 默认决策、多轮 PT 默认决策及相同多轮下的校准 PT。按最新用户指令，当前先比较相同多轮输入下 Listen 的默认与校准阈值，Speak 校准后置，不以其缺少数据阻塞本实验；未来训练前后对照仍需分别评价四类回归。

不预设一个新的 start 阈值。先查看完整与未完成陈述的分数分布、PR 曲线及配对排序，再依据事先约定的误抢话和误停预算选择工作点。测试集只使用已冻结工作点；不能用这批 FLEURS 的 start 比例选阈值。

XTurnix-ZH-Base 可作为独立的官方微调参考，不能把其中文定位解释为英文效果保证。若增加音频对照，优先离线比较 VoxTurn，并保留输入、硬件和触发策略差异；不要求为开展 XTurnix 试训先部署替代控制器。

训练时采用新的 VAD 辅助输入时，还需在完全相同的输入和触发协议下测量未训练 PT，以区分新增观测、触发方式和参数更新的贡献。官方文本基线单独报告，不能只比较“旧文本管线”和“新观测＋新权重”的总差异。

需要记录两类结论：校准已经解决的大部分偏置，以及校准后仍无法区分的错误。后者才是首轮训练应重点覆盖的内容。

## 6. 小规模训练的技术可行性

本节仅描述候选试验。XTX-007 的分析与讨论尚未完成时，不安装训练环境、不编写训练入口、不进行前后向或更新参数。

### 6.1 模型与输入合同

起点沿用 `xcczach/xturnix-pt@d4b0403e5a6744b46fa7602b6d77bbac2768d5b5`，复核权重和 tokenizer 哈希。根据冻结的 [config.json](https://huggingface.co/xcczach/xturnix-pt/blob/d4b0403e5a6744b46fa7602b6d77bbac2768d5b5/config.json)及[官方管线](https://huggingface.co/xcczach/xturnix-pt/blob/d4b0403e5a6744b46fa7602b6d77bbac2768d5b5/turn_pipeline.py)，预检应包括：

- 两个状态、三个动作和 pause 均为既有单 token；不新增词表、不改其 ID。
- 官方文本基线使用标准状态 system prompt、交替的 user/assistant 历史，并以当前用户消息结束；模型权重不替代真实运行状态。
- 训练和推理均关闭 thinking，按官方规则处理最后用户消息的末尾标点。
- 上下文沿用 XTurnix 的 2,048 token 上限，计入提示词、历史、模板和目标；不使用底座更大的位置上限擅自扩窗，不静默截断。
- 首轮先复现上述官方文本基线，再冻结 VAD 辅助输入协议及单独版本的预处理。实际语音活动与静音持续时间作为外部观测，不能伪装成用户发言；原版管线的固定提示词校验不直接兼容新增块，需要明确适配与对照。不在句末附加合成 pause 代替真实观测。

### 6.2 监督目标与参数更新

建议首轮采用 LoRA 监督微调，冻结底座，不从头训练。仅在当前预测位置监督一个合法动作 token：历史用户/助手正文、状态提示、模板和 padding 的损失均屏蔽；后续 CoT 输入也必须屏蔽。采用下一 token 的词表交叉熵，推理仍按状态比较两个合法动作分数，不让模型生成回答或解释。

先用少量可人工检查的样本验证：官方基线与官方推理前缀一致，扩展版本的训练与推理前缀一致；目标 token 位置和 causal shift 正确；只有目标位置参与损失；梯度确实流向 LoRA。新增外部观测块同样屏蔽损失。历史助手消息不能因通用 SFT 的默认规则而全部参与正文预测。

以下为一个起始配置，需经资源探针确认，不进行自动网格搜索：

| 项目 | 建议起点 |
| --- | --- |
| LoRA | `r=16`、`alpha=32`、`dropout=0.05`；先作用于 `q_proj/k_proj/v_proj/o_proj` |
| 学习率 | `5e-5`，作为小规模试训起点，不冒称官方最佳值 |
| 长度与批次 | 最大 2,048 token，micro-batch=1，梯度累积 16 |
| 训练长度 | 最多 2 epoch 或 200 个优化步，先到者停止 |
| 精度与内存 | 核验后使用 BF16、梯度检查点，训练关闭 KV cache |
| 类别处理 | 训练采样覆盖四类，控制同一事件的密集 keep 前缀；不默认叠加过采样和大类别权重 |
| 对照 | 首轮一个配置和种子；出现正向证据后，第二次用相同配置、另一个种子复核 |

先核对 FP32 与 BF16 的动作及分数差异；训练前后主比较使用相同精度和输入。保存底座 revision、adapter、tokenizer 引用及完整训练配置；重载后核对动作分数，不能只检查文件存在。初期不合并覆盖官方权重。

### 6.3 训练机制与资源探针

在远端调度 GPU 作业中执行小批样本的前后向，逐步测量 512、1,024 和 2,048 token 下的峰值显存与步耗时，覆盖真实长度分布。用极少量明确样本检查损失能否下降、目标动作分数能否变化；这只证明优化链路可用，不计泛化成绩。

0.6B 参数的权重本身约需 BF16 1.2 GB 或 FP32 2.4 GB，仅是数量级下界。激活、全词表 logits、梯度、优化器和检查点会增加占用，不能据此承诺单卡必然装得下。用实测步耗时估算完整试训耗时并留出保存、验证和退出余量；超出上限时停止或缩短试验，不能静默截断样本。

## 7. 评价标准与继续条件

### 7.1 如何证明有效

训练前默认决策保留为参考；主结论比较“校准后的原模型”和“按相同开发规则校准后的训练模型”，避免把单纯更积极接话算成训练收益。

| 方面 | 必报内容 |
| --- | --- |
| 陈述句接话 | 完整陈述的 start 召回、漏接话；与问句、请求、上下文回答分别统计 |
| 合理等待 | 未完成表达及句中停顿的误抢话，包含语义完整分句后的继续表达 |
| 用户打断 | Speak/stop 召回及延迟、用户附和导致的误停 |
| 整体区分 | 四类混淆矩阵、宏平均指标、PR 曲线；完整计划分母及失败 |
| 在线行为 | 每个机会的提前、有效、迟到或未触发；条件延迟 P50/P95 和命中数 |
| 泛化与资源 | 不同来源、ASR 误差与长度切片；显存、RSS、吞吐、保存和重载结果 |

离线动作快照用于诊断，在线重复判断按事件归并：一次错误 start 不能被后续多个 keep 稀释。延迟只在相应事件上计算，并同时报告覆盖和未命中，不能把缺失填成零。

开发集上先约定误抢话、误停预算和可接受回归幅度，在测试前冻结。按照原对话或场景做配对比较与置信区间，不把重叠窗口当独立样本。若方向正向但样本不足、区间过宽，只能判断值得扩大验证，不能宣称已经改善。

后续在线诊断仍采用影子决策，输入仅含当时可见信息；不接 Layer 1/2、TTS 或真实停播执行。这样得到的是控制动作延迟，不是用户可听接话或停播延迟。

### 7.2 如何决定下一步

| 观察结果 | 判断与下一步 |
| --- | --- |
| 多轮上下文和校准已达到可接受水平 | 当前主要是输入或工作点问题；普通接话不急于扩大训练，后续训练聚焦任务策略 |
| 试训改善陈述句召回，误抢话与误停受控，独立数据和第二种子方向一致 | 支持继续 XTurnix 领域适配，再评估数据扩充与 CoT 条件化训练 |
| 只提高整体 start 比例，PR 权衡无改善或明显损伤 Speak 能力 | 不能认定有效；检查采样、标签和损失，不直接上线 |
| 仅训练集、同模板或参考转写改善 | 证据不足，检查过拟合和输入分布，不以增加 epoch 代替分析 |
| 相同文本存在依赖声学的歧义，音频对照在同等误触发预算下明显更好 | 优先评估音频控制底座，避免继续用文本监督强行拟合 |
| 数据、资源或保存重载不满足要求 | 记录阻碍项；不能进入扩大训练或宣称可部署 |

### 7.3 CoT 条件化训练的后续可行性

普通控制通过后，再依据[倾听训练约定](../../research_design/listening.md#7-倾听训练数据与训练目标)分析主动介入数据。输入需要可追溯的 CoT 发布版本、观察截止点和真实 Listen/Speak 状态，覆盖尚未返回、已过期、缺口自行消解与已有介入等情形；CoT 本身不能带动作建议或候选问句。

官方管线只接受固定提示词和对话角色，不能把 CoT 伪装成用户发言。实施前要设计单独版本的内部分析输入、确认 2,048 token 预算、修改对应预处理并补充文档；与原版分别评测。控制目标独立审核，不能把“有 CoT”或“有信息缺口”自动标成 start。当前尚无这部分数据和输入协议，不能把普通话轮试训通过解释为 CoT 训练已经可行。

## 8. 资源、记录与交付

XTX-007 分析与讨论及随后获准的首轮来源审核未消耗下列 GPU 试训预算。表中资源与规模供估算和讨论，不能视为已经同意自动启动相应作业。

沿用[远端目录约定](../../remote_workspace.md)。拟使用独立训练 conda 环境，只读引用冻结 PT 权重，不升级现役 ASR、TTS 或 XTX 推理环境。GPU 训练和真实模型测试均在远端调度作业内执行。

| 项目 | 可行性阶段建议上限 |
| --- | --- |
| GPU 与工作数 | 1×24 GiB GPU，最多 1 个活动作业；训练与模型评分串行 |

每次运行建立独立 `run_id`，记录源码提交、数据分组与哈希、底座与依赖版本、实际样本数、训练步数、阈值选择过程、资源峰值、退出码和清理情况。后续脚本应具备超时和资源停止机制，而不只在报告中声明限额。
