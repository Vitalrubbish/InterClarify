# ASR 时间信息辅助的无训练话轮控制路线

更新：2026-10-24。用户明确决定先利用 ASR 提供的时间信息、不训练模型，并归档训练相关工作单。本路线由 [XTX-014](../../issue/XTurnix/xtx_014_asr_time_control.md) 承接；随后用户要求检查并尝试原生 pause，当前先进行[pause 机制诊断](pause_usage.md)，完整 ASR 时间适配尚未完成。先验证 Listen 下 keep/start，Speak 校准继续后置。

## 1. 为什么调整

[Listen 文本校准](../../../reports/xturnix_training/20261023-listen-calibration/README.md)在留出集上将误抢话由 10.78% 降至 5.39%，末端接话召回却由 44.31% 降至 28.74%，未达到原定工作点。固定文本分数配合单一阈值没有取得需要的权衡，因此先增加当时可获得的时间观察。

ASR 无文字更新的间隔可以作为带延迟和误差的静默估计。独立 VAD 不是必要前置；此前一律禁止利用该间隔、要求先引入 VAD 的约束过强，现按用户决定修正。NVIDIA 的 token-silence 端点实现也以最后非 blank 帧后的间隔工作，可作为时间观测思路的参考；本项目仍复用当前 Nemotron/Transformers 后端，不因此更换运行库。[参考实现说明](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/main/docs/asr/configuration.md#endpointing)。

## 2. 第一版观测合同

| 观察 | 含义与取得方式 |
| --- | --- |
| 当前转写及版本 | 复用原生在线前缀、有效增量、会话 ID；保留原始文字 |
| `text_idle_ms` | 当前单调时钟减最后一次有效转写增量到达时刻，作为静默估计，不冒充精确声学静默 |
| 输入音频进度 | 已接收的真实样本数及接收时刻，用于识别网络输入中断 |
| ASR 消费进度与健康 | 已消费样本数、最近进度变化、错误和结束状态，用于识别积压或计算停滞 |
| 状态与来源版本 | 实际 Listen/Speak、当前输入版本、语义分数对应版本和计时策略版本 |

有效文字变化沿用既有末尾标点归一规则，内部标点保留；词内增量同样计入，不等待整词才重置。单纯末尾标点/空白变化另记，不重新伪造发声时刻。新有效增量到达时重置 `text_idle_ms`。从未收到有效文字时，时间值为缺失，继续等待，不从会话创建时刻推定已让轮。

当前服务的 `consumed_samples` 在特征窗口读取时推进，不等于解码器已经完成对应帧的推理。这一信息可帮助判断输入与消费是否推进，不能直接命名为“已解码截止点”。若实现时可因果取得非 blank 帧或可靠解码进度，则单独记录定义与音频时间；第一版不以提供这些额外字段为前提。

时间计量基于实际在线到达，必须在持续音频流中记录。ASR 延迟、网络中断、消费停滞与健康异常分别保留；异常期间无增量不能自动计为可接话的时间证据。此前 160ms 配置和历史平均词延迟不是固定延迟或最坏上界，不能直接减去一个常数就宣称得到真实静默。

## 3. 不训练时如何用时间

第一版复用冻结 PT 的官方输入模板、分词器和权重，不扩词表。先核查并尝试原生 `<|pause|>` 的 pending/gate 合同；ASR 时间估计可以提供停顿事件，但事件生成尚待因果验证，不能假定句末追加 pause 就等于官方用法。停顿 token 不编码连续毫秒值，时间与语义阈值联合仍作为后续候选；不向官方固定 prompt 塞入模型尚未验证理解的 `silence_ms` 字段。

候选选择规则为：根据 `text_idle_ms` 所在时间区间，对 Listen 的 `p_start` 使用相应阈值。较长的有效无增量间隔可以对应较低 start 阈值，以争取接住原先低分的真实末端；较短间隔保持保守。时间区间、最早允许动作时间、阈值和缺失值行为在开发集确定，独立评测前冻结，本文不预设具体毫秒值或上线门槛。

先保留一个“固定最小等待＋固定语义阈值”简单对照，再判断分时长阈值是否有额外收益；候选数量与搜索范围在实现前固定，不能无界扫参。无训练指不更新模型参数，开发集上的阈值/时间配置选择仍需记录并与测试隔离。

ASR 增量触发新的语义打分；无增量时，跨越已定义时间区间边界可基于同版本的缓存分数重新选择动作。这里变化的是控制策略观察，不要求对完全相同文字重复调用模型。单会话最多一个在途模型请求、一个待处理最新观察；新前缀已到而分数仍旧时，不用旧分数提交新前缀的 start。状态变化、会话结束和异常都会使旧观察失效。

时间与语义选择属于同一个控制策略版本，仍经唯一仲裁执行点提交。当前验证只记录影子 Listen 动作，不启动真实播放，不与 DuplexCascade 同时执行；已听内容不可撤销。Speak 下继续沿用原有路径，本轮不把文字无增量解释成 stop。

## 4. 先验证什么

先检查少量真实因果轨迹：持续讲话、词内无新字符、句中停顿、轮末静默、恢复讲话、ASR/网络停滞和 EOF 排空。需要分清“ASR 正在正常消费而文字未更新”与“整个链路没有推进”，记录本次静默估计的实际可用性和误差；不通过未来词、录音长度、EOF 或解码补零制造停顿点。

随后在相同 ASR、精度、输入时钟和数据分组下比较：纯文本固定阈值、ASR 时间单独等待基线、时间与文本联合策略。评价以相同误抢话预算下的末端接话召回为主，兼报等待时间、漏接话、提前动作、过期/失败、推理开销与全部计划分母；按话轮归并错误，按原会话统计不确定性。改善召回不能只靠无限等待，预算和等待上限须在评测前明确。

上一轮已查看的 167 个留出话轮以后仅作回归/探索性诊断，不再称为新路线的独立测试，也不据其结果反复调参。参考词时间可以用于机制检查，不能替代真实在线 ASR 到达；后续声称在线收益时必须使用实际因果回放。FLEURS/FDB 继续不用于选择新策略配置，不恢复已取消测试。

若单靠 ASR 时间估计不足，再依据错误证据讨论 VAD 或其他观测；不会因本路线未达标自动恢复训练工作单。静默时间只提供时机证据，不证明文字或用户意图已被模型充分理解。

## 5. 实施与资源边界

ASR 时间完整适配尚未实现；用户随后明确授权的原生 pause 机制诊断先在远端短作业执行，不创建训练环境、准备训练集或编写训练入口。后续按 [XTX-014](../../issue/XTurnix/xtx_014_asr_time_control.md) 分步验收，复用现有 conda 与模型，不升级现役 ASR/TTS 环境。

真实模型/集群验证只在远端调度作业运行，最多 1×24 GiB GPU、8 CPU、32 GiB RAM、batch=1、1 个活动作业，单作业≤4 小时；下载和评分 worker≤2。启动空闲盘≥30 GiB，累计新增资产≤10 GiB、trace/报告≤2 GiB，不自动扩容。每个实验保留独立 run_id、源码/模型/输入哈希、配置、资源和退出证据；阶段 GPU 使用承接已发生作业记录，不按路线更名重置预算。

训练相关 XTX-008、009、011—013 已按用户指令搁置归档，未完成内容保留。XTX-010 的纯文本结果作为基线保留，Speak 校准不作为 XTX-014 的前置。
