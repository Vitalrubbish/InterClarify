## 1. 建议结论

**目前值得继续诊断 XTurnix，但证据不足以直接进入 VAD 辅助微调。建议先补监督来源与少量英文场景审核，再比较真实上下文和开发集校准。** 若校准已满足需求，可以不训练；若剩余错误主要依赖语调，应优先比较音频控制路线。只有校准后仍有可学习、可审核的错误，才值得申请受限试训。

| 问题 | 本次判断 | 仍缺什么 |
| --- | --- | --- |
| 必须训练吗 | 未证实；当前有动作偏好、上下文缺失与停顿不可见等混杂 | 真实英文对话的未训练、多轮和校准对照 |
| 四类监督可直接取得吗 | 有可访问素材，尚未得到满足合同的英文四类训练集 | Speak 状态、真实重叠、打断意图和因果到达时间 |
| VAD 辅助输入成立吗 | 技术上可设计，原版输入接口不能直接兼容 | 单独版本的输入合同、缺失值与因果对齐 |
| 单卡能训练吗 | 0.6B 加 LoRA 的数量级可讨论，未实测 | 长序列显存、步耗时、环境和暂存峰值 |
| 当前能启动什么 | 本报告及路线讨论 | 用户明确同意的下一阶段范围 |

本次只进行了已有报告复核、官方源码/元数据阅读和少量公开样例检查。使用现有本地 conda 环境 `interclarify-dev` 执行标准库检查；未安装环境或依赖，未登录服务器、启动 GPU 作业、生成训练数据、实现训练脚本或更新参数。没有改动现役控制器、原 FLEURS 配置及历史证据。

## 2. 已核查的证据与解释边界

### 2.1 项目已有实测

| 来源 | 已知事实 | 可以支持什么；不能支持什么 |

| [pause 诊断](../../../reports/xturnix_fleurs/20261023-pause-token-probe/README.md) | 100 条参考文本无 pause 时 start 1/100；句末 pause 后 0/100；问句 sanity 存在 start | ASR 错误不是唯一因素，start 路径可用；人工补点不能代表真实 VAD 停顿 |
| [XTX-002 协议](../../../reports/xturnix_fleurs/20261023-xtx-002-protocol/README.md) | 固定状态、去标点、合法动作与长度检查通过；没有启用停顿输入 | 已排除部分明显接口错误；不能排除目标领域、上下文或其他输入问题 |

原 pause 报告把陈述句 keep 解释为合理、把调用问题完全排除，结论偏强。本次保留原始数值，但不采用该推断：陈述句也会让轮，少量 sanity 不能证明所有条件正确。XTX-006 正式测试已取消，本报告没有恢复测试或借用其数据选择阈值。

### 2.2 官方证据

[XTurnix 论文第 5.3 节及附录 A](https://arxiv.org/html/2610.04400v1)明确讨论 PT 的 keep 偏好，并提出目标领域校准。英文 Smart-Turn 无 endfiller 子集的 PT start 召回为 3.47%、ROC-AUC 为 86.44%。这支持先检查排序与决策边界；这些异域结果不是本项目的预期收益，中文微调变体也不是英文适配保证。

[论文第 4.1 节](https://arxiv.org/html/2610.04400v1#S4.SS1)的训练标签依赖后续说话人及时间顺序，是离线构造依据。真实人类的下一步行为不一定等于助手应采取的动作；不能把自动标签直接当成策略金标，也不能在当前输入中泄漏未来内容。

### 2.3 四种错误需要分开处理

| 解释 | 当前证据 | 最小区分方式（尚未执行） |
| --- | --- | --- |
| 动作边界过于保守 | 默认 keep 多；官方结果显示存在排序信息 | 在独立开发来源上画合法动作分差的 PR 曲线，检查相同误抢话预算下的召回 |
| 缺少对话上下文 | FLEURS 为孤立朗读，现有结果未检验真实问答历史 | 对同一决策点比较末句与因果多轮历史，阈值规则保持一致 |
| 停顿没有进入输入 | 原协议只因 ASR 文本变化触发；无增量不代表无发声 | 检查真实音频活动、ASR 到达与观察版本；无新观察时重复调用不会产生时间信息 |
| 语调等声学歧义 | 当前没有同文本、不同声学实现的成对验证 | 收集经审核的成对例子；若文本和 VAD 仍相同但动作不同，纯文本适配存在信息上限 |

预期收益应表达为“在相同错误预算下，提高合适接话/打断覆盖或降低延迟”，当前无法给出可信百分点。普通接话诊断也不能验证后续 CoT 主动介入的收益。

### 3.4 标签与隔离是否可行

四类都需要“当前可见输入＋真实系统状态＋可审核动作”，不能只取语义标签。Listen/keep 要有句中停顿与完整分句后续说；Listen/start 要覆盖陈述、请求、回答；Speak/keep 与 Speak/stop 必须保留助手已播放前缀及用户重叠输入。短确认、等一下和停止解释等容易分歧，审核时应允许“当前信息不足”。

后续建议两人独立审核当前观察，再仲裁分歧；未来录音只用于离线核实续说与事件边界，不给当前动作教师看。遇到相同规范化输入/状态的冲突标签，先检查声学、历史和时间是否缺失，保留歧义或排除出确定性主评，不能多数投票制造确定标签。

按原会话、说话人及场景/模板族先分组，再派生前缀、ASR 版本和改写。DailyTalk 与 DailyDialog 派生内容视作同源，不能跨集合证明泛化；Easy-Turn 文件中的会话前缀只作候选分组，未验证前不允许按行随机切分。FLEURS/FDB 继续隔离。测试应来自独立、具备真实音频和时间的来源；当前尚未落实该来源，属于进入试训前的实质缺口。

初始建议先审核 40—60 个英文独立场景，检查四类是否可判定和原始素材是否能追溯。用户已同意并完成[48 个不同源会话的首轮辅助审核](source_audit.md)，其中 30 个为条件候选、18 个歧义项，没有确认 Speak/stop 候选，当前可直接冻结记录为 0。已阅样例仅作为训练/开发候选并排除出独立测试；正式约 200 场景双人试标尚未实施。训练≤2,000 个快照并不等于 2,000 个独立对话，开发/测试各≥100 个场景也不保证每类有足够事件。

## 4. 输入与训练机制的可行性

### 4.1 官方接口已经核实什么

核查固定 revision 的 [config](https://huggingface.co/xcczach/xturnix-pt/blob/d4b0403e5a6744b46fa7602b6d77bbac2768d5b5/config.json)、[tokenizer 配置](https://huggingface.co/xcczach/xturnix-pt/blob/d4b0403e5a6744b46fa7602b6d77bbac2768d5b5/tokenizer_config.json)和[管线](https://huggingface.co/xcczach/xturnix-pt/blob/d4b0403e5a6744b46fa7602b6d77bbac2768d5b5/turn_pipeline.py)：

- 状态 ID：listening `151669`、speaking `151670`；动作 start `151671`、keep `151672`、stop `151673`；pause `151674`。无需新增词表，本次只核对配置映射，未重新加载 tokenizer 做编码实测。
- 固定 system prompt，user/assistant 交替且末条为 user，最后用户文本去尾标点，关闭 thinking；训练合同上限为 2,048 token。旧历史按完整轮次移除，末条放不下会报错，后续需记录被移除历史。
- 推理在最后输入位置取得下一 token logits，对两个合法动作重新 softmax。返回分数是条件于动作对的分数，不能当作校准过的真实正确率。

### 4.2 VAD 扩展需要解决的具体问题

官方 `prepare_messages` 会检查精确 system prompt 和角色；新增 tool、任意 system 后缀都不属于原接口。把时间写进用户文本虽然可能通过字符串校验，却混淆观测来源，也不能证明权重理解字段。因此必须另建版本的预处理和输入合同，保留原版对照；本报告不冻结具体格式。

候选外部观测至少区分真实语音活动、已观察静音时长、ASR 是否尚未交付、观察截止点和实际 Listen/Speak。时长从因果音频帧计算，不能从最终词位置、录音长度或 EOF 计算；文本素材缺时长时明确缺失，不填虚假精确值。Speak 历史只含已实际可见/播放内容，不能把尚未播放的完整回答当成历史。

训练与推理必须使用同一观测版本、量化/缺失规则、角色归属、标点和截断规则；每条样本保留音频截止点、ASR 接收版本和输入摘要。触发来自真实 ASR/VAD 变化或合同中定义的时间桶跨越；不对完全不变的输入反复请求来表示等待。

VAD 能补发声和时间，不能补音高、语调、音色或重叠语义。相同文本/状态/VAD 观测对应不同应答动作时，增加训练次数不能恢复未观察信息。当前也不继续采用句末合成 pause。

### 4.3 只监督动作可以实现，但尚未验证

候选做法是冻结底座，在注意力投影加入 LoRA；输入正文、状态、外部观测、历史和 padding 的标签为忽略值，只保留当前一个合法动作 token 的词表交叉熵。因果模型在前一位置预测该动作；不能把标签放错一位，也不能默认监督所有历史助手正文。[Qwen3 训练接口](https://huggingface.co/docs/transformers/v4.57.1/en/model_doc/qwen3)和 [PEFT LoRA 接口](https://huggingface.co/docs/peft/main/en/package_reference/lora)支持构造该机制，但本项目未做梯度、损失掩码或保存重载实测。

“输入位置不计算预测损失”不等于“模型不利用输入”；动作损失仍通过上下文计算更新 adapter。未来若加入 CoT，它也是输入而非动作标签；本次不涉及该训练。

### 4.4 独立控制与同卡延迟

独立请求通道有利于在 Layer 1 正文生成期间受理控制，但不同进程仍共享 GPU 内核、显存和调度，不能保证无排队。后续需测控制请求排队、推理服务时间、ASR 竞争和过期返回；保持单会话最多 1 个在途请求和 1 个待处理最新观察，按状态/输入版本拒绝过期动作。

XTurnix 只提交决策，实际 start/stop 仍经唯一仲裁器和单一 TTS 播放所有者；已听内容不可撤销。本轮影子结果不执行播放动作，不新增 Layer 3 或第二条控制执行路径。

## 5. 成本估算与预算是否足够

下表除历史资源行外均为计算或规划值，不是训练实测。GPU 型号按已有 A10 24 GiB 记录讨论，不跨硬件套用性能。

### 5.1 参数、显存和存储

固定 config 为 28 层、hidden 1024、16 个查询头、8 个 KV 头、head_dim 128、词表 151,936、共享输入/输出 embedding。由此得到 q/o 投影维度涉及 2,048，而不是全部 1,024。按这些维度计算底座约 596,049,920 参数；这里只作结构估算，未枚举真实权重张量。

| 项目 | 估算或历史事实 | 含义 |
| --- | --- | --- |
| BF16/FP32 底座权重 | 约 1.11/2.22 GiB | 仅权重，非训练显存 |
| 注意力 q/k/v/o、r=16 LoRA | `28×16×(3072+2048+2048+3072)=4,587,520` 参数，约底座 0.77% | 不含 MLP、embedding 或新增词表 |
| adapter 参数/梯度/优化器 | 按 16 B/参数粗计约 0.068 GiB | 实际 dtype、主权重与优化器实现待测 |
| 2,048 token 全词表 logits | BF16 约 0.580 GiB；FP32 约 1.159 GiB | 损失只保留一个标签，不保证前向只分配一个位置的 logits |
| 激活、注意力、CUDA 与临时张量 | 未测 | 不能用上述小计承诺峰值；拟用梯度检查点、micro-batch=1、关闭 KV cache，停止线 22 GiB |
| 历史推理资源 | XTX-005 整个作业 GPU 峰值 5,972 MiB | 不能换算为训练峰值 |
| 历史环境/模型 | XTX-002 apparent 环境约 7.43 GiB、模型约 1.13 GiB | conda 硬链接使当时实际新增较小；新的训练环境不能假定同样节省 |
| adapter 文件 | 每份 BF16/FP32 参数约 8.75/17.5 MiB，四份约 35/70 MiB | 另计优化器等恢复状态；避免 embedding 全量保存和底座重复保存 |

新环境若完整复制相近的约 7.43 GiB 依赖，再叠加缓存、音频和报告，很容易接近 10 GiB 新增资产上限。是否有兼容包可只读复用、conda 硬链接是否跨文件系统、安装解压峰值多大，必须在后续预检核实；不能把历史 893.91 GiB 可用当作今日配额，也不能把旧环境计数从阶段预算重复扣除或重复赠送。

音频只作量级估算：16 kHz、16-bit、单声道为每秒 32,000 B；2,000 个互不重复的 10 秒片段约 0.60 GiB。真实场景可能有长历史、双声道及重复派生窗口，必须按源音频去重预算，并计压缩包与解压共存峰值。整个 Easy-Turn 归档路线不符合当前上限。

### 5.2 GPU 时间

候选 micro-batch=1、累积 16、最多 2 epoch 或 200 个优化步，以先到者为准。若恰有 2,000 个训练快照，200 个更新对应约 3,200 个微批次，仅约 1.6 epoch；不能把优化步和前后向次数混为一谈。

| 单微批次前后向耗时假设 | 3,200 个微批次的计算时间 | 判断 |
| --- | --- | --- |
| 0.5 秒 | 约 27 分钟 | 仍需额外计验证、保存和启动 |
| 2 秒 | 约 107 分钟 | 可能放入受限试训，尚无 A10 实测支持 |
| 5 秒 | 约 267 分钟 | 计算本身已超过单作业 4 小时，必须缩短或停止 |

8 GPU 小时是整个阶段上限，含未训练基线、训练机制探针、两次试训和独立验证。候选分配可为基线 1h、机制探针 0.5h、试训各 2.5h、验证 1h、余量 0.5h，合计 8h；不是每项都能占满后再额外运行。第二种子仅在首轮开发集有正向证据且剩余预算足够时执行；长录音实时回放也占用预算，应先按冻结音频时长检查可否安排。

以上只是敏感性分析，没有测出可承诺的训练速度或 GPU 费用。维持 1×24 GiB GPU、8 CPU、32 GiB RAM、1 个活动作业，数据/评分 worker≤2、下载并发≤2；训练与同卡模型评分串行。触限保留失败，不自动扩卡或扩盘。

### 5.3 人工成本

按两名审核人每个独立场景各 2—4 分钟，200 个场景的首轮审核约 13—27 人小时，仲裁与说明整理另约 4—8 人小时。后续 2,000 个快照若每条各需 30—60 秒复核，双人约 33—67 人小时；若可共享场景审核，应记录真实节省，不能直接假定全免。另需独立开发/测试、音频听审、对齐和失败清理时间。当前没有记录工时实测，候选总量未证明足够覆盖四类。

| 路线 | 当前支持与预期价值 | 主要代价或限制 | 建议 |

## 7. 最小验证设计与停止条件（仅首轮审核已获同意）

### 7.1 建议按证据逐步决定

1. **先补非训练证据**：小规模英文来源与场景审核，确认四类、原始历史、音频及因果时间能否取得；没有可审核 Speak 监督或独立测试来源，就暂停训练路线。40—60 个场景只做可判定性检查，不作为正式质量结论。
2. **若同意实施，再冻结输入和数据**：分别保留官方文本、真实历史、VAD 扩展版本；由用户确认对现有 XTX-008—010 的推进范围，不跳到 XTX-011。若决定只做校准，应先同步相关现有工作单依赖与方法说明，不新建未经指令的 issue。
3. **比较未训练与校准**：Listen 使用 start/keep 分差，Speak 使用 stop/keep 分差；各自仅在开发集选阈值。若已满足事先商定的错误和延迟预算，普通控制不进入训练。
4. **仅对剩余可学习错误考虑 LoRA**：新输入同协议、同精度、同触发条件比较未训练与训练，双方使用相同校准规则；单独保留官方文本基线，区分输入贡献与权重更新贡献。

### 7.2 如何评价值不值得继续

| 指标 | 统计约定 |
| --- | --- |
| 误抢话 | 用户仍持有话轮的独立机会中，任一提前 start 记该机会失败；不能用大量 keep 快照稀释 |
| 误停 | 不要求让轮的用户附和机会中，出现 stop 的比例 |
| 合适转移 | Listen/start、Speak/stop 分别报告召回、漏触发、过期和失败；keep 两类同步报告 |
| 动作区分 | 四类混淆矩阵、状态内 PR 曲线，陈述/问句/请求/回答/附和/打断切片 |
| 控制延迟 | 从离线审核的可行动窗口起点到有效动作返回；另报观察到达、排队与推理耗时，VAD 等待计入总延迟 |
| 延迟与覆盖 | P50/P95 只在命中条件下计算，同时列命中数、null、提前、窗外、未触发和运行失败 |
| 不确定性 | 按独立会话/场景配对比较与区间估计；同一会话的窗口不是独立样本 |

建议讨论目标工作点是否先采用误抢话/误停各≤5%，并要求在相同预算下提高转移覆盖、控制延迟不回归；这只是讨论用起点，**本报告没有冻结 5% 或任何延迟门槛**。明确事件窗口、延迟预算、最低覆盖、最小有意义收益和回归容限后，才能选择阈值或检查点。不能在看完测试结果后移动门槛。

100 个总场景若均分四类，每类可能只有约 25 个事件；即使某类 0 错误，95% 单侧错误率上界仍约 11.3%。必须报告真实类别分母，不能把总样本量写成每类有力保证。该上界按独立 Bernoulli 假设由 `1−0.05^(1/25)` 得到，相关事件只会进一步削弱证据。

满足以下任一情况应停止扩大训练：监督来源无法满足因果性与隔离；上下文/校准已经解决主要问题；新增模型只提高 start/stop 频率而没有改善相同错误预算下的权衡；收益只发生在训练集、同模板或参考转写；误停、误抢话或资源越线；残余错误需要未观察的声学信息。方向正向但样本不足应记“证据不足”，不能写通过。

影子测试只得到控制动作与返回延迟，不能报告可听接话/停播时间，也不能验证 thinking 流任务收益。保留全部计划分母及失败，未命中不填 0 ms。
