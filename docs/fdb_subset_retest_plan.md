# 新英文主线的全链路 FDB 子集推进方案

日期：2026-10-18。当前主仓库为 `main`；本地独立 X-Talk checkout 为 `dev@c68d81a`。本方案依据现有代码和历史实测提出下一步顺序，本轮没有实现新适配器、提交集群作业或启动训练。

## 1. 先解决的阻塞

目标链路是 **Nemotron EN 160ms → 现有 DuplexCascade Layer 1 → Pocket TTS → X-Talk 唯一播放管理**。当前选型已经完成，运行时接入尚未完成。

| 项目 | 核对到的现状 | 对下一轮的影响 |
| --- | --- | --- |
| Nemotron ASR | `xtalk/src` 没有对应适配器，主仓库没有现役部署配置；历史五例官方权重接话仅 1/5 在 2s 内启动新正文 | 不能直接把 ASR 选型结果视作完整链路可用 |
| Pocket TTS | `xtalk/src` 没有对应适配器；测试过的接口接收完整字符串、流式返回音频 | 需要明确 LLM 文本何时组成可提交片段，以及取消后的旧音频如何隔离 |
| 现役诊断配置 | `configs/xtalk_duplex_x2_runtime.json` 固定 X2 + MOSS | 原样重跑只能得到旧组合结果 |
| 节点入口 | 只接受 `DUPLEX_ASR_BACKEND=x2`，固定启动 MOSS，并要求三张 GPU | 不能只换模型名就启动目标组合；Pocket CPU 不应继续占用第三张 GPU |
| 输入结束 | FDB 驱动发完文件后等待诊断尾窗；现有路径未显式触发连续 ASR 的真实 EOF 排空 | 必须核验尾部识别文本交付，暂停不能冒充 EOF |
| 指标 | FDB 批处理把传输完成写为 PASS，语义状态为 `PENDING_OFFICIAL_SCORING` | 必须跑对齐/评分，且补充新回答与停旧回答的证据 |

工程细节及原始证据分别见 [ASR 选择](asr_selection_decision.md)、[TTS 选择](tts_selection_decision.md)、[历史缺口清单](x2streaming_asr_retest.md#10-修复与诊断清单2026-10-16-复核)。不恢复已退役的 Qwen3-ASR。

## 2. 推荐执行顺序

### 第一步：把接入和测量补齐

通用客户端适配放在独立 X-Talk fork，主仓库保留独立服务、部署配置、集群入口和实验记录；两处实现均同步对应中文说明。

- **ASR**：接入 Nemotron 真实流式输出，使用已选的 160ms 模型分块；音频运输包大小与模型解码块大小分别记录，不能随意等同。保证文本单调追加、结果在无新增音频时仍能交付、真实 EOF 排空、会话复位和取消后的代际隔离。保留现有每个 micro-turn 读取最新累计结果的机制，能力按后端显式声明，不默认把 X2 的生命周期照搬给 Nemotron。
- **TTS**：通过原有 TTS 扩展点接 Pocket，使用隔离的 CPU conda 环境。先确定普通字符串/文本段输入契约，核验 flush、finish、取消、排队、重采样及采样率握手。不能把原生音频帧流宣称为已支持增量文本。若需要聚合 LLM 文本，必须显式记录策略和聚合等待，并用实际逐增量输入测试，不能预先给它完整回答。
- **真实音频输入**：对有限文件输入实现明确 EOF，并等待在线尾部交付；持续麦克风、声学暂停和普通话轮结束不因此重建会话。EOF 不传给 LLM 作为隐藏“用户已说完”标签。官方计分音频之外的尾窗只能作诊断。
- **运行与资源**：为 Nemotron/Pocket 新增显式配置和后端选择，不覆盖保留的 X2 诊断配置。初始资源预算为 LLM 一张 4090、ASR 一张 4090、Pocket 使用 CPU；显存、线程数及 CPU 配额先通过远端短跑校验，不预先保证资源足够。同步调整节点的三 GPU 硬检查与分卡逻辑。
- **来源冻结**：本地验证接口契约后固定两个仓库提交、权重、依赖、文本分片策略和回放配置。作业使用不可变源码快照与独立输出目录；禁止运行期间更新入口脚本。沿用单一协议执行者、单一 TTS 播放所有权，不加入 Layer 2/3 或系统附和。

本步只在远端运行真实模型。现有 `submit_xtalk_duplex_a4_job.sh` / `run_xtalk_duplex_a4_node_job.sh` 是改造起点，尚不是新组合的可直接执行命令。

### 第二步：先验证控制模型确实会接话

先用实时 ASR 轨迹进行小样本 Layer 1 验证，再跑完整声音链路。历史 Nemotron 的 1/5 不能证明必须训练，但足以说明不能跳过此步。

建议用已有五个 Candor 接话例作回归，再加入五个明确不应抢话的停顿/继续补充/用户附和例。所有条件使用各自真实 ASR 增量、到达时间与生成历史，固定官方控制权重及 600ms micro-turn，不加入句末补点规则、隐藏边界或替代语义决策器。

记录“2s 内新正文启动”作为与既有诊断一致的观察窗口，另保留超时后的诊断轨迹。初步进入全链路的建议门槛是正例至少 4/5 启动新正文，负例五例均不因空拍无条件抢话；这是小样本工程门槛，不是最终质量保证。若控制模型仍持续输出等待，先对照文本内容、增量分组、时钟、历史和标点，不先改窗口掩盖问题。

只有确认瓶颈属于 Layer 1 兼容性后，才按 [已有适配设计](asr_selection_decision.md) 盘点数据与小规模短跑，再决定是否执行原样、去句读、混合增强对照；不直接启动长周期训练。已有 FDB 回归样本不得进入训练。

### 第三步：真实声音 smoke，再跑固定 FDB 子集

先在远端做正常问答、句中停顿后继续、有效插话换话题、用户短附和、同会话连续两轮五类 smoke，重点确认：

- 真实输入在按墙钟发送，播放期间 ASR 和 micro-turn 持续工作；
- 新正文产生后能收到并播放非空音频，TTS 没有等待完整长回答才出首音；
- 有效插话停止旧 response，旧音频不会进入新 response；短附和不误停；
- 停止、EOF、flush 和 close 的职责分开；取消后不再交付旧代际结果；
- 就绪意味着真实音频预热、在线输出和清理均完成，不以 health 成功代替模型准备完成。

传输、生命周期或播放隔离失败时先修复，不靠增加 FDB 样本量解决。

## 3. FDB 子集与对照矩阵

冻结 FDB 源码为现有 `3e799c45a045256f47d5f1c9cda90157e2d2ec9e`，复用远端现有 v1.0 数据。该版本要求产生与输入时间同步的输出音频，再做转写对齐和任务评分，见 [官方说明](https://github.com/DanielLin94144/Full-Duplex-Bench/blob/3e799c45a045256f47d5f1c9cda90157e2d2ec9e/v1_v1.5/README.md)。

| 子集 | 首轮目录数 | 本轮用途 |
| --- | --- | --- |
| candor_pause_handling | 5 | 句中停顿避免误接话 |
| synthetic_pause_handling | 5 | 合成停顿控制、尾部文本交付检查 |
| candor_turn_taking | 5 | 需要接话时启动新回答及首音延迟 |
| synthetic_user_interruption | 5 | 停旧回答、启动与新话题相关的新回答 |
| icc_backchannel | 5 | 保留历史可比性与禁用系统附和后的行为诊断，不作为系统附和质量门槛 |

首轮共 25 个目录，其中 20 个为核心行为子集，5 个为范围受限的诊断。冻结具体 ID 与输入哈希，优先覆盖历史失败例；旧记录的“字典序前五个”只能作为回归，不是随机代表性抽样。目录有 clean/overlap 两个输入时按官方数据契约成对处理，同时报告目录数、变体数和实际会话数，不能直接称作 25 次请求。

**ICC 不能代替用户附和抗误打断测试。** 官方 `eval_backchannel.py` 统计系统短附和的频率及时间分布，而项目关闭系统附和；零附和导致的 Freq/JSD 变化不据此判为新底座退化。用户附和抗误打断在上述真实声音 smoke 中单独检查。官方实现见 [固定源码](https://github.com/DanielLin94144/Full-Duplex-Bench/blob/3e799c45a045256f47d5f1c9cda90157e2d2ec9e/v1_v1.5/evaluation/eval_backchannel.py)。

推荐首轮只做两组，使用同一份修正后的输入生命周期、控制模型、Pocket 配置和回放器：

| 条件 | 用途 | 比较边界 |
| --- | --- | --- |
| X2 + 官方 Layer 1 + Pocket | 已有 ASR 接口上的工程对照 | 检查 Pocket 接入及新回放流程，不把 X2 重新定为英文主线 |
| Nemotron EN 160ms + 官方 Layer 1 + Pocket | 目标英文主线的适配前基线 | 只改变 ASR；控制兼容性失败也要保留，不能不回复就剔除样本 |

若第二步显示官方权重兼容性不足，先记录该诊断，不宣称目标链路质量通过。后续获得适配权重时，仅替换 Layer 1，在同一批样本复跑。需要量化 TTS 替换收益时才追加同条件 X2 + MOSS；旧历史轮次的生命周期、镜像或记录方式不同，不能直接当成严格单变量对照。

## 4. 必须一起交付的指标

- **官方行为指标**：Pause 的 TOR 越低越好；Smooth Turn-Taking 与 User Interruption 的 TOR 越高越好。单独报告 user interruption 的相关性 judge，不把同名 TOR 在不同轴按同一方向解释。[官方指标定义](https://github.com/DanielLin94144/Full-Duplex-Bench/blob/3e799c45a045256f47d5f1c9cda90157e2d2ec9e/v1_v1.5/README.md)。
- **新回答覆盖**：需要回答的样本中，新 response 正文与新语音各自成功多少；分母保留漏答。模型拒绝接话、只有状态 token、旧正文续写或仅停旧回答均不能冒充新回答成功。合理静默的 pause 例不按漏答计。
- **停止证据**：实际 interruption token、stop request、播放停止及停止后旧 response 冻结分别记录；teardown 导致的停止不算有效打断。新话题回答是否相关另行检查。
- **延迟时间线**：标注的用户结束/插话时刻 → ASR 前缀交付 → 消费该前缀的 micro-turn/模型请求 → 首 token/新正文 → 文本片段提交 → 首 PCM → 首段可听代理/离线对齐首词。以实际 response_id/request_id 关联，不拼接跨请求事件，不用各组件独立 p50 相加冒充全链路延迟。
- **稳定性**：每条输入发送迟到、队列积压、ASR 回写/尾词缺失、空音频、播放断流、取消后的过期结果、冷启动和错误数。失败样本不剔除；缺失延迟留空并列出覆盖率。

结合项目已有目标，建议将标注的用户结束/插话结束到首个新语音的间隔作为端到端响应延迟，插话开始到旧语音停止的间隔另作停播延迟。响应延迟目标约 1s、平均不超过 1.5s，短问题单列亚秒覆盖率；成功样本的条件均值、p50/p95/max 必须与未回复率同时报告。首包里只有静音不视为已达到首音目标。首次小子集只用于定位，不能据此宣布总体 SLA 达标。

## 5. 评分、资源与产物组织

1. 推理作业运行真实全链路并保存 timeline、逐请求状态、带时间轴输出 WAV、日志及输入 manifest；官方 WAV 保持输入等长，默认 5s 额外尾窗另存 diagnostics，不能把窗外回答混入官方分数。
2. 推理结束释放服务 GPU，再以独立单 GPU 作业运行已有官方 ASR 对齐；judge 在单独阶段执行，避免多 GPU 作业内长期空转触发 LowGpuUsage。各阶段使用 conda。
3. 事先核验 judge 端点当前可用性，固定同一个模型及参数。旧脚本默认 `gpt-4-turbo` 不代表今天仍可调用；更换后明确记录，不与旧 judge rating 直接比较，必要时用同一 judge 重评对照。
4. 汇总依次给出：执行是否完成、传输/协议是否通过、官方语义分数、覆盖率及延迟、人工抽查。`fdb_scoring=SKIPPED` 或 `semantic_status=PENDING_OFFICIAL_SCORING` 只表示推理产物已就绪，不表示 FDB 验收通过。
5. 每个阶段先核验产物再进入下一阶段。25 目录回归能解释主要失败且机制正确后，再扩到各核心子集 10–20 个未参与调试的新目录；抽样规则和未回复分母固定，不按结果选样。

最终交付为固定来源清单、逐例行为与时间线、官方分数、端到端延迟分布、失败案例及关键试听。该轮验证阶段 A 参考底座，不把它包装成 Layer 2 澄清能力实验。
