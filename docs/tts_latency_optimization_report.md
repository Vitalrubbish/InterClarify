# TTS 端延迟优化报告

日期：2026-10-17。本轮作业均已结束，候选通过与否见结果。

## 结论与使用边界

本轮固定 MOSS 权重、音色与官方采样，保留唯一 TTS/播放所有权。实现了批次上限、开头编译和稀疏文本局部 prefill 的可关闭候选路径。产品默认配置未切换：模型输出与音质尚未通过人工试听、真实播放器和 FDB 集成验收。

首 PCM、波形 RMS 语音起点和模拟播放有声时刻是三个不同指标。模拟欠载使用立即消费、零启动缓冲的 headless 模型，不能解释为真实播放器已经断流。RMS 起点为 10ms 窗口、阈值 0.01，未人工核查；不能据此声称已完成扬声器首音测量。音频秒/墙钟秒包含连接、输入间隔和真实结束等待，不等于纯模型稳态 RTF。

本轮尚未达到拟议的可听首音 250–350ms、p95 不高于 500ms 预算，整体约 1 秒目标未做端到端验收。建议先扩大 prefill4 的稀疏文本验证，并补全组合配置、完整预热与人工试听；不直接将 deadline200 切为默认。

本轮实测要点：

- batch4 的整句配对首 PCM 平均提前 0.548 秒，中位数仅提前 0.011 秒，收益集中于长句。18 个整句/增量配对的 PCM 一致性见下表，不把平均收益外推到所有短答。
- 早期编译修复复测：前 10 帧 p50 从 1.443 降至 0.921 秒；正式响应的新图、token 和 PCM 差异分别核查。音频发生变化时不宣称逐 token 无损。
- prefill4 在 3 条文本 × 3 轮 sparse 筛选中，首 PCM 配对平均提前 1.099 秒，模拟有声平均提前 1.156 秒；这不是完整 30 条质量验收。
- deadline200 的 worker 文本至 prefill p95 为 0.201 秒，说明有界等待路径生效；正式区间仍有 1 条响应产生新图。首包或有声时间不能用 200ms 门槛等待替代，也不能去掉编译长尾后宣称达标。
- 独立 ASR 检查 135 条记录、20 个不同 WAV；重复轮次不等于同样数量的独立语音内容。逐模式词错误见下文，人工自然度仍未验收。

## 阶段分解与剩余问题

服务端阶段使用单一进程单调时钟，客户端端到端时间使用客户端单调时钟，两者不直接相减。prefill/step/codec/音色准备按区间分割，重叠单列，未归因等待不擅自称为排队。每响应的文本等待、前 1/5/10/50 帧及阶段数据在 JSON 摘要中；不存在的帧数为缺测。

启动兼容处理仅在 codec CPU 加载期间设为单线程，之后恢复 8 线程；它避免初始化停滞，不能归为热态首音收益。冷启动与首次新形状编译曾达数十秒，不能凭长句预热一次就认定所有短句均为热态。

小门槛与超时路径不伪造 final，文本流保持开启；但它们改变模型 prefix 条件。token 全部消费只证明输入没有在服务中丢失，不能证明生成语音没有漏词、重复或韵律退化。批次路径在相同采样条件下另核对 PCM 摘要，数值不一致必须保留并调查。
