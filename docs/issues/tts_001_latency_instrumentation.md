# TTS-001：补齐 TTS 分阶段计时与性能基线

状态：进行中：本地测量工具已实现，远端基线作业已启动，等待正式回放及结果核验。日期：2026-10-17。分支：`feature/tts-latency-optimization`。

## 问题

现有首包指标无法区分文本等待、排队、prefill、批量生成、codec 与播放开销，需要先建立可复核的当前基线。

## 依赖

无；本 issue 是后续优化的测量前置。

## 范围与共同约束

按 [延迟分析](../tts_latency_analysis.md) 的 1–4 顺序执行：先测量，再调整生成批次，再优化开头编译，最后依据占比优化。目标是降低短回答和澄清问句的可听首音延迟，同时保持语音连贯、自然和可打断性。

用户明确要求保留批量策略，适当降低每批帧数。此前“首帧生成后立即发送”的建议据此修订。帧数小不必然导致不自然，帧数大也不保证自然；模型上下文、codec 状态、供音节奏和播放器缓冲需要共同验证。本组 issue不预设逐帧发送方案。

本轮固定 MOSS 权重、参考音色、采样参数、ASR、LLM 和话轮窗口，不开展训练或模型替换。沿用 [工程方案](../engineering_implementation.md) 的单一协议执行者与单一播放所有权，不启用 Layer 2/3，不回滚已播放内容。所有集群测试在远端 conda 环境运行。

拟议 TTS 预算为“首个回答文本可用 → 客户端可听首音”约 250–350ms，p95 目标不高于 500ms；这是优化方向，不能视作已有性能或整体 1 秒目标的保证。

## 共同实验协议

先记录并核对实际加载的 MOSS、服务适配器、X-Talk 和本仓库源码提交及补丁摘要，固定模型 revision、依赖、GPU 与音色文件摘要。复用本地及远端 conda 环境，必要时为实验新建隔离环境，不直接升级现役依赖。

每个实验只变更一项；步骤 3 使用步骤 2 已通过的配置作对照，同时保留原始基线用于比较累计收益。冷启动、编译预热和正式热态测试分开记录。独占同型号 4090，按交错顺序运行对照，避免其他 GPU 任务干扰。

文本集至少覆盖 30 条非 FDB 短答与澄清问句，另加长句、数字、专名、标点和极短回答。固定种子，热态至少重复 3 轮；既测试一次输入整句，也回放固定的 LLM 文本增量及到达间隔。两种输入模式分别汇总，不能混成一个延迟分布；新方案不得提前使用未来文本。

共同产物为逐响应时间线、配置与版本清单、完整 WAV、批次记录和汇总报告。汇总至少包含均值、p50/p95、样本数、无音频/失败比例、首包有效样本数、实时倍率、播放断流和显存。失败样本独立计数，不靠剔除失败改善均值。

自然度采用同文本、同音色、隐藏配置名的成对试听，重点听批次接缝、节奏、词尾、数字和长句，记录退化样本及原因；小规模试听用于筛选，不能声称已完成正式人评。

## 处理方案与验收

### 工作内容

沿同一 `request_id/response_id` 关联以下事件：

| 阶段 | 必需记录 |
| --- | --- |
| 文本和排队 | 首个文本可用、服务接收、队列进入/取出、实际 prefill token 门槛及达标时刻 |
| 会话准备 | 音色 token 缓存命中、模型/codec 状态准备起止、输入前缀长度 |
| 模型 | prefill 起止、首音频帧、每批生成起止和帧数、前 1/5/10/50 帧耗时、eager/compiled 计数 |
| codec 和传输 | 每批解码起止、首非空 PCM、PCM 样本数、发送和客户端接收 |
| 播放 | 实际消费起点、缓冲音频时长、欠载次数与持续时间、取消及最后消费的旧响应 |

服务端和客户端分别使用单调时钟；跨进程时钟不直接相减，使用可说明误差的对齐方式。GPU 阶段用 CUDA event 采样，避免每帧全局同步。完整 profiler 另跑，不把受 profiler 干扰的结果计入性能验收。

可听首音用保存 PCM 的能量/语音起点估计，并抽样人工核查；同时保留原始首 PCM 与首词对齐结果。远端回放器若没有真实音频设备，只能报告模拟消费和波形语音起点，不能称为扬声器实测延迟。

### 完成条件

同一有效响应的阶段可串联，能区分文本等待、排队、模型、codec 和播放；缺失事件明确标注。复现当前实际加载版本的基线，不要求强行重现历史约 0.73s。形成各阶段占比和批次大小与首音的关系后进入步骤 2。

## 集成回归要求（四项共用）

本地在 conda 环境验证确定性逻辑与现有相关测试，实际 GPU 性能和音质在远端验证。先通过组件测试，再使用冻结的同一 ASR/LLM 链路运行 FDB 小子集，对照顺畅接话、停顿、用户附和与插话，单列实际新回答和无回答比例。

取消测试覆盖生成中、待解码、待发送、已入播放缓冲及 EOS 邻近时刻，检查旧响应未提交音频不再进入播放、重复响应完成事件不会结束新响应。已播内容不可撤销。

若 ASR/LLM 尚不能可靠接话，先用固定文本流验收 TTS 组件，FDB 只如实记录集成阻塞，不把沉默算作 TTS 优化通过。组件收益不能直接替代完整 FDB 质量结论。

最终交付为四步实验结果、选定批次与编译配置、前后阶段占比、音质/断流证据和未解决问题。若完成四步仍超出预算，记录剩余瓶颈后另行规划替换模型对照；不在本分支计划中提前承诺某个模型或参数必然达标。
