# TTS-003：覆盖 TTS 每轮开头的编译路径

状态：实验实现已准备（默认关闭）；等待 TTS-002 选定对照。日期：2026-10-17。分支：`feature/tts-latency-optimization`。

## 问题

当前重复惩罚历史窗口未满时使用 eager，短回答可能无法享受已有编译加速；启动预热不会填满新回答的历史。

## 依赖

按顺序在 [TTS-002](tts_002_bounded_generation_batches.md) 完成后执行；单项无收益时记录结论并沿用原配置。

## 共同约束

遵循 [TTS-001 的范围与实验协议](tts_001_latency_instrumentation.md)：固定模型与输入链路，保留单一播放所有权，使用远端 conda 环境进行 GPU 测试；每项单变量对照，同时验证首音、断流和自然度。

## 处理方案与验收

### 设计

当前历史窗口未满时走 eager，启动预热不会填满下一轮的历史。将历史存储保持固定形状，额外传递有效历史长度或掩码；重复惩罚只读取有效位置，不能用填充值制造不存在的历史。对首帧无惩罚和后续有惩罚分别准备稳定编译路径，避免按每个历史长度重新编译。

保留官方采样和重复惩罚参数。每轮仍清空逻辑历史，预分配缓冲区可复用，历史内容与 KV 不得串会话。新图编译在启动阶段覆盖首帧、未满窗口和满窗口；正式测试中记录重编译及回退，不能只凭启动时出现 compiled 日志判定成功。

### 验证与完成条件

为有效历史 0、1、少于 50、达到窗口和超过窗口等边界做确定性语义对照，并覆盖惩罚开关、窗口截断与会话重置。先用确定性输入检查惩罚及 token 一致性，再检查真实采样下的音质；若 kernel 数值差异导致音频不同，单独披露，不能自动认定无损。

对比每轮前 1/5/10/50 帧、短句完整耗时、首音、实时倍率和编译次数。短句收益应稳定可见，且不引入随帧数增长的编译、断流或显存增长。失败回退 eager 必须可观测，本步有独立关闭开关。
