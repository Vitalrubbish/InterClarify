# TTS-005：消除稀疏 micro-turn 文本的无界启动等待

状态：候选修复与稀疏文本筛选完成；未切换产品默认值。日期：2026-10-17。

## 问题与来源

用户指出每个 micro-turn 可能只产生少量文本。固定 MOSS 服务实际 `prefill_text_len=12`，计数为 TTS tokenizer 的 token；不足门槛且未收到真实文本结束时不 prefill。全双工实现跨 micro-turn 累积，在模型进入 thinking 后才发送结束，不能把每个 micro-turn 都当作文本结束。现有基准按 100ms 增量推送且末块立即结束，不能充分覆盖 600ms 间隔和短文本迟迟未结束的情况。

## 修复设计

保留原默认值，增加两个独立实验开关：

- `XTALK_TTS_PREFILL_TEXT_TOKENS`：0 沿用 processor；候选 8、4，12 可显式作对照。只改变启动 prefix 长度，不改变文本 token 顺序。
- `XTALK_TTS_PREFILL_MAX_WAIT_MS`：0 关闭；候选 200ms。从原 worker 首次接受不足门槛的非空 token 后开始计时，同一 worker 在 command queue 等待超时时尝试用已有真实文本启动。没有新线程、定时器或播放队列，不插入假 token，不设置 `_text_ended`，不伪造 final。

超时启动时仅临时把门槛设为实际已有 token 数，使原 `_prefill_if_needed` 消费该 prefix；调用后恢复配置门槛。后续真实文本继续同一模型 KV、重复惩罚历史和 codec streaming 上下文。结束事件已排队时优先处理真实命令；取消后不再启动。等待上限只约束 worker 空闲时的文本门槛等待，不保证模型、排队和网络耗时。

降低 prefix 或提前用部分文本启动会改变模型条件，可能影响漏词、重复、韵律与接续。该实现是可关闭的候选修复，不能因首 PCM 提前就默认上线。原生播放所有权、Layer 边界及已播放内容不可撤销的约束保持不变。

## 实验与验收

1. 等当前 TTS-001 基线完成，冻结其结果和源码；新实验使用独立 Git checkout。
2. 同一 4090 上按固定文本、采样和音色比较 12、8、4，再独立比较 12 与 12+200ms。批次与早期编译不同时改变。
3. 增加 600ms 小文本增量和末块后仍等待 600ms 才收到真实 final 的输入；保留整句与 100ms 增量，三种模式分别汇总。记录实际每块 TTS token 数，不使用 LLM token 数代替。
4. 先作小集合筛选并明确样本数，记录首 PCM、波形有声起点、最终文本接收/消费、断流、失败与完整 WAV；收益明确后再扩大到至少 30 条三轮和真实全双工集成。
5. 无音质与文本完整性证据时不改默认配置；必要时结论为“交付等待解除，但可听首音/质量未达标”。
