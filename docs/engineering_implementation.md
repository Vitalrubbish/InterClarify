# InterClarify 工程实施方案

更新：2026-10-18。研究范围以 [研究设计](research_design.md) 为准，当前可执行任务统一登记在 [issue 索引](issue/README.md)。

## 1. 当前决策与状态

用户已确定英文 ASR 使用 **Nemotron Speech Streaming EN 0.6B / 160ms**，TTS 使用 **Kokoro 82M**，开始投入 Layer 1 训练适配。沿用已测音色 `af_heart` 作为首轮配置；权重 revision、包版本和设备在接入任务中核验后冻结。组件选择已定，不代表运行时接入、训练或验收完成。

现存诊断入口仍为 X2 + MOSS，不能用它产生的 PASS 证明新组合已通过。Qwen3-ASR 已退役；Kyutai 仅保留历史与官方控制权重对照，Pocket 不再作为当前接入目标。现有脚本保留用途见各自同路径文档，后续按 issue 改造，不将旧启动命令当成新链路入口。

官方输入对齐后 EN 160ms 五例原样/去标点均为 0/5，Kyutai 为 5/5、3/5；有关请求通过 token 级审计。320ms 分片异常使整轮只有 98 条已保存结果。详见 [复测记录](asr_official_input_retest.md)。这些证据支持开展有限适配，不证明标点是唯一原因。

## 2. MVP 与控制边界

- 运行底座只有独立维护的 X-Talk fork；通用 ASR/TTS 客户端和双工能力放在 fork，本仓库维护服务、训练、配置、评测与研究层。
- Layer 0 关闭，不生成系统附和。用户附和识别与有效插话停播保留。
- Layer 1 由 LLM 生成既有五类控制 token；DuplexRuntimeAdapter 只执行协议，不重新判断语义。保留完整官方 checkpoint、ChatML、控制 token ID 与 assistant 原始生成 ID 历史。
- 阶段 A 只保留唯一协议执行者；启用 Layer 2 后才使用唯一 OutputArbiter，优先级为有效 L2 > L1，不新增平行仲裁路径。
- Layer 2 只输出 NO_OVERRIDE 或短澄清问题，不阻塞正常监听与回答。研究仍限单一日程日期/时间任务域。
- Layer 3 当前关闭；后续只能提交针对未提交片段的版本化修订补丁。已被用户听到的内容不可撤销。
- X-Talk 是唯一 TTS 播放所有者；响应、会话和取消代际隔离贯穿文本、合成与播放。
- 在线输入只包含当时可见的音频、文本和状态；未来转写、人工边界、隐藏任务目标仅用于离线标注与计分。

## 3. 组件与输入契约

Nemotron 的 160ms 是模型分块配置，不能等同音频传输包大小或 600ms micro-turn。先保持模型对照的 600ms 时钟，分别记录产品会话起拍与历史首非空起拍；后续调窗口必须单独验证。no-voice 表示窗口没有新识别文字，不能当作声学静音真值。

ASR 保留真实增量与到达时刻，验证文本追加、词内增量、尾词交付、暂停恢复和会话复位。若增加词片段暂存，必须仅依赖已到达信息，定义超时/EOF 刷新并计入等待，不能规则补句号或用人工边界促使接话。有限音频的真实 EOF 只用于排空 ASR，不作为送给 LLM 的让轮信号。

每拍提交边界 strip 首尾分隔空白，空拍使用实际 no-voice ID；BOS 按 tokenizer 条件处理。模型预算、结束 ID 与原始生成历史均固定并审计。

Kokoro 按已形成的短文本段合成，先明确 LLM 增量到文本段的提交条件、最大等待、长度上限及 finish 刷新。不能等完整长回答再提交首段；测试使用真实增量时序，不预先提供完整回答。语音采样率、重采样、分段韵律、取消和旧 PCM 隔离都须验收。无需重开 TTS 选型。

## 4. 训练设计

目标是适应真实流式 ASR、降低对句读形式的依赖，保留等待、接话、用户附和及插话控制能力。先完成输入有限诊断和数据审计，同时准备训练加载与远端资源短跑。

从完整恢复的官方 checkpoint 继续训练现有 q/v LoRA，首轮冻结基础模型、已有 embedding/lm_head、ASR 与 TTS。官方原训更新过 embedding/head，故必须恢复其发布状态，不能只加载基础模型加一个不完整 adapter。冻结方案是本项目的有限适配假设，不能保证收敛。

对照包含未经训练官方权重，以及同数据、初始化和预算的原样继续训练、用户侧去句读、混合增强三组。只改变用户普通句读，保留控制 token、词内撇号、连字符、小数与时间格式。assistant 文本与监督协议保持完整，不新增系统附和标签。

根据用户确认，首轮使用官方论文采用的 UltraChat dataset，自行实现论文 micro-turn 生成管线，混合组按对话每个 epoch 固定种子平衡分配 50% 保留用户句读、50% 去句读；先固定分拍与控制事件，再增强。尚未取得精确 50k 清单与完整作者生成代码，须冻结实际 UltraChat 来源并注明本项目生成器与论文的对应关系。所有训练臂从同一完整官方 checkpoint 继续更新既有 q/v LoRA，本轮不从原始 Qwen2 模型重新训练双工能力。首轮准备 1,000 条训练对话、200 条文本开发、300 条内部文本测试；内部保留集不能保证未参与官方原训。真实 Nemotron 轨迹先用于独立迁移评测，不作为开始文本训练的前置采集数量门槛。两者分别标记，不能把完整人工转写切块冒充在线轨迹。训练标签来自边界/对话标注和前缀审查，不能照抄原模型的持续等待。开发和测试轨迹自由生成自己的 assistant 历史。

按说话人/原始对话划分，增强版本不跨集合；FLEURS 100 条、既有五例和完整 FDB 均保留为外部回归，禁止训练。先做远端单卡 24GB 显存和每步耗时短跑，再按实测选择多卡方案，上限 8 张 4090，不把显存视为统一内存。首轮最多两轮适配，预算与门槛在看模型结果前冻结；无稳定收益时停止扩大训练。

## 6. 验收与延迟

必须同时报告新正文/新语音覆盖、未回复、过早正文、停顿误抢话、用户附和误打断、有效插话停旧回答、回复相关性与质量。只输出状态 token、旧正文续写或 teardown 停播不能冒充成功。

端到端响应延迟从标注用户结束或插话结束到新语音首可听代理；另记录插话开始到实际停旧音频。目标平均约 1s、不超过 1.5s，简单问题要求亚秒；报告成功条件均值、P50/P95/max、亚秒覆盖及未回复率，不将未回复设成零。首 PCM、首可听代理、离线对齐首词与设备实播分别标注。分段等待纳入端到端，不将独立组件 P50 相加。

先跑固定 25 目录 FDB v1.0 历史回归，再跑未用于调试的新样本，最后完整 v1.0。Pause TOR 越低越好，接话与用户打断 TOR 越高越好；系统附和 Freq/JSD 为范围外诊断，用户附和抗误打断另测。推理、对齐、judge 分阶段，judge 变更不能直接跨轮比较。官方音频与额外诊断尾窗分开，跳过评分不算通过。

## 7. 交付、文档与后续研究

本地与远端均使用 conda，真实模型训练和集群测试在远端调度作业中运行。每次实验冻结两仓库提交、逐文件摘要、模型/tokenizer revision、依赖、数据切分、随机种子、时钟与参数；独立 run_id，保存 manifest、配置、指标、逐例时间线、退出码、日志与资源峰值。失败和缺测保留。

新代码同步新增 `docs/` 同路径说明，修改代码同步更新文档，说明文件作用、类与核心方法；文件名、代码注释和 commit message 使用英文，开发文档使用中文。issue 中列出的文件只是拟交付物，未创建前不是可执行入口。

底座通过 008 后，恢复 Layer 2 的规则/提示策略、30–50 条日程探索轨迹、盲前缀审计和小规模真人闭环；存在足够适合接话的澄清窗口且任务可恢复后，才扩大 Layer 2 数据和训练。历史来源与已清理文档见 [证据索引](baseline_evidence.md)。
