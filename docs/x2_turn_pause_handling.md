# X2-Turn 句中停顿与接话策略核查

更新：2026-10-22。对应 [093 工作单](issue/archive/093_arbiter_outputs_and_x2_pause_review.md)。本次核查作者论文、公开模型卡和实时控制器源码，未执行本项目远端音频实测。

## 1. 能确认的结论

X2-Turn 没有把“停顿”直接定义成 complete。论文的 idle 覆盖词间、句中和结尾的空白位置；complete 对应有完整语义的语音内容。用户说话中的静音也可以输出 idle，因此仅看最新一帧 idle 无法区分停顿与结束，必须保留此前语义状态和实际播放历史。

这说明模型具备处理停顿的设计，不能由此保证实际不会误判。一个完整短句之后继续补充、犹豫或自我修正，也可能在当前证据下出现 complete；有语义不完整的前缀同样可能预测错误。

来源：[论文第 2.2—2.3 节](https://arxiv.org/html/2608.10878#S2.SS2)。

## 2. 论文系统表现及其限制

论文表 1 的 Pause TOR 为英文 0.224、中文 0.033，分别表示对应系统测试口径下的 22.4% 和 3.3% 接管率，越低越好；不是逐帧 complete 误分类率。不同语言测试数据不同，不直接把差距归因为模型语言能力。

这些结果来自 X2-Turn、Qwen2.5-7B-Instruct、Qwen3-TTS-Streaming 和下游控制策略组成的完整系统。作者在第 4.1.1 节明确要求 complete 后再确认连续 idle 帧以减少停顿误接话，因此不能将系统成绩全部归于单个状态头，也不能拿掉确认策略后继续引用相同成绩。

EasyTurn 的 88.49% 英文结果取最后一个非 idle 状态评分，不覆盖所有中间误触发。判断线上停顿风险，应保留全过程状态与已执行动作，不以最终预测纠正此前抢话记录。

来源：[论文表 1 与第 4.1 节](https://arxiv.org/html/2608.10878#S4.SS1)。

## 3. 当前发布控制器并不只依赖 complete

核查的作者 main 分支 [controller.py](https://github.com/X-Square-Robot/X2-Turn/blob/main/voxtral-realtime/src/voxtral_realtime/turn/controller.py)中：

- turn_end 开始接话候选确认；用户恢复 speaking/noidle 时可取消未提交候选。
- 尾窗等待转写稳定；恢复语音可以取消候选。确认与尾窗造成的等待不是固定 micro-turn。
- 另外有 silence_end 分支：此前已有有效语义后，连续 idle 达到 silence_end_frames 即可开始 soft endpoint；这条分支不要求此前出现 complete。
- 默认 silence_end_frames=10，80ms 一帧，对应约 800ms 的计数；还可能叠加声学 hangover、尾窗和实际推理时延，不能说正好 800ms 发声。
- 此分支最终可以返回 turn_class=turn_end 和 event=accept，即使原始模型最后输出的是 idle。原始状态与控制器的最终动作必须分开。

[config.py](https://github.com/X-Square-Robot/X2-Turn/blob/main/voxtral-realtime/src/voxtral_realtime/config.py)支持环境变量覆盖这些参数；其中注释区分实时麦克风与离线 FDB 静音配置。当前默认值不一定等于论文实验或其他部署的实际值，正式使用必须固定 commit 与完整配置。

因此，“模型不会因一停顿就必然 complete”与“默认系统会不会在长停顿时接话”是不同问题。后者在当前代码里确有静音兜底风险，尤其是语义尚未完整的长思考停顿。

## 4. 本项目接入与开发检查

采用原始转写与逐帧状态进入唯一仲裁器。由仲裁器关联系统已播/待播历史选择 Layer 0 或 Layer 1 的适用输出，允许继续等待或停止；当前不实现 Layer 0，但接口职责保留。上游控制器不作为第二个执行者，也不无条件继承约 800ms 静音自动接话。

不要求附加完整 600ms micro-turn 才处理 complete；若配置连续帧确认/尾窗，单独报告其时延。单个 complete 可唤醒空闲 LLM，不等同一定提交普通回答。用户仍持有话轮也不能一律阻止有依据的主动澄清，相关价值判断仍由 Layer 2/表达路径处理。

正式 FDB 前，在独立开发集检查：

1. 未完成句后停顿，例如“我想订一张去……”，后续继续补充目的地。
2. 语义完整但话轮继续，例如“先订去北京的票。……另外日期是周五”。
3. 犹豫、填充、自我修正、数字/实体报读中的停顿。
4. 0.3、0.6、0.8、1.2、2 秒等不同间隔，单列自然音频与人为修改的诊断音频；这些值是覆盖点，不是规定接话阈值。
5. complete 候选后恢复语音、模型未出 complete 却触发上游 silence_end、候选取消前后已经实际发声等情形。

每例保留原始帧、累计转写、观察到达时间、完整历史、状态分数、策略/取消原因、LLM 启动及实际首音频。单列长停顿误接话、正常接话漏答与延迟；固定配置后再做 FDB。没有远端实测前，结论限于设计与公开系统证据，不能宣称本项目已“处理好所有停顿”。
