# NTF-019固定FDB30对照评分

对应`scripts/analysis/analyze_native_frontend_fdb.py`。离线读取双路与单路独立run，不加载模型；复用逐批来源／EOS／生命周期审计，核对两臂相同manifest及018验收文件摘要。固定30条和全部有参考样本均保留，失败例不从分母剔除。

`score_case()`分别用控制主块、真实观察、原始状态可用、联合发布／本路服务返回及实际读取五种坐标计分。接话统计提前／超过160ms提前及边界后complete；停顿统计区间内complete；打断统计有效nonidle及结束后complete。单路没有联合Context或读取探针，对应字段不伪造；原生规则调整和原始模型token单列。

正文仅使用最后已联合提交的EOS正文。WER复用仓库既有英文归一化和确定性编辑距离纯函数，不调用旧模型加载器；失败例的可见部分仍与完整参考计分并标记不完整，EOF drain不回填。每次complete保留当时正文及之后新增词，跨闭合组的无空格续写只列候选供逐例检查，不自动改词。

`compare_inputs()`按真实采样截止及三个窗口摘要配对，比较音频token、控制文字、原始／规则后状态；未配齐范围单列，该配对子集只用于协议核对，不替代质量固定分母。`summarize_arm()`汇总延迟、阶段耗时、首次正文、EOS至发布、未读PCM／资源及各任务状态指标，保存每批CSV积压曲线数据。

`analyze()`给出两臂工程验收和质量结果，要求双路30/30、退出0及资源／逐批审计通过；质量改善不作为虚构的必要结论。NTF-030后不以延迟超过800ms单独判失败，绘图移除800ms停止线，仍保留真实积压曲线，失败后的未发布批次不补点。019已由用户审核归档，原始机械验收标记仍保留，不将新的时延政策回填历史结果。
