# 短延迟控制对照评分

`scripts/analysis/compare_xturnix_latency.py` 读取真实回放的到达/分数事件，在相同事件流上比较纯文本、纯等待、联合策略。它不加载模型，不从参考停顿生成控制事件。

模块使用函数，不定义业务类。`partition` 按原会话固定分组；`candidates` 在配置刻度上枚举有限候选；`first_start` 只读取当时前缀版本、健康和已返回分数，拒绝旧版本分数和过期健康观察；`metrics` 用参考锚点事后计算预算内安全首次接话、提前、超时、无动作和失败；`compare` 先在校准会话选配置，再应用于评估会话。

每个预算独立选择三种策略，不将不同预算混成一项成绩。始终等待候选必须保留；无动作不是零延迟命中。旧 dev 的会话分组只支持探索性对照，不升级为独立测试。

`main` 核对执行时的配置/清单哈希，读取完整计划状态和逐例事件，输出不可覆盖的新目录。执行资源、数据与延迟解释见[协议](../../dev/XTurnix/short_latency_comparison.md)。

校准轨迹不完整时不选择任何策略，明确输出未完成；评估失败保留在计划分母。评分摘要另统计健康观察、推理错误和旧版本分数返回数量。参考末词与静默锚点只在 `metrics` 内使用，不进入 `first_start`。
