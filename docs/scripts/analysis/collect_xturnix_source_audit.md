# collect_xturnix_source_audit.py

## 作用与范围

对应 XTX-009 首轮 40—60 个英文场景审核，收集 24 个 DailyTalk 原始会话和 24 个 SwDA 原始会话的受限文本审查包。使用固定来源版本、确定性选择和源文件摘要；只准备审核观察，不生成动作金标或训练样本，不运行模型，也不下载音频。

原始文本、当前历史和源话语行为标签留在本地 `artifacts` 下，不提交 Git；仓库只保留小型摘要、定位信息、逐例中文意见和报告。本轮已阅会话全部排除出未来独立测试，不能通过换窗口重新进入测试。

## 设计

`SourceReader` 顺序执行有超时、单次及累计字节上限的 HTTPS 读取，保存 URL、实际响应范围、字节数和 SHA256。完整响应与 Range 响应分别验证；服务忽略 Range 时停止，不退化为整包下载。

`read_swda` 先读取固定 ZIP 的尾部和中央目录，再读取选定 24 个 CSV 成员及会话元数据所需压缩区间，交由标准库校验解压。元数据记录主题和原始说话人 ID，以便核查跨会话复用；DailyTalk 记录其共用的说话人 ID，不能把不同会话误称为说话人独立。只在内存构造稀疏内容，不解压目录或执行来源代码。源 ZIP 结构大小有上限，成员大小与选取数量也有上限。

`read_dailytalk` 按原会话 ID 分组，按 SHA256 的确定性顺序选 24 个会话，不使用动作预测或质量结果抽样。选择第三轮作为观察点，保存至该轮的完整历史，不包含未来轮次。

SwDA 按 ZIP 中 CSV 成员路径排序选 24 个不同会话，轮换查找附和、百分号、问句和反对/修正类来源标签作为审查切片；百分号不能直接理解为未完成。找不到目标类型时保留回退记录；这些标签只用于定位材料，不能自动转为 Listen/Speak 或 start/stop。每包只展示目标及此前话语，记录来源记录序号和观察摘要；CSV 记录序号计入表头，不保证等于文件物理行号。

`main` 创建独立输出目录，写入 `packets.json`、网络读取台账和源元数据。单次读取≤1 MiB、总网络正文≤8 MiB、ZIP 结构≤32 MiB、成员解压≤1 MiB；串行、单 worker、每次请求超时 20 秒。旧输出不覆盖。若来源不可读或结构超限，显式报错，不自动扩样或改来源。

## 运行与核验

使用已有 conda 环境，示例：

```bash
conda run --no-capture-output -n interclarify-dev python scripts/analysis/collect_xturnix_source_audit.py \
  --output artifacts/xturnix_source_audit/20261023-first-review
```

核对 48 个不同来源会话、每包完整当前历史、SHA256、来源版本、抽样规则和无未来消息。随后逐例审查候选动作、分歧、实际状态依据、音频和时间缺口；脚本输出不等于审核已通过，更不等于双人人工标注完成。
