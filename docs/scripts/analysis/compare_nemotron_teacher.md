# 教师门控对照分析

`compare_nemotron_teacher.py`读取两轮独立回放结果及逐帧证据。`compare()`以case_id对齐固定输入，分别汇总全清单运行成功率、共同完整样本及共同主块音频覆盖，不拼接不同轮成功样本。`metrics()`计算主块/完整观察范围的提前及边界后complete、停顿complete、打断nonidle位置与实际墙钟延迟；`group()`按三轴聚合并计算在线/排空WER。

`audit_teacher()`复核原始字符只追加、逐步屏障、实际覆盖、门控关闭不消费、开门后消费序列等于规范化教师token、历史修订账本与消费序列一致、有效状态反馈及KV计数。控制token首次在已完成教师前缀出现到实际输入的时间单独汇总，关闭期间保留最早可用时刻；末尾pending与连续积压帧数如实保留。

`distribution()`给出中位/P95/峰值；输出JSON保存分组、逐样本和失败证据，报告从这些数据撰写。官方边界前complete仅为时序诊断，不自动判为语义错误。该文件无类。

门控EOS按冻结模型定义151674核查；消费滞后只覆盖已消费token，另记录未消费部分的持续时间和EOF年龄，避免幸存token掩盖长时间积压。

墙钟变化另对两轮都检测到相应事件的相同样本计算candidate减baseline，避免检测集合不同而直接解释两组中位数。历史基线非同时作业，墙钟差异不单独归因于配置。
