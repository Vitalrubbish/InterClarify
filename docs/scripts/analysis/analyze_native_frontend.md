# 原生前端远端证据审计

对应`scripts/analysis/analyze_native_frontend.py`，用于NTF-018固定矩阵的离线验收，不加载模型或修改运行证据。输入是完整run目录，输出是独立JSON摘要；缺失条件或文件按未通过处理。

`audit_case()`逐帧核对批次连续、实际回执、下一步开始晚于上次释放、两路真实覆盖、EOS组数量、append-only正文和单次联合快照；对首帧、稳定阶段、原生／联合发布延迟分别统计。失败case固定计入三轴分母，不以共同成功子集放行。

双路批次数必须恰好等于源160ms批次数。单路允许reset后的额外原生调用，使用名义批次数作为下界；原result退出失败仍记录失败，不能通过离线重判追溯覆盖旧退出码。

`audit_condition()`核对条件result、退出码、预热覆盖、两轮reset随机数一致性、真实原生等价性以及固定三条case。`analyze()`并列三种条件与资源峰值，仅双路完整条件满足全部门槛且无资源停止时给出019候选放行；单路／有限臂失败照实保留，不冒充完整臂失败，也不因缺少参考臂而宣称完整矩阵完成。外层作业因有限臂失败而非零时，单独使用各条件退出码判断。

`warmup_details()`保留每轮实际状态与远场拒绝计数、预热覆盖、原生SenseVoice dtype／长度／耗时、第二轮稳定耗时及控制／X2计算分布；失败在线调用中已完成的SenseVoice阶段另行保存，不因该批次未发布而删除长尾。

通过该工具仍须人工检查首次提交的调度失败、资源额度和失败日志；它不提交或重跑作业，不输出预热对历史失败的因果比例。

可选`--plot`用Matplotlib导出独立积压图，只展示有限臂已成功联合发布的真实批次，控制／X2分别以本路主块为坐标；失败后的未发布批次不补点。完整预热未启动在线时钟时不绘制虚构的在线曲线。

可选绘图在本地interclarify-dev conda解释器配合临时依赖目录验证，使用Matplotlib 3.10.7；该依赖不属于核心运行环境。调用--plot前须提供Matplotlib，未提供该参数时不导入绘图库，本次没有修改公共conda环境。
