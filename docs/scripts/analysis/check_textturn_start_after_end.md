# 正常接话录音结束后的start计数

对应 `scripts/analysis/check_textturn_start_after_end.py`，服务TT-004的已有轨迹检查。只用标准库读取原音频manifest、逐例trace和ASR服务日志，不运行模型或重新评分。

`collect_case`提取每条正常接话的有效start返回时刻、ASR会话ID、当前Context完整参考可见时刻及模拟生命周期。`locate_audio_ends`流式累计同ASR会话收到的PCM字节，在首次覆盖原音频全部采样点时登记包接收时刻；追加1.92秒静音和EOF不作为原录音终点。边界粒度至多一个80ms包，表示原音频输入已交付，不声称人工核验的最后有声时刻。原WAV可有首尾静音，二者不能混淆。

`summarize`区分结束后任意start、首次start在结束后、结束前后均有start、仅提前start及全程无start。1秒内出现另计，既不要求没有提前start，也不称及时成功率；该指标只回答动作是否出现。已经处于模拟Speak的轨迹不需要再次start，因此不能把结束后无新start一概解释为漏接话。

参考全文首次精确匹配的Context时刻只作第二口径；没有匹配的记录单列，不强算失败，不据此判断语义边界。输出逐例CSV、汇总JSON及输入摘要。使用全600例计划分母，分别列问句300、陈述300，保留缺日志、无动作和异常；原始结果不覆盖。远端使用已有conda，单线程、2GiB地址空间和60秒超时，不消耗GPU。
