# 已有ASR轨迹的前缀稳定性分析

对应`scripts/analysis/analyze_asr_stability.py`。本脚本只读本地已有模型轨迹并做轻量CPU统计，不加载模型、不运行集群测试，不修改前端发布行为。

`load_groups()`读取原始`asr_observation`，按样本、控制器generation与真实音频起点分组，仅保留连续音频覆盖。组内至少3个不同音频截止点才可分析；滑窗左移后的单次观察、reset后的新组和失败／排空不互相充当稳定票。所有输入文件保存SHA256。

`analyze_group()`在相同音频起点下比较小写化的英文词／数字及中文字符前缀，忽略大小写和标点，保留英文撇号。以该组最后一次可比较输出作为回看终点，对每个词前缀端点计算：首次有足够词数的假设、最后一次变化后的开始、3次新音频一致确认、实际返回时钟耗时及额外ASR更新数。首次有足够词数不代表已正确听出该词，更不代表声学词起点。

为防止短轨迹的最后一次输出被自动判稳定，至少要求从最后变化起再有两次新增音频的同前缀观察；否则标记证据不足。仅记录返回可见时钟，不用名义160ms推算实际间隔；无新音频的重解码不能增加一致票数。另模拟连续2／3次新音频相同的首次提交，检查后续同起点结果是否又改写了候选前缀；仅有“同组”还不够，确认窗口中的ASR调用必须确实连续。

`summarize()`汇总时间与次数分布、证据不足分母、候选提交被反例推翻的数量。主统计仅用标定完整FLEURS和官方英文示例，截断／重复视图只单列，避免把同源重复前半句当独立样本。每个词位置的前缀端点相关，不能将其当独立词样本或准确率；最后结果也不是正确性金标。

运行时给出`--input-dir`和全新的`--output-dir`；逐组观察、端点和反例保存于`analysis.json`。未做词级音频对齐，因此不能回答词发声到稳定的端到端延迟；也不能保证滑窗移出后或以后重识别不再更正。分析结论必须同时说明此范围和大小写／标点未计入的限制。
