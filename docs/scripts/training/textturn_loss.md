# 完整轨迹的动作损失权重

对应 `scripts/training/textturn_loss.py`，只负责权重与训练顺序，不生成标签。2026-10-26按用户授权增加阶段内动作质量平衡。旧方案虽减少重复keep，train中keep仍占原始权重质量1094/1346≈81.28%；pilot两轮开发集全部keep，因此本次将三类动作分开归一化。该观测支持重新平衡，尚不能认定损失是退化的唯一原因。

## 基础权重与动作平衡

`assign_loss_weights`保持冻结数据原定义。keep按scenario_id、状态和类别组成组，组内有K窗，单窗基础权重b_i=min(1,2/K)；start、stop基础权重均为2。完整轨迹所有窗口保留并反传，输入、正文和finish位置仍为-100，不修改既有数据文件或摘要。

`stage_loss_weights`在pilot、full各自训练阶段开始时读取该阶段全部训练行，设窗口数为N、动作a的基础权重总和为B_a。目标份额p_keep=p_start=p_stop=1/3，计算：

\[
 w_i=N\,p_{a_i}\frac{b_i}{B_{a_i}},\qquad
 L=\frac1N\sum_i w_i\,\mathrm{CE}_i
   =\sum_a p_a\frac{\sum_{i:a_i=a}b_i\,\mathrm{CE}_i}{B_a}.
\]

这里的CE仍在完整词表上预测该窗口唯一动作token；没有新增finish预测或改变合法动作。每类总有效权重均为N/3，总权重为N、固定平均权重为1。keep类内部短组与长组仍按基础权重贡献，长段重复keep不能凭窗口数占据绝大多数权重。原keep组质量上限2属于基础权重约束，平衡后该上限也乘以该类缩放系数，不能再把2解释为最终有效质量上限。

当前train的9977窗包含keep9851／start84／stop42，基础质量1094／168／84；平衡后各类有效质量约3325.667，占比分别33.33%。每个start有效权重约39.59、每个stop约79.18；keep随组长度变化。原始窗口频率、来源数与轨迹顺序均不改变。pilot使用自己的N及B_a，不借用full、dev或外部测试分布，避免数据泄漏和子集尺度变化。

选择等份额是一个明确、容易核查的起点：让保留状态、接话和打断各自贡献一份加权平均损失，同时保留keep内部的重复控制。它不是已验证最优比例；可能提高误start／误stop，仍由独立开发指标约束。这里平衡的是损失系数，梯度大小还取决于模型误差、轨迹内顺序和梯度裁剪，不保证三类实际梯度范数相等。

## 核心方法与执行边界

`stage_loss_weights`返回与输入行一一对应的有效权重及审计摘要，不覆写行内冻结`loss_weight`；缺少任一动作、非正／非有限基础权重或份额错误直接报错。阶段摘要记录基础质量、目标份额、类缩放系数、有效质量与有效权重范围，供训练前核查及运行追溯。

`complete_trajectory_groups`要求快照编号从0连续递增、时钟严格递增且没有排除帧；`trajectory_order`每轮只打乱轨迹次序、内部时序不动。`weight_summary`保留基础统计。`weighted_action_loss`使用逐样本CE乘有效权重，再除以固定阶段平均权重和样本数；梯度累积只按实际组样本数平均，不按当前批或当前累积组的权重和归一化，因此单样本下权重不会抵消。训练通过snapshot_id绑定权重，打乱轨迹后仍使用正确值。

新配置将阶段平衡放在`loss_balance`，冻结manifest的`loss_policy`继续表示基础权重，必须仍完全相符。这样可以复用已冻结完整轨迹，旧数据和历史结果无需重写。无`loss_balance`时保留原损失。
