# TextTurn v2 流式trace评分

对应 `scripts/training/score_textturn_trace.py`，属于TT-004。仅用Python标准库读取已有trace，不加载模型、不访问网络、不重新回放音频。

`score_trace`从真实输入及返回事件提取证据，只在合法状态和当前可见文字上判断。附和与停止指令使用显式冻结的短表达规则，无法确认的ASR文字为未知；Speak下实际stop单独统计，不等于可归因的附和误停。没有调用、超时、输入未覆盖机会或生命周期提前结束均单列，不能算正确keep。完整参考文本归一化匹配仅输出ASR诊断，不产生语义让轮标签。

正常接话使用可选审核文件：每个锚点绑定Context可见版本的文本SHA256、首次可见时间、审核人和理由；每个禁止区间绑定决策输入SHA256。只承认已有Context／输入中的事实，拒绝未来或冲突标注。未审核的提前start保留未知，不能因为参考后文后来出现便自动判错。缺少完整语义区间审核的历史trace不产生接话通过结论。标注规则对模型动作盲审，不能为某个错误输出量身改标签。

每个已发布控制窗须有对应结果或明确合并覆盖；缺失窗、异常或被合并后失去的中间语义证据均不得算成功保持。已明确发生的错误仍判fail，不因同例另有缺失而抹除。停止指令使用完整词／已冻结短命令，否定句或仅包含stop字样不自动判打断。

`summarize`保留全部计划机会，分别报告pass/fail/unknown、实际动作错误、输入缺失、运行异常、可判定覆盖和条件Wilson95%区间。计划分母上给出成功率及错误率的保守上下界；未知不能被从总体中删掉。门槛判断要求覆盖充足，未知若足以改变通过结论则记证据不足。延迟从依据首次可见到动作返回计，必须核验该调用实际包含依据；控制耗时、聚合等待、ASR匹配诊断分列，EOF排空不进入在线评分。

命令入口接受音频manifest（仅用原计划和参考文字）、trace目录及可选审核JSON，拒绝非空输出。输出规则身份、输入摘要、逐机会CSV和汇总JSON，v1数据与模型不改写。全量离线重评分在远端conda、单线程、2GiB RAM和明确超时下执行，不消耗GPU预算。
