# TextTurn新版数据修复入口

`repair_textturn_dataset.py`使用原train160／dev200来源，验证上游摘要后只读取这两组正文。`ReleaseStream`以160ms、1／2 token各半、连续1—8拍和90%短／10%长空串发布文字，首字前0—3拍。纯句读不并块，原始字符跨度与token预算分别核查；句末检测仅看当前前缀，缩写表和版本冻结。`RepairTrace`是唯一模拟执行点，维护提交游标、原用户时钟和单输出生命周期；生成3／3／2、播放最多1 token，首包后等1—3拍，stop后80ms确认。当前前缀句末且无新文字才start，已经提交的前缀不可重启；中途start用过渡句，原文完整后用对应完整回复。打断的新请求保留并在句末后重新start，明确停止继续keep。

每来源选择原始完整对话中的一对用户／助手，保留真实历史。优先在第四条文本及以后选择，以使用两种句式均可出现的历史位置；不将依赖上下文的陈述剪成首轮。选择自然较短完整回复，超长快照整来源排除。每来源普通／接管轨迹构成逻辑组；缺stop时补同源对照，实际比例分开记录。每个初始输出只分配一次40／30／20／10机会，阶段与模板独立选择，原用户续说占用时不插第二用户流。恢复输出不递归插入，避免合成级联。成对附和结束／请求／停止对照单独标记，不混入基础机会比例。

`build`先完整CPU构造候选来源并记录成本、排除及句式／历史／阶段交叉覆盖，再选择完整来源组，冻结train≤100000、pilot≤10000且目标来源≥100／20；不能满足则失败保留估算，不训练。全部200开发来源保留；同规则开发和未见过渡／接管表达、真实回复背景分开标记。所有快照保留正损失，输入长度2048，不截断回答或删空拍。产物包含压缩快照、来源与选择、完整事件、连续样例、审计和manifest。边界检查只证明合成弱标签合同，不证明开放域语义质量。

自然续说的离线弱判断采用当前未提交前缀中已经带分隔符的非附和功能词以外的完整词；歧义词列表冻结于实现，不按字符长度，也不读取未来续写。这个保守词面代理仍有语义局限，需与合成短语锚点分开报告。重复／旧版本统一经过`update`入口去重，不构成有效增量。机会级基础抽样与补充对照各自统计，不能拿补充对照后的总比例冒充40／30／20／10。

最终配对先在各切分的原始后续轮次中分配问句／陈述各50%，再在该句式内选择自然较短完整回复。原因是单纯跨句式取最短回复会偏向陈述。来源无需新增，历史不剪裁；train／pilot按两种句式成对选完整来源，使快照预算不破坏该目标。
