# 四配置适配计划

`scripts/training/prepare_layer1_adaptation.py`仅生成可审计计划，不加载模型或提交作业。无类；`build_plan`核验共享索引、三臂数据、预算、T3分配和正式参数，记录B0及三训练臂、保存点、开发集视图和来源摘要；`release_blockers`给出当前开训缺项，`validate_formal_config`由正式训练入口复用以防绕过门禁。

029切换2048时，窗口、对话数和完整单epoch步数改为从正式配置读取并与协议及完整索引交叉检查，不在校验器中固化旧512/5,763常量。B0仍不训练，三臂必须使用同一登记窗口与监督预算。

030按用户确定的训练后FDB路线调整：开训门禁只保留001/004/005已通过、`training_released=true`及固定最终epoch checkpoint选择，不再要求独立自由回放器、dev选择配置或内容judge。正式训练器仍会核验实际数据、资产和完整索引。

`build_plan`为B0记录官方权重，为三训练臂记录全部恢复保存点和唯一用于测试的最终步1,214；测试计划引用相同的历史FDB小子集音频。各模型在全链路测试中自行生成历史，不额外构造原样/去句读测试视图。中间checkpoint不能因小子集分数被选为最终权重。

独立真实`acceptance.sample_manifest`及历史FDB测试清单均不作为额外开训门禁；后者由030冻结以便训练后执行。所有输出拒绝覆盖，计划不包含可误提交的B0训练命令。计划只登记将执行的测试，不能冒充已生成四配置能力报告。

`validate_alignment_config`验证036独立配置、父协议摘要、完整索引、冻结条件及预算；短跑限制100步且不放行正式候选，正式训练要求本轮资源/精确恢复/推理重载报告通过。

用户明确取消短跑后，正式入口可按独立协议中的精确豁免记录放行；仅绕过本轮短跑证据要求，不绕过配置、父协议、数据、资产或预算。缺少有效豁免时仍须实际资源报告。
