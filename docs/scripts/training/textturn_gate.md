# TextTurn 开发集放行与选模

对应 `scripts/training/textturn_gate.py`。2026-10-26按用户指令修复全部keep仍被综合分放行的问题，门槛设低，作为继续实验的最小能力检查。

`development_gate`返回通过标记、各条件、分母和拒绝原因。新配置要求正常接话、陈述接话和打断成功率各至少1%；按当前开发集分别至少8/800、4/400、4/400，陈述是正常接话的子集，不另外增加样本。保持综合机会分严格高于基线，停顿误start及附和误stop不高于基线加0.02。三项正例与两项负例均须完整可判定、分母与基线相同且非零，开发窗口须全部执行成功；缺字段、非有限数、未知或缺失不算通过。这个宽松门槛只拦截零能力或覆盖极低的候选，不能证明模型质量足够。

`selection_key`先按是否通过上述全部条件排序，合格full优先于合格pilot，同阶段再比较综合分，以免full已训练却仍选择pilot。若full没有通过门槛的轮次，可保留pilot用于诊断，最终online放行仍要求选中的候选来自full并重新通过同一门槛。每轮记录gate明细，pilot只决定是否继续full，最终候选另行验收，不沿用pilot的布尔结果。

无`development_gate`的新旧历史配置保持原综合分选模与放行逻辑。未改变独立测试、标签、评分公式、动作集合或运行时阈值。

`candidate_gate`负责最终选择的重复核查，并将已完成阶段与被选阶段均为full加入条件；这一条件及其拒绝原因写入`online_gate.json`和candidate。门槛是训练候选资格，不是推理时对动作logit增加阈值。
