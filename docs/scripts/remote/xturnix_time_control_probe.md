# 真实 ASR 短延迟事件采集

`scripts/remote/xturnix_time_control_probe.py` 串行回放冻结音频，记录真实 Nemotron 转写到达、健康进度和 XTurnix 返回。它只采集共同观察，不执行 start、不调用 LLM/TTS；评分策略由独立入口在事件流上回放。

`EventLog` 用锁生成单调时间与事件序号，保存不含正文的逐例轨迹。`LatestScorer` 维持一个真实推理和一个可替换的最新待处理前缀，记录旧版本返回以供评分器拒绝。`AsrObserver` 每次轮询都记录音频接收/消费进度，只有有效文字变化才增加文本版本、重置无增量时间和提交推理。

4090 r2 出现显存持续上升并触发保护线后，`LatestScorer` 在每次分数写出后释放未使用的 CUDA 分配器缓存，同时记录清理前的 allocated/reserved、清理后的 reserved 与耗时。先写出的分数时间仍表示分数实际可用时刻，缓存清理占用下一次推理的调度时间；它不改变权重或合法动作 softmax。分配器缓存是否为主因要以新轨迹的内存记录核实，不把资源中断解释成模型能力不足。

`replay` 验证归一化音频哈希，按包的结束时刻实时发送 80ms 数据；50ms 独立观察不依赖新输入。统一尾部静音不作为模型的文件结束信号；先关闭在线观察，再执行 EOF 排空与取消会话。异常保留失败状态；清理失败时停止后续会话。

轨迹另记录单调时钟原点，以便核对 ASR 服务日志；EOF 排空仅记录是否有文字及其摘要，不再提交推理，也不参与在线判定。这用于区分实时无结果与仅排空后才有结果。

`main` 核对下载完成标记、配置摘要、模型锁、GPU 和 ASR 后端，复用官方 FP32 Listen 管线和 2,048 token 限制，记录源码、环境、资源和计划/完成数。不把特征消费进度称为解码完成，不把 ASR 无增量称为声学静默。

正式计时前以固定 `Hello` 输入执行一次 PT 预热，调用数单列，避免首次算子初始化影响个别话轮；不使用评估文本。执行摘要同时保留关键脚本逐文件 SHA256，不能只凭提交号推断实际执行文件。

真实执行必须在远端调度作业和既有 conda 环境内，协议和资源上限见[短延迟对照](../../dev/XTurnix/short_latency_comparison.md)。本地只检查纯逻辑与编译，不运行真实模型。
