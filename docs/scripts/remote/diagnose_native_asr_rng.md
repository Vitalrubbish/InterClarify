# 原生 ASR 随机状态诊断

对应 `scripts/remote/diagnose_native_asr_rng.py`，用于 NTF-056 对 NTF-054 的原因调查。仅在独立远端调度作业运行，不修改冻结源码、共享依赖或正式验收结果。

## 功能与实验合同

从 NTF-054 固定源码和既有模型资产加载 SoulX／SenseVoice，使用同一固定预热语音，串行执行两组真实权重对照：原始参考与跳过 complete 的基线；原始参考与“只补做被省略调用的 CPU 特征提取”的干预。干预不调用该次 ASR 模型、不恢复服务正文，只检验补齐 dither 随机数消耗能否恢复后续短窗一致性。两组均保留原有严格控制对照，不忽略短窗差异。

保存每次识别的 PCM 摘要、样本数、dtype、文字和 CPU 随机状态；保存特征前端的输入／输出随机状态、特征摘要和耗时。基线与干预各保存完整对照、识别记录和特征记录。固定文本差异与调度故障仍以失败现场为准；诊断通过不等于三条 smoke 或 FDB30 已通过。

## 结构与核心方法

脚本不定义类。`tensor_digest` 对张量原始字节做摘要；`run_comparison` 包装当前 ASR 与特征前端，记录随机状态，在诊断模式下临时替换 `NativeSoulX.complete_text`，退出时恢复原方法；`main` 核对固定源码提交、加载模型与音频、顺序运行两组、输出来源及资源摘要。所有模型调用仍由同一主线程执行。

## 资源与验证

单作业、1×4090、4CPU／32GiB、最长1200秒；各计算库2线程、interop1，GPU分配上限22GiB；输出文件上限64MiB，总输出上限128MiB。复用远端 soulx conda；禁止在登录节点加载模型。输出独立目录，已存在即拒绝覆盖；不启动下游 Qwen／TTS、X2、完整 FDB 或评分。

本地只检查编译与命令参数。真实机制结论须依据远端基线和干预结果、实际 dither 值及随机状态记录。该脚本是诊断工具，补做 fbank 不是建议的生产修复。

2026-11-05远端验证已完成：基线完整复现原失败，补齐特征提取后原有控制对照通过。34对短窗中，RNG／特征差异由13对归零，文字差异由3处归零；耗时149.65秒、CPU峰值8.57GiB、GPU保留峰值4910MiB，输出约0.48MiB。完整证据见[调查报告](../../reports/soulx/20261105-ntf054-retest/failure_analysis.md)。
