# NTF-018完整预热与三轴预检

对应`scripts/remote/native_frontend_probe.py`。入口只支持NTF-018的`dual-limited`、`dual-full`、`single-full`，每次独立进程。固定manifest、三轴顺序、预热语音与长度见[工作单](../../reports/soulx/20261103-ntf018-warmup/README.md)。本模块不执行NTF-019正式30条。

`SingleLane`只作原生控制参考，保持同一连续PCM账本、真实到达时钟和4MiB限制；NTF-030取消单／双路未读PCM及进度的800ms停止线。它以完整调用结束后的游标计算积压，不能把中途得到音频token当作完成。

单路reset回收未消费PCM后，原生调用数可能多于ceil(源采样／2560)，不能仅因额外调用把无异常的EOF会话记为失败。完成计数使用名义批次数下界，保留实际调用与尾部余量；双路仍严格等于源批次数。该修正不抹去原始r2退出码或异常。

`fresh()`在每次独立会话前重置种子42与原生reset，权重常驻；双路创建独立X2会话和私有SharedContext。`replay()`在正式模式中使用唯一生产者，按80ms包的真实到达时钟持续入账，计算屏障不能暂停生产者。预热模式只按下一步所需音频供给，不建立无界PCM队列。每批保留实际回执、采样摘要、内部ASR／状态、屏障等待、联合快照、读取时间和未读PCM；EOF部分批次只处理实际存在的80ms步。

`cleanup()`关闭观察、解除原生插桩，清空控制KV／历史／语音标志并记录reset缓冲摘要；X2 clear同时清除其会话缓存、文字、计数和回调。预热结果仅进入私有Context和诊断文件，不进入正式话轮；常驻权重和内核缓存保留。

清理记录的布尔值及原生缓冲长度必须符合冻结配置，否则该case失败；两轮reset缓冲摘要还须一致。NTF-052起，两轮完整预热和正式回放均由调用线程执行SoulX、常驻辅助线程执行X2，不再交换模型所属线程。实际完成顺序仍按回执记录；两种完成顺序的协议检查不通过迁移SoulX执行线程实现。

`limited_warmup()`复现有限控制覆盖（三次静音状态调用、一次3.36秒静音SenseVoice），X2仍执行两轮固定真实语音。`full_warmup()`每轮先用固定真实语音覆盖1.6／3.2／3.36／6.72／10.08秒识别形状，再运行完整原生拓扑；共两轮。直接长度探针的循环语音明确标记，不冒充自然话轮。自然文字修订、有效complete、reset、WAIT及多token EOS缺失均列入missing；覆盖不足直接停止，不启动在线时钟或019。

`compare_native()`在完整预热后用同一常驻真实权重，分别运行未插桩官方process和封装，输入为固定9.4秒预热流，种子与reset一致。NTF-053默认使用control_equivalence_skip_complete_asr：原始记录全部保留，仅将complete服务整段识别单独保存到complete_recognitions，并允许对应服务text从识别结果变为空字符串。逐批核对这类调用与跳过事件一一对应；其余音频token、LLM输入／logits、短窗ASR、有效状态、服务字段及reset缓冲不等都拒绝放行。显式skip_complete_recognition=False可运行strict_native完整对照。官方参考会执行原始重识别，正常预热回放和正式路径不会；不再将默认路径称为完整服务输出严格等价。

直接长度预热、有限预热和原生对照的实际模型调用均在本线程inference_mode内执行。run记录execution及X2 ready资源回执，replay记录controller_execution和complete识别策略；原生逐帧回执包含实际执行线程和CPU预算，供远端复核预热／正式是否同线程。

`summarize()`报告首帧、稳定阶段、首遇长度／分支与P50／P95／max；阶段为同步墙钟，ASR阶段包含门控／识别／修订，不能与SenseVoice子阶段重复求和。原始模型时间、联合提交和读取时间分开，首个闭合正文可见及EOF未知尾词另记。逐帧文件用于积压曲线和失败轨迹；没有闭合组时无新字不算漏发射。

`run()`核对输入摘要，冻结配置并依次执行两轮预热、清理、真实原生对照和固定三轴预检；每个case及最终result保存错误和退出码。只有完整预热、原生对照及3/3完整通过，才为NTF-019提供候选门槛证据；真实作业结果仍需核验资源与全批次来源。

首轮远端发现原固定语音峰值0.00316低于原生0.02远场阈值，导致有效complete覆盖不可能触发。待复测修正中，`prepare_warmup()`先沿用FDB确定性RMS0.05／峰值0.9增益，再做PCM16往返量化并追加原定1.6秒静音；保存原始RMS／峰值、增益、输出摘要和策略标识`rms_005_peak_09_pcm16_v2`。波形仍由同一文件产生，两双路条件的X2完全一致；正式FDB不变。静音或非有限预热输入直接拒绝，不伪造状态或强制触发分支。

直接SenseVoice长度探针改用与原生缓冲一致的float64，并保存dtype。r1的float32直接探针没有覆盖首遇原生float64调用，不能以相同长度认定相同路径已热。r2已通过完整覆盖和真实权重对照，但串行在线三轴2/3；用户已撤销次数限制，继续复测。

r2后双路预热和在线两条件统一使用`concurrent=True`，同一160ms内并发推进两个单worker模型，联合提交后才开始下一批。单路不变，模型和输入不变；与r2比较时必须明示调度已变。实际完成顺序据回执报告，不人为延迟结果。

NTF-018已通过并归档后，本入口增加`--suite fdb30`供019复用：只接受dual-full／single-full，运行原manifest的全部30条；必须给出018验收JSON及SHA256，摘要、双路通过标记、资源通过和三轴3/3任一不符均在模型加载前拒绝。默认preflight仍只运行018固定三条。`select_samples()`集中执行该门槛；结果记录实际套件、固定顺序及验收证据摘要。

正式套件逐帧文件使用gzip无损压缩，`replay(compress=True)`保留所有原字段并记录回放起点供墙钟评分；默认本地／预检文件不压缩。压缩及写盘在Context锁外且计入后续在线排队；生产者按真实时钟持续运行。每臂仍只有两轮起始完整预热，30条间只清理会话，不逐例重载或给失败样本补热。

`replay()`继续保存送音迟到、控制／X2主块及观察延迟，不因它们超过800ms中止；不暂停音频时钟或丢弃PCM。`run()`在新结果中明确记录时延和未读PCM时长停止条件为空、PCM容量4MiB，区分新合同与历史run。远端显存、RSS、磁盘及作业总时长保护仍由受限包装执行。
# 完整系统评测扩展

`fresh()` 与 `replay()` 可显式传递 `pcm_limit_bytes`，只用于双路完整系统评测，默认4MiB。原先预热与前端验收入口不传参数，保持原限制。

2026-11-05：`replay()` 新增可选的逐批消费与会话完成回调。消费回调只在联合发布及读取后运行，供半双工运行时异步启动或取消回答；完成回调在前端 session 清理之前关闭输出。默认不传回调，原前端预热和验收行为保持。可选输入结束后的静音由独立评测入口显式添加，不回填原历史轨迹。
