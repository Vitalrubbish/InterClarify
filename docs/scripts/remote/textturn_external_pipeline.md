# TT-011 冻结与串行续接

对应 `scripts/remote/textturn_external_pipeline.py`。`prepare`先核对TT-008的30来源／150例与TT-007的100条FDB录音，逐文件验证历史资产，绑定逐前缀审核结果；保留原分母和缺失信息，不换样。生成独立`prepared.json`，不会改动历史清单。

`Pipeline`维护独立状态、事件日志和调度回执。`wait_training`每30秒只读检查训练日志、退出码与调度历史；只有原训练Completed、退出码0、调度EndTime存在，才由`freeze_candidate`核验学习／重载与候选并冻结两份新清单。绑定训练源码和数据摘要，不以best提前存在代替完成。等待截止见配置。

`submit`在提交前再次核对没有活动作业；先落盘提交意图，再调用调度器，再保存job ID回执。未知回执不自动重试，跨进程的`flock`防止重复续接；重启时复用已保存job ID。`wait_job`要求调度结束、EndTime及退出码0、计划运行分母完整，UltraChat释放GPU后才提交FDB。运行错误停止；质量低而执行成功时继续，不按成绩重选候选。失败状态不能直接重启覆盖。

等待器使用已有conda Python、单CPU亲和、线程1、2GiB地址空间和外层超时；GPU测试另通过调度器申请1卡／8CPU／32GiB。日志节点不加载模型。状态与提交记录位于独立输出目录，不修改训练冻结源码。旧累计GPU限额已按用户授权取消，单作业上限保留。

初始化时再次核对准备阶段记录的协议和审核摘要；原冻结源码中的配置被改变时拒绝继续。
