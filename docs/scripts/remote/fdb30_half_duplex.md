# FDB30 完整半双工链路

## 整体功能

完整评测通过 `--pcm-limit-mib` 显式选择16MiB（兼容选择4MiB），保存到总报告 limits。默认前端合同不变。提高上限用于修复 r1 因积压触及4MiB的工程停止；新批次重跑全部样本。

`scripts/remote/fdb30_half_duplex.py` 把既有实时双路前端连接到普通 Qwen 与可取消 IndexTTS 回答会话。运行必须使用远端 conda 与调度显卡，输入为冻结 FDB30 manifest。每条原始输入末尾增加八秒诊断静音，正式评分截回原时长。

## 类与核心方法

NTF-057按用户最新指令在main中显式关闭原生控制一致性对照；完整预热及覆盖检查保留。warmup.equivalence明确记为用户取消、未执行、passed=null，不修复或补齐被省略的RNG消耗；复测直接评价当前适配路径的实际表现。

`Trace` 以输入回放开始为零点，线程安全地记录事件。`JointReplyConsumer.consume` 顺序消费每个联合快照，只允许有效 complete 启动新正文回答，有效 nonidle 取消；通过正文前缀游标避免跨 reset 重复追加全文。

`run_case` 启动实际播放录音，在前端逐批回调中消费状态，在结束回调中等待最后回答、关闭播放线程并保留录音摘要。取消后使用同一 SenseVoice 识别实际已播尾段；给共享教师的 generate 加互斥锁，避免与控制路同时进入模型，等待时间计入实测。`main` 校验固定 manifest、完整预热，逐例保存快照和结果，工程失败立即保留现场并停止，不跳过样本。

NTF-052／053：main将加载后的实际前端资源策略和X2 ready回执保存到总报告execution／x2_execution。SoulX由回放线程执行，X2使用常驻辅助线程，所有模型进程CPU计算线程为2。有效complete后的整段SenseVoice重识别被跳过，当前批次的X2正文仍为回答来源；空正文不启动、等待兜底不额外启动等消费者合同不变。已播尾段历史识别保持。

默认正式 30 条；`--smoke` 固定接话17、停顿16、打断104三条，只验证协议、生成、取消及录音，不以质量低分阻止正式运行。

失败清理再次异常时，将其单独记录为 `close_error`，仍写出样本结果和现存录音摘要，避免清理异常覆盖原始故障。
