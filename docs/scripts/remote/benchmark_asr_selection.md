# benchmark_asr_selection.py

只用于服务器 ASR 对照，不接入 LLM/TTS。`RealtimeAudio` 由独立线程按 80ms 时钟释放音频，模型只能读取已释放的前缀；原始输入进度、处理进度和输出时间独立记录。`EventSink` 保存原始 token 和累计文本，直接核查前缀，禁止冻结或修补文本。

`NemotronBackend` 使用官方 Transformers 音频特征 generator 和连续 RNNT 解码状态；按 processor 指定形状分块，真实 EOF 后补齐末块并增加明确记录的排空静音。`KyutaiBackend` 使用原生 Moshi 的 Mimi/LMGen 流式状态，每次只编码一个已到达的 80ms 帧，前置静音在测量前运行，后置静音仅在 EOF 后排空。

`score_sample` 使用同一规范化和编辑对齐计算 WER 及标点边界指标；无词尾时标不报告词级声学延迟。输出原始事件、逐样本错误／空结果及汇总，异常不从分母移除。`main` 先独立语音完整预热，然后执行固定配置和重复次数。

规范化固定 `whisper-normalizer==0.1.12`。标点评分只在表面词对齐后的边界计算，未匹配词上的标点计入假阳性／漏标点，不能只统计成功对齐的标点。预热必须存在真实 EOF 前的非空输出。Nemotron 使用 FP32，Kyutai 按官方入口使用 BF16，实际精度差异随结果报告。

存在独立 `alignments.json` 时，对最终正确匹配的词查找原始增量首次包含该完整词的时间，减参考词的估计声学结束时间。对齐规范词必须完全一致，且平均标签 log probability 至少为 -3；低于此固定阈值或词表不支持的样本不填时间。汇总同时给可测词数、正确词数、可对齐参考词数及全部参考词数，保留负值，不能只报延迟而隐藏覆盖率。数字参考可能不在英文 CTC 字母词表内，仍保留其 WER 和未对齐状态。

实际冷启动探针显示首次 CUDA 初始化可超过短预热音频时长，因此预热固定两遍同一独立 dev 样本：第一遍完成冷初始化和 EOF 排空，第二遍必须出现 EOF 前非空结果。两遍均单独保存，不进入评分；第二遍仍积压则拒绝测量。

编辑路径先最小化错误数，再在同代价路径中最大化正确词匹配数，使重复词等歧义尽量保留可测声学对应关系；该次级规则不会改变 WER。

chunk 参数映射包含 160/320/560ms，但实际可用值始终由发布模型的 processor 验证；多语言版本使用 320/560ms。
