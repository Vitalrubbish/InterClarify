# TTS 报告与试听包

`scripts/tts_selection_report.py` 从已完成的候选目录收集证据，生成汇总及匿名试听页，不做模型推理。无类。

`collect` 按 `--candidate 名称=目录` 收集逐条 JSON、环境与退出码，并复制固定 6 条试听 WAV。要求每个候选存在 60 条正式记录、退出码为零及一致的文本哈希；不接收失败或未完成目录冒充完整比较。原始全量 WAV 留在服务器。

`build` 读取收集结果，生成分位数表与按长度类别统计、冷启动记录、阈值敏感性、断流及 RTF。原始数据保留在 `reports/tts_selection/`，WAV 和试听 ZIP 放在 `artifacts/tts_selection/`。试听页按文本排列，随机匿名模型标签，模型映射单独保存。评分 CSV 的自然度和清晰度留空，由用户填写；没有自动自然度分数。

所有时间线 JSON 保留原始值，表格只为阅读取整。脚本不会修改现役配置或模型。

本轮 MOSS 的 60 条请求、逐条时间线和汇总已完整写出，包装 shell 随后因开发期更新脚本而退出 127。为避免把测量后的包装错误误当成音频推理失败，收集器增加显式 `--accept-wrapper-failure 名称`：仍须验证 60 条逐条无错、汇总成功数一致、完整块时间线；保留原始非零退出码及异常说明。该选项不改写退出码，不允许缺样本或请求失败。报告必须显式显示“测量完成、包装作业失败”。后续提交使用冻结入口，禁止更新正在读取的 shell 文件。
