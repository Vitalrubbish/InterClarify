## 1. Thinking 流与表达流

thinking 流指与表达流分工的内部任务分析过程，在当前信息和预算内分步推理，形成供表达使用的增量结果。“独立”表示调度与职责分开，不要求两者使用不同权重，也不要求一直运行或公开思维链。thinking 流不是把事先算好的答案按时间切块播放。

- **边听边想**：用户仍持有话轮时处理已到达信息，持续更新任务状态，并在有依据时提出主动澄清。
- **边说边想**：系统已经开始表达时继续进行尚未完成的任务分析，使后续表达得到实质补充或必要修正。仅在 TTS 播放前算好全部答案，不属于该能力的机制证据。

持续思考允许等待新观察，也允许在没有新输入时继续求解已有任务。回答递进指正确且相关的信息逐步增加，不要求固定话术或唯一顺序。已听到的错误只能通过后续明确纠正修复，不能从播放历史中删除。

## 2. 模块与动作边界

| 模块 | 职责 | 输出 |
| --- | --- | --- |
| Nemotron ASR | 提供真实在线转写，保留会话、前缀版本及观察截止点 | 累计文本、增量与实际到达时间 |
| XTurnix 控制策略 | 根据对话历史及系统 Listen/Speak 状态判断保持或转移，后续适配 thinking 条件 | Listen 下 keep/start，Speak 下 keep/stop 及合法动作分数 |
| Layer 0 | 小型预测器，仅判断当前是否适合发出系统 backchannel；通过专项训练获得时机预测能力 | 发出系统附和或继续等待的决策 |
| Layer 1 | 请求思考，利用结果生成澄清或回答，组织递进表达和必要的口头纠正 | 待表达文本与思考请求 special token |
| Layer 2 | 倾听期间自主发现缺口并判断介入价值；表达期间继续求解、检查约束和更新结论 | 带观察截止点、任务状态和版本的结构化增量结果 |
| 统一仲裁器 | 接收 XTurnix 控制决策、Layer 0 结果及 Layer 1 待表达内容，结合实际播放状态执行 | 单一执行路径上的选择、等待、提交与停止 |
| TTS 与播放 | 流式合成并播放已提交内容，回传实际播放状态 | 用户可听音频 |

XTurnix 输出状态条件下的控制动作，不是独立的用户 complete/backchannel 类别；Speak 下 keep 也不等同于用户附和标签。Layer 0 与 Layer 1 不重复训练这套通用控制，系统附和不由用户短确认或 keep 自动触发。Layer 0 既不负责普通接话、停播，也不判断澄清价值。Layer 2 的结果进入上下文后，由 Layer 1 继续正常自回归生成，不增加独立的任务语义复核或否决层。

表达和 thinking 请求保留 DuplexCascade 协议。XTurnix 原生 keep/start/stop 交给同一个仲裁器，在新控制模式下不同时执行旧 DuplexCascade 控制 token；历史 token 保留为真实生成记录。Layer 0 系统附和编码在实现时冻结，不复用用户附和 token 表达相反方向。

Layer 0 与 Layer 1 的结果分别交给 Unified Arbiter，仲裁器结合 XTurnix 决策及实际播放状态执行。Layer 0 只提供抽象结果，具体字段、token 和编码尚未确定，不引入 backchannel cue 协议。Layer 2 的 thinking 结果仅提供给上下文，Layer 1 生成表达；thinking 条件化控制的输入格式和训练在后续明确。实施顺序见[工程计划](../engineering_implementation.md)。

系统保持单一仲裁器与单一 TTS 播放所有权。控制和思考请求 token 均为内部信息，不直接送入 TTS；Nemotron、XTurnix、Layer 0 和 Layer 2 不独立播放音频。用户已听到的内容不可撤销。不设计 Layer 3，也不引入候选表达文本替换或回滚机制。Layer 2 不产生候选表达文本，只提供任务分析结果；Layer 1 基于真实生成历史继续表达。系统 backchannel 保留在总计划，当前步骤不训练或接入；未来其正文由表达路径提供并经同一播放路径发声，具体短语方案待定，不把措辞选择扩展为 Layer 0 的训练任务。

### 2.1 前端状态与系统附和

Nemotron 只输出转写及流式生命周期信息。XTurnix 结合完整的当前可见历史和显式 Listen/Speak 状态给出动作。状态由统一运行时依据真实会话及播放维护，控制结果返回、提交和可听播放分别记录，不能由 ASR 停顿或模型推测直接冒充执行状态。

停顿不等于用户让轮。XTurnix 的 `<|pause|>` 输入来自因果 VAD 或真实上游分段，不能由文件 EOF 或离线最后 token 锚点生成。原版模型不保证理解内部 thinking 结果；后续需要训练其利用明确来源的分析上下文，在主动介入、继续等待和过期结果等对照中学习动作，不能把 Layer 2 返回直接映射为 start。

Layer 0 仍只预测用户持有话轮时是否适合简短附和。输入可结合当前声学信息、转写、XTurnix 决策、必要历史及真实播放记录；特征与模型后续确定，不能将 Speak/keep 直接当作系统附和正例。

系统附和训练是总计划中后续明确要做的工作，不以 XTurnix 控制能力不足为触发条件，也不阻塞当前前端接入。当前不采集或训练 Layer 0；后续数据需标注系统听者附和的有效事件窗口与继续等待，区分机会与实际发声，保留无需回应、即将交接和已有输出冲突等负例。训练、开发与测试按原对话分组；FDB 测试不参与训练或阈值选择。具体数据来源、规模、标注和模型参数在实施前细化，与两篇能力文档中的 thinking 流专项数据分别计数。

当前先规划[Nemotron＋XTurnix 的 FLEURS 测试](../dev/XTurnix/quality_test_on_fleurs.md)，尚未实施，不新建工作单；用户已取消的 FDB 测试不因本次调整恢复。后续 Layer 0 实现后，若另行开展系统附和评测，可参考 FDB v1.0 ICC 的频率与时机分布指标并检查误抢话；用户附和/打断可参考 v1.5 相应子集。只凭频率不能证明附和合理，需独立事件集和人工抽查。这些基础工程评测与两组 thinking 流 benchmark 分开报告。

所有控制决策与系统附和建议保留外部来源、输入截止点和版本，不冒充 Layer 1 实际生成的历史 token。仲裁器协调同一时刻的附和、普通回答、主动澄清与停止请求，实际用户打断时能停止当前附和。已被用户听到的附和不能撤销或从历史删除。

## 3. 思考任务调度

Layer 1 长期保留会话历史与可复用状态，随新增输入窗口和事件执行推理，表达期间正常自回归生成。Nemotron 的转写与 XTurnix 控制结果持续送达；接话事件可立即调度空闲的 Layer 1，不额外等待固定 micro-turn。正在执行的推理在明确边界消费后续观察，不能因每帧状态取消重算。用户持续表达时，Layer 1 仍有机会处理新增信息并请求思考；Layer 0 的附和建议不是 Layer 1 唯一启动条件。没有新增信息且没有待生成内容时可以等待后续输入，不要求持续空解码。Layer 2 结果到达后的处理遵循[第 4 节](#4-结果回写与真实历史)的正常边界注入规则。

Layer 1 通过独立 special token 请求异步思考，倾听或表达时均可调用，无需先开口或伴随口头回应。运行时识别该 token 并启动 Layer 2，Layer 1 继续接收输入和生成表达。

每个会话最多一个活动思考任务。同一逻辑任务可以包含多次串行短推理调用。任务活动期间，重复请求合并到现有任务，不创建并行任务或重启；新增 micro-turn 自动进入任务输入缓冲区，无需再次唤醒。

### 3.1 持续输入与分步推理

Layer 2 唤醒时，在模型上下文预算内读取截至当前的完整可用对话历史，包括用户表达、系统实际生成与已播放记录及可用任务信息。活动期间在短推理边界读取新增观察，结合紧凑状态更新澄清判断或回答分析。输入已有全部条件时，也可以继续完成尚未解决的推理，无需等待新的用户内容。Layer 2 维护自己的上下文与缓存，任务状态辅助分析，不替代原始历史。

处理期间累积的多个窗口可以合并读取，原始事件历史仍完整保留。推理只使用实际已到达的信息，ASR 修订按版本处理；结果记录实际依据的观察位置。输入已进入缓冲区不代表当前模型调用已经使用该输入。历史超出上下文预算时不得静默截断。

Layer 2 的处理窗口时长可配置，独立于 Layer 1 当前的 600ms micro-turn、音频传输和 ASR 分块时长。接收每个 micro-turn 不要求每个窗口都单独完成一次推理。

| 任务状态 | 行为 |
| --- | --- |
| 继续观察或推理 | 保留活动任务与状态，等待新观察或继续求解；尚无可用结果时无需回写 |
| 发布增量结果并继续 | 当前已有可供表达使用的可靠分析，发布结果版本并保留活动任务；发布不等于结束 |
| 结束并继续倾听 | 问题已解决或无需继续跟踪；返回最终继续倾听结果，结束任务并休眠 |
| 结束并建议澄清 | 当前判断值得介入；返回结构化澄清结果，结束任务并休眠 |
| 结束并返回回答分析 | 当前回答分析完成，返回最终结论、关键条件及必要的修正依据，结束任务并休眠 |

任务休眠后由新的请求 token 再次唤醒。信息变化及其对澄清或回答的影响由 Layer 2 持续处理；增量结果不要求在每个窗口产生，也不允许建立多个并行思考任务。

### 3.2 唤醒覆盖与介入频率

采用“唤醒覆盖优先、澄清介入从严”的策略。Layer 1 根据可能影响任务的信息缺口或复杂判断需求请求思考，无需先完成完整的介入价值推理。Layer 2 根据持续可见的信息权衡现在澄清与继续观察，仅在有充分依据时返回澄清建议。

原型通过 Layer 2 的 system prompt 约束介入频率，强调插话和恢复表达的交互成本；训练数据包含合理等待、已有介入和无需反复思考的对照。表达期间根据任务未解决部分请求或继续思考，不以持续输出进展话术作为唤醒理由。本阶段不设置运行时硬性冷却时间、次数上限或频率限流。

唤醒、思考开销、结果发布与实际发声分别记录。倾听任务按[倾听文档](listening.md#5-benchmark-评分与优势判定)评价，表达任务按[表达文档](speaking.md#2-信息标注与实际可听评分)评价；两者共享[第 6 节](#6-共同实验协议)的对照。失败、计算开销与各阶段实际时延同时用于覆盖统计和机制分析，不等同于用户交互成本。建议、分析结果与实际可听内容分别标识。

## 4. 结果回写与真实历史

结构化结果区分继续倾听、建议澄清和回答分析，并包含任务标识、结果版本、实际观察截止点、任务是否结束及适用条件。澄清结果包含目标与简短依据；回答分析包含已确认信息、待解决条件、当前结论，以及与先前结果发生变化的内容；这些均为语义分析信息，不是待播放的回答草稿或替换片段。结果作为外部上下文供 Layer 1 使用，具体措辞和口头纠正由 Layer 1 生成，不直接改写播放队列。

首版不为 Layer 2 返回额外新增 special token，先用结构化状态区分增量发布与逻辑任务结束。一次短推理输出结束不等于整个任务结束。结果块的来源、版本与边界由运行时明确标识，注入内容不冒充 Layer 1 自己生成的返回事件；具体编码仍待实现。版本用于保持结果顺序及追溯依据，不增设独立语义复核层。

结果到达后先暂存，在 Layer 1 下一次实际构造 micro-turn 推理输入时，与该边界可用的对话信息一起注入。若本次输入已构造，则等待后续推理边界。结果到达本身不取消当前生成、不触发重算，也不中断当前播放。回写保留既有对话与真实生成历史。

Layer 1 直接基于包含结果的上下文继续自回归。待表达文本与 XTurnix 控制决策、Layer 0 的附和建议进入统一仲裁器，再交给单一 TTS 播放路径。普通回答、系统附和和主动澄清具有不同用途并记录输出类型；不能仅凭用户仍持有话轮就一律禁止主动澄清。Layer 0 不承担澄清价值判断。

后续结果使原判断变化时，Layer 1 根据真实生成历史继续组织后续表达，必要时明确纠正已说出的错误。Layer 2 不生成、替换或撤销候选表达文本；结果版本是分析结果的版本，不是文本修订补丁。不设计 Layer 3，不回滚生成历史、已提交片段或已播放内容。尚未发声的文本错误不计已听错误，也不因此赋予运行时新的文本修改动作。

## 5. 预算与失败处理

单次 Layer 2 任务受计算预算约束。调用失败、超时或总预算耗尽后，记录原因并释放活动任务，不自动重试；Layer 1 继续正常运行。后续允许由 Layer 1 新生成的请求 token 再次唤醒。

失败和超时与正常结束分别记录，不作为模型已判断无需澄清或回答完成的结论。仅明确发布的结果版本可供 Layer 1 使用；未发布的中间推理不能冒充正式结果。后续失败不删除已发布结果或已播放内容，其有效性仍按当时依据及最终表现评分。评测保留失败与超时覆盖情况。计算资源预算与介入频率约束分别处理。

## 6. 共同实验协议

| 对照 | 用途 |
| --- | --- |
| 直接流式响应，不启用独立 thinking 流 | 建立不额外思考时的质量与时延起点 |
| 延后思考 | 倾听任务在当前观察点需要作决策时才启动，表达任务在完整思考后开口；区分计算重叠带来的收益 |
| 完整框架 | 倾听与表达期间均可运行 thinking 流，按真实到达的结果更新表达 |
| 分阶段消融 | 分别关闭倾听期间或表达期间的思考，其他条件尽量一致，定位两种能力各自的贡献 |

倾听任务另报告等用户让出话轮才思考和澄清的轮后策略，作为覆盖范围的参照；它无法在轮内介入，不能单凭该参照的轮内遗漏证明框架优越。消融时明确既有结果是否保留、活动任务何时停止，避免把此前计算的结果误算为当前阶段的思考。

优先采用相同基础模型、前端、TTS、语速、输入时序与输出长度预算，并在可比较的总计算预算下报告多档质量与时延结果。不同模型或额外硬件的比较另列；同时报告输入/输出 token、调用次数、硬件、并发及实测运行时间，不能把增加计算资源直接归因为架构收益。

按同一样本配对比较，正式测试前冻结评分协议和时间预算，报告不确定性及任务分组结果，不以单个演示或一个综合分数下结论。所有系统只读取当时可用的信息；记录观察截止、计算完成、结果送达、注入、提交与实际播放时间，分别验证行为收益与真实的计算重叠。

无独立 thinking 流的对照仍可由 Layer 1 持续观察并作决策，不等同于一律沉默；表达期间关闭 Layer 2 也不等于禁止 Layer 1 正常生成和推理。两篇能力文档分别说明检查点、保留上下文及思考关闭边界，避免用金标时机启动对照。

## 7. 共同训练与数据约定

### 7.1 训练对象与损失边界

研究包含大规模对话数据构造与实际训练。原型可冻结 Layer 2 权重，用于验证协议、采集异步轨迹和建立未专项训练的起点；正式研究不限定为 prompt 调用。

| 模块 | 两项能力共用的训练约定 |
| --- | --- |
| Layer 1 | 训练倾听与表达期间的思考请求、结果利用、可靠的早期表达、递进回答与口头纠正 |
| Layer 2 | 覆盖澄清判断、回答分析、增量发布和任务结束；是否更新权重与采用何种分析监督，在试标和模型选型后确定 |
| Layer 0、Nemotron、XTurnix | 保持附和、转写与通用控制分工；thinking 条件化控制后续训练，附和专项另行规划 |

先对审核后的轨迹开展监督训练。Layer 2 结果是 Layer 1 的外部输入，在 Layer 1 训练中屏蔽该输入块的损失；Layer 1 的请求和后续正文参与监督。若训练 Layer 2，其目标仅为内部任务分析与状态结果，按对应模块另计损失，不监督其生成候选表达文本。结果输入不计损失不等于后续表达不训练。

训练需要目标输出文本，不能拿 judge 分数代替自回归目标；教师可基于当前可见前缀和已到达结果生成表达目标，再做审核。教师的紧凑分析状态可作为候选 Layer 2 监督，不默认采用冗长思维链，也不以“未使用人工参考问句”推导出“不需要表达目标”。

不奖励思考调用、推理长度或改口次数。先验证监督训练，其他优化方法、是否更新 Layer 2、参数更新方式、损失权重及批次规模待试验确定。未确定的训练细节在两项能力中采用相同状态，不能一篇默认冻结、另一篇默认已完成联合训练。

### 7.2 共享轨迹记录与数据隔离

每条轨迹保留场景/对话/分支标识、当前可见前缀、ASR 版本、思考请求、任务与结果版本、观察截止点、结果到达和注入顺序，以及 Layer 1 真实生成、提交和播放记录。Layer 2 分析结果与 Layer 1 表达字段分开，禁止把分析结果当作已生成或已播放的回答。

教师生成和被测系统均不得读取未来用户续说或隐藏评测答案。输入进入缓冲区、被调用读取、结果生成、结果注入和实际可听是不同事件；生成监督不得把它们合成理想的同步时刻。

两组 benchmark 各自建立试标、开发与正式测试集，和训练集分别统计。场景、共享前缀、任务模板、资料来源及其派生改写按组隔离并去重；同一推理题换数字不能分散到训练和测试。正式测试不用于教师筛选、prompt 调整、阈值选择或训练数据生成。

分别报告独立任务场景、对话、分支轨迹、有效音频时长和 token；窗口切片、重叠视图与多次采样不计作新的独立场景。总目标是大规模语料；旧澄清专项预算不是总量上限，两项数据规模、配比、生成预算与人工审核数量仍待试标确定。

### 7.3 生成审核、语音实现与联合训练

两项能力分别构造任务和目标、通过教师与框架生成因果可行的轨迹，再进行可核验检查、自动筛选和分层人工抽检。抽检同时覆盖正负例、难度、审核通过和拒绝的样本，记录通过率、错误类别与分歧；生成模型与 judge 相互认同不能代替核验。

先明确语义事件与调度，再确定语音采集或合成、ASR 可见输入及对齐方式。标明教师、合成语音和模拟延迟来源；训练可以采用明确标注且因果可行的模拟调度，正式 benchmark 必须实测推理、传输和播放时序，不能提前注入教师结果冒充在线收益。

除单项轨迹外，训练集可包含先倾听澄清、再回答并继续分析的组合对话，以验证状态衔接。组合对话的后续用户回答只有实际到达后才能供思考与表达使用；两组首版 benchmark 仍按各自独立协议评分，不要求用户模拟器。

训练实验比较未专项训练、仅倾听数据、仅表达数据及联合训练，在资源允许时增加数据规模实验。联合对话只计一次独立对话，同时标明其中两种行为；不能在汇总规模时重复相加。两篇能力文档具体说明各自训练轨迹和验收目标。

### 7.4 实施边界

本地和远端统一使用 conda。正式训练和集群测试在远端执行，实施前明确最大工作数、CPU/GPU 内存、磁盘、日志和检查点预算。文档拆分不启动数据生成、训练或集群作业；工作单依用户明确指令建立，代码与对应中文实现文档同步维护。
