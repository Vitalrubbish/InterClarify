## 1. 总体分工

系统将任务思考与语言表达分开调度，使思考既能发生在倾听期间，也能在系统表达后继续进行。

| 模块 | 职责 |
| --- | --- |
| X2Streaming-ASR | 持续提供用户转写正文 |
| SoulX-Duplug | 利用音频和内部 SenseVoice 链路预测用户五状态；后续适配为同时利用转写与思考结果 |
| Layer 1 | 在持久 Context 中接收输入、请求思考、生成系统附和 token 与实际表达正文 |
| Layer 2 | 冻结模型按周期分析对话，正常结束时交付任务结果 |
| 共享上下文与任务调度 | 保存前端快照、交付逐批输入、维护思考任务和结果来源；其中逐批交付尚待实现 |
| 输出运行时、TTS 与播放器 | 统一管理正文入队、合成、播放和取消，记录实际执行事实 |

Layer 2 提供事实、缺口、结论及依据；SoulX 判断用户状态及后续主动澄清机会；Layer 1 决定自身表达并组织措辞。全部实际发声经过唯一输出执行点与单一播放路径。

## 2. 前端与共享上下文

SoulX 与 X2 读取同源 PCM。每个 160ms 批次等待 SoulX 本步与 X2 两个 80ms 步完成，再将已闭合正文、状态和实际进度一次联合提交，成功后推进下一批。无新增文字也提交新状态；两路先完成的一方只在内部暂存。联合提交保证批次一致性，尾词覆盖仍须单独核验。

现有 SharedContext 保存最新联合快照。Layer 1 接入时还需有界逐批缓冲、消费位置和去重，避免慢读漏掉短暂状态；仅轮询最新快照不能满足协议。Layer 1 自身 Context 保存实际输入与生成的 token 历史，两者用途不同。具体前端合同见[独立流式前端](../dev/SoulX-Duplug/independent_streaming_frontend.md)与 [Context 接口](../dev/SoulX-Duplug/shared_context_interface.md)。

SoulX 后续在合法输入边界联合读取音频、权威转写和已发布的 `result`，训练结果条件化的控制与主动澄清能力。输入编码、缓存、控制输出及澄清生成边界仍待设计，现有五状态不表示已经支持主动澄清。无结果时仍须持续观察音频和处理有效打断。

## 3. Layer 1：持久 Context 与表达

Layer 1 首轮常规周期为 **3 × 160ms＝480ms**。每周期在合法输入边界按顺序读入三个前端批次的新增转写与状态，再生成一个有界 token 片段。组内三批完整保留，不能只取最后状态；480ms 表示输入覆盖范围，实际处理耗时与持续吞吐待远端验证。

常规生成 token 留在同一 Context，后续继续解码，历史不重复注入；首音前取消的回答按第 5 节删除。新增执行事实和已发布 `result` 在后续合法边界作为外部输入写入；已构造的在途输入保持固定。前端持续推进，不等待 Layer 1。

| 生成内容 | 运行时处理 |
| --- | --- |
| `THINK_REQUEST` 专用 token | 启动或合并 Layer 2 任务，无需同时开口 |
| `SYSTEM_BACKCHANNEL` 专用 token | 记录一个系统附和事件，不附正文或专用闭合标记；内容与发声留待后续 |
| 普通表达正文 | 按合法生成边界提交 Text FIFO，再由 TTS 与播放器输出 |

表中 token 名称表示语义，具体字符串和 ID 在接入时确定。用户的 `user_backchannel` 是外部状态，系统附和是 Layer 1 自身生成，二者分别记录；两个 special token 均不送入 TTS。

普通回答须在 Layer 1 实际读到当前话轮已联合提交的有效 `user_complete` 后生成。此前可请求思考或产生系统附和 token；重复或已失效 complete 不得重新开启回答。回答在原 Context 中继续，不因 complete 清空会话或另建回答调用。主动澄清的独立生成边界仍待讨论。

## 4. Layer 2：异步思考

Layer 2 使用冻结权重与提示词执行协议，不训练或适配参数。每会话最多一个活动任务，每任务最多一个在途调用；重复请求合并。周期为一次短推理调用，独立于前端和 Layer 1 的节拍。

每周期只读**当前可见对话与同一任务上一轮 `analysis`**，首轮分析为空。用户正文取自最新联合快照，助手正文取自 Layer 1 整理后仍保留的生成历史，首音前已删除回答不再读入；整理时去掉状态、行为 token、结果封装及播放／取消信息。读取新用户正文不等待 Layer 1 消费积压批次。

输入在调用开始时固定，新对话在下一周期读取。本轮增量 `analysis` 替换上一轮分析，更早分析不作为输入，也不能通过旧缓存隐含保留；因此该协议只提供相邻周期的分析衔接。

| `progress` | 含义 |
| --- | --- |
| `continue` | 继续计算，无新对话也可推进 |
| `await_input` | 保留任务和本轮分析，等待对话文本更新；纯状态或播放变化不唤醒 |
| `done` | 同次调用另生成可独立理解的 `result`，通过更新检查后发布并结束任务 |

返回 `done` 或 `await_input` 时，若已有未读取的对话更新，先在同一任务下继续一轮，本轮候选结果不发布。正常结束后由 Layer 1 新请求启动后续任务；用户打断或停播不自动清空活动思考。

两个下游只接收同一份 `result`，不接收中间 `analysis` 或 `progress`。结果可以解决一个缺口或子问题，包含必要结论与依据，不含话轮指令、候选问句或回答草稿。运行时附来源、任务标识、版本、实际读取位置及读入／发布时间，SoulX 和 Layer 1 各自在合法输入边界消费。

结果发布不授予话轮、不触发播放，也不中断当前解码。调用失败、超时或预算耗尽时记录原因并释放任务，不自动重试，不以中间分析补造结果；既有结果保留原依据。

## 5. 输出执行与打断恢复

普通表达由唯一输出运行时登记 `output_id`，再提交 Text FIFO，文本块、TTS 与音频块统一检查输出资格。生成、提交、取消和实际播放分别记录；已经生成不等于用户已经听到。系统附和 token 只记录事件。

有效 `user_nonidle` 从每个 160ms 已联合提交批次消费后，由同一执行点处理活动输出：准备阶段取消尚未开播内容，播放阶段请求停播并取消未播内容。**打断不等待三拍、Layer 1 解码结束、TTS 完成或思考结果**，前端不另设提交前停止旁路。

停止时先关闭旧输出入口，旧标识的迟到文本和音频不得播放；停播或取消确认后才视为输出关闭。停止失败须记录，并阻止新播放启动。`user_backchannel` 等其他状态只供 Layer 1 理解，不映射为播放器开始、维持或恢复指令。

取消后的上下文以播放器确认的实际已播采样为准：**首音前取消，删除本次系统回答，将用户前后两段拼接为同一条消息；首音后打断，保留系统全部已生成文本，续说作为新的用户片段。** 已生成与实际已听范围分开记录，首帧与取消并发时以最终播放确认为准。该分组与整理层尚待接入，ASR 会话及 SoulX 内部 reset 不代替这一边界。

首音前删除须同步处理 token 与 KV／解码状态，必要时重建上下文；原始生成记录只留审计，不能再次注入已删除回答。具体规则见 [Layer 1 取消协议](../dev/layer1/protocol.md#51-首音前与首音后取消)。已听内容不可撤销，Layer 1 结合新条件与执行事实组织接续或纠正；普通恢复回答仍等待对应有效 complete，使用新输出标识，旧队列不自动续播。

## 6. 训练范围与待定事项

专项训练对象为 Layer 1 与后续结果条件化的 SoulX，Layer 2 保持冻结。Layer 1 首轮基座为 Qwen2.5-7B-Instruct，Qwen3 保留为后续候选；监督思考请求、单 token 系统附和和实际表达。外部转写、状态、结果及执行事实作为条件屏蔽预测损失；新增 token 须覆盖相应词表与输出参数。轨迹只使用当时可见信息，同源对话及分支按组隔离。

token 编码、Context／缓冲容量、解码与任务预算、缓存适配，以及 SoulX 结果注入和主动澄清边界，在实施前另行确定。集群测试与正式训练使用远端 conda，明确并发、内存、磁盘及运行时限。

倾听与表达的专项任务、benchmark 和详细训练方案留待后续讨论。当前研究目标见[研究方案](../research_design.md)，已有数据构造思路见[数据设计](../dev/layer1_training/data_construction.md)，实施状态见[工作单](../issue/README.md)。
