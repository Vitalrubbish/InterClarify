# Layer 1 训练设计思路

更新：2026-11-05。本文说明 Layer 1 学什么、用什么数据训练，以及如何验证收益。系统分工与行为边界见[架构设计](architecture.md)，具体训练参数在实验阶段确定。

## 1. 目标与分工

Layer 1 从通用指令模型出发，学习在持续输入下组织自己的表达。SoulX 提供用户状态，X2 提供转写；Layer 1 负责等待、系统附和、正式回答，以及取消后的表达恢复。原 Layer 0 的附和能力统一纳入 Layer 1。

训练围绕四类行为展开：

- **等待与回答**：结合当前正文和外部状态判断自身行为。普通回答须在模型实际读到当前话轮有效的 `user_complete` 后生成，避免提前回答和重复回答。
- **取消恢复**：用户续说或修改条件后，结束旧表达方向，根据新信息重新组织回答。
- **系统附和**：学习是否在当前机会输出一个专用 token，同时在无需回应、刚触发过或存在输出冲突时保持等待；当前不学习具体内容。
- **thinking 利用**：基础交互稳定后，学习请求 Layer 2 分析，利用已到达的结果补充回答或明确纠正自身表达。

初期固定 SoulX、X2 与 TTS，集中训练 Layer 1。停止播放由运行时执行；模型训练负责正确利用取消和播放事实组织后续表达。

后续 thinking 阶段保持 Layer 2 权重冻结，通过提示词执行周期协议。专项训练集中于 Layer 1 的请求与结果利用，以及 SoulX 的结果条件化控制；不增加 Layer 2 训练目标。

## 2. 训练基座与输入输出

首轮以官方 [Qwen2.5-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct) 为训练起点，Qwen3 可作为后续底座候选。若采用支持 thinking 切换的 Qwen3 模型，Layer 1 先使用非 thinking 模式，以便单独评价外部 Layer 2 的收益。

采用参数高效微调，输入输出按 [Layer 1 周期协议](../dev/layer1/protocol.md)组织为持久 Context 中的 token 流。首轮常规周期为三拍 480ms，每周期按顺序读入三个前端批次的新增转写与各自 SoulX 状态，再解码并保留实际生成 token；历史不重复注入，普通回答可跨周期继续。新增执行事实及最终 `result` 在合法边界作为外部块写入，不读取中间 `analysis` 或 `progress`。训练切片匹配三拍输入，周期对照须说明训练与推理节拍是否一致。

思考请求与系统附和使用各自专用的 special token。系统附和仅为一个完整事件，不跟随附和正文或附和专用闭合标记；当前只监督 token 选择和时机，不设计内容及发声。具体 token 字符串、ID、普通表达片段结束与等待编码在实施时冻结。新增词表 token 时，训练须覆盖其词表及输出参数。监督两类标记和普通表达正文；外部转写、状态、结果及执行事实为条件，不计算相应预测损失。

## 3. 数据与监督

数据以独立对话或任务片段为来源，保存随时间推进的可见信息及目标行为。通过冻结的前端获得真实转写增量与状态轨迹，覆盖正常交接、短暂 complete、识别滞后、续说、改口和取消恢复。训练样本选取有意义的决策时刻，避免用大量重叠切片代替来源多样性。

核心原则是**只根据当时可见的信息监督模型**。例如“订周五的车票……不对，是周六”，在“周六”到达之前，不能要求模型预知改口；当时合理的回复也不因后来被取消就成为错误样本。教师与学生使用相同的可见信息，未来音频和完整转写仅用于离线审核。

恢复数据区分两种情况：首音前取消时，未播生成不能当作助手已经说过的话；已播后取消时，保留已听事实，依据用户新条件回答，必要时明确纠正。取消后的旧文本不作为自动续写目标。

附和数据按机会标注“适合但可不触发”“不应触发”“不确定”，正例只要求输出单个系统附和 token，不编写参考附和语句。用户的 `user_backchannel` 与系统附和分别标注。若当前转写与状态不足以判断，不强行给出精确时机标签；允许不触发的机会不自动视为负例。

构造流程为：先划分来源，再生成前缀轨迹与目标，人工抽查含噪状态、恢复和附和样本，最后补充训练分区中的模型失败案例。同一对话的裁剪和分支进入同一分区；FDB、SoulX-Eval 及其改写不用于训练或阈值选择。

<a id="12-路线-b分阶段训练协议表达与恢复"></a>

Layer 2 提供的条件采用[周期协议](../dev/layer2/protocol.md)：自身每周期只读对话与上一轮分析，输出增量 `analysis` 和 `progress`，结束时另生成 `result`；Layer 1 只读取同源结果及真实依据，不接收中间分析、回答草稿或任务进度作为开口指令。现有 pilot v1 尚未适配该输入和结果监督；本轮不改变普通回答边界。

## 4. 分阶段训练

先开展监督微调，按以下顺序逐步增加能力：

| 阶段 | 学习重点 | 需要确认的结果 |
| --- | --- | --- |
| 协议适配 | 理解外部状态，输出等待或合法回答，区分动作与正文 | 能遵守基本生成边界，普通回答能力保持 |
| 含噪状态与取消恢复 | 处理短暂 complete、续说、改口及首音前后取消 | 使用最新条件，避免错误续写和过度等待 |
| 系统附和 | 学习单 token 的触发机会、时机与重复抑制 | 机会覆盖、误触发和重复触发可评估，不评价附和措辞或音频 |
| thinking 适配 | 请求思考、利用异步分析、递进回答与自我修正 | 在基础交互稳定的前提下检验 thinking 收益 |

先用约 300—500 个独立来源试标和小规模训练，确认协议与恢复行为可学，再扩大任务和噪声覆盖。扩展数据量由开发集表现和学习曲线决定，同时保留普通任务回答，避免模型只学会等待或短附和。

各阶段保存可比较的检查点。thinking 阶段的主动澄清还需 SoulX 的 CoT 条件化与相应生成边界设计，具体任务分别见[倾听研究](listening.md)与[表达研究](speaking.md)。

## 5. 评估思路

以完成协议适配的模型为比较起点，观察加入恢复、附和和 thinking 训练后的变化，并开展去除对应训练内容的消融。同一组比较保持底座、输入信息、前端控制、语音输出条件与预算口径可比。

共同关注回答质量、协议遵守、过度等待、重复回答、实际抢话、首音与停播延迟、恢复时条件更新及计算成本；实际表达依据播放事实评价。系统附和当前只评价 token 触发的覆盖、时机、误触发和重复，不将其等同于实际发声。

基础交互训练与 thinking 收益分别报告。取消恢复能力不直接证明主动澄清有效；附和 token 的触发恰当也不直接证明边说边想改善了任务求解。
