# 边说边想：benchmark 与训练数据

更新：2026-10-23。[研究背景与参考文章](../research_design.md) · [架构设计](architecture.md) · [边听边想](listening.md)。

本文检验系统开口后的 thinking 流能否改善有效内容到达与回答质量，并设计相应的大规模训练数据。统一采用架构合同：不设计 Layer 3，Layer 2 仅把分析结果送入上下文，不生成候选表达文本；Layer 1 继续生成后续表达，必要时口头纠正已说出的错误。所有发声经过同一仲裁器与 TTS 播放路径，已听内容不能撤销。

## 1. 任务设置与两个子任务

主测试在系统开口前提供完整的用户任务和可用资料，开口后不额外释放隐藏条件。系统需要在表达期间继续分析已有问题，避免把接收新信息的收益混作持续推理收益。用户中途补充条件可作为后续独立扩展，不与主测试合并评分。

| 子任务 | 场景设计 | 评价目标 |
| --- | --- | --- |
| 回答递进 | 存在可以先说明的有效部分，完整答案还需计算、多约束比较或推导 | 早期内容可靠，后续增加实质信息，最终满足任务要求 |
| 表达修正 | 较早的直觉判断可能因遗漏约束而变化，系统可自主决定是否先表达结论 | 发现变化后及时调整；已经说错时明确纠正，避免继续扩散错误 |

两个子任务属于同一组 benchmark，分别报告。数据包含无需长推理、无需改口和暂不适合下结论的对照；不要求每个回答必须递进多层或发生修正，不因正确答案直接给出而扣分。

例如，用户比较两种采购方案：A 有 100 元固定费、每件 1 元，B 无固定费、每件 3 元，采购 20 件，并询问数量变化时应如何选择。系统可以先给出成本关系“A 的总价是 100 加数量，B 是数量的三倍”，随后算出当前 A 为 120 元、B 为 60 元，给出 B 更低的结论，再说明数量超过 50 件时 A 才更低、50 件时相同。每个新增信息点都有可核验内容；仅说“我先比较一下成本”不计有效内容。

若系统先声称 A 更便宜，随后发现遗漏固定费，需要明确纠正此前比较并给出正确结果。纠正成功与先前错误分别记账；直接答对的系统无需为了获得修正分而改口。相同费用设置可构造数量和约束变化的对照，但相关变体必须处于同一数据划分。

## 2. 信息标注与实际可听评分

每条任务标注必要信息点、正确结果、关键约束及信息依赖，允许多种合理回答顺序。计算题、约束比较优先采用程序核验；开放式任务采用明确的要求清单、模型辅助评价和独立人工抽检，不按公开推理的长度或措辞深度打分。

| 指标 | 含义 |
| --- | --- |
| 首次有效内容延迟 | 从用户任务输入完成到用户实际听完第一个正确、相关且有用的信息单元；问候、复述任务和填充语不算 |
| 固定时间内有效信息覆盖 | 在预先冻结的若干时间预算下，已听完的正确必要信息点占比；重复内容不重复计分 |
| 任务完成质量与到达时间 | 最终正确性、关键条件覆盖，以及首次完整表达正确任务答案的时间；未完成与失败保留在总体统计中 |
| 早期错误与前后冲突 | 已说出的错误判断、无依据承诺，以及是否得到明确修复；最终答对不能抹去早期错误 |
| 修正质量与延迟 | 对实际发生的错误，检查是否准确指出变更并纠正；从错误可听完成到明确修正可听完成计时 |
| 表达效率 | 重复、无效填充和总时长，辅助判断有效内容是否被冗余表达推迟 |

固定时间预算统一从用户任务输入完成计起，包含开口前的等待；另报从实际开口起的曲线，解释表达期间的行为。结合实际播放记录与语音对齐判断信息单元何时完整可听，不能用文本生成时间代替。语速、TTS 和输出预算尽量一致，不靠加速播放获得优势。

Layer 2 的分析结果更新不等于表达文本修订。尚未发声的文本错误不计已听错误，也不计口头纠正成功；本架构不提供候选文本替换或回滚，用户可听的自我修正必须由 Layer 1 后续明确表达。主测试中的修正率以实际发生的错误为条件，同时报告总体错误率、未修正数及最终质量；没有错误的样本不记修正失败。未修正错误保留为未修复，不能只在成功纠正的样本上计算延迟来掩盖失败。

可单设固定错误表达前缀的修复压力测试，使系统面对相同已听历史；该测试仅分析恢复能力，与自主运行的主结果分开，不用人为制造的改口证明整体系统更好。

## 3. 优势判定与机制证据

按[架构文档的共同实验协议](architecture.md#6-共同实验协议)运行直接流式回答、想完再说、完整框架与表达期间关闭思考的对照。固定任务信息与预算，观察完整框架能否在较早交付可靠信息的同时达到更好的完整质量，或在相近质量下更早完成有效表达，并保持可接受的早期错误与修正表现。

真实 trace 需要表明：系统开始表达之后仍有未完成的任务推理，其新增结果在后续边界进入表达上下文，并影响了可核验的后续内容。仅发现时间重叠不证明因果收益，仍需相应消融；仅最终答案正确、口头展示思考过程或改口更多，也不足以支持结论。两组 benchmark 分别报告结论，不要求合并为一个总分。

## 4. 表达训练数据与训练目标

### 4.1 数据组成与轨迹记录

训练对象、数据隔离及损失边界采用[架构共同约定](architecture.md#7-共同训练与数据约定)。本项构造大规模表达对话轨迹，记录系统开口后的分析继续、结果版本、上下文注入和真实表达，不只收集最终答案。

| 数据类型 | 应覆盖的行为 |
| --- | --- |
| 可靠的早期表达 | 在尚未完成全部分析时，先交付已经有依据的有效信息，避免空泛拖延 |
| 回答递进 | 后续结果增加关键条件、计算、解释或方案，表达依赖顺序合理 |
| 自然发生的自我修正 | 系统确实先说出了错误，进一步分析后明确指出变更并给出正确内容 |
| 无需修正与简单任务 | 直接答对、无需长推理和无需额外调用，不为了训练修正而强行改口 |
| 条件尚未解决 | 表达已有依据的部分，恰当保留不确定性，不提前承诺结论 |

独立任务、对话及轨迹分别计数。组合对话可承接倾听澄清后到达的用户回答，但主 benchmark 仍从完整用户任务出发独立评分；组合数据不将尚未到达的澄清答案提前提供给任一模块。

### 4.2 轨迹生成与审核

1. 构造可核验答案或明确要求清单，标注必要信息点、约束与依赖，并覆盖复杂推理和简单直接作答的对照。同一题的数字、措辞和约束变体按家族划分，防止跨集合泄漏。
2. 在当前任务上下文下生成 Layer 1 请求、Layer 2 分步分析与 Layer 1 表达。Layer 2 只给出内部分析状态、结论和更新依据，不写回答草稿或替换文本；结果到达后才成为 Layer 1 上下文。
3. 保留分析发布、注入、表达生成、提交与播放的顺序。表达期间可以继续完成已有任务，不要求新增用户输入，不用预先算好的完整答案假装在线递进。
4. 核验各阶段内容的正确性与任务价值，剔除冗余填充、无依据承诺、假装改口和表达不利用分析结果的样本。计算与约束尽量程序核验，开放内容按清单审核并人工抽检。

主训练轨迹保留直接正确的回答。自然发生的错误可经审核转成恢复轨迹，但先前错误不当作正确正文目标；需要明确其上下文身份，监督可靠表达与后续纠正，避免训练模型先说错再改口。若另用固定错误前缀扩充恢复训练，应单独标识来源和配比，不能混入主测试的自主运行结果。

紧凑分析状态可以作为候选分析监督；不把公开思维链、层次连接词或回答长度当成质量。数据审核规则不增加运行时语义复核或文本修订模块。

### 4.3 模块监督与结果边界

| 对象 | 本项训练内容 |
| --- | --- |
| Layer 1 请求 | 判断表达期间何时还需要继续分析，不把进展话术当成调用理由 |
| Layer 1 表达 | 利用当前已注入结果生成可靠内容，按依赖组织补充，必要时明确纠正已说出的判断 |
| Layer 2 分析（若训练） | 分步求解、检查约束、发布增量结论与变更依据，标明继续分析或任务结束，不生成候选表达文本 |

Layer 2 结果输入块在 Layer 1 损失中屏蔽，Layer 1 请求及后续表达参与监督；是否更新 Layer 2 权重按架构共同约定决定。训练不设 Layer 3 目标，也不监督文本替换补丁或播放历史回滚。

目标时间顺序依据可行的回放调度。允许标明来源的模拟延迟用于训练，但正式测试必须运行真实推理与播放。分析完成、结果送达和用户听到修正是不同时间，不能用人为指定的理想返回点当作完成证据。

### 4.4 规模与数据验收

数据总量、各类型配比、任务难度、教师模型及语音实现方式待试标确定。验收同时检查独立任务覆盖、信息点可核验性、分析与表达字段分离、因果顺序、最终质量及早期错误，不能只按生成条数或成功修正的数量验收。

## 5. 训练实验与待定事项

按架构共同实验协议固定前端、TTS、语速、输入顺序与可比较预算。表达期间关闭 thinking 流的消融须明确开口时仍活动的 Layer 2 任务如何停止、此前结果是否保留；允许 Layer 1 正常生成，不能把表达能力一起关闭来制造优势。

比较未专项训练、仅表达数据、仅倾听数据与联合训练，并在资源允许时做数据规模实验。本项同时报告有效内容到达、最终质量、总体错误和条件修正表现，检查联合训练是否损害倾听任务；不同模型或额外计算资源的结果另列。

尚待确定：训练及测试规模、题型与难度配比、信息点和依赖标注协议、时间预算、语音对齐方式、开放任务的 judge 与人工审核、固定错误前缀压力测试是否启用。当前不增加 Layer 3，不将这些待定参数解释为候选文本修订能力。
